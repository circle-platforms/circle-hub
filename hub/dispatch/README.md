# 作业派发

本包只实现通用生命周期；远端工具名、参数名、状态词、JSON 指针及核对条件来自管理员登记的 `executor@1` 定义。Hub 不生成用例、工作簿或模型判断。开发和测试仅使用本机回环合成服务。

## 执行器资源（D07）

定义为规范 JSON，保存为内容寻址对象，由 `resource_config` 许可按摘要生效。每次改动生成新定义和许可；禁用不改历史。密钥只存 `executor.<id>.bearer`，不属于定义。管理员权限每次重新读账号状态。明文只允许字面回环地址；HTTPS 必须给出固定 CA；地址不允许凭据、查询串、片段。生命周期工具必须全部在允许清单中。外部状态词可自行定义，映射结果只接受生成词表的 action_result、acceptance、effect_outcome、dynamic_terminal。

## 接口与偏离

通过 `api.ts` 暴露。依赖 records、leases 的公开 API；这一轮获授权扩展记录唯一业务键和只读围栏快照。executor@1 暂在本包定义，待 contracts 主人接收。B06、B07 暂记在 action@1.detail；设备凭据仍由外部执行环境保管，外部接收核验过的字节，而不是引用。

意图键按 B06 的血缘、条目、槽位、次序计算，设计第 4 节的派发绑定摘要另存。管理员保持未知不解冻；标记失败未确认风险时不解冻；明确确认接受可能重复执行的副作用并写原因、记录确认人和时间后才解冻。核对身份、摘要和投递时间窗全相符才能经对账解冻，查无记录不能证明未执行。

## Needs from other packages

- effect@1、request@1 和 executor@1 进入共享 contracts。
- 引擎受理 submit_result 后触发派发；这一轮只由管理员命令触发。
- 作业移入服务进程长期运行；这一轮在命令行进程运行，恢复不得重交。
- 工作簿核验的字段身份、资源键清单与运行时包对齐；远端认证和真实验收由集成者负责。

## 验证

`node --test --test-concurrency=1 'hub/dispatch/**/*.test.ts'`，`npx tsc --noEmit`。基础存储与租约另运行各包测试。合成通过只证明 Hub 分支处理，不证明目标认证、真实执行或设备结果归属。

## 传输（D02、D03、B05）

MCP 初始化后先逐页读取 tools/list；允许清单缺任何一项就停止。其他工具不调用。每次 JSON-RPC 只发送一个 HTTP POST，不跟重定向、不重连、不重试，不发送取消通知；TLS 仅使用定义中的 CA 并核对端点身份。读取有字节上限；超时、断开或超限时先保存已经收到的有界字节并标不完整，再报错。JSON 和 SSE 均先交存储回调，后解释 JSON-RPC 和工具数据。密钥只在 Authorization 请求头；存储前剔除本次密钥的字面量、JSON 转义形式和 URL 编码形式，错误只给固定说明。操作者请求头为作业摘要。测试的证书和私钥在临时目录生成，不入 Git。

执行器还必须固定生产核验要求项所属的包和清单身份；字段指针由定义提供。本轮台架身份为 `{id, manifest_sha256}`，两个字段均逐字核对；物理资源键由管理员从同一份清单登记。不是预期包的同名要求项不作为派发依据。

## 派发前提与意图（D02、D04、B05、B06）

读取指定包的锁定发布定义和最近受理结果：全部必需条目要求项满足，运行级必需要求项有有效支持；派发要求项是必需的函数事实。核验数据的字节和清单摘要都必须在运行绑定来源中，清单身份与执行器逐项相符，用户有效，前驱链可完整读取且同属该用户。逐个核对管理员登记的全部资源的血缘持有者、有效期和围栏；只读核对之后再检查一次。

目标预留采用每个物理资源上的追加记录唯一键，按资源摘要排序，在同一事务取得，避免多个命令行进程竞争。写意图事务同时争用作业提交闸门、血缘次序和 `dispatch.bytes:<S>`；任一竞争失败全部回滚，不提交。恢复关闭提交前作业也争用同一个闸门，旧进程不能随后派发。S 的业务键不因处置删除：每份字节全局至多派发一次。意图带请求 id、notAfter、动作摘要、两层租约绑定摘要、实际署名模式和代表用户。提交期间不因 SIGINT/SIGTERM 发取消，强制终止只能从已写意图恢复，不重交。

## 进程恢复与冻结

回执缺失、提交超时、连接断开、不带阶段的拒绝、受理身份不符、未知状态均追加未知和管理员处置请求，并保持物理目标冻结。已受理但没有终态的作业只恢复状态和结果读取；有意图无回执的绝不重交。冻结和目标占用由追加动作记录推出，不另建冻结表。按相交物理资源检查未完成作业，避免更换执行器别名绕过未知。进程级测试通过标准输入给两个独立 Node 进程合成配置，验证同 S 仅一方成功；另测试提交中强杀和受理后强杀的恢复，调用计数不增加。

## 管理员处置（B07）

保持未知始终冻结。标记失败必须有原因；未带显式风险确认的选择只记处置，仍冻结。带确认时记录原样确认文本“接受可能重复执行的副作用”、确认人和时间，才解除冻结；旧效果的未知记录不改，也不允许重发同一 S。可用新核验字节做后续作业，但历史潜在副作用仍需承担。

对账先用管理员从审计取得的远端编号只读查询状态和结果，逐项核对编号、S、原投递窗口；缺记录、摘要不符、编号不符或时间不符均拒绝且继续冻结。通过后追加处置与回读回执，继续只读状态和结果，不能重新提交。每次处置重新核管理员身份；原始未知动作及摘要保持不变。

## 只读预检与结果（D02、V03）

独立 precheck 只取得目标租约、核对、释放，没有派发意图；预检失败记未发出，不记效果未知。独立预检的预期值来自 `precheck_context`，有预订运行时可取该运行锁定构建；不猜构建。实际派发仍在自己的目标租约内重新核对。

结果必须回显本作业远端身份和 S。逐条记录目标原样词经定义映射得到的报告；结果通道不完整、空条目或未映射值不给判决。“结果按派发身份归属”尚未认证，所以即使目标报告通过，本轮动态层也一律无判定；都带“目标对本次派发的报告”“未排除本地操作”。结果源文件仅运行用户及管理员可读。摘要或身份不符整份不采信并冻结。日志、会话保存在原始源文件中，不作解释。

目标租约按期限三分之一安排心跳，中断单独记录，继续状态读取，不重交；终态后停止心跳再释放。派发后 Hub 围栏变化单独记漂移，不声称保持同一租约。结果包含这些限定。登记时可明确租约期限和提交时间的数值缩放，避免猜时间单位。全产出测试扫描对象、文件和全部种类的记录，确认目标回显的调用密钥也已剔除。

核验事实另含 `plan_run`，按执行器声明的指针读取，必须等于核验运行自己的 predecessor。缺失或不相等时拒绝，提示“用计划运行作 predecessor 重开核验运行”；不会猜计划运行或挪用其他前驱。
