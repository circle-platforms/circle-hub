# 作业派发

本包提供管理员的执行器登记、预检、派发、查账恢复、对账处置和一致性采证，不新增 MCP 工具，也不自动从提交触发派发。Hub 不调用模型、不生成工作内容；只核验已经受理的产物和目标的观察。公共入口为 `api.ts`。

## 模型与范围

按 D02、D03、D04、B05、B06、B07、P07、V03 实现。`executor@1`、`write-declaration@1`、`effect@1` 定义在共享合约 resources.ts；本包只保留调用绑定与运行服务。词表类型和标签来自 `contracts/generated`。目标的工具名、代表身份头、字段指针、阶段词、状态词、命令和收尾标记都来自部署的执行器定义；核心不识别任何产品命令或网关专有字段。

开发只使用临时 PostgreSQL、回环 MCP 桩和合成字节；不能据此认证真实目标。真实协议、固定 CA、设备座位、全部物理资源键、版本别名、日志格式及结果保留规则由集成者核验后登记。

## 执行器与传输

定义固定端点和 CA、资源键、最长运行时间、字节与超时上限、允许工具及各生命周期调用。HTTPS 核对证书；明文仅允许回环。密钥经命名密钥命令的标准输入写入 vault，定义只写 `${secret:名字}`；`executor add` 不读标准输入，`update --secret` 和 `setSecret` 已退役。派发与连接器共用脱敏器，当前和上一版的全部已知密钥及发送形式先登记，再保存脱敏应答和解释。改变字节的接收摘要只进不带运行号的管理员动作；运行者可读的动作不带该摘要。

- `actor: {header, pattern, max_length}` 指定代表身份头及约束。值为原运行用户编号和作业摘要，以 `/` 连接；恢复或管理员对账仍代表原用户和原作业。值不合声明时不发送任何请求；不能覆盖认证和 MCP 协议头。
- `allowed_tools` 必须全部存在。`refused_tools` 中任何工具出现在任一清单页时立即停止，生命周期调用次数为零，原因是“密钥权限超出运行权限”。允许和拒绝清单不能重叠。
- `calls` 声明 acquire、heartbeat、release、precheck、submit、status、result，以及可选的 query。模板的 `{$value: ...}` 绑定 Hub 的事实；真正的内容参数由 `payload_argument` 定位，必须且只能绑定一次 `payload_base64`，其他角色不能携带它。
- 启用请求协议时 submit 必须各绑定一次 `request_id`、`not_after`；query 必须绑定原 `request_id`。`receipt.request_id` 是回显指针，必须与意图逐字相等。
- JSON-RPC/SSE 先交存储回调再解释。每次调用只发一个 POST，不跟重定向、不重连、不在传输层重发提交、不发取消通知。截断、超限和超时的已有字节仍保留并标不完整；SSE 可在完整匹配响应边界停止接收，不能假称读完无限流。
- `read_retry_when` 复用条件表语法，声明哪些明确的工具拒绝可安全重读（例如部署声明的“忙且未触达”条件；具体字段和值全由定义提供）。默认不重试明确工具拒绝、认证 HTTP 错误、完整协议错误或本地存储失败；停止该批后续探测，不反复登录。网络和暂时性 HTTP 失败最多自动重读三次。
- 工具错误的原件同样先保存。只有提交角色允许解释这种回答中的结构化拒绝；只读工具错误仅在明确的安全重读条件满足时重读，不能当作“查无记录”。

## 变量、命名密钥和固定定义

`ExecutorSource` 保留完整引用并补默认值；登记摘要指向它。普通变量只准用于 `target`、`manifest_sha256` 及主条件、附加预检条件的期望值，指针和其他字段不许引用。解析后严格通过 `ExecutorDefinition`，变量不能引入 `$value`。登记在同一事务取得排序名字锁并重核决定；密钥可以尚未设置。

每次开会话按 `credential` 的名字取当前版本，核对执行器、完整 endpoint 和 CA 的登记指纹。换值不用重启。没有引用、没设置、已撤回或未登记此地址时不发请求，给出迁移或 `secret set --name`；恢复、对账缺钥匙只追加缺口和 `job resume` 下一步。旧 bearer 迁移先写新条目，再原子写密钥和源定义决定，成功后删旧条目；迁移与改 endpoint、CA 分开做。

作业固定源摘要、解析后摘要及每处普通变量的决定；解析后定义单独存成对象。提交前再核源摘要及当前解析后摘要，不同就拒绝，提交为零。登记更新、预留和意图按同一顺序取得执行器、资源、目标与来源配置锁；写意图的同一事务再取得原变量名字锁，重核配置及变量决定，封住最后一次只读检查以后的变更窗口。身份或资源重绑还在这些锁内重核占用，不能靠并发更新绕过。写意图后，当前变量只用于发现漂移，绝不替换原变量决定。物理资源改名也要核对原执行器及旧资源上的未完成、冻结作业，不能绕开处置。

集成者于 2026-10-24 确认以模型 D02 R[6] 保留兼容的只读修补：允许管理员更新读取策略和认证，但用原作业固定的变量决定解析，固定派发字段逐项相同才采用；新修补另存对象，追加源摘要、解析摘要和变量决定。新变量名字缺原决定、旧值不合新模式或派发字段改变时，记录拒绝修补及下一步，继续使用原定义，不取当前变量。这样认证以后仍能重读原作业而不重交。任务页“意图后整份定义不再解析”的文字按这次确认收窄为不采用当前变量。

`executor list` 保留源摘要的原行前缀，另列解析后摘要及变量版本；无法解析的停用定义仍列出源摘要和 `var set` 下一步。管理脚本第零步按源模式补默认值并比源摘要，通过管理员 `var show --value` 取得普通值后独立算解析后摘要；只在私有命令采证文件保留输出。每次派发前同时复核两个摘要。

## 核验依据、资源和意图

核验运行必须属于指定包，最近提交已经受理，所有必需要求项满足。本轮只接受一个明确目标条目及一个用例。只采信 `proof.warrant_id` 指定函数、指定要求项的有效支持事实；其他支持事实不参与产物比较。核验字节必须占据声明的待判定产物槽，清单也必须绑定该运行。计划运行必须等于核验运行的 predecessor，不能猜测或替换前驱。

运行用户有效、前驱链同属该用户；全部物理资源按血缘持有，期限覆盖最长运行时间，围栏在只读核对后再次检查。相交资源上的未完成或冻结作业阻止新派发。目标预留按资源摘要排序，在同一事务用唯一键争用，不能换执行器别名绕过冻结。

意图先持久化再发出：包含意图键、尝试号、请求 id、notAfter、实际动作摘要、S、目标键、Hub 围栏、目标租约、服务署名及代表用户。意图键由血缘、条目、槽位、次序确定；请求 id 为该键加 `:<尝试号>`。提交前先按目标公开 schema 核参数名、必需字段和本地字节预算，不把额外参数被目标忽略后的旧式调用当作请求协议调用。此检查不替代目标的完整值约束核验。提交闸门、次序和 `dispatch.bytes:<S>:<尝试号>` 在同一事务写入；失败不调用。旧版没有尝试号的 S 唯一键仍阻止重交。

相同 S 只有在此前每次尝试均明确结束为 `target_rejected` 或 `proven_not_executed`，而且运行、已核验输入和实际提交调用不变时，才允许新尝试。认证、只读核对、轮询和超时等观察配置可更新；不静默改绑内容、目标、提交参数模板、代表身份头、物理资源或核验运行。每次仍重新核对当前前提。新尝试沿用原意图键，递增请求号。已发出、已生效、未知或只有风险处置的尝试都不能再次派发同一 S。

## 请求记录、拒绝与恢复

`receipt.stage/reached_device/stages` 声明拒绝字段和阶段映射。只有明确映射到 `target_rejected`、受理字段表示拒收、是否触达字段严格为 JSON `false`，并且该会话版本的请求记录前提有效时，才记“目标拒绝”、释放目标租约并解除冻结。其他情况保留未知及原件，明确缺什么和管理员的下一步，不能重交。

`reconciliation` 声明 found、state、request_id、sha256、id、stage、reached_device 及日志身份/主体指针和状态映射。gateway_time、gc_before、journal_since 及结果 submitted_at 等时间仅作记录，不参与受理、负面证明或管理员对账；旧 clock_skew_ms 也不再放宽或限制结果。pending_states 仍按登记值完全相等识别并按 Hub 自己的有界窗口重读。

提交断开、超时或提交中进程退出后：

1. 活命令自动等到 notAfter，再按原请求号只读查询；已退出进程用 `job resume` 走同一路径。可安全重读的查询失败自动重读最多三次；只有下文显式认证的重试类允许一次同键重发。
2. 查到已发出的正面记录，且请求、摘要、远端编号相符，reached_device 严格为 JSON true，就追加回读回执，继续状态和结果读取。正面记录不要求负面证明的认证。处理中尚无开始标记时的 null 只表示缺开始事实，不转换成 false，也不凭状态映射或编号代替开始标记；明确 pending 的状态继续自动查询，超过窗口请原操作者核对处理进程。
3. 查到明确未触达的拒收或未启动记录，只有当前版本请求记录前提有效时才采用。
4. 查无记录一律不能凭跨机器时间顺序证明未执行：可能有在途请求或已回收记录。保持未知、冻结和原件，按原请求明确拒收/未启动的记录或管理员具名处置解决；绝不重交新请求。
5. 状态、身份、摘要或保留边界不足，或者连续三次读取失败，保留冻结，指向原件和管理员恢复/对账动作。没有源记录的“没找到”从来不是未执行证明。

已受理作业的状态和结果读失败只重读原作业；读不到时追加待恢复动作。未完成作业的恢复和管理员对账可采用当前已授权的观察规则修正，但只在目标、CA、提交参数及物理资源仍绑定原操作时采用，并另记读取定义摘要；不会偷偷改绑原操作。恢复还核实原目标租约，核实不了则记录连续性未证明；不把它当成新提交。未知状态、内容不符仍冻结。管理员可按远端编号只读对账；保持未知不解冻，标记失败须原因，显式接受可能重复副作用才解除风险冻结。旧结局不改。

## 目标版本前提与一致性采证

`premises.request_journal` 和 `premises.result_ownership` 各为 `{version, evidence: [src引用...]}`，默认没有认证。每个会话从 initialize 保存目标版本；只有当前定义的目标、端点和 CA 与原操作相同、版本逐字匹配、证据仍可读且摘要正确，才采用该前提。使用时追加版本、定义摘要和证据引用，便于重算；更新认证不改已冻结的操作定义。

请求协议的声明增加 `reconciliation.protocol_versions`（管理员确认支持该协议的精确版本列表）、`reconciliation.identity` 和 `receipt.identity`。两处 identity 均为 `{epoch, since, subject}` 三个 JSON 指针：部署分别指向查询和投递回答中的日志身份、可靠记账起点、完整解析主体；since 沿用 time_scale_ms。字段位置可以不同，核心不固定目标的字段名。投递前在已取得的同一远端租约、同一 MCP 会话及代表身份下，按将要投递的请求号查询一次；只接收尚不存在且边界完整的回答。身份、完整主体、发送会话版本及查询/initialize 原件引用随意图冻结；投递回答和后续查询都须逐字对应。日志重建、主体或起点改变、字段缺失时保留未决，请具名管理员人工核对原投递事实、原日志及调用身份，不重复提交。

旧定义仍可读，缺少上述声明时不得开始新的请求协议投递。旧意图没有投递前快照或发送会话的协议支持事实时，升级后的查询会话不能追认；查空不产生未执行证明。conformance 仍只做四次协议调用，同时核各次日志身份、记账起点和主体的一致性，不自动认证。

`conformance: {expected_stage, payloads}` 只保留为历史定义的兼容字段。当前采证只读，不外发探测字节；完整前提认证须由管理员登记受限审计证据，见下文 P11 与一致性采证。

## 逐座位只读探测

探测只由执行器定义声明，Hub 发出。形状如下，工具名、命令和字段均为合成示例：

```json
{
  "probes": {
    "devices": "/devices",
    "dispatch_targets": {"type_field": "/type", "types": ["load-balancer"]},
    "command_pattern": "^inspect (?:version|interfaces)$",
    "call": {
      "tool": "inspect_seat",
      "arguments": {
        "seat": {"$value": "seat_index"},
        "command": {"$value": "command"},
        "ticket": {"$value": "lease_id"},
        "guard": {"$value": "lease_token"}
      }
    },
    "output": "/output",
    "seats": [{
      "seat": "synthetic-seat-0",
      "index": 0,
      "manifest": {"device": "/devices/0", "addresses": "/interfaces", "address": "/address"},
      "version": {"command": "inspect version", "pattern": "^version: (?<value>.+)$"},
      "interfaces": {"command": "inspect interfaces", "pattern": "^address: (?<value>.+)$"}
    }]
  }
}
```

每个声明座位必须同时有 version 和 interfaces；座位和序号不得重复。call 必须各绑定一次命令、序号和目标租约身份。两条命令都先匹配 command_pattern；每条提取正则恰好一个命名分组，按多行全局匹配取值。没有额外的“用途”枚举。所有真实座位和命令由转换脚本从运行环境配置起草，管理员核对后登记，不能拿示例命令当真实命令。

**哪些设备是派发目标由声明决定，不由名字或关键词识别。** `devices` 指到绑定清单里的设备数组；`dispatch_targets.type_field` 指到一台设备里声明类型的字段，`dispatch_targets.types` 是派发目标的类型闭集，按完全相等比较（P07 R[1]、C07 R[4]）：只有类型在闭集里的设备是派发目标，只有它们必须有探测座位，座位与目标一一对应。清单里其余设备（真实台架里的路由器、客户端、服务器、控制台等；编译要用它们的地址做绑定，所以清单必须列全）不做版本探测，只按清单身份参与拓扑和地址绑定，也不派发命令；预检回答用 `unprobed_devices` 按清单位置和声明类型列出它们（CLI 写“未探测（非派发目标）”），探测报告原件里的同一份清单叫 `unprobed_non_targets`。设备缺声明的类型字段、或类型不是文字时停止采证，写明缺的事实和下一步（管理员按清单模式补齐类型字段，或在定义里改用显式派发座位声明），不按名字猜它是不是目标；声明了 `dispatch_targets` 却没有任何设备命中闭集时同样停止（没有派发目标就不能采证派发）。未声明 `dispatch_targets` 的旧定义保持原规则：清单里的每一台设备都是派发目标，都要有座位。

manifest.device 相对于绑定清单；addresses 相对于选中设备；address 相对于地址列表中的每个成员（成员直接是文字时用空指针）。清单从运行绑定的同一摘要读取，不把地址复制进定义。接口比较只比 IP 集合，CIDR 前缀用于验证格式，IPv6 规范化后比较；缺地址、多地址、非法地址均不通过。没有匹配文字是确定的“回显里没有”，不是未知。

version 的单个提取值须逐字等于锁定构建的名字、基础名或知识库记录的同基础构建别名；正则应把格式空白排除在命名组外。CLI 通过公共知识端口注入查询；基础名优先取运行 target_basis 中 Hub 当时锁定的 base；知识根内容更新不改变构建名字归属，不用当前知识根替换运行锁定根。没有知识端口时只核锁定名字，不猜别名。独立预检要核别名时需给 booking，或在 precheck_context 绑定产品和构建；缺事实就停止派发并说明如何补齐。

独立 precheck 和实际 dispatch 都在各自同一个目标租约里逐座位执行。可重读的失败自动重读三次；明确拒绝未匹配安全重读声明时立即停止后续探测。仍未取得必要原件时记未发出；实际值、期望和原始回显只进运行用户及管理员可读的源文件，动作说明给座位、version/interfaces、缺什么和下一步。全部通过后还会重读当前核验支持事实，过期或内容改变时不写意图；写意图时绑定这次新读取的核验记录。实际派发不能复用以前一次 precheck 的结果。

## 结果、运行器声明与动态层

结果先核远端身份及 S，不符整份不采用并冻结。每个输入条目只取唯一对应的报告，额外、缺失、重复或不完整条目不给动态判决。目标原样词按定义映射，另存 reported_terminal，不能冒充 Hub 的事实。

`result.request_id/log/closing_marker/sessions` 分别声明结果请求回显、每条日志、字面收尾标记和会话位置。动态 pass/fail 要求：结果归属前提在当前版本有效；请求、远端编号、S 相符；通道和条目完整唯一；唯一归属目录的日志含收尾标记；本次同租约逐座位观察通过；围栏和租约连续性没有中断。任何一项不足都记 no_verdict、integrity_unproven，列 missing_facts 和补证动作。

此外 `result.ownership: {pointer, value, reason}` 声明该结果回答的归属字段、唯一归属的精确目标取值和原因字段。只有当前结果明确等于这个正面取值，且版本归属前提有效，才满足 owned；缺字段、否定值或未登记值都不通过。运行结果保存这一项的观察和原因，不把版本认证当成本次唯一归属的替代。缺唯一归属时，下一步是具名管理员检查原派发日志、收集器目录和保留证据，恢复归属或明确登记该版本的能力缺口；重复读取本身不能恢复已丢失的归属。

所有者已明确 D02 R[5] 与本轮判定的边界：共享目标仍未排除本地入口时，满足上述条件可给 pass/fail，但 qualifier.nature 为 judgment，带 local_ops_not_excluded，accepted_as_fact 为 false，不作为只接受事实的根据。这个选择集中在 `dynamicDisposition`，没有在多处放宽。结果始终带“目标对本次派发的报告”和“未排除本地操作”。首个真实用例在结果归属认证前仍无判定。

`side_effects: [{message, marker?}]` 只记录证据边界。给 marker 的在声明的本次已保存日志/会话字节中查字面量，写“本次日志里有/没有这一项的标记”并给引用；不完整结果仍照写覆盖范围，不推断动作是否发生。没有 marker 的写“运行器会这样做（执行器定义声明，Hub 看不见）”，附 declared 和定义摘要，不把声明提升为观察事实。

## 管理命令

- `executor add <文件>`、`update <编号> <文件> [--secret]`、`list`、`disable <编号>`；密钥只从标准输入读。
- `job precheck --executor <编号> [--booking <运行>] [--save <仓库外目录>]`。
- `job conformance --executor <编号> [--save <仓库外目录>]`。
- `job dispatch --run <核验运行> --executor <编号>`；`status|resume <作业摘要>`。
- `job dispose <作业摘要> --reconcile <远端编号> [--numeric-id]`，或 `--keep-unknown`，或 `--mark-failed --reason <说明> [--accept-possible-duplicate-effects]`。
- `bed baseline record <执行器> --probe <id> [--reason <说明>]`、`bed baseline list [<执行器>]`、`bed baseline show <执行器> --probe <id>`。
- `bed hold clear <执行器> --reason <理由>`：管理员结清该执行器上一次留下的未结清床面占用。理由必填且为一行。没有未结清占用时说明这一点，不写记录。记录只追加，不改原来的 open 记录。未恢复时它和“按清单处理后重开”并列，确认当前状态是干净的（例如设备已重启过、占用时的配置已不存在）才用。

终端只输出阶段、码、摘要、引用及补证动作，不打印目标正文或实际接口值。导出使用 0700 目录、0600 编号文件和排他创建，不覆盖已有文件。checksums.json 给原件摘要、操作名、座位/核对项、声明的提取位置及基于 records RFC 8785 的内容摘要；预检导出也包含逐座位的原始回应，不只主核对和缓存来源。字段缺失时仍能给原件字节摘要，不捏造内容摘要。剔除密钥前的接收摘要、是否转换和 SSE 接收边界另在动作里。跨包只通过 api.ts 调用。CLI 关闭自己持有的租约数据库池；外部注入服务仍由调用方管理。

## 床面快照与恢复

执行器可以声明 `bed_state`：一组只读快照项。每项给出调用、输出指针、首尾去除字面、清理执行者及命令；亦兼容声明旧版解析器。新口径参照成熟框架处理设备回显的标准方式：**回显永远当原文，不做结构化解析（capture + compare same）**。先前合入的 `text_table` 等结构化解析代码保留不删，但床态门不再依赖它们。

- 原文抓取与首尾去除：每个探针声明 `seat`、只读命令 `call`、取原文的指针 `output`（默认 `/output`）和要去掉的回显首尾字面 `lead` / `trail`（只按声明的逐字字面比对去除，例如命令行回显与提示符行 `DEVICE#`，不用正则或关键词）。
- 跑前残留检查：跑前抓取与该探针的“登记基线”原文逐字节相等。基线由管理员在床干净时登记（`circle-hub bed baseline record <执行器> --probe <id> [--reason <说明>]`，亦支持 `circle-hub bed baseline list [<执行器>]` 和 `circle-hub bed baseline show <执行器> --probe <id>`）。不等时阻止派发并列出逐行差异和出口（清理后重抓，或管理员确认当前状态为新基线并写明理由）。没有登记基线的探针：只做跑前跑后对比，跑前门照实记“未登记基线，无法判残留”并给出口，不当成通过。
- 跑后恢复核验：跑前抓取与跑后抓取的原文逐字节相等（存入原件摘要与引用）。相等时判定为 `restored`，结果去掉“未排除共享床影响”；不等时给出逐行差异作为证据，挂在作业结果上，标记为 `unrestored` 并维持“未排除共享床影响”与“床面未恢复”，阻止该床的下一次派发，直到后来的预检恢复干净，或管理员确认当前状态干净后用 `bed hold clear` 结清。未恢复的下一步同时给出按清单处理后重开，以及“确认当前状态是干净的（例如设备已重启过、占用时的配置已不存在）才用 `circle-hub bed hold clear <执行器> --reason <理由>`”。下一次门按交集比较：两边都有的探针比占用时的原文；现在有、占用时没有的探针比登记基线，没有基线就写明缺基线和 `bed baseline record`；占用时有、现在没有的探针不比较，并写明没有比较。交集为空，或两边探针集对不上而无法比较时，说明上一次派发留下的占用未结清、两边的探针集，下一步是 `circle-hub bed hold clear <执行器> --reason <理由>`。只有这次确实没读到的探针才写“探针缺失”。
- 结构化解析兼容：先前合入的 `text_table` 解析、设备基线收窄及 `snapshot_only` 代码保留；未登记基线且仍带有历史完整结构声明与清单的原件仍可走历史解析路径。

派发在写入意图之前取 pre。解析只走声明的指针和地址结构；探针输出里的其他文字不参与比对。冻结原件带有床面声明时，残留、空表和清理方式按该声明判断：只有表头的空表不是残留；可自动清理的残留记成一条尚未执行的派发动作，经派发和授权，Hub 不自己执行清理命令；需要交互确认而通道是单发的，阻止派发并给出声明里的出口。没有这份声明时，pre 仍与冻结台架清单的接口地址、基线配置逐项比较，多出来的、对不上的或清单里有而探针没有的都是差异。有差异就阻止派发，原件记下差异项和来源探针，下一步写明由谁按声明的清理命令处理后重开。探针没有按声明解析出结构时记未知，下一步是重读该探针，不把它写成残留。

作业到达终态后再取 post，和同一组 pre 比较。差异为空才算床面已恢复，结果去掉“未排除共享床影响”。差异不为空则结果带“未排除共享床影响”和“床面未恢复”，差异挂在作业结果上，并阻止该床的下一次派发，直到后来的 pre 与当初的 pre 一致。探针缺失同样保留“未排除共享床影响”。目标报告的 pass/fail 不因这道门改写；“未排除本地操作”仍按 D02 R[5] 保留。

## 本轮偏离与后续

- 认证暂放执行器定义，不新增认证记录合约；管理员提供认证，Hub 只核版本、范围与可读取证据，不自动认证真实目标。
- retry_safety 使用生成的四类词表。缺写声明的旧定义按 unsafe 运行；完整声明可启用下文的认证重发策略。
- B06/B07 暂以 action@1.detail 表达，旧记录保持不变；运行状态仍归引擎，本包不回写条目终态。
- 派发由管理员 CLI 触发，尚无提交后自动派发钩子；CLI 中断的查询由 resume 自动继续。一次作业同时只允许一条观察：`serve` 的运行维护会把尚未 complete、结局仍是已发出的作业再调一次 `job resume`。原观察还在读床面时，这次 resume 不开第二会话。作业已经 complete 且床面 restored 后，晚到的收尾不写 open 占用，不把 restored 改成 unknown，也不再 release 租约。
- 目标的全部入口隔离和真实结果归属不能由合成桩证明。第一步网关的真实目录、报告地址、保留规则，以及真实探测和版本认证仍由集成者核验；本分支不部署、不触达真实设备。

### 网关字段复核第 1 条 — 已复现并修复

protocol_versions 声明不替代认证。否定结论同时重核查询会话和原发送会话的证据认证；发送版本还须在当前定义的协议支持列表里。证据按原摘要读取，发送认证引用原意图所封存的来源，不把新查询会话当作旧发送会话。发送版本未认证或已移出列表时保留未决，要求管理员采证、认证或登记协议支持后 resume；旧版无法取得保证时人工核对原投递事实，不重交。两个会话版本不同、以及支持版本被撤回的回归均在改前错误解除冻结，改后保持未决。

### 网关字段复核第 2 条 — 已复现并修复

查询成功的受理字段不表示原请求被受理。查到拒收记录时直接核 reconciliation 的请求、摘要、状态、阶段与触达标记，加身份绑定和两会话的证据认证；不再拿 submit 的受理字段解释查询。明确拒收即写 rejection 与 target_rejected 终态，释放租约；缺认证、触达标记为 null 或日志身份改变仍保持未决。带 ok:true 的拒收查询回归在改前永久未知，改后结束为拒收，后续只允许新的请求尝试。

### 网关字段复核第 3 条 — 已复现并修复

归属观察的 matched 只表示字段值相符，certified 单列，不把未认证伪装成字段不匹配。缺声明时要求登记字段；值相符但未认证时给当前结果源引用，请管理员复核后为该版本登记认证；值不相符时依据源与原因恢复归属或登记能力缺口。完成作业不重读结果，说明不再推荐无法执行的“重读原作业”；本作业保留无判定，认证用于后续核验，不重交。逐条动作同时投射到完成状态，CLI 能看到。三个原因分支及完成后 resume 不重复读取的回归先失败后通过。

### 网关字段复核第 4 条 — 已复现并修复

结果声称唯一归属时，原因字段必须缺失或为 null。肯定值同时带任何非 null 原因是矛盾记录，即使认证有效也不给动态判决；matched 仍反映实际字段相符，consistent 单列，原原因保留并引用原件。说明要求管理员核对协议实现和报告归属，修复矛盾或登记能力缺口。歧义原因、空串和错误布尔类型的反例均在改前得到 pass，改后为 no_verdict；正常肯定夹具改成协议实际给出的 null。

### 网关字段复核第 5 条 — 已复现并修复

投递前拒绝使用固定公开文案的 PrecheckFactError：版本未登记、缺查询/投递身份声明、快照中缺日志身份或记账边界分别给出具体缺事实和下一步。完成记录保留 public_reason、missing_fact 和类型化动作，CLI 的说明与下一步直接可见；不回显目标值。三个反例在改前都没有公开原因，改后状态与 CLI 一致。两会话版本的认证同时显式要求版本相同，不能靠两次读取期间分别登记不同版本拼出否定证明。

复核确认：`credential` 的名字属于原作业的固定字段，不在兼容只读修补范围内。恢复和对账仍可取得这个固定名字的当前密钥版本；修改源定义为另一个名字只记录漂移并拒绝采用该修补，不能替换已发出作业的钥匙名字。状态、结果和认证的兼容只读修补沿用集成者确认的 D02 R[6] 口径，只用原作业固定的变量决定解析。

期望值引用不得进入任何 `$value` 路径段，包括嵌套对象；登记、更新、离线解析和已有定义的 `var set` 都先核对源引用位置。字面的管理员调用绑定仍可登记，变量不能决定其绑定键名；旧的不合格源定义须先通过 executor update 修正。

## D03/P11 contract assembly

`executor@1`, its source-definition validator and `write-declaration@1` now live in contracts/resources. The dispatch module retains runtime binding helpers and ordinary-variable resolution only. Credential references and all existing expected-value positions move with the schema; write declarations and environment never accept ordinary variables. A submit declaration uses generated interaction, effect, retry and signing axes. It names a target-key binding, reversibility, audience, read-back tool/pointer, refusal pointers, optional before-state read and Hub-record behavior. Executors admit job effects only, with no external audience and with durable Hub records. Before-state calls cannot use the submit tool.

A historical definition without a write declaration retains the existing job/service-on-behalf semantics and unsafe retry semantics; executor list explicitly reports 写声明未写. Environment is not guessed: an absent environment prevents dispatch until an administrator updates it. Ordered multi-step writes are outside this round. The request-record integration remains pending hub-unknown-exits; existing action details do not stand for a sent durable request.

允许的效果表随 requirements.json 冻结。资源种类和动作是通用 executor/submit 协议角色，不是目标工具名。参数范围只针对通用作业参数 target、manifest_sha256、build、sha256、items、generator；可以列取值集合，或绑定 policies/ 表及编译时同一个检查。政策引用要求正反例齐全，发布仍运行样例。触发方式取生成词表。运行者收窄效果表不在本轮；包未声明效果表时发布行为兼容，但派发边界不留下旧路。

全局政策表在 policy/boundary.json，按生成词表的效果类、可逆性与环境逐格列出。生产只允许 none/read，测试和共享另允许 job；同步写与通知全部拒绝。表摘要和逐个变量解析后的执行器摘要在 start_run 用同一次变量快照冻结，真实定义另存对象，运行只保存登记对象摘要。内部端口不借运行者身份列管理员清单，也不读密钥值。

### P11 与一致性采证

`executor conformance` 只读取请求日志身份、主体、时刻与保留边界，导出受限原件。管理员给的探测字节没有核验运行，不能满足 P11 第 8 款，因此不再提交这两份字节，也不写 `probe_intent`。缺少的过期拒收、同键去重等事实，由管理员从目标自己的受限审计记录只读取证，连同版本与证据引用登记到 `premises`；只读查空不自动认证这些前提。已有探测意图的历史对账继续支持。

### 有序边界、预算和效果快照

写意图前按 P11 的九款依次核对，前款拒绝不运行后款。效果行、通用参数、放行事实与预算先在准备阶段核一遍；提交前完整重核，预算还在写意图的同一事务中以（运行、行号）加锁复核。只按已经写下的意图累计次数和最长运行预留时长，不用远端成功与否归还额度。参数匹配多行也拒绝，不能挑预算较宽的一行。拒绝记 dispatch 动作、固定码、款号、效果行及其要求项，effect@1 为 not_dispatched，对方提交次数为零。

政策版本和所用执行器解析后摘要必须与开跑快照相符，缺环境也在此拒绝；别的执行器更新不影响。包政策重核通过 runs 的只读端口复用 evaluate 的被判对象、冻结包脚本与表，不增加提交或修复轮。生产核验结果以原运行记录摘要识别，仅全事实包且摘要与受理结果相符时按原生产路径重核；普通提交仍须解析原提交，不能用任意摘要冒充生产结果。内容只发绑定原件，不重新生成外发内容；摘要、支持事实和当前完整凭据扫描都须相符。XLSX 同时解析完整模型、逐个读取有界安全解压的所有成员，扫描原文及 XML 模型；未知二进制成员或任何不完整扫描都拒绝。作业的 audience 固定 null，没有通知/评论的外部受众空间，第九款在此不启用受众写入。

声明 before_state 时，在提交的同一远端租约下只读一次并比较绑定值；不相等就未发出。仅在 conditional_write 为真、premises.conditional_write 的目标版本与证据已认证、提交参数恰好带一次 before_state 时记已绑定；只读比较通过而目标不支持条件写，仍记未绑定前状态。写声明的 target_key 用同一份核验事实绑定并取摘要。

丢回复按 `Record<RetrySafety, …>` 的全表处理。same_key_safe 须 premises.retry_safety 的版本与受限证据认证；dedup_window 还须 premises.window_resend 的显式认证及 window_ms 时长，并在该窗口与原投递截止的较早者之前；duplicate_tolerant 认证后最多再发一次，追加 possible_duplicate；unsafe 和任何前提未认证的类只读原请求/结果，不重发。重发复用相同意图键、请求号、截止与原字节，再核 P11（自身已花的意图预算不重复扣）。任何重发前提失败都不能抹去第一次投递：继续原请求对账。

effect@1 随意图、回执、终局与处置追加快照，保存上个快照摘要，原 action detail 保持可读。未分配意图的边界拒绝，其请求号、截止、动作摘要为 null；未声明或未观察到的目标主体也保留 null，不冒称实际账号已认证。未决快照明确缺的执行事实，出口指向具名发起管理员的 disposition 请求及持久化期限。

## 只读放行诊断

管理员运行 `circle-hub job explain-release --run <核验运行> --executor <执行器>`，用当前执行器登记及冻结核验记录逐条查看第 3 款的每个条件。条件的 `satisfied` 为 true、false 或 null（缺少前置事实、尚未核对）；`fields` 列出字段名、是否相等及两侧摘要，均不输出字段原值或原文。摘要算法为 SHA-256(canonical JSON `{present:true,value}`)，缺值使用 `{present:false}`。这份诊断供定位原因；实际派发仍重新核对九款。

诊断复用实际放行的条件函数，不连接执行器、不加载密钥、不调用参数政策重放、不预留资源、不写意图或作业记录。退出码 0 表示至少一条适用效果行的第 3 款条件满足；退出码 1 表示仍有未满足或未核对条件。每行的效果行身份也只给摘要。

真实放行被拒时，用户仍收到中性 EFFECT_RELEASE_UNMET。管理员日志逐条写失败条件及字段摘要；`job dispatch` / `job status` 的“管理员放行说明”从管理员专属产物读取完整条件。普通运行投影去掉该说明；原文、异常消息和字段值不写入说明。意外异常只保留发生的检查位置及异常摘要。日志或说明保存失败不改变拒绝，也不会授权派发。

物理占用查询先定位预留，再按相关作业分批读取完整追加历史（每批至多 128 个作业），不再按阶段白名单漏掉 boundary_refused 等终态。已证明未发出的终态作业释放占用，保留原拒绝记录；不需要把它改标为失败或伪造效果未知处置。进行中的预留、未终结意图、冻结和效果未知仍阻塞；旧终态不能遮住更新的意图。明确接受风险的管理处置沿用原规则，不据此声称旧效果没有发生。

## 报告晚到与只读恢复

执行器声明的状态已到可信终态而结果字段尚未完整时，Hub 按原请求读取状态及结果，指数退避且间隔最多 4 秒；每次补报告窗口最多 30 秒、8 次结果读取（传输故障仍受原来的最多三次只读重试约束）。只认声明的 complete、条目和结果字段，不从消息文字猜“正在生成”。身份或摘要不符仍转对账，未声明的非空结果值不当作暂缺报告。

窗口耗尽后保留未知判定，记录 report_pending 和可执行的 `circle-hub job resume <job>`。执行已结束与报告是否齐备分开记录；resume 不再因旧 done=true 直接返回缓存。旧版 no_verdict 快照按 Hub 已保存、绑定原作业与产物摘要的结构化 missing_facts 中 report/complete 缺口识别；不再要求旧网关应答 complete=false、结果字段为空或旧原始应答仍可读取。传输完成且结果字段非空也可能尚无设备判定；管理员 resume 是新的只读补取指令，是否能判定由新应答的完整性、身份和原执行证据决定。补读沿用原请求身份、原件摘要及原执行窗口已有的完整性证据，不把正常释放后的租约当作执行期间失效，也不把真实的原完整性缺口修好。执行已结束后的报告补取不会 acquire/heartbeat/release 或再次 submit；新应答、新结果和更新后的轮次观察全部追加，旧原件不改写。

报告未齐的轮次暂停，不能通过再发下一轮掩盖缺失报告。补读只更新已经提交的轮次，不启动新轮次。多份轮次观察按每轮最新记录展示，历史缺报告记录仍保留。

旧快照未被选作补读时，管理员日志记录 `report resume skipped <job>` 及拒绝识别的结构条件名（例如原件摘要、原请求或归档绑定缺失），不再让“没有发出只读调用”的原因不可见。已知 PASS/FAIL 的完整结果仍可直接返回缓存，管理处置和不相符的归档绑定不会被这个入口绕过。

## 结果字段与可选 sessions

`report` 缺口仅表示声明的结果字段尚未得到通过/不通过映射：先核 `result.complete`，再由 `result.items` 取列表、用每项相对 `item_id` 匹配冻结条目，最后取相对 `item_outcome` 并按 `result.map` 完全相等映射。`sessions` 只收集可选日志，不参与判定；成功用例没有它不会产生缺口。日志中的检查点成功文字也不替代结构结果字段。

对明确声明的 `cases=[{case_id, result:"pass", log, log_stale:false}]` 形状，条目指针为 `items:"/cases"`、`item_id:"/case_id"`、`item_outcome:"/result"`，并需显式声明 `map:{pass:"pass",fail:"fail"}`。后两项相对列表元素，不应写成响应根路径。其他身份、摘要、请求和完整性字段仍按各执行器定义核验。

每条判定的 `report_check` 保留实际组合指针、声明的相对指针、存在性、完全相等映射结果、值摘要和 result 定义摘要。缺失时给出具体字段和修正只读定义后 resume 的出口；作业说明、管理员日志及 Hub 回注也保留该原因。只读定义修复沿用旧作业的写入身份，不重交 submit，不从常用字段名、大小写变体或 sessions 猜结果。

## 序号派发与本机截止（gw-no-wallclock / hub-dispatch-seq）

签发方负责截止：Hub 在写意图后、实际发出前及任何已授权同键重发前，按自己的时钟检查剩余窗口。过期不调用提交，追加 not_dispatched、submit_invoked=false 与修正/重新核验出口。not_after 在 Hub 意图中是本地窗口记录；不要求目标比较它。

每个执行器有持久严格递增的 dispatch_sequence。分配在 PostgreSQL 事务和执行器专用锁中追加独立序号记录，以历史最大整数递增，服务重启或墙钟回拨不会回退；失败可留空号。执行器 calls.submit.arguments 必须各绑定一次 `$value: request_id`、`$value: dispatch_sequence`、`$value: sequence_scope`，后者为执行器稳定身份。序号在准备请求前分配，纳入 action_digest 的完整参数和固定意图/效果记录；多轮派发也使用同一个持久分配器。原血缘 sequence 另行保留，不能充当执行器序号。

升级旧执行器登记时，将绝对截止参数绑定替换为上述两个序号绑定（网关参数同名），重新核验当前协议和执行器身份；旧定义缺序号绑定会明确拒绝，不能静默发出。远端查询支持传 sequence_scope 查看 sequence_floor。网关以认证主体和执行器序号流隔离回收线，显式按序号回收；旧截止收到时只记录并注明 not_after_ignored，低于或等于回收线及重复请求都不会再执行。跨系统旧墙钟查空规则已退役。

网关租约使用本机单调 TTL 和本机启动身份；Hub 只消费相对 ttl_ms 并从自己的接收点计时。回执、结果、起点和墙钟都不是有效性判据；日志身份仍由不透明 epoch 与认证主体完全相等核对。
