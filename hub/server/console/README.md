# 控制台视觉统一

依据决定 92 与任务页 `docs/hub-r4-tasks/console-visual.md` 的 Claude 审查结论。这里记录控制台自身的实现边界；阶段进度由集成者记录。

## 设定、字体与标志（第一块）

- 运行 `node tools/gen-console-style.ts`，从共享设计目录的 `tokens.json` 和原样的 `components/bundle.css` 生成 `style.generated.ts`。`node tools/gen-console-style.ts --check` 检查漂移；`style.test.ts` 对照完整源文件与生成文件，放在控制台目录以纳入常规单元测试的发现范围。运行时只导入生成模块，不读取设计文档，也没有构建或网络依赖。
- 深色是 CSS 基础值，未显式选择时跟随系统。`theme.ts` 的固定脚本在页头、样式之前执行，恢复浏览器本地的选择；界面为“跟随系统 / 浅色 / 深色”。存储不可用仍可切换本页；关闭脚本时隐藏控件，CSS 继续跟随系统。不同标签页的选择通过浏览器存储事件同步。
- `html.ts` 继续按内容哈希允许固定资源：样式、主题脚本、按需加载的实时模块。主题脚本不请求网络、不订阅 SSE；CSP 不允许动态样式、事件属性、任意脚本或外部资源。未认证页面也能切换主题，不读取账号和区域数据。
- 字体仅为系统字体与共享组件中 `Circle CJK` 的本地字形，中文调整为 92%，不合成粗体；旧布局中已有字重一并归到 400/500/600。表格数字与时间用等宽字体，统计大数字保留正文字体。轨道标志使用 `ch-hubmark` 和共享品牌设定；favicon 的原始字节未变。
- 模型词表值仍从生成的 `ui` 标签读取；静态文字留在控制台代码中，遵守共享规范。第六块才修改模型并生成合约，由 Claude 安排与同步分支的合并顺序；不增加静态文案登记表。

## 当前限制与后续需要

第一块替换了旧调色板，接入完整共享组件样式。`style.ts` 中的 `LEGACY_CSS` 暂时保留既有布局与未迁移页面的选择器，只通过共享设定的别名取色；没有第二套深浅颜色表。第二至第五块迁移框架、知识库/工作流、其余区域与图表交互时删除相应旧规则，不能把该兼容层算作最终完成。

目前八区与登录相关页面仍是既有布局；全量截图、对比度与渲染页面用词回归在第六块完成。本块的 Chromium 核对使用直接由 `page()` 渲染的合成页面，证明主题与 CSP 行为，不是八区完整视觉验收。共享规范与摘要只读；它们若需更改，交 Claude 同步两仓库。第一块没有向其他包提出新接口需求。
