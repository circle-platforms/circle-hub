# case-review-report（评审终稿）

每次用例评审的最后一步，单块也一样：绑定同一份目标脑图和各块已受理的独立复核记录。
Hub 只按固定规则排出已核验数据的视图，模型只提交简短的总体意见与等级理由，不新增评审维度。

## 决定（集成者 2026-10-23，决定 35）

- 表在投影里排：用例文字来自 target 的 kityminder@1 模型；发现、处置和建议是已受理复核记录里的原声明。
  排法不增加主张；模型判断与 Hub 自己的字面、目录事实分列，模型名取结论声明。
- 测试子项是用例往上第一个既不是用例、也不在用例内部的节点，找不到用文档根；
  嵌套用例跟随外层用例所在的子项。表和行按文档次序，块顺序不影响字节。
- 位置优先按已解析的 /location 引用，没有时按提交条目；先碰到已评审用例就进该行，
  先碰到子项就进子项的说明行，其余进入跨子项。建议按目标 grounds 落点合并；
  没有目标引用则明确写“没有写落点”，由复核包阻断并要求补齐。
- 没有发现、Hub 核对问题或建议的子项折成一行；存在这些信息时保留整表，避免折叠掉信息。
  review_tables 是给最终回答的折叠版；只有完整表不同于折叠版时才另存 review_tables_full，否则 review_tables 本身就是完整表。计数放 review_counts。
- Hub 核对仅列源角色 subject、函数产生的反驳，且原要求项静态层明确归责 author_input。
  反向用例的预期反驳没有这项归责，不列成输入缺陷。“无”只表示没有这类已存问题，不是总体通过。
  复核包保留原声明、原层结果及 rec: 引用，不重判或改写事实。旧复核缺快照须重做，不能推断为空。
- 转义只有固定规则：反斜杠、反引号、星号、下划线、方括号、左尖括号、竖线、波浪线、& 前加反斜杠；
  原有 ↵ 也加反斜杠，换行显示为 ↵。解码后除 CR 和 CR LF 统一为 LF，文字可原样恢复。
- 结论和等级仍按各块取最差；同样最差结论取复核格式表中最差的等级；结论和等级仍并列时，按原记录引用的字节序取最小者，输入块顺序不影响表格或整体引用。
  缺结论、等级、条目或 Hub 快照时不排表，明确指出缺什么及补齐、重开终稿的动作。
- 终稿不再逐条引用发现，不再另交 suggestion；三段式建议及目标落点由复核包检查。
  最终回答原样贴表，再贴已受理的简短总体意见和证据缺口，最后给控制台运行页。

## 限制和接口

- 格两端的空白在 Markdown 渲染时不显示；备注不列。
- 只排各块已交付的用例；没有进入任何一块的用例不在表中，不能把表的计数当成整份脑图的覆盖证明。
- 模型发现和建议的业务内容未经平台验证；Hub 核对的是位置、引文、处置一致性及既有的确定性检查。
- target 改必填，precondition_priority 为 1..9 的整数或 null，默认 3，与初评保持一致。
- 终稿条目固定为 items[0]；get_nodes 读 #/items/0/fields/review_tables，按返回的继续信息读完。
  运行页以通用字符串字段区保留完整值；核心不出现测试子项、用例等工作流专用字段名。
- tests/acceptance/26-review-report.test.ts 用真 Hub、临时 PostgreSQL、合成来源和脚本模型验证；
  真实 Circle 里的呈现由集成者验收，本包不以合成验证代替它。

## 2.0.2

准入按生成词表判独立性，先核对复核包身份；嵌套用例按完整源结构归组，不依赖外层用例是否交付。未决状态写明层终态、原因和已存的缺失事实，先执行复核回答中的证据补取动作再重核；缺判断时先提交判断，独立性未知时另开独立会话，可修复错误保留原回执的 fix。词表码、类型、标签、守卫和 labelOf 由 tools/gen-contracts.ts 的通用包轴登记表生成在包内，既有包的码/类型快照字节不变。

## 2.0.1

每条源反驳单独检查 statement.data.expected：即使同要求项的静态层归责 author_input，expected:true 的期望结果也不进入初评事实快照或 Hub 缺陷栏；整层归责不能替代逐条判定。

终稿准入先检查已存结构化状态：复核仍有错误、已交付条目仍有未满足要求项，或复核模型独立性未知/不成立时，返回 block_unsettled。动作先修复重交原复核，轮数耗尽或独立性不足则另开会话、换模型家族重做，再用新回执开终稿。无落点的展示规则不构成绕过阻断复核的特例。

子项说明与最后一条用例表格行之间固定留空行，确保 GFM 把它们作为子项说明而非伪造的用例行。

排表先把位置映射到目标节点。不同条目号交付同一节点时，按节点拒绝 overlap 并指出两块与两条目；不可解析的位置拒绝 target_mismatch。纯排表函数返回结构化成功或拒绝，不抛可修正条件的普通 Error，也不从消息猜错误类型。

完整投影（而非单条表格字符串）按 JSON 的 UTF-8 字节数限制为 8 MiB。删除未被检查使用的 findings 和逐条 dispositions 重复正文；达到预算时返回带实测字节数的 too_large，要求分块独立复核、分批终稿并明确范围，不删内容或静默截断。

缺快照按结构化版本区分：只有锁定复核包低于 1.1.0 的块提示补新版快照；当前版本缺处置支持事实则按该回执修复重交，不误称升级。摘要先给动作，再列有界的块/条目清单；完整缺口清单仍在冻结字段中。尚有处置驳回的块已在准入处按其真实错误拒绝。

嵌套边界按初评的源结构规则识别，不以交付清单代替：用例内部的非空 resource 节点在 marked/tagged 两种规则下都是独立嵌套用例，整棵子树不并入外层原文格。内部无标签的优先级步骤仍是步骤。未交付的嵌套用例不凭空增加表行或覆盖计数。

通用控制台字符串字段展示的授权见 docs/hub-r4-progress.md 决定 42。

最终回答容量不足必须明确标“部分”，给出已贴子项表数和原文字符数，并指向控制台与完整原记录。review_counts.characters 冻结原文总长度和每张子项表的字符边界，模型照读，不自行猜计数；空表折叠行也计一个子项。完整字段与折叠字段相同则只存 review_tables。不能贴完整一张时按 0 张说明，不制造半行完整的假象。

## 版本说明

- **1.4.2**：任务包列表中的标题改为“评审终稿”，去掉已过时的“合成示例”标记；检查与报告语义不变。

- **1.4.1**：
  - 仍按提交 pointer 对照 Hub 的 final 支持事实，但整体结论的 `reference` 使用模型 final 主张在结果记录 `cross_item` 数组中的实际下标；两种下标不能混用。验收场景 26 同时核对支持事实和引用指向的模型结论。
- **1.4.0**：
  - 没交付的条目按真实分区名判定（delivered、rejected、quarantined、incomplete 里只要不是 delivered 都算），此前比对的是不存在的分区名 `unfinished`，哪一块都没交付的条目从来不会被列为缺漏；
  - `finalOf` 只采信 Hub 对这块结论给出支持事实（final 要求项、指针对得上）的那一条：被 Hub 驳回或记未知的块，结论记为未知，不再取 cross_item 里第一条带结论码的主张；
  - `finalOf` 的引用改为真实引用（`rec:<结果记录>#/cross_item/<序号>`），写进终稿条目的 `fields.overall.reference`（原来一直是空串）；
  - 缺了块结论（或条目没交付）时 overall 检查记未知（missing_input）并写明原因，不再记驳回；有缺漏条目时整体结论记未知，写明覆盖不完整并列出缺漏条目，不给结论码。等级的并列规则（取第一个最差块的等级）不动，待所有者定。
- **1.3.0**：
  - 各交付条目的摘要（`summary`）写出该条目要引用的发现引用（证实、部分正确、新增）及被推翻条数，超出限额时自动截短并提供位置指针；
  - 终稿条目（`id: report`）的摘要明确给出 Hub 计算的整体结论码与等级（各块取最差，照抄）；
  - `SKILL.md` 明确指引模型直接从开始运行回答复制整体结论、等级及 `rec:` 发现引用，严禁手动拼造引用或通过 `get_nodes` 翻找。
- **1.2.0**：
  - 各块复核结果作输入，Hub 按“各块取最差”算出整体结论和等级；
  - 证实、部分正确和新增的发现一条不漏，推翻的不能引，建议三段齐全；两块重叠时开始运行被拒。

**2.0.3**：缺少块的有效判定或等级、或条目在所有块中都未交付时，在投影阶段拒绝启动并点名块和条目；先复核、重交，再用新受理回执重开终稿。这取代了上面 1.4.0 的整体未知历史行为。已有异常冻结主体缺判定时，检查给可修复的 report_missing 反驳，不能在未知上通过。
