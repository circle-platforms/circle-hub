# case-review-report（评审终稿）

评审方法（docs/hub-r4-architecture.md 第 6 节）的第 6、7 步：报告由初评方用中文写、材料取自复核方；大文档分块时整体结论取各块最差（FAIL 重于 PARTIAL 重于 PASS）。这个包把两步接在 case-review / case-review-verify 后面。

## 决定

- **Hub 算整体，不猜**：`overall` 是事实要求项（生产者 fact），投影把各块复核结果的 `final` 读出来，取最差；等级取最差那块的等级。任何一块没有 `final` 或不可读时整体记未知（缺输入）。
- **按条目合并交付**：真实数据里出现过第二块带全部条目、前半未完成的情形。一个条目在某块已交付、在另一块未完成时，以已交付的那块为准；同一条目在两块都已交付时整次开始运行被拒（重叠）；整份目标里有条目在任何一块都没交付时，整体记未完成并在投影里写出缺哪些条目（绝不当成 PASS）。
- **发现一条不漏、不引推翻**：`report` 的检查核对终稿主张的 grounds 引用了每条证实、部分正确和新增的发现（`rec:` 引用，可解析到本运行绑定的记录），推翻的发现不能被引用，凭空引用被拒。
- **结论等级照算出的**：结论主张的 code 等于 Hub 算出的整体结论、rank 等于算出的等级（直接比对，不做文字匹配），否则被拒（修复 2 轮）。每条建议（code=suggestion）按「补：…；因为：…；期望：…」三段写全，缺一段被拒（修复 2 轮）。
- 各块必须是同一份源文件（锁定构建相同），否则开始运行被拒。

## 限制

- 只总结，不重新评审：终稿不改判任何复核结论；对复核本身有异议走重新复核。
- 推翻的发现在报告里只能以"复核推翻了它"的口吻提及，不能作为发现的引用（`data.findings`）。
- 各块里的证据缺口没写进 `gaps` 的只作提示，不阻断。

## 需要别的包做的事

- case-review-verify 的结果里 `cross_item` 的结论主张（码 PASS / PARTIAL / FAIL，`rank` 是最终等级）和 `partitions` 的交付/未完成划分是这个包的输入，形状变了要同步这里。
- case-review / case-review-verify 的 SKILL 里"分块与报告"一节指向这个包。

## 版本说明

- **1.4.0**：
  - 没交付的条目按真实分区名判定（delivered、rejected、quarantined、incomplete 里只要不是 delivered 都算），此前比对的是不存在的分区名 `unfinished`，哪一块都没交付的条目从来不会被列为缺漏；
  - `finalOf` 只采信 Hub 对这块结论给出支持事实（final 要求项、指针对得上）的那一条：被 Hub 驳回或记未知的块，结论记为未知，不再取 cross_item 里第一条带结论码的主张；
  - `finalOf` 的引用改为真实引用（`rec:<结果记录>#/cross_item/<序号>`），写进终稿条目的 `fields.overall.reference`（原来一直是空串）；
  - 缺了块结论（或条目没交付）时 overall 检查记未知（missing_input）并写明原因，不再记驳回；有缺漏条目时整体结论记未知，写明覆盖不完整并列出缺漏条目，不给结论码。等级的并列规则（取第一个最差块的等级）不动，待所有者定。
- **1.3.0**：
  - 各交付条目的摘要（`summary`）写出该条目要引用的发现引用（证实、部分正确、新增）及被推翻条数，超出限额时自动截短并提供位置指针；
  - 终稿条目（`id: report`）的摘要明确给出 Hub 计算的整体结论码与等级（各块取最差，照抄）；
  - `SKILL.md` 明确指引模型直接从开始运行回答复制整体结论、等级及 `rec:` 发现引用，严禁手动拼造引用或通过 `get_nodes` 翻找。
- **1.2.0**：
  - 各块复核结果作输入，Hub 按“各块取最差”算出整体结论和等级；
  - 证实、部分正确和新增的发现一条不漏，推翻的不能引，建议三段齐全；两块重叠时开始运行被拒。
