# 评审终稿（case-review-report）

每次用例评审的最后一步都开这个终稿运行；不分块也开，verifications 只写一条。
表由 Hub 按已受理的记录和源文件原文排出，是已核验数据的视图，不是 Hub 新写的判断。
报告正文由初评方写简短总体意见和等级理由，不重新评审，也不重抄逐条用例、发现或建议。

## 1. 开始运行

- 这个任务包不绑定产品线：不要给 start_run 的 product、version、build，也不要写进 parameters。
- verifications 每块一条：写那次复核的运行编号，或省略。省略时 Hub 按 predecessor 血缘里的 case-review-verify 运行缺省。Hub 把该运行的已受理结果解析成 rec:，并在回答里写明。不要问人要摘要。运行不存在、没有已受理提交、或不是 case-review-verify 运行时，按修正说明改。仍可直接写复核 submit_result 回执中的 rec:<摘要>，不带 # 指针。
- target 必填，绑定各块评审的同一份脑图；被拒时按修正说明改用 src:<摘要>。
- precondition_priority 与初评一致，默认 3；初评关闭这条规则时传 null。
- 同一用例只能由一块交付，某块未完成但另一块已交付时以已交付者为准。
- 若摘要指出缺结论、缺等级、缺条目或缺初评 Hub 核对快照，先按它写明的动作补齐：
  把那块复核完，或把缺的条目重新初评、复核，再开终稿；旧快照需用新版复核。不要猜出一个结论。

终稿条目在条目列表第一个（序号 0）。整体结论和等级直接照抄它的摘要：
整体结论码 <码>、等级 <等级>（最差那块的，照抄）。Hub 按各块取最差，初评方不另算或改判。

## 2. 提交简短评审意见

所有投影条目都按回执列出的编号处理；没有条目槽位时写 slots: {}。
cross_item 写一条结论主张：nature 为 judgment，code 和 rank 照抄整体结论和等级，
statement 写简短的总体意见和等级理由。grounds 不要求逐条引用发现，可以为空。
证据缺口可另列 code=gap，rank 仍照抄所属报告的整体等级，不另给缺口定级；写明缺什么事实和下一步。能取得的原件先重读、核对，模型没完成的工作先补完，不能当作已完成的缺口。不要再提交 suggestion 主张，建议已由复核方提交并在表里原样列出。

## 3. 读取评审表

- 开始运行回答的“完整的槽位模式”那一行有运行记录的 rec: 引用。使用这条引用，不手拼摘要。
- 用 get_nodes 读取 <运行记录>#/items/0/fields/review_tables。
- 有下一页就按返回的继续参数接着读取，直到读完；不要把截断的一页当成完整表。若当前回答或上下文容纳不下，按第 4 节明确标部分并交接权威记录，不声称未读部分已读完。
- 每页只取“原文…：”那行之后、页末说明和“追踪”行之前的原文内容；表不是 JSON，不要再转录成 JSON。
- 续页的“（接上页：…）”也是协议提示，不贴入表。页头若说从某一行中间继续，就接在上一页同一行后，不添加换行；从下一行起则保留原换行。
- review_tables 中没有发现的子项折成一行；完整表保存在同一记录的
  #/items/0/fields/review_tables_full（仅当完整表与折叠表不同时存在；否则 review_tables 已是完整表），也在控制台运行页的通用字符串字段区保留全文。

## 4. 最终回答

先原样贴 review_tables 的每一页，一页接一页，一个字不改，不重排、不合并格。
先读取冻结的 review_counts.characters：total 是原文总字符数，subitems 给每张子项表的 start/end 原文字符边界。按 get_nodes 的原文字符偏移使用这些数，不把页头、追踪或续页提示算进原文，不让模型自行猜计数。
当前回答放不下全部时，优先只贴容得下的完整子项表；已贴的前缀到第 X 张表的 end，已贴字符数就是该 end。不得把半行或半个格说成完整表。一张完整表也放不下时，写已贴 0/N 张、0/T 个字符，不勉强截断。
凡未全部贴出（跨子项部分也算原文），先留一个空行结束 GFM 表，再固定补一行：
部分：已贴 X/N 张子项表，C/T 个原文字符；其余未贴，不代表没有问题。完整内容见控制台运行页 <运行页链接> 和本运行记录的 #/items/0/fields/review_tables_full；该字段不存在时 review_tables 本身就是完整表。
这行不能省，不能在表或格中途结束而不交代；接着仍给出评审意见和权威引用，未贴、未读范围明确交给控制台/原记录继续读取。
接着写“## 评审意见”，贴你提交并被受理的简短报告正文和证据缺口。
最后一行给出控制台运行页。你另外加的话明确标“模型转述，未经校验”。

表中的“Hub 核对”只列已有的字面和目录事实中归责于源文件的反驳。
模型发现和建议仍是复核方的判断，表头已写明模型及性质；不要把它们说成 Hub 验证了业务正确性。

本包的跳过不是完成：handling=skipped 必须附 reason，列入待续做清单，按回执继续本条目或以当前运行为前驱续做；不能因跳过而省略发现、处置、结论或等级。缺判定时按修正说明补齐并重交；初评缺等级、报告缺块或有未交付条目时先修复所列块或条目，再用新回执重开后续运行。

喂入层：这个包读到的用例、缺陷、构建、规格凡经 Hub 读的都由程序自动进喂入层（带锁定树苗和冻结序号），视图按"锁定树苗 + 冻结序号之前的喂入层"读；版本未声明和矛盾的对象单列计数，不进版本差。Circle 只经 knowledge-contribution 回注补程序填不了的语义（带逐字引文），运行中不问人；结构契约见该包 tables/knowledge-structure.json 或 get_nodes 根路径。
