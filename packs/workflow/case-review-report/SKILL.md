# 评审终稿（case-review-report）

各块都复核完（case-review-verify 的运行都已受理）以后用这个包写评审终稿：Hub 按各块复核结果算整体结论和等级，初评方按复核方的材料写中文报告。

## 什么时候用

- 一份目标（测试脑图）分了几块，每块各自初评（case-review）、复核（case-review-verify）都已受理。
- 不分块的目标不需要这个包：复核的结论就是终稿。

## 怎么开始运行

`verifications` 每块给一条：那次复核运行 submit_result 回执里的 `rec:<摘要>`（Hub 记录，不带 # 指针）。可选 `target` 给被评审的同一份脑图（只用来核对各块是同一份源文件）。开始运行被拒的两种情形：

- 各块不是同一份源文件（锁定构建不同）。
- 同一条目在两块里都已交付（重叠；真实数据里出现过第二块带全部条目的情形）。一个条目在 A 块已交付、在 B 块未完成时以 A 块为准；整份目标里有条目在任何一块都没交付时整体记未完成，报告写出缺哪些条目。

## 怎么写结论和报告

- **整体结论与等级从回答照抄**：开始运行（`start_run`）的回答中，条目 `report`（评审终稿）的摘要直接给出了 Hub 算出的整体结论码和等级（例如“整体结论码 <码>、等级 <等级>（最差那块的，照抄）”，各块取最差）。结论主张的 `code` 和 `rank` **直接照抄回答给出的整体结论和等级**，不要自己猜或自己从各块算。任何一块没有可读的结论时整体是未知，不要猜。
- **引用直接从回答复制，不要自己拼**：开始运行回答中每个用例条目的摘要列出了该条目要引用的所有发现引用（证实、部分正确、新增）以及被推翻的条数（例如“证实 rec:...；推翻 0 条”）。结论主张的 `grounds` **直接从回答各条目摘要里复制每一条 `rec:...` 引用**（一条不漏；标为“推翻”的不要引，只在报告文字里写）。**绝对不要自己拼 `rec:` 引用，也不要用 `get_nodes` 翻找自己造引用**。如果某个条目摘要较长被截短，照提示的指针读全文。
- **报告是跨条目主张（cross_item）**：
  - 一条结论主张——`code` 写整体结论（PASS、PARTIAL 或 FAIL，封闭集合，照回答抄），`rank` 写整体等级（P0-P7，照回答抄），`statement` 写中文报告全文，`grounds` 列从回答复制的所有证实、部分正确和新增的发现的 `rec:` 引用（一条不漏；推翻的不能引）。和复核包的结论主张同一写法。
  - 每条建议另立一条 `code=suggestion` 的主张，陈述按「补：<用例>；因为：<原因>；期望：<结果>」三段写全。
  - 证据缺口各一条 `code=gap` 的主张。
- 报告只总结复核方的材料，不重新评审、不改判复核结论。
