# 设备台架（search / facts / acquire / extend / release）

读管理员发布的台架清单，按需求搜索台架、算环境事实、预订台架、续期和提前释放自己的预订。Hub 直接算出结果，不需要你提交。上机操作（查看设备上的构建、升级）不在这个包里。

1. 台架清单是管理员用 `circle-hub doc put bed-topology <文件>` 发布的命名文档（JSON，形状 test-bed-manifest@1：台架、设备、接口地址、服务、保留段，每台设备可带 `installed` 装机声明）。开始运行时 inputs.inventory 写 `{"external": "doc:doc:bed-topology"}`（管理员用了别的名字就写那个名字）。清单有问题时整份拒绝，回答里逐条写出位置和改法，原样转述给用户，不要猜。
2. 先搜索：参数 `action: "search"`（或不写），需求 `need`：`devices` 是 `[{"type": "load-balancer|router|client|server|console", "count": n}]`，`build` 是要求设备上装的构建，`hours` 是打算用几小时。每个满足条件的台架一个条目，结论写空闲状态、构建是否一致、缺什么。**“Hub 记录里空闲（未排除本地操作）”或“Hub 记录里最早 <时刻> 空闲（未排除本地操作）”这句限定必须原样转述**：Hub 的记录排除不了有人在设备上本地操作。构建判定读清单里每台设备的 `installed`（构建名，可选 `base` 基础构建）——那是管理员写的声明，没有核对过，结论写“构建一致/不一致（…，声明，未核对）”，同样原样转述；NSAE 名按它声明的 `base` 算同一构建；没有 `installed` 的设备结论写“没有记录（未知）”，**不当作不一致**。台架上有人直接登录过没有，这个包不知道。
3. 环境事实：参数 `action: "facts"`。每个台架一个条目：监听候选（负载均衡的地址所在网段有路由器或客户端）、盲地址（所在网段没有触发设备，不能当监听地址）、后端候选、每网段空闲地址数。
4. 预订：参数 `action: "acquire"`。`bed` 指定台架（不写则按 need 选最佳匹配：设备够、现在空闲、构建不冲突的第一个），`hours` 1 到 8（单次最多 8 小时），`addresses` 要地址时写 `{"segment": <网段>, "count": n}`。成功时运行记录里带租约（键 `bed/<台架>/<设备>` 和 `bed/<台架>/ip/<地址>`）和到期时刻；同一台设备已被别人占着时，开始运行被拒绝，错误是 `LEASE_UNAVAILABLE` 并写明最早空闲时刻——原样转述，不要换台架重试，除非用户让你换。
5. 续期：参数 `action: "extend"`，`booking` 写预订那次运行的编号（run_…），**开始这次运行时 `predecessor` 写同一个编号**（预订类租约按血缘持有，Hub 核对持有运行在前驱链里且是同一用户）。`hours` 是要再延长几小时（1 到 8）；累计上限 24 小时由 Hub 判，超过得到 `LEASE_TTL`。要操作的键不用手列：包从冻结的租约视图里取血缘持有（mine 为真）的全部键，设备和地址一起续。
6. 提前释放：参数 `action: "release"`，`booking` 和 `predecessor` 同续期一样写。血缘持有的全部键立即结束，别人随后就能订。**释放不可逆：这次运行随后失败也不会把租约放回去**——用户没确认前不要做这一步。
7. 续期和释放只对自己的预订有效：血缘里没有未过期的租约行时，开始运行被如实拒绝“你没有持有这个预订”；别人的预订不能续期或释放（管理员用 `lease release` 强制释放，那是另一条路）。
8. 结论照写不补全：条目摘要和逐条结论（result.reference 里的校验结果，用 get_nodes 读）原样转述；缺的设备、不认识的网段、不够的地址按回答里的原因写，不编造。
