# 设备台架（search / facts / acquire）

读管理员发布的台架清单，按需求搜索台架、算环境事实、预订台架。Hub 直接算出结果，不需要你提交。上机操作（查看设备上的构建、升级）不在这个包里。

1. 台架清单是管理员用 `circle-hub doc put bed-topology <文件>` 发布的命名文档（JSON，形状 test-bed-manifest@1：台架、设备、接口地址、服务、保留段）。开始运行时 inputs.inventory 写 `{"external": "doc:doc:bed-topology"}`（管理员用了别的名字就写那个名字）。清单有问题时整份拒绝，回答里逐条写出位置和改法，原样转述给用户，不要猜。
2. 先搜索：参数 `action: "search"`（或不写），需求 `need`：`devices` 是 `[{"type": "load-balancer|router|client|server|console", "count": n}]`，`build` 是要求设备上装的构建，`hours` 是打算用几小时。每个满足条件的台架一个条目，结论写空闲状态、构建是否一致、缺什么。**“Hub 记录里空闲（未排除本地操作）”或“Hub 记录里最早 <时刻> 空闲（未排除本地操作）”这句限定必须原样转述**：Hub 的记录排除不了有人在设备上本地操作；设备上装的构建版本只是管理员或报告人在清单外声明的，没有记录时结论就是“没有记录（未知）”。台架上有人直接登录过没有，这个包不知道。
3. 环境事实：参数 `action: "facts"`。每个台架一个条目：监听候选（负载均衡的地址所在网段有路由器或客户端）、盲地址（所在网段没有触发设备，不能当监听地址）、后端候选、每网段空闲地址数。
4. 预订：参数 `action: "acquire"`。`bed` 指定台架（不写则按 need 选最佳匹配：设备够、现在空闲、构建不冲突的第一个），`hours` 1 到 8（单次最多 8 小时），`addresses` 要地址时写 `{"segment": <网段>, "count": n}`。成功时运行记录里带租约（键 `bed/<台架>/<设备>` 和 `bed/<台架>/ip/<地址>`）和到期时刻；同一台设备已被别人占着时，开始运行被拒绝，错误是 `LEASE_UNAVAILABLE` 并写明最早空闲时刻——原样转述，不要换台架重试，除非用户让你换。
5. 结论照写不补全：条目摘要和逐条结论（result.reference 里的校验结果，用 get_nodes 读）原样转述；缺的设备、不认识的网段、不够的地址按回答里的原因写，不编造。
