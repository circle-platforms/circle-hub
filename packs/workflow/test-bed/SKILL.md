# 自动化测试环境的登记、预订与释放

先读取任务包和管理员发布的自动化测试环境清单，缺省 inputs.inventory 为 `{"external":"doc:doc:bed-topology"}`。
清单内容由管理员发布；使用者登记只记归属，不修改清单。所有结论原样转述，保留
“Hub 记录里…（未排除本地操作）”，不能据此声称已经排除本地操作或已经停止网关作业。这个任务包不绑定产品线：不要给 start_run 的 product、version、build，也不要写进 parameters。搜索条件里的 need.build 仍是 need 的字段。

- `search`：可按 need.devices、need.build 搜索。不写 need 也展示每台设备的占用。
  管理员或登记人能看到持有人名字；别人只看运行号、取得时刻和未终态作业号。在装构建以设备上实际看到的为准：结论给出最近一次观察和它的时间（观察只对那个时刻成立），没观察过的设备写“没有观察记录”；清单里写的在装构建不再使用。
- `facts`：从冻结清单计算监听、盲地址、后端和网段，给出各设备最近一次观察到的构建和时间，并保留当前占用的披露。
- `help`：问自己预订的设备“这一行的这个位置该写什么”。参数 booking（预订那次运行的编号，开始运行的 predecessor 写同一号）、device（清单里当前账户预订的那台设备的名字）、line（要问的命令行，不带问号），设备有分级时再写 mode。
  Hub 先问整行，设备没有说明就去掉最后一个词再问，一路问到设备回了说明为止；不按回车，不执行，不改设备上的任何东西。回答列出问过的每个位置、设备在那里的原话和观察时刻，以及设备回了说明的最长前缀和它后面的那个词。
  设备的话只是设备当时的自述，带“目标自报”“未排除本地操作”两个限定，只对观察的那一刻成立：它不是命令树，不是手册，不能当期望值的依据，命令存不存在以命令树为准；说明里举的例子只是例子，不要抄进断言。
  没问成（执行器没有声明问法、目标这一版没认证只读、设备上有作业在跑、设备没答）时，回答写明缺什么和下一步，不是错误。只能问当前账户预订的设备，别人的不行。
- `read`：在自己预订的设备上读一条只读命令的输出，看设备实际怎么打印。参数 booking（预订那次运行的编号，predecessor 写同一号）、device（当前账户预订的设备名）、line（一条只读命令，一次一行，整行要符合管理员在执行器里声明的命令形状），不带 mode。回答原样给出设备的输出和观察时刻，带“目标自报”“未排除本地操作”两个限定，只对那一刻成立：它只说明输出的写法和排版，不能当期望值的依据；没读成时写明缺什么和下一步，不是错误。
- `register`：参数 bed。登记前先确认这确实是使用者自己的环境，再把清单中的自动化测试环境登记到其名下。
  已有登记人时停止登记，请管理员核对，不能以重试冒领。
- `acquire`：指定 bed 和 need.devices，需要地址时加 addresses。自动化测试环境预订不限时长，租约由运行持有到释放。
  每个用例自己一条谱系；之后的脚本编写、脚本合并和上机验证派发以预订运行为前驱，沿用同一份租约。
  预订成功后 Hub 会在预订到的设备上执行一次只读的版本探测，回答的“预订时在设备上看到的构建”逐台给出构建和时间；没看成的写明原因，派发前的版本探测还会再看一次。
- `release`：booking 为原预订运行号，开始运行的 predecessor 写同一号。用例的作业有终态以后释放，
  下一个用例再占。不在自己的谱系内就重新核对，不释放别人的预订。
  可直接照抄 `start_run` 请求（`predecessor` 与 `parameters.booking` 填同一预订运行号）：
  ```json
  {
    "pack": "test-bed",
    "inputs": { "inventory": { "external": "doc:doc:bed-topology" } },
    "predecessor": "<原预订运行号>",
    "parameters": { "action": "release", "booking": "<同一预订运行号>" }
  }
  ```
  设备只能通过 Hub 上机验证或 `test-bed` 动作交互；严禁用终端工具（如 terminal_connect、telnet、ssh）或本机脚本直连设备。
- `force_release`：参数 bed、必填 reason，可选 devices。强制释放前先问使用者，理由照原话写。
  不写 devices 时释放该自动化测试环境下所有当前占用键（包含地址），写了则只释放指定设备。
  有未终态作业时按返回结果等它结束，或请管理员用 `circle-hub job status` 核对、用 `job dispose` 处置；
  本地释放停不了网关作业，不能用它替代远端核对。原谱系之后的派发会被拒绝。
- `unregister`：参数 bed、必填 reason。由登记人或管理员带理由注销；还有占用时先强制释放，或等它释放。

没有续期操作，不传 hours、need.hours 或 extend；旧调用会收到明确修正说明。
管理员用 `lease register <前缀> --owner <使用者> --reason <理由>` 纠正冒领，或用 `lease unregister` 注销。

空闲原文示例：Hub 记录里空闲（未排除本地操作）。
