## 在装构建以设备为准（1.2.14）

所有者 2026-11-01 定：管理员不再声明在装构建，以设备上实际显示的为准；Hub 在预订时自动看一次。workflow.json 的 context 加 `observations`：开始运行时 Hub 把它管的设备最近一次观察（同一份清单的摘要和设备的 JSON 位置，加构建、按知识库解析的基础构建和时间）放进上下文，投影和检查都从这里算在装构建；预订的投影结果用 `observe` 列出预订到的设备，Hub 授予租约后对其中有执行器版本座位的设备做一次只读版本探测，结果作为观察类主张写进运行并在回答里给出。比较时构建名或基础构建逐字相等才算一致。


## need 的形状写进声明（1.2.15）

决定 114（所有者 2026-11-01）：模型把设备名写进 need.devices，拒绝却说设备类型是 ""，位置写在清单输入上，任务包列表里 need 也看不出形状。现在 need 声明了完整的 JSON Schema（devices 每项 {type, count}，build 是构建名），列表里显示这个模式，Hub 在开运行前按它核对，并写明错在第几项、要什么、给的是什么。包自己的这条拒绝也照实写给的是什么，并带上位置（/parameters/need/devices/<序号>）。行为没有别的变化。
