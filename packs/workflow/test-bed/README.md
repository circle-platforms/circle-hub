# test-bed 1.2.8

读取管理员发布的台架清单，计算搜索和环境事实，并通过 Hub 租约请求登记、注销、预订和释放。
不连接设备，不生成测试内容，不调用模型。清单的装机版本只是声明，结论保留“声明，未核对”。
所有占用都写“Hub 记录里…（未排除本地操作）”。

决定 35 第 13–16 项已定：预订按运行血缘持有；设备归登记它的用户；没有时长限额，租约由运行持有到释放。
每个用例自己一条谱系，作业有终态以后释放。`workflow.json` 不再声明 max_ttl_seconds，取得请求没有 TTL。
旧 hours、need.hours、extend 仅用于明确拒绝，修正说明为“台架预订不限时长，用完由运行释放”。
为让这个说明能通过核心参数入口，hours 与 extend 保留为标注“已移除”的拒绝入口，不具有时长或续期语义
（集成者在本任务答复中确认）；SKILL 不把它们列为可用操作。

可用动作是 search、facts、acquire、release、register、unregister、force_release。后三者分别要求清单中的 bed、
注销理由和强制释放理由；理由按用户原话传递。强制释放可选 devices，不写时选择台架下所有当前占用键。
检查从冻结的清单、规范化参数、登记与租约视图重新计算。tables/codes.json 记录本轮拒绝和不符的包码。
每个新动作都有成对正反样例，经直接合成测试和真实沙箱发布检查核验。已移除续期的旧支持样例由新动作样例替代，
旧调用的拒绝另有测试；没有将旧时长约束悄悄当成默认值。

核心缺口中的持有人可见性已补齐：所有视角看到占用运行、取得时刻和未终态作业；主人和管理员另看到持有人编号和名字。
登记表对普通用户只给前缀和是不是自己的，主人的名字不向其他普通用户显示。管理员虽有原始登记身份，包的摘要仍只写
“有主人”或“你登记的”。不写 need 的 search 也列出每台设备。没有到期时刻的占用不会当成空闲，也不会捏造最早空闲时刻。

Hub 在执行强制释放前核对当前主人、占用行和未终态作业，拒绝时给 status/dispose 的动作。
用户在包中只能强制释放自己登记的台架；管理员可通过核心命令跨主人处置。清单来源仍是管理员部署数据，
注册不证明实际物理所有权，冒领由管理员带理由改登记。

subject 模块仍负责把 parameters/groups 交给检查；核心默认 subject 不包含这些冻结事实。
历史快照缺运行号或取得时刻时如实标明并要求重开运行读取，不伪造旧事实。
接口地址按“设备主机地址/网段前缀”解释；一台设备 ipv4 和 ipv6 都为空（没有任何接口地址）在清单导入时拒绝，不进台架。大网段的计数限制、盲地址和后端算法保持原有合成测试覆盖。
台架可以声明 `baseline`：一组带 id 和字符串字段的基线配置。不写就是空列表。床面语义在 `tables/bed-surface.json`：探针座位、解析字段、基线与残留、空表判据和清理引用。产品包填写具体探针和清理命令。空表只有表头时不算残留。需要交互确认而通道是单发的，标成不可自动清理并给出出口。
