# 需求追溯矩阵

独立工作流包 story-traceability 1.0.1。按任务页 gold-trace 第 5 条实现；Hub 仅分发和核验，用户给出的需求编号是主路径。编号精确数字规范化，需求号只连接 stories 键，不读取 defects。只有视图未截断、没有未读来源、缺正文或裁剪键且计数完整时才投影；无连接是锁定知识根完整需求号索引覆盖内的确定事实，不推出未索引用例不存在。PLM 未返回仍是条目，状态和阶段各自保留原样，不定义已交付。

可选构建路径由 PLM 资源 settings.build_story_field 指定真实顶层编号数组，配合 build 槽和 build_id。字段名属于管理员部署数据，不是用户参数。缺配置或字段时拒绝并向用户索取编号。有效范围在条目摘要和事实数据明确注明“需求范围取自构建记录”。主路径优先，避免混合两种范围。一个条目最多一份一致 PLM 详情；批次冲突拒绝，不采用最后写入。

## 决定与限制

完整视图中的连接与无连接都交付支持事实，并给出知识根、视图引用、条目数与键数；无连接不是全局无用例。部分视图在投影拒绝，错误保留来源说明、缺失计数与裁剪键，要求管理员按根的来源清单恢复来源、知识同步并重新绑定完整视图。Hub 不自动同步、不重试、不调用模型，也不声称已经自动衔接外部动作。


视图瘦身后没有原始 stories 字段，按知识索引键作为连接证据；字段存在但不含需求号（包括空数组）则反驳。引用保留 PLM JSON 位置及用例树引用。统计按 PLM 原样状态分组，返回但字段缺失用 fields_absent 记录，status 缺失单独计数、不作为未知状态；显式 null 与数字、布尔、字符串均原样保留。应答未包含的编号请用户确认，不推断需求不存在。原始构建列表按原件保留，只有 PLM 配置投影给出的范围可用。每运行最多 8000 条和 5 MiB 投影预算，超限明确分批。

## Needs from other packages

需要集成者注册 scripts/real/accept/story-traceability.ts 场景，本分支不改 accept-circle.ts。真实 PLM 需求状态、阶段和构建需求字段由集成者核实后配置；目前无新词表轴需求。客户端必须执行 SKILL 的后续动作，用户不能触发管理员知识同步。发布、分配、部署和真实验收由集成者执行。


独立答案脚本 `scripts/real/gold/trace-stories.ts` 只读需求编号清单、PLM 原件、脑图、敏捷树和显式文档清单；不导入 Hub 或包的运行代码。参数为 `--stories <文件> --plm <文件>… --cases-dir <目录> --tree <文件> --docs <文件> --product <产品> --build <构建> --out <文件>`。空文档清单或漏导出的文档不作为通过。场景核对逐需求展示的用例、原样状态和阶段及运行计数，诊断只写序号、计数和摘要。

临时差异：本分支基线的 `gold/locations.ts` 排除零前缀编号，但产品索引保留；独立答案只在标题和目录文本内将零前缀数字映射为无碰撞、等宽的数字占位值，交给共享提取器后还原并规范化；等宽保留日期和版本边界规则，文档编号不改动。集成者已通知 gold-trace 的 36455d4 修复了共享提取器；按集成者要求兼容先保留，待该分支合入并通知后再移除，不改共享文件。

复核 4：兼容占位值从全部同宽非零前缀数值取，避开八位日期；只统计实际编码的标题和标签中的占用，不再让节点或文档标识挤占空间。空间确实不足时只报位宽及剩余个数，不打印原文或编号。

复核 5：文档清单中没有用例节点的合法脑图计入 documents_without_cases，不影响其他文档连接；只有明确的“无用例节点”错误可跳过，坏脑图仍整份拒绝。终端只增加无用例文档个数。
