# 需求到用例的追溯

Hub 只分发和核验，所有交互动作由客户端执行。本包没有模型调用，不生成用例。

1. 先问用户产品、构建和要核对的需求编号；没有编号就询问，不猜。可选已有 PLM 构建列表与明确的构建记录编号：管理员核实真实字段后配置资源 `settings.build_story_field`。只有指定字段是编号数组才可从构建取范围；范围依据代码为 observed（用户提供编号时为 declared），显示文字来自词表标签。未配置或字段缺失则说明缺少哪个设置或字段，并说“构建记录里没有需求字段，请给出需求编号”。不要让用户填写字段名。用户给出编号的路径优先。
2. 编号按数字去前导零，数值排序去重，每批最多 50 个，绑定多个 `stories: [{external: "plm:stories:<编号>+…"}]`。在 `cases` 绑定 `knowledge:index:<产品>:<构建>?kind=case&key=stories&fields=document,node,title`。可选构建路径只绑定 `build: {external: "plm:builds:<产品编号>"}` 并给 `parameters.build_id`，Hub 从构建范围自动分批读取需求详情。不要从发布说明的缺陷范围猜需求范围。
3. `start_run` 指定 `pack: "story-traceability"`。这是事实生产运行，不提交模型生成的结果。分页读取完整条目及跨条目统计。每个条目列出原样状态和阶段、用例、来源；PLM 没返回不算任何状态。没有状态到“已交付”的映射，不推断已交付。字段未提供只是原件里的观察事实，不要求补写或修补原件；应答里没有某编号时，立即请用户确认该编号，不宣称该需求不存在。
4. 视图不完整时运行会在投影拒绝。按错误中的来源说明读取缺失来源清单，请管理员恢复来源并运行知识同步，重新绑定完整视图后重跑；用户无权同步，不绕过，也不宣称交付完成。
5. 完整视图中无连接是确定的、有覆盖范围的事实：在锁定知识根的需求号索引中未见用例携带该编号；不推出未索引的用例不存在。汇报需求数、已追溯、无连接、PLM 应答及状态计数，引用完整视图和原件。不得把已经限定范围的事实再改成未知。
