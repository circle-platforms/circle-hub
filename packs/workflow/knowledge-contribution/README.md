# knowledge-contribution 1.0.0

所有者 2026-10-23 傍晚决定：候选留在 Circle 本地。Circle 的整合技能判定成为事实后开独立回注运行；Hub 核对原文、来源和归位，要求项全部满足才入回注层。依据是新版 `docs/hub-r4-tasks/kb-candidates.md`、知识库方向第二节及 K03、W07 R[4]、P10、K02 F[6]。

## 声明和提交

`workflow.json` 的 `contribution.slot` 声明专用回注通道，`requirement` 指定逐条目的事实核验要求项，本包为 `verified`。普通工作流没有这个声明，不写知识层。`subject` 是 Circle 给的工作清单（`examples/manifest.json`）；它只标识工作，不当知识根据。产品和构建锁定根；引用的 `src:` 另绑定 `originals`，`tree:` 受锁定根约束。`rec:` 仍须过运行绑定和权限核对，但本版记录转述不是原文，不进入回注层；应改引原始源文件或树片段。

每项一条槽位记录。`code` 来自生成词表 `document_output_kind`，`text` 是 Circle 整合陈述，`data` 仅收根、路径、source 引文，以及关系所需的第二端引文。`relation_kind` 的 same_subject 只表示同一议题，不表示内容等价；contradicts 表示互相矛盾。关系只记双方地址，不改原文、不改树。

两个要求项：`contribution` 保留 Circle 的判断及归属；`verified` 用结构表和逐字引文表产生 Hub 支持事实。层写入还要求边界确定性核验通过，且条目的全部要求项满足。Hub 核实的事实是原文、路径、来源和约束符合，不把整合陈述的语义提升成 Hub 观察。

源的出处、来源类型和摘要取自实际记录，模型自报的来源类型、依据等级、置信分数和适用条件均拒收。适用条件不从陈述文字猜出，结构化值为 null（未声明），条目仍绑定产品和锁定根；这不表示适用于任意产品或构建。模型判断的依据等级保守记 judgment。本版不承诺接收记录转述，也不会写出不可达的 relay 等级。

## 边界和存储

- 引用使用本次运行同一个 resolver：源文件和记录必须绑定，树引用必须属于锁定根；权限及逐字比对使用现有边界规则，只忽略空白差异。
- 结构、引用无法解析和逐字引文不符才是整份边界拒绝。其余准入政策由 Hub 产生具名规则的条目事实，落在 `verified` 上（修复预算 2 轮），不冒充结构错误，不影响其他条目。当前无法补齐根据时，将本条标为 skipped 并写明原因，其余条目照常交；需要重新核验时用新提交摘要。
- 陈述、原文引文、关系另一端引文必须完整通过凭据扫描；有命中或未完整扫描就不入层。清理敏感文字后重交，凭据留在 Circle 本地。关系不得把同一片段或重叠引文当作两方；同文档的不同片段须用各自选择器。
- 本版只收运行 target_basis 中 build 事实钉住的组成快照里的原文。同根可以有不同构建、不同原文摘要；后来的生产不得替换已开运行的组成。缺失快照不能猜成最新组成，须恢复记录或重开运行。运行已绑定但根中没有的来源也拒收，修正说明为：“来源不在锁定的根里，这一版不收；以后按 K03 R[5] 只绑片段和源的修订、不绑节点”。本版没有把这类来源挂到根中节点的旁路。
- 根中的来源按组成钉住的 source_artifact 记录查证。个人来源不通过回注放宽可见性；上传声明或生成血缘里的人提供环节不收，修正说明为：“需要负责人署名，署名流程以后做”。本版没有署名通道。
- 共享、Hub 自己读取的原件才可作为根据。生成片段逐环追溯输入；输入地址必须能指到已存源文件记录。src 输入按生成时已有记录、Hub 来源优先的规则核对，后来的读取不能追认更早的上传。不能追溯的输入有明确拒绝说明，须修复来源记录后重新回注。
- 普通提交规则不变：原始参数完整存为 submission@1，摘要覆盖全部内容，没有候选剥离、私有上传用途或模型可传的幂等键。
- 验证结果与 knowledge-contribution@1 在同一事务中写入。同一运行、同一提交摘要重交只返回已存回执，不重跑，不产生新效果；换会话也一样。当前可见性与读取档位在读侧核对。条件修复后要再次核验，须改正提交内容或更新 notes 后提交一个新摘要。入层另按产品、根、路径、产出种类、陈述及双方引用与引文去重；运行、提交、会话、模型和提交人不改变同一内容的身份，保留首次归属，后续归属可从各自运行回执查证。记录写失败则回滚，没有“回执未受理但条目已入层”的状态。

`contracts/src/contributions.ts` 集中定义记录及关系形状，供 K3 合并对齐。条目带实际来源记录、引文片段摘要、节点片段摘要、根、提交人、会话、时间和依据等级。运行编号和提交摘要仅留在运行内的回执映射中，不放进产品可读的记录。回注在树旁，不计根摘要，也不修改组成。

## 读和回执

`get_nodes {root, paths, depth}` 的节点附带 `contributions`；没有条目时不增加空字段。每条标回注，带来源、提交人、时间、依据等级和 `rec:` 引用。按产品读者过滤，管理员同样经过产品读者端口，没有独立的管理员绕过。产品可读不放宽原件的 ACL：src/rec 原件引文另用当前读者核对，不能读原件就不返回整条回注，也不从关系另一端透露它。tree 引文已经在产品读者能读的树片段中，服务账号仅复核其原件此刻的档位；两种核对不共享权限缓存。读记录的服务未接通知识层时拒读，不能落到通用管理员分支。同一查询共享同种读取核对，调用 records 的既有入口，不重扫字节。树引用本身仍解析不可变的树片段；回注记录独立引用。

同路径片段在另一个根变了，显示“被引片段已变（根 X → Y）”，原根上的条目仍有效。提交文本从结构化验证结果渲染入层和未入层条数、记录引用或修正说明，不回显整段提交。普通提交文本和上传行为不变。

按任务的产出声明为 `workflow.outputs.tasks`（generated 的 ranking、selection、score），提交在 `task_outputs`；只进运行及提交记录，不写回注层。

## 验证与后续

`node pack-files.ts` 从生成词表写槽位声明并重签本目录；`node pack-files.ts --check` 核对生成槽位和清单。包测试还通过真实目录读取及发布校验器验证，运行测试使用临时 PostgreSQL、合成产品根和沙箱，没有真实资料或设备。

签名流程、尚未入根来源只绑片段/修订、Circle 本地整合技能不属于本版。矛盾关系读侧标记由 K3 分支实现；本包提供集中关系形状，不冒充已经完成矛盾裁定。模型其他段落仍有旧候选隐私措辞（例如 B02 R[3]）；本次按负责人指定的模型改写范围处理 K03/W07/P10/K02 和 knowledge_layer，旧措辞由集成者一并对齐，运行时没有新增或保留候选写通道。
