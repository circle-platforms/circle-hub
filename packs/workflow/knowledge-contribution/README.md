## 声明和提交

`workflow.json` 的 `contribution.slot` 声明专用回注通道，`requirement` 指定逐条目的事实核验要求项，本包为 `verified`。普通工作流没有这个声明，不写知识层。`subject` 是 Circle 给的工作清单（`examples/manifest.json`）；它只标识工作，不当知识根据。产品和构建锁定根；引用的 `src:` 另绑定 `originals`，`tree:` 受锁定根约束。`rec:` 仍须过运行绑定和权限核对，但本版记录转述不是原文，不进入回注层；应改引原始源文件或树片段。

每项一条槽位记录。`code` 来自生成词表 `document_output_kind`，`text` 是 Circle 整合陈述，`data` 仅收根、路径、source 引文，以及关系所需的第二端引文。`relation_kind` 的 same_subject 只表示同一议题，不表示内容等价；contradicts 表示互相矛盾。关系只记双方地址，不改原文、不改树。

两个要求项：`contribution` 保留 Circle 的判断及归属；`verified` 用结构表和逐字引文表产生 Hub 支持事实。层写入还要求边界确定性核验通过，且条目的全部要求项满足。Hub 核实的事实是原文、路径、来源和约束符合，不把整合陈述的语义提升成 Hub 观察。

源的出处、来源类型和摘要取自实际记录，模型自报的来源类型、依据等级、置信分数和适用条件均拒收。适用条件不从陈述文字猜出，结构化值为 null（未声明），条目仍绑定产品和锁定根；这不表示适用于任意产品或构建。模型判断的依据等级保守记 judgment。本版不承诺接收记录转述，也不会写出不可达的 relay 等级。

## 边界和存储

- 引用使用本次运行同一个 resolver：源文件和记录必须绑定，树引用必须属于锁定根；权限及逐字比对使用现有边界规则，全部空白、大小写、标点、字符宽度和 Unicode 规范化形式都不能改。
- 结构、引用无法解析和逐字引文不符才是整份边界拒绝。其余准入政策由 Hub 产生具名规则的条目事实，落在 `verified` 上（修复预算 2 轮），不冒充结构错误，不影响其他条目。当前无法补齐根据时，将本条标为 skipped 并写明原因，其余条目照常交；需要重新核验时用新提交摘要。
- 陈述、原文引文、关系另一端引文必须完整通过凭据扫描；有命中或未完整扫描就不入层。清理敏感文字后重交，凭据留在 Circle 本地。关系不得把同一片段或重叠引文当作两方；同文档的不同片段须用各自选择器。
- 本版只收运行 target_basis 中 build 事实钉住的组成快照里的原文。同根可以有不同构建、不同原文摘要；后来的生产不得替换已开运行的组成。缺失快照不能猜成最新组成，须恢复记录或重开运行。运行已绑定但根中没有的来源也拒收，修正说明为：“来源不在锁定的根里，这一版不收；以后按 K03 R[5] 只绑片段和源的修订、不绑节点”。本版没有把这类来源挂到根中节点的旁路。
- 根中的来源按组成钉住的 source_artifact 记录查证。个人来源不通过回注放宽可见性；上传声明或生成血缘里的人提供环节不收，修正说明为：“需要负责人署名，署名流程以后做”。本版没有署名通道。
- 共享、Hub 自己读取的原件才可作为根据。生成片段逐环追溯输入；输入地址必须能指到已存源文件记录。src 输入按生成时已有记录、Hub 来源优先的规则核对，后来的读取不能追认更早的上传。不能追溯的输入有明确拒绝说明，须修复来源记录后重新回注。
- 普通提交规则不变：原始参数完整存为 submission@1，摘要覆盖全部内容，没有候选剥离、私有上传用途或模型可传的幂等键。
- 验证结果与 knowledge-contribution@1 在同一事务中写入。同一运行、同一提交摘要重交只返回已存回执，不重跑，不产生新效果；换会话也一样。当前可见性与读取档位在读侧核对。条件修复后要再次核验，须改正提交内容或更新 notes 后提交一个新摘要。入层另按产品、根、路径、产出种类、陈述及双方引用与引文去重；运行、提交、会话、模型和提交人不改变同一内容的身份，保留首次归属，后续归属可从各自运行回执查证。记录写失败则回滚，没有“回执未受理但条目已入层”的状态。

`contracts/src/contributions.ts` 集中定义记录及关系形状，供 K3 合并对齐。条目带实际来源记录、引文片段摘要、节点片段摘要、根、提交人、会话、时间和依据等级。运行编号和提交摘要仅留在运行内的回执映射中，不放进产品可读的记录。回注在树旁，不计根摘要，也不修改组成。

## 读和回执

`get_nodes {root, paths, depth}` 的节点附带 `contributions`；没有条目时不增加空字段。每条标回注，带来源、提交人、时间、依据等级和 `rec:` 引用。按产品读者过滤，管理员同样经过产品读者端口，没有独立的管理员绕过。产品可读不放宽原件的 ACL：src/rec 原件引文另用当前读者核对，不能读原件就不返回整条回注，也不从关系另一端透露它。tree 引文已经在产品读者能读的树片段中，服务账号仅复核其原件此刻的档位；两种核对不共享权限缓存。读记录的服务未接通知识层时拒读，不能落到通用管理员分支。受理撤回后，对仍有来源权限的读者另给 credential_unreadable 标记，移除陈述与两端引文，并写明管理员核查、误报受理或真凭据清理的动作。原记录和摘要不改，底层 rec 字节读取拒绝；get_nodes 只返回独立的受限元信息，不把删字段后的对象冒充原记录。没有来源权限则整条隐藏。同一查询共享同种读取核对，调用 records 的既有入口，不重扫字节。树引用本身仍解析不可变的树片段；回注记录独立引用。

同路径片段在另一个根变了，显示“被引片段已变（根 X → Y）”，原根上的条目仍有效。提交文本从结构化验证结果渲染入层和未入层条数、记录引用或修正说明，不回显整段提交。普通提交文本和上传行为不变。

回注与树条目共用节点页的字节预算，每节点至多 100 条，按新到旧从索引限量读取。还有记录时 coverage 标为部分，按原 root/paths/depth 带 next 自动续读；树条目跨页不会重复附带回注。单条正文超过节点页预算时只给固定记录引用和缺正文的说明，按该 rec: 引用分段读取，不把巨大正文挤入节点回答。游标绑定查询和路径，切换查询须从第一页重读。知识层 `page()` 提供显式 next；`list()` 仅适合单页小结果，超出时给出改用 page 的明确错误，不悄悄返回残缺数组。

按任务的产出声明为 `workflow.outputs.tasks`（generated 的 ranking、selection、score），提交在 `task_outputs`；只进运行及提交记录，不写回注层。

## 操作记录

Circle 做过的事走同一回注槽，不另开通道。产出种类用 `assertion`（声明）。结构化内容放在 `feeding`：`fed-observation@1`（做了什么、结果引文）、`fed-procedure@1`（目标、每步带引文）、`fed-pitfall@1`（现象、建议、引文）。根据必须是本次上传、出处为 `client_captured` 的原件；观察到的、投影的、声明的和候选的原件仍拒收。

不要在提交里写 `object`、`binding`、`by`、`run`、`at`、`version`、`build` 或 `line`。Hub 用规范化后的陈述和引文计算身份，并从本次运行锁定的构建或台架结构里的在装构建填写版本；两边不一致就两边都留，不选边。结构里没有时记未声明，并写明缺什么、下一步是什么。模型自己写的版本一律拒收。

引文必须逐字出自该上传原件，比对规则与边界相同。产品读者可以读这三类；读不到原件的人整条都看不到。和手册或来源结构矛盾时只打 `contradicts`，两边都返回，Hub 不裁决。管理员追加撤回后条目失效但不删除，默认不再当作有效条目。依据等级轴目前没有「声明」这个码，存储的 `basis_rank` 仍是既有的 `judgment`；这三类的喂入主张性质是未知，不进入核验、评分或放行当证据。

## Circle 的操作采集技能（随本版提供）

技能位于 `tools/operation-capture`，自成一体，Node 24 直接运行，只用内置模块和 fetch。安装时把清单所列的该目录原样复制到目标 Circle home 的 `skills/operation-capture/`，不要复制成整个回注包，也不要改写 `hooks.json`、`egress.json` 或 `generated.json`。官方核验命令是 `node packs/workflow/knowledge-contribution/pack-files.ts --verify-install <安装目录> --skill operation-capture`；它核大小、SHA-256、缺项、额外文件和链接，Jev 不带 `--skill` 的原命令不变。

技能只在会话加载后启动 `after_tool` 钩子，且默认不采。用户按技能说明为明确会话执行 `enable`，提供 Hub 地址和单独配置的 0600 令牌文件；不读 Circle 密钥库、环境密钥或其他配置。状态目录在该 Circle home 的 `operation-capture/`。`disable` 与进行中的采集、上传和整合串行，返回后不再执行这些动作；`flush` 只在重新开启后重试。钩子没有模型输出，失败只写不含原文的本地结构日志。

输出先做 Circle 同形替换和当前 Hub 令牌的字面替换，再按 `credential-scan@2` 精确脱敏并复扫；上传初始化后再读一次令牌，内容检查与实际上传 Authorization 使用同一快照。无法完整处理就整条不采。保存的是脱敏后的完整 UTF-8 输出，不是摘要。追加清单把采集与 Hub 上传回执分成两类事件，文件 SHA-256、前序摘要和自身摘要都可核；并发由会话锁串行化，旧 owner 原子隔离后才允许回收崩溃锁，不删除新锁。元数据先扫描，追加失败回滚本次新文件或未完整行，目录及父目录链接均拒收。`recover` 将未登记输出和不完整清单尾部保全到 `recovery/` 并计数，无法证明完整的片段不上传。钩子直传 `upload_file` 的 `provenance_type=client_captured`，不让模型改写上传字节。普通工作清单仍按默认值 `declared` 上传。

整合提案只收 `operation-integration@1` 的 observation、procedure、pitfall，引用必须是已上传原件的带行号逐字片段。脚本核验整份清单和引用后开独立回注运行，从运行回答取 product/root；操作者给的构建仅用于运行锁定，不进入提交条目。Hub 对同字节输出取本次运行绑定的具体 artifact，不任选旧上传。模型不得写版本或 Hub 采集字段。`receipts.jsonl` 只追加，未受理返回非零。

清单没有外部信任锚，能重写整个状态目录并重算全部摘要的人可伪造自洽链；这里保证的是检出未同步重算的修改，不是抗恶意重写。验收 `tests/acceptance/37-operation-capture.test.ts` 使用临时 PostgreSQL、真实 Hub 和合成 ORBIT/COMET，未安装到真实 Circle home，未验证真实设备效果；没有启动完整 Circle 会话，协议测试直接执行安装后的 `hooks.json`。

## Circle 的 Jev 技能

技能位于 tools/jev，自成一体，Node 24 直接运行，只用 Node 内置模块和 fetch。Hub 核心、知识层、包内函数不导入它；它不会把 Jev 密钥交给 Hub。技能脚本从 Circle 执行命令的标准输入读取密钥，既不读环境密钥，也不读 Circle 文件或钥匙串。官方接口说明见 [TypeSafe System One](https://docs.typesafe.ai/api/system-one)；本版有意保留仓库对 noul/choice/score 的字符串问题子集，服务商增加的其他能力不在技能接口中。

先按 pack.json 下载并核对整个包，再将其中 tools/jev 的已列文件原样复制到 circle-home-skills 任务所备上机和技能用 Circle 主目录的 skills/jev（不是把整个回注包当技能安装）；运行 `node packs/workflow/knowledge-contribution/pack-files.ts --verify-install <安装目录>` 逐项核大小、SHA-256、缺项、额外文件和链接。不要改写目录内的脚本、hooks.json、egress.json 或 generated.json。generated.json 的 id 和 version 分别记录包名与版本，本版为 knowledge-contribution、1.3.10；不写包号或清单摘要，以免自引用。真实身份核对仍以 pack.json 的规范清单摘要和每文件摘要为准。`pack-files.ts --check` 同时比对四个词表轴及外发策略快照，重签命令无参数。

默认只向 Jev 发送 Hub 原树中的定义、行为和题目；默认不发用例、缺陷、观察或 src。选择加入只在本次 --send 生效；技能加载后钩子才要求确认，另备主目录也须安装同一钩子；档位必须是 model_readable，不能选择加入绕过。条目的种类、原文、引用以 Hub 返回为准，输入文件自报的 text/kind 无效。子节点说明永不取用例、缺陷或观察。问题最多 2000 字、选项说明最多 160 字；脚本不能证明模型撰写的问题里没有夹带受限原文，规程明确禁止。请求记录与未提交的判断记录留在 Circle 的工作目录内，不在仓库；submit 才上传这批提议引用的判断记录（题目、候选、摘要、版本、概率、用量等），以 notes 的 src 引用使判断可追查，不上传 Jev 凭据或 state 原文。

ask 的拒收、概率及模型校验、令牌估算与复用键照保留的 hub/jev 纯规则改写；实际分批走 questionWork/Judge，按每题依赖的 state 分组并核同一预算，测试直接覆盖运行路径（不再分发未调用的 batch.ts）；客户端传输由已移除的旧客户端改写。每题判断哪些片段由作者在 jev-ask@1 的该题上用 `pieces` 显式声明（id 取自本次 pieces 列表），分组、外发 state 和判断记录里的 input 都只按这份声明：缺声明、声明为空、声明了列表外的 id，或声明的片段不在本批 state 里，都是结构问题，整批不发并在回报里写明缺的事实和下一步；技能不从 instructions 的反引号里找片段 id，instructions 里的反引号只给服务商的模型读（所有者 2026-10-24 规矩，普查 A82）。真实地址只用 HTTPS，回环假服务可 HTTP；scripted 模型只能对回环端点。每次尝试读取本进程 stdin 提供的密钥，密钥只进对应服务的 Authorization 头，不进请求体、记录、错误或终端。应答含密钥或连续 12 个字符时整份丢弃，不跟随重定向。请求每批最多 10 题，保守预算 48000/24000，默认并发 2；429/529/408/5xx/断网/超时重试两次；Retry-After 超过 60 秒直接失败；401/403、3xx、端点或账户类 4xx（除 400/422 的题目拒绝），以及重试耗尽的限流/服务不可用都会停止本批后续题目；413/上下文超限拆半一次。重跑复用同版本、同问题、同候选顺序和同 state 摘要的记录；改一片段只影响依赖该片段的批次。

校准以当前提供根的原树 entries 为金标，排除 contributions。按集成者的明确前提，只提供 Hub 按决定 15 停止判断归位以后生产的根，历史含判断挂法的根不得提供。当前 get_nodes 没有逐条挂法字段，客户端不能机械证明每条的挂法；后续须由核心在条目上提供挂法，本任务没有补这个接口。校准按条目摘要排序、遮路径字面及 data.words，在每个已知层级提问；子节点说明也遮字且排除被抽条目。阈值按 placement.choice 和确切模型，样例按 input 后来覆盖先前集合，使用至少 30 个且 Wilson 下界不低于 0.95 的最低概率。30 个全对仍可能不足，不能放宽规则。--dry-run 只读 Hub、计数，不问 Jev；去掉该参数才调用。

place 保留停法、下一步、候选、阈值、版本、概率及判断记录摘要；没有校准只留候选，不出提议。原文和树不由技能改写。提议仅有槽位需要的 code/text/data；版本和 p 只在 text 中，不向 data 增加置信分数。submit 开独立回注运行、核根、上传判断记录、提交，并原样交付 Hub 回执文字。data 里的概率、模型自报依据等字段仍被本包拒收。首次 receipt.json 不覆盖，后续按摘要命名，receipts.jsonl 只追加。未受理必须照回执修正或逐条写理由跳过，不能声称已经入层。

旧 hub/jev、placement.ts、calibration.ts 只剩纯规则和测试形状；客户端不导入它们，通过对照测试保证收拒、复用身份、遮字和阈值一致。开发只用回环脚本化假 Jev；真实服务首次合成内容调用、技能安装和持久部署回注由集成者在所有者存好密钥后验收。


本技能安装在 circle-home-skills 任务通过 `scripts/real/circle-home.ts --profile skills` 创建的上机和技能用主目录，位置为该主目录的 skills/jev/；不能装到 `--profile review` 的评审主目录，后者只放行六个 Hub 工具及 write_todos。所有者在 skills 主目录保存 JEV_API_KEY、HUB_TOKEN、JEV_MODEL、HUB_URL。技能目录指已安装的 skills/jev，入口为 `node <技能目录>/jev.ts`。实际主目录由集成者创建，本分支不配置真实主目录。

技能 hooks.json 只在会话加载技能后生效，单靠它不能保证直接执行脚本时出现确认卡片。skills 主目录自己的数据目录钩子始终生效，并会再次运行技能目录 hooks.json 中的 before_tool 钩子；因此未加载技能直接执行 `jev.ts --send` 也会走 ask。主目录及其钩子由 circle-home-skills 任务和集成者准备，本技能不修改它们。

read_tier 的全部取值和标签同样由 pack-files.ts 写进 generated.json，运行时从快照读取，--check 比对。submit_result.model 写 `<确切版本>（Circle 技能 jev，<包 id>@<包号>）`；这里包号只取 start_run 回答的运行摘要 pack_digest，并保存于 lock.json 或 run-identities.jsonl，不写进 generated.json。Jev 版本同时留在提议陈述和判断记录里。

判断记录上传不绑定为可共享运行输入，仅经 submit_result.notes 的 src 引用关联；上传只对本人和管理员可见，普通回注读者不能据此查看判断记录。因此 K04 R[5] 的记录可查只对提交人和管理员成立，这是本版限制，不声称对所有回注读者成立。

外发流水先写 `phase: sending` 再发请求，完成后追加 `phase: completed`；用 request_digest 和 attempts 配对。sending 记时间、片段摘要/引用/种类、选择加入和题目标识；completed 另记状态及服务请求号。被终止时只有 sending 表示可能已外发、处理情况未取得，不能当作未发送。

校准阈值只计有判断记录背书的样例：按样例同行的 judgments 摘要读取记录，核 requested/returned/exact_model、题型、输入及 state 摘要、候选顺序和回答概率；再从该集合的原树 root/under 重做遮字及正确子项推导，核 expected。手写样例、缺记录或任一字段不符均不计入阈值；校准和归位共用这条核验路径。旧输出缺记录时使用 place/calibrate 的原 --out，或在当前根重新 calibrate。

提交在校准及归位记录核验之前解析 --skip；明确跳过的条目不核提议、不上传其归位判断记录，只提交条目标识和跳过理由。局部拒绝带条目标识、原索引和判断摘要；缺记录时用 place 的原 --out。proposals.json 另存当时的校准阈值和样例数，当前校准不同会明确报告两者并要求重跑 place，不把补校准说成改写判断。

本地预算超限写入校准集合的 excluded 或 placement.json 的 excluded=true，不属于未回答，不进入重试队列；只剩此类确定排除时退出 0。记录包含原条目引用、节点和令牌估算，并区分片段与节点选项超限。该项没有调用 Jev，也不会产生提议。

状态诊断不猜处理结果：3xx 明确没有跟随并核对 --base-url；400/422 在 ask 可改题，calibrate/place 的题由技能生成，应报告集成者核对接口。HTTP 408 及 5xx（包括 503）均不能单凭状态证明远端未处理，按可能已处理/计费披露；429/529 只披露服务限流/过载及等待动作，不断言处理或计费事实。错误原因只取应答正文里结构化的原因码（`type`/`code` 成员，按完全相等取声明值，例如 `max_tokens_exceeded`）；正文的句子（`detail`/`message`/`msg`）不认定原因，正文被截断或不是 JSON 时记“没有可核对的结构化原因码，不推断原因”，并写明缺的事实（服务的结构化原因码）和下一步（缩小请求后重跑，或由集成者向服务方索取带原因码的错误正文）（所有者 2026-10-24 规矩，普查 A81）。

1.0.1 删除包内重复码表；回注准入码由 contracts/codes.json 的核心登记和生成物唯一提供，发出方是核心准入核对，不是包解释器。凭据拒绝使用 CREDENTIAL_IN_UPLOAD。每个异常在抛出时绑定生成码与登记修正动作，不依赖包名或错误文案分类。

## 结构声明与适用条件主张

作者声明只认 famx-applicability@1 的完整 JSON 代码块，scope.section 与原解析章节路径精确相等，descendants:true 明确授权机械继承；不按正文连词、否定词、单位话题或型号词触发条件。模型不进入生产器：在现有 knowledge-contribution 运行中以 code=applicability_claim 提交 data.applicability_claim={entry,field,value,section,evidence}，evidence 为共享 QuoteEvidence（原件摘要、parser/路径、原始 byte span 和逐字 text），source 与该引文一致。Hub 核对锁定根上的具体条目、冻结闭集、构建语法/已知名单、原始字节和章节位置，受理后保存独立判断记录，保留模型/运行/提交/原件身份，不改写原条目的作者条件。字段语义仍是判断，引文存在不证明语义正确。

FAMX_MODELS、FAMX_PLATFORMS 与已有 FAMX_COMPONENTS、FAMX_LICENSES、FAMX_DEPLOYMENT_FORMS 都是精确部署闭集；空闭集不放行任何成员，大小写、全半角、空白或同义词不映射。构建不增加变量，由原包构建名语法和根中冻结的已知构建记录共同核对；数组保持原声明次序，不从文字推连续区间。内存只接显式字节边界及 inclusive，raw 必须在原引文内，不读“至少/大约/例外”等关系词。

读取分开给 declaration_status 与 judgment_status。没有结构声明为 undeclared，没有已核主张为 unjudged，条件值 null 不代表无条件适用；旧条目声明出处未核时明确缺出处，不强填确定状态。分页或保留来源尚未核读完时判断状态保持未知，按 next/回注引用续读或由管理员恢复来源。相互冲突的作者字段和模型值都保留，不能挑有利值合并。主张只用于其受理时的相同组成与校验准则；上下文改变后按新组成重跑回注。

缺原包、闭集或保真范围时走具名管理员请求并带期限；结构声明报错保留 missing/next_action，不以空结果冒充完整生产。旧根和记录不改写；旧关键词规则受影响的适用字段需用新包重产新根、新模型运行并按原件和前驱保留血缘。本次续接未运行验证、测量或真实模型。

## 可执行槽 Schema 修正（1.1.6）

槽声明仅保留 Hub 可执行的结构约束，去掉 pattern、patternProperties、format。摘要、引用解析、原件身份、路径及逐字引文仍由现有受理边界核验，槽位收到字符串不表示身份已核对。case-review 的 expected_quality 继续逐字核对冻结原件与全部期望叶子；knowledge-contribution 从权威 ContributionInput Schema 生成受限槽投影，不修改权威受理合约。生成器按 Schema 结构遍历，名为 pattern 或 format 的普通字段不会被误删。case-review-verify 与 quality-board 槽声明未发现这些关键字，无须升版。
