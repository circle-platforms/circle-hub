# 用例编译 2.0

你在客户端填写受限结构，Hub 只核验，不生成内容、不调用模型。核对通过不证明在真实设备上跑得通。

1. 先取得 test-bed 的台架预订；编译运行以前驱串联该预订，沿用本血缘的设备和地址。开始运行用 `case-compile`，绑定 subject（用例脑图）、contract（运行器原格式合约）、inventory（台架清单）、profile（runtime-profile@1），后三项是管理员发布的 `doc:doc:<名字>`。product/build 锁定所需命令目录。parameters.autoid 必须是从原文复制的字符串，不转数字；本轮只选一个，未找到或重复时按回执修正文档并重新开始运行。
2. 用 get_nodes 读本次绑定的来源。合约已按完整原文重算身份，并与 profile 的期望值核对；不能换成另一份旧副本。对象、方法、参数原名照合约，只用启用且本轮允许的组合；内部条目、认证候选、默认值脱敏的参数不可用。不复制默认值，不通过计划申请认证或扩大授权。
3. 在条目的 plan 槽中填写 claim.data：
   - bucket：profile 选定的台架名；blocks：只能 `[]`。
   - steps：`[{object, method, args, keywords}]`。args 是显式文字列表，keywords 是签名参数名到文字的映射；没有位置参数或没有关键字时分别写 `[]`、`{}`，但每一步至少有一个显式值；两者不能同时为空，空 G 会变成文字 None。仅位置参数只能写进 args，必填齐全，不多写关键字。steps 禁止 literal_assertion：断言写进 expects，带引文和 after；工作簿断言行只能由任务 2 的生成器从 expects 产生，紧跟 after 指向的命令步骤。
   - expects：至少一条 `[{text, quote:{reference,text}, after}]`。quote 是用例、手册或修复说明的逐字原文；after 是它判断的设备命令行或主机 shell 步骤号，从 1 开始，不能指向等待或断言步骤。
   - replacements：`[{case,bed}]`，没有替换写 `[]`。地址一一对应；steps 和 expects.text 都写替换后的最终文字。quote.text 保留原文，期望必须是按替换表处理后引文的逐字片段。Hub 只重算核对，不改写步骤。
4. 所有值是单行，首尾无空白，不以 `=` 开头，没有 `{}` 或 `{0}`。设备命令通过锁定构建的命令目录和设备拒绝表；主机 shell 通过主机拒绝表。每个字面地址在台架上；设备命令只许本座位设备接口地址、本血缘已分配地址和服务器地址。
5. submit_result 后读取 result.reference 和全部错误。按 slots.schema.json 给出的具体形状及修复行修正，并自动重交同一运行，最多两轮。缺输入时写清缺少哪个文档、身份或事实，向用户取得正确来源，以当前运行为前驱重新开始；冻结输入不能在旧运行里替换。未知不得转述成通过。
6. 原样转述限定：profile.synthetic 为 true 时是“按合成合约核对”，否则是“按发布的运行器合约核对”，都带身份前 12 位和“不证明在真实设备上跑得通”。合约核对支持结论的 data.runtime_version 和 data.contract_sha256 供客户端脚本使用，不能拿它当作上机结果。
7. 先将计划运行的所有必需要求修到满足，再调用任务 2 提供的确定性客户端工作簿脚本；核对脚本摘要，从满足的槽位、合约身份、profile 和条目字段生成并上传，按任务 2 的流程开工作簿核验运行。这一版尚未包含该脚本或工作簿核验，不能声称已经生成、核验或派发；缺少脚本时请求集成者接入并核对摘要，随后继续。真实台架动作由集成者在所有者答复设计第 6 节后处理。
