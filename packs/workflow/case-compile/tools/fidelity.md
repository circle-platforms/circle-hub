# 场景保真审计（交卷前）

照 InfoTest 的场景保真：编写出来的计划还实现不实现作者写的场景，由新开的审计会话逐条判断，判断随计划交给 Hub。写计划的会话自己判，会顺着自己当初的理由判保住，所以审计要另开会话；审计规则写在简报里，不由你转述。

每次计划写好或改过之后、交卷之前，做这三步：

1. **算简报。**
   `node <技能目录>/tools/fidelity-brief.ts --run <计划运行目录>/run.json --plans <计划目录> --out <简报目录>`
   简报目录从头到尾用同一个。工具先像 submit-plans 一样展开长度占位并写回计划文件，再给每条有作者动作原句的用例写一份简报，文件名带简报摘要的前 8 位（如 `00.1a2b3c4d.brief.json`）。答复的 `to_audit` 列出这次要审计的简报：新的，和计划改过的；计划没变的沿用已有审计结果，不用重审。
2. **审计。** 用 task 开新的子代理审 `to_audit` 里的简报，一个子代理可以审几份。任务说明只写下面这一句，把路径换成实际的，不加别的话：
   `审计这些场景保真简报：<简报路径，逐个列出>。每份按简报里的 rules 独立判断，把结果 JSON 写到它旁边、文件名里 .brief.json 换成 .verdict.json 的文件（例如 00.1a2b3c4d.brief.json 的结果写 00.1a2b3c4d.verdict.json），不写别的文件，回答只说写了哪几份。`
   不要把你对计划的解释、设备返回、手册或你希望的结论写进任务说明。
3. **并入计划。**
   `node <技能目录>/tools/fidelity-apply.ts --run <计划运行目录>/run.json --plans <计划目录> --briefs <简报目录>`
   工具核对每份审计结果针对的还是现在这份计划，把它写进计划的 `data.fidelity`（摘要由工具填）。答复的 `ready` 为 true 就可以交卷。`attention` 里列的要先处理：
   - 简报过期、缺审计结果：回到第 1 步。
   - 审计结果不合式：让审计子代理按简报里的规则重写那一份。
   - 审计判这条计划要改（改了、没实现，或判保住却没写步骤）：按审计理由改计划，再从第 1 步重来。不改审计结果，也不靠改任务说明换结论。

Hub 按同一规则重算简报、核对摘要，只核能机械核的：每条作者步骤恰好一行、结论在三种之内、判保住的写出实现它的计划步骤。判改了、没实现，或判保住却没写步骤的，Hub 退回编写。
