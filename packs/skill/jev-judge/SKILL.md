# Jev 判断客户端

在客户端把一份材料（`state`）和几道题交给 TypeSafe 的 Jev，拿回类型固定、带概率的模型判断。把 Jev 作为判断器的工作流（例如自动化用例工作流）自带内嵌的同一个客户端（模块 `jev-client`），不需要装本技能，也不经过这里的命令行。这里的命令行只给集成者已在守卫里放行本工具的主目录用。Hub 不调用任何模型，本技能也不替 Hub 转发。

和 Plumb 技能并列。使用者没有明说要用 Jev 时，不用本技能代替 Plumb；Plumb 没有就绪，也不自行改用本技能。

## 先说清楚

- 答案是模型判断：`status` 是 `未确认`，`decided_by` 是 `模型`，`model_version` 是服务应答里的模型名。没有为任何用途校准过阈值，答案只作核对时的参考，不当作已核准的结论，也不单独决定任何事实：命令是否存在、值是否正确，仍由程序核对，上机验证看设备输出。转述答案时不省略模型版本、状态未确认和决定者模型。
- 外发的就是调用者放进 `state` 和题目里的内容，原样发往 TypeSafe 的固定地址（`https://api.typesafe.ai/v1/systemone`），没有别的；只有所有者允许的内容能放进请求。所有者 2026-11-23 的决定：选用 Jev 的自动化用例工作流里，原始用例的步骤、已写的命令和手册片段可以发，只管这类判断；范围外的内容（缺陷、设备输出等）要发先问所有者；密钥和令牌任何时候都不放进去。
- 密钥由使用者在客户端用 `/secrets JEV_API_KEY` 存。命令里只写占位符 `%JEV_API_KEY%`，客户端在执行时展开；密钥不写进命令行、请求 JSON 或任何文件，工具也不读环境变量。

## 命令

选项一律写成 `--选项 值`，不用 `=` 连接；密钥只从标准输入第一行传入。

```text
node '<技能目录>/tools/jev-judge.ts' ask --input '<请求JSON>' --out '<输出目录>' --key-stdin <<'EOF'
%JEV_API_KEY%
EOF
```

- `--model` 可以省略，省略时用 `jev-latest`（它会随服务方更新而变）；要让这次判断日后能对得上同一个模型，写确切版本号（形如 `jev-1.14.0`）。
- `--timeout-ms` 是单次请求的时限，默认 30000，最大 600000。
- 标准输入只读第一行（密钥，最长 4096 字节），请求文件最大 32 MiB，和客户端一个请求的上限一致；超出就拒绝，没有发出任何请求。
- `--out` 目录里得到 `answers.json`（答案）和 `audit.jsonl`（审计记录）。同一个目录里已经有 `answers.json` 时不覆盖，换一个目录。
- 屏幕上是一份中文小结：每题的答案和概率、模型版本、状态未确认、决定者模型。退出码 0 是完成，1 是没完成（出错的那一行写明类别、事实和下一步）。

## 请求怎么写

`{ "state": …, "questions": { "<题目标识>": { "type": …, "instructions": …, "criteria": … } } }`，可以另写 `"model"`。示例见 `examples/`。

- `state` 是文本、数组或对象，所有题都针对同一份 `state` 回答。材料有几部分时用有名字的字段，题目里用反引号写路径指它，例如 `step`。
- 题目标识用 1 到 128 个字母、数字、下划线或连字符，不会给模型看。
- 一道题问一件事：确切的条件写进 `instructions`，边界情况写进 `criteria`。互不依赖的几道题放进同一个请求一起问。
- 是非题（`noul`）：`criteria` 可以写 `{ "true": …, "false": … }`，答案是为“是”的概率。接近 0.5 表示模型拿不准。
- 单选题（`choice`）：`criteria` 是“选项名 → 说明”，1 到 255 个，顺序算数（模型偏向靠前的选项）；选项名不能是纯数字。没有弃权的答案，可能都不对时自己加一个 `none` 选项。
- 评分题（`score`）：`criteria` 是按顺序排列的 2 到 10 条等级说明，每条写一种具体的情形。

## 答案怎么读

`answers.json` 有 `model`、`model_version`、`status`、`decided_by`、`answers` 和 `usage`。单选题和评分题的概率各自合计为 1。`confidence` 是概率的集中度，不是答对的概率。

## 约束与口径

- 请求先在本地逐项核对，不合格的一个字也不发；答案也逐项核对（题目一道不缺、概率在 0 到 1 之间、选的项在选项里……），不合格的整份丢弃，报“暂时不可用”，不修补、不猜。
- 只有 `429` 和 `529` 会按服务给的等待时间重发一次。超时和连接中断的请求不重发，因为服务可能已经处理并计费：先确认要不要再问一次，不要直接重跑。
- 审计记录每次发请求一行，只有时间、地址、题数和题型、请求的字节数和摘要、状态、模型、用量和耗时，没有 `state`、题目和密钥。
- 服务地址是固定的，没有选项、环境变量可以改它。
