# 命令工具通用技能包

`functions/modules/command-check/` 是可复用模块。`grammar.ts` 由 `tools/gen-contracts.ts` 从 `contracts/src/command-grammar.ts` 生成，类型在那里检查；`command-policy.ts` 和 `value-domain.ts` 在这里改。`value-domain.ts` 处理手册对参数取值的说明（取值范围主张）：主张的形状、对引文的机械核对和对字面值的应用，设计见 `docs/hub-r4-tasks/value-domain-claims.md`。Hub 尚未提供取值范围主张，没有主张时这项检查不起作用；模型、契约和 Hub 接收部分见设计页中的提案。

只在这里改模块，不改工作流里生成的副本；改了要升本包版本，再改工作流的 `embeds` 并重签。发布时 Hub 核对内嵌文件等于这里已发布的版本，所以要先发布本包（决定 153、154）。

## 持久化通道与互斥组合

产品命令规则可以声明 `persistence_channels`（命令留下的状态活过运行器每个用例的清理，例如落在设备磁盘、写到对端设备）和 `forbidden_combinations`（产品文档禁止放进同一卷的两组命令）。两者都是锁定命令树的路径前缀，按完整路径段匹配，可选 `with_parameter` 写明某个可选参数给出时才算；不读命令文字，没有正则。模块里 `caseProfile` 把一个用例已解析的命令分到通道和互斥两侧，`volumeOrder` 把有通道命令的用例排到卷尾（其余次序不变），`volumeConflicts` 找出同一卷里两侧都在的组合（可以是同一个用例）。测试在 `command-policy.test.ts`。

## 目录选择要读的逆命令行

工作流的目录选择函数（case-compile 的 `catalog_select`）把计划的命令行交给 Hub，Hub 沿锁定命令树的精确边走，只把走过的节点上的定义交给检查，不交整棵树。清理义务要用到命令的逆操作，所以逆操作的定义也得在选出来的目录里，由 `inverseLines` 算出要多读的行：

- `alternativeLines`：产品声明的互逆对（`inverse_alternatives`，例如 on/off、enable/disable）。互逆对有两种写法：同一签名里枚举参数的两个取值（命令自己的定义里有两个值，不用另读），和两条同级命令（`x on`、`x off`，要读配对命令的定义才知道清理义务）。对第二种，一行里每个不带引号、是某个互逆对成员的词，换成它的配对词、后面的词都不要，就是要读的行（树按精确的词走，走不下去就停，后面的参数不改变路径）。计划或作者的行已经走到那里的不重复要。
- 前缀规则推出的逆命令行（`inverse_rules`，例如 `no …`）：放得下就全要，放不下一条也不要。
- 互逆对的行排在前面，**一条也不删**：计划按读不到配对命令来判，等于判这个开关不需要清理。放不下选择的上限（128 条行、每条 8192 字节、512 个条目、1 MiB）时，选择就超限，Hub 以「拆分计划后重核」拒绝读取，检查给出未知，而不是在缺了配对命令的目录上放行。
