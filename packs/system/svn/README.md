# SVN 只读系统包

`system@1` 包 `svn`（版本以 `pack.json` 为准），仅适用于支持 HTTP v2 的 mod_dav_svn。网络请求、凭据注入、原件保存、请求记录和 `xml@1` 解析均由核心连接器完成；包内函数是没有网络的纯函数。

## 读法与批次身份

- `svn:directory:<编码后的目录路径>`：先在最新目录上执行 `PROPFIND`，`Depth: 0`，取 `DAV:version-name`；再对 `!svn/rvr/<修订号>/<目录>/` 执行 `PROPFIND`，`Depth: 1`。返回 `content` JSON：`directory`、`revision` 和按名称排序的 `members`。成员包含 `name`、`directory`、`size`（目录为 null）、最后修改的 `revision` 和文件的 `external` 标识。
- `svn:file:<修订号>/<编码后的文件路径>`：在指定修订号执行一次 GET。`original` 是响应原始字节，`meta` 给出修订号和解码后的路径，读取结果的 `revision` 是批次修订号。CRLF 和 NUL 都保留，不清洗源文件。

例如，先读 `svn:directory:manuals`，再使用返回成员的 `external` 读取文件。路径可以整体用 `encodeURIComponent` 编码；包只解码一次，连接器按路径段编码后发出请求。文件标识的修订号是批次修订号，不能替换为成员最后修改的修订号。多个文件由产品包的同步计划组合读取；本包不递归抓取，不解析 include，不负责知识树写入。

同批身份由资源、目录和固定修订号组成，每个文件另有原件 SHA-256。连接器的读取 manifest 记录请求方法、路径、响应摘要和读取结果修订号；它将本轮请求与原件关联。原件沿用核心的内容寻址记录，不额外修改核心原件结构。真实源是否遵守修订号不可变的语义仍需集成者验收；合成测试只验证本包始终请求相同修订号，以及假服务的字节保真。

只有三条路由：最新目录的 PROPFIND、固定修订号目录的 PROPFIND、固定修订号文件的 GET。不存在登录或写路由。修订号仅接受 1–200 位数字，不转为浮点数比较。每段路径沿用 OpenKM 的 255 字符与禁止分号约束，另由规划函数拒绝空段、点段、反斜杠和控制字符。

XML 支持带前缀及默认命名空间的元素、带 xmlns 属性的 response；逐层解析 xmlns 绑定及其作用域，只采信 DAV: 命名空间的元素，错误命名空间和前缀重绑定不能提供修订号或成员属性；以配置的仓库根路径拼出最新与固定修订号的完整目录路径，解码后逐段核对目录和直接成员。只采纳 HTTP 200 的 propstat，要求明确的目录属性、修订号和文件大小；文件大小必须是非负安全整数。成员比批次修订号新、重复成员、缺失属性或越界路径都导致读取失败，不返回部分清单。列表里的链接从不成为请求地址；带协议的绝对 href、查询、片段、编码分隔符和非直接成员均被拒绝。

## 配置

资源记录的 `system_pack` 为 `svn`，唯一角色为 `svn`；资源的 `origins.svn` 指向仓库根地址。地址、仓库路径、账号均为部署数据，不写进包。资源是否允许明文传输由管理员按核心规则决定，测试只对临时回环服务声明。

必须由管理员在资源的 `settings.repository_path` 配置服务器 href 中仓库根的绝对路径；它是部署数据，不是本机文件路径，也不包含协议或主机。例子使用合成路径：

```json
{ "settings": { "repository_path": "/synthetic-repository" } }
```

该值应与资源地址所对应的服务器 href 前缀保持一致。允许 `/` 和一个可选的尾斜杠；路径段中的百分号编码只解码一次，不接受查询、片段、空段、点段或编码分隔符。读取 `manuals` 时，最新目录应答必须对应 `/synthetic-repository/manuals/`，固定修订号 17 的列表必须对应 `/synthetic-repository/!svn/rvr/17/manuals/`；解码后按完整路径逐段比较，不能仅有相同目录后缀。配置值不会被用作请求地址，请求仍由资源的 `origins.svn` 与只读路由决定。

缺少、为空或无效的 `settings.repository_path` 时，目录和文件规划均不发出请求；包的投影错误明确指出该设置。核心对这种零请求计划只采集投影错误作为管理员诊断，不接受投影成功或任何派生件：管理员备注能看到设置名，用户回执和工具文本仍是中性失败，持久读取清单也保留通用失败原因。

认证为 `static_header`：密钥库凭据名 `authorization`，存完整的 Basic Authorization 头值。通过 Hub 的资源与密钥命令配置，包与资源记录不存凭据值。401 后核心停止使用该凭据，直到管理员操作；没有登录流程或自动重试。发出的认证头不写入原件；本包测试核对正常响应的原件、读取记录、日志与错误不含认证值。若源响应回显凭据，按模型 B02 R[4] 的平台统一规则，核心原样保存为 `retain_only` 原件，不给函数和读者，也不作为可读原件或投影返回。集成者已确认本任务沿用这一隔离语义；本包不另设凭据处理机制，也不宣称底层存储绝无源端回显的凭据。

## 验证

```sh
npx tsc --noEmit
node packs/system/svn/api.ts check
node --test --test-concurrency=1 "packs/system/**/*.test.ts" "hub/connectors/**/*.test.ts"
```

本包测试使用临时 PostgreSQL、沙箱和本机回环假 SVN 服务，认证值在测试进程内随机生成。覆盖路由白名单、非法修订号和路径、缺失或无效的仓库根设置零网络拒绝、完整目录身份与编码比较、XML 形状、成员修订号上界、凭据隔离、401 停止、读取记录和固定修订号的原件字节一致性。没有连接真实 SVN；真实系统验收由集成者完成。

## 决定、限制与其他包需求

本任务只增加 `packs/system/svn`；不修改共享包目录注册表，使用 `api.ts` 的 `check | sign | stage <目录>` 完成本包打包。测试独立暂存包，再通过现有测试 PacksPort 注册。集成者若需要统一打包入口，可在其负责的入口注册本包。

目前路径必须是仓库根下的非空相对路径，与任务给出的 `{dir*}` 路由和 OpenKM 先例一致；仓库根目录自身不作为目录读取对象。新生产器及产品同步计划由后续任务负责；核心连接器与 contracts 无新增需求。没有更改其他包、部署设置或持久服务。

`svn:directory-at:<修订号>/<编码后的相对目录>` 用父目录已经固定的修订号直接 PROPFIND 版本根，绝不先读当前修订号。只复用原有 `list` 只读路由；返回的文件外部号也带同一修订号。每次最多 512 个直接成员，指定目录路径最多 32 段；超限给 `svn.directory_budget` 并整份拒绝，不截断。调用方递归时须继续使用根目录固定的修订号，并另设整组深度与总量上限。
