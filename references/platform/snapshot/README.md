# infosec-platform

**面向网络安全产品全生命周期的通用全自动化 AI 平台。**

我们正在构建一个能持续承担产品工作的 AI 平台。用户给出目标、资料和允许的操作范围，平台组织知识查询、需求分析、开发、设备操作与测试，把工作推进到经过验证的交付结果。

一次产品故障可能要查手册、看代码、连接设备、复现问题，再修改和回归。infosec-platform 希望让这些工作围绕同一个目标连续完成，保留过程、依据和结果。等待构建、设备响应或用户反馈后，任务能够继续；换入口或会话，也能接着做。

## 可以交给平台的工作

| 工作 | 目标交付 |
|---|---|
| 产品答疑与支持 | 按型号和版本回答问题，给出资料依据，跟进需要研发或现场调查的问题 |
| 需求、设计与开发 | 澄清需求、评审方案、分析影响、实现改动并检查结果 |
| 故障定位与修复 | 采集现场状态、复现问题、验证原因、完成修复和回归 |
| 测试与验证 | 生成和评审用例，编译测试资料，执行功能、协议、流量或性能验证 |
| 设备与 Web 操作 | 通过 SSH 或管理页面配置产品、观察状态、核对变更和业务效果 |
| 发布与版本维护 | 构建和检查制品，验证升级与回退，管理版本兼容和发布结果 |

平台覆盖不同网络安全产品。产品资料、型号和版本、操作方法、测试标准分别接入，同一套任务组织与结果核验方法服务多个产品。负载均衡工程是首批实践来源，更多产品通过各自的能力包和适配器进入平台。

## 从目标到结果

用户应当能直接提出这样的任务。

> 复现这个版本的连接异常，找到原因，修复并完成回归。
>
> 根据这份规格检查测试用例，把遗漏和有争议的预期列出来。
>
> 修改指定设备的配置，验证是否生效，给出变更前后的结果。

平台自动分解任务、选择方法、执行检查，并根据实际反馈继续工作。100% 置真的内容交给脚本，其余内容由 LLM 判定，完整披露实际输入和输出。脚本事实、模型判断和现场效果分别呈现，依据和缺项都能追查，见[判断与披露原则](docs/design/truth-and-disclosure.md)。发现目标不清、权限不足或证据缺失时，平台指出具体缺项，等待对应信息或决定；已有授权内的常规工作持续推进。

用户可以随时看进度、补充材料、调整目标或接管。SSH 显示真实终端过程，Web 显示正在操作的实际页面。Otty 这类带浏览器的终端可并排显示，普通终端可打开 Chrome 查看同一执行会话。

交付包含产物、核验结果和可展开的证据。执行成功、业务通过和任务交付分别确认；没有取得的结果明确保留为未验证或未知。

## 产品框架

平台按产品、能力和任务组合组织工作。一个产品可以提供多种能力，一种能力可以服务多个产品，一项任务可以组合知识、代码、设备、测试和发布操作。能力和资料固定版本，运行过程记录输入与目标，后续任务可以使用已经检验的方法。

当前采用 Circle 客户端与 circle-server 服务端的分工：用户在 Circle 默认插件库启用连接插件，配置 server IP 或域名并登录；资料、长期任务、真实执行和专业方法由 server 管理。管理运维入口由 circle-server 自己提供，不另外建设 Web 管理站点。Circle 保留通用 harness，其他兼容入口通过共同契约接入。平台自研程序使用 TypeScript，见 [ADR 0028](docs/decisions/0028-circle-server-split.md)。

总框架、模块与函数设计、组合方式以及 GitHub 工作组织见[产品框架](docs/product-framework.md)和[工程文档](docs/README.md)。
