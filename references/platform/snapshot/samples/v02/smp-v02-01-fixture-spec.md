# SMP-V02-01：APV 协议夹具规格（规格文档，非真实设备）

状态：草稿，待人工核验。本文件只定义 P2/P4 阶段要实现的**模拟夹具**长什么样，不连接任何真实 APV 设备，不包含真实设备的连接信息、口令或未公开协议细节；协议行为按公开常识化的请求/响应模型抽象，命令名为示意。

## 1. 夹具职责

- 模拟一台 APV 类负载均衡设备的管理面：会话建立、配置读取、配置变更（以虚拟服务 virtual service 为对象）、变更生效与回滚、状态查询。
- 每个操作产生确定性回执，支持在指定点注入故障（见第 4 节），供 V02 验收与 R02/R08 类实验使用。
- 夹具自身的状态（配置版本、会话表）可被测试前后快照比对，用于“清理已验证”断言。

## 2. 示意命令集（逻辑名，非真实命令字）

| 逻辑命令 | 语义 | 副作用 | 预期回执要点 |
| --- | --- | --- | --- |
| `session.open` | 建立管理会话 | 占用会话（资源） | sessionId、设备标识（型号/序列号/固件版本） |
| `config.read` | 读取指定对象配置 | 无 | 对象当前值 + 配置版本号 |
| `config.stage` | 暂存一项变更（不生效） | 写暂存区 | stageId、基于的配置版本号 |
| `config.commit` | 使暂存变更生效 | 真实变更（夹具内） | 新配置版本号、生效回执 |
| `config.rollback` | 回滚到指定配置版本 | 真实变更（夹具内） | 回滚后版本号 |
| `session.close` | 关闭会话并释放 | 释放会话 | 释放确认；未释放要可查 |

## 3. 状态机（夹具内）

`no-session → in-session → staged → committed`；任一步失败停留在失败前状态并给出结构化原因；`commit` 后配置版本号单调递增；基于旧版本号的 `stage/commit` 必须被拒（版本冲突）。

## 4. 故障注入点

| 注入点 | 注入行为 | 被测契约 |
| --- | --- | --- |
| INJ-APV-1 commit 后回执丢失 | 变更已生效但回执不达 | unknown 与对账（RC-03、EFF-04） |
| INJ-APV-2 commit 中途断连 | 生效结果不确定 | unknown；禁止盲重试 |
| INJ-APV-3 设备身份漂移 | 会话中途返回不同序列号 | AUTH-07 立即停手 |
| INJ-APV-4 版本冲突 | stage 基于旧配置版本 | conflict-stale 拒绝 |
| INJ-APV-5 慢响应 | 回执延迟超过窗口 | 超时分类（目标不可达 vs 未知） |

## 5. 与真实设备的边界

真实 APV 的接入、命令字、固件差异属于 OPEN-06（P4 专用环境授权后处理）；本夹具的任何行为都不构成“真实 APV 已验证”的证据。
