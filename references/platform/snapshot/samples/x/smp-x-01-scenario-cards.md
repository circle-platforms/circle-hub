# SMP-X-01：R01–R08 横切场景卡（草稿，待人工核验）

每卡固定四项：前置、注入、期望状态、证据要求。卡片是实验定义，不是执行记录；执行在对应层级（L1/L3/L5）进行并另留回执。

## R01 回执丢失

- 前置：一项可对账的操作通道（如 SMP-V02-01 夹具）。
- 注入：操作已执行、回执在返回路径丢失（INJ-APV-1 或桩的 drop-receipt 脚本）。
- 期望状态：操作进 `unknown`；禁止盲重试；reconcile 后以目标侧事实定案。
- 证据要求：操作记录、对账查询记录、目标侧状态快照各一份，时间线可对齐。

## R02 执行进程被杀

- 前置：一个运行中的长任务（桩 slow 脚本或 P2 的真实 run）。
- 注入：在运行中终止执行进程。
- 期望状态：租约到期后可被接管或标 `unknown`；不得出现双执行；原尝试留痕。
- 证据要求：进程终止记录、租约时间线、接管/对账记录。

## R03 模型超时或格式错误

- 前置：一条含语义判断的链（V01/V04 的样本）。
- 注入：让模型调用超时，或返回不符合 schema 的输出。
- 期望状态：语义层记为不可用/弃权，任务不假装完成；程序校验拦截坏格式。
- 证据要求：原始输出（脱敏）、schema 校验失败记录、任务状态变迁。

## R04 Jev 取消四段

- 前置：一个已越过准入、正在执行的任务（桩 cancel 场景为最小形态）。
- 注入：Jev 发起取消。
- 期望状态：依次出现 requested → delivered → stopped-observed → 残留核对；只完成第一段时对用户只能说“已请求取消”。
- 证据要求：四段各自的时间与证据记录；残留项（会话/租约/临时文件）的处理结果。

## R05 证据或产物损坏

- 前置：一份已登记的证据/产物及其哈希。
- 注入：篡改产物字节（副本上）或提供错误哈希。
- 期望状态：交付前校验失败并拦截；结论引用该证据的记录被标受影响。
- 证据要求：哈希校验记录、被拦截的交付尝试记录。

## R06 跨 harness 接管

- 前置：任务由 harness 甲启动并运行中（P3 起，真实 harness）。
- 注入：甲退出，Jev 指定由 harness 乙接管。
- 期望状态：乙从 C/D 的权威状态恢复（新 run、新租约、递增 fencing）；任务与既有证据不丢；甲的私有上下文不被当作状态来源。
- 证据要求：接管前后两份状态快照、租约与 fencing 记录、两侧的 run 记录。

## R07 多传输路径对拍

- 前置：同一操作可经 MCP 与 CLI（及可用时的 Tasks 增强路）发起。
- 注入：无故障注入；同一输入分别走各路（P1-3 桩级已做 MCP/CLI/HTTP 版）。
- 期望状态：各路的业务状态、错误与回执一致；差异只允许在传输层字段。
- 证据要求：各路的完整信封存档与差异比对记录。

## R08 设备或页面中途变化

- 前置：V02/V03 的目标在操作进行中（夹具/测试站）。
- 注入：目标身份漂移（INJ-APV-3）或页面结构在流程中改变。
- 期望状态：立即停手并报告变化点；已发生的副作用如实列明；不得按旧绑定继续。
- 证据要求：变化前后的目标身份/页面证据、停手点记录、已发生副作用清单。
