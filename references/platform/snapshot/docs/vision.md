# 目标与范围

状态：产品方向已确认；成功指标和具体功能范围待逐项细化。

## 产品目标

infosec-platform 的产品定位是面向网络安全产品全生命周期的通用全自动化 AI 平台。用户提交目标、资料和允许的操作范围，平台组织并持续完成答疑、需求/设计、开发、故障修复、测试、设备/Web 操作、发布与维护，交付经过核验的结果。多产品、能力与任务组合以及工程组织见[产品框架](product-framework.md)。负载均衡产品的既有工程实践用于建立和验证通用抽象；产品特有语义通过能力包与适配器表达，沿用 [ADR 0010](decisions/0010-product-line-scope.md)。产品目标不代表当前功能已全部实现或通过真实环境验收。

Circle 的通用 coding-agent 基础能力应至少达到 Pi 的同等可用性。对齐需要固定版本、模型、环境、预算和行为验收；工具数量相同或界面相似不构成对齐证明。本次未进行对比实验。

产品平台的入口不限于 Circle；Pi/OpenCode 等满足共同契约时可替换。知识、任务、操作和专业规则由平台四类对象持有，不随客户端更换而重建，见[适配计划](harness-adaptation-plan.md)。

产品差异化重点是长任务持续执行、Web 与设备操作、从故障中恢复、以实际结果验证完成，以及经过验证的操作经验复用。

## 完整工作范围

| 工作领域 | 代表工作 |
|---|---|
| 用户支持 | 产品答疑、配置解释、已知问题分析、支持问题转研发任务 |
| 需求与设计 | 需求澄清、规格评审、影响分析、兼容性和验收条件 |
| 开发与修复 | 代码理解、需求开发、bug 复现、根因分析、修复和评审 |
| 测试 | 用例评审、Excel 编译、单元测试、集成回归、协议/流量/性能分析 |
| 产品操作 | Web、CLI、API 配置、状态观察、环境准备和故障定位 |
| 发布维护 | 构建、制品检查、升级回退验证、发布、维护分支和版本兼容 |

这些工作会交叉。Excel 编译和用例评审用于检验通用设计，不能据此把平台收窄成固定流程工具。

## 用户希望的最终体验

用户交付一个目标后，可以查看进度、补充材料、调整方向、必要时接管，并得到有依据的交付结果。工作可在等待 CI、设备执行或人工反馈时暂停，并在条件满足后继续。

任务应能跨 Circle 会话和执行进程存在。团队成员能够围绕同一任务交接，了解哪些结论已验证、哪些仍是假设，以及结果属于哪个产品版本和运行环境。

## 已明确的技术边界

- 保留 Circle，不重写 Circle。
- 其余相关自研项目和代码全新用 TS 实现；skill 的说明文档保留 Markdown 形式。
- 旧项目提供需求、资产、正确行为样本、缺陷样本和设计经验，不作为新生产系统的 Python 实现依赖。
- 基础设施与第三方系统通过协议接入。数据库、设备固件、文档转换服务和既有测试框架的具体依赖边界仍需单独讨论；不能借此默认保留旧自研 Python 运行链。
- 内部资料可以作为迁移资产，不能直接整批进入源代码仓库。

## 待量化的成功指标

- 在相同模型和预算下的任务完成率、人工介入次数和有效自主执行时长。
- 中断、重启、上下文切换和环境变化后的恢复能力。
- 真实业务结果与报告结论的一致程度，及错误宣布完成的比例。
- Web 操作在页面变化后的成功率，稳定流程的重复执行成本。
- 同类经验在新输入和相似环境中的复用收益、失效识别能力。
- 多角色协作相对于单 agent 的收益和额外成本。

上述指标尚未设定阈值，不能用作当前完成声明。
