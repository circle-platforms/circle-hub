# Excel 输出契约与脑图格式范围 V1（P1-5 冻结）

日期：2026-10-10。

状态：**结构层已冻结；XMind 确切版本范围与二进制探针明确延后（见第 5 节）。** 依据：[ADR 0008](decisions/0008-mindmap-and-excel-scope.md) 的推进方式与已冻结样本 [SMP-V05-01 / SMP-V05-02](../samples/v05/)（2026-10-10 经用户核验冻结，见 samples/registry.json）。本契约是 V05 链（人工脑图编译为 Excel）的输入/输出合同；实现与一致性执行属 P2，本文件不构成已实现声明。

## 1. 中间表示 IR（冻结）

编译只经一个中间表示进行，任何输入格式先转 IR 再生成工作簿：

- IR 是一棵主题树：节点 = `{ title: string, note?: string, children: Node[] }`，根节点深度为 0。
- 标题规范化（结构层，生成工作簿与计算路径时统一应用）：去首尾空白；内部换行替换为单个空格。其余字符（全半角、标点）不做改写。
- IR 必须可序列化为 JSON 并计算 SHA-256；同一 IR + 同一契约版本必须生成单元格内容完全相同的工作簿（文件级元数据如生成时间戳不参与等价判断，见 3.4）。

## 2. 脑图输入格式范围（冻结部分）

- **原生候选**：XMind（ADR 0008）。结构层接受的输入形态之一定为 XMind（2020+）的 `content.json` 主题结构（sheet → rootTopic → children.attached，notes 取 `notes.plain.content`），样本形态见 SMP-V05-01 的 content.json。
- **主题树 JSON**：符合第 1 节 IR 的 JSON 文件可直接作为输入（与格式无关的调试/对拍入口）。
- **转换输入候选**：FreeMind（.mm）与 OPML 只经转换进入 IR；转换保真度（丢失/未解释元素清单）必须随产物单独记录，不承诺原生支持。
- **不在范围**：图片脑图（需 OCR/视觉链，另立议题）；XMind 之外的专有脑图格式。

## 3. Excel 输出契约（冻结）

### 3.1 文件与工作簿

- 文件格式：`.xlsx`（OOXML），无宏；一份输入脑图生成一个工作簿。
- 工作表固定两张，顺序与名称冻结：`用例清单`、`说明`。不得增删工作表或改名；列集合与顺序冻结如下。

### 3.2 `用例清单` 列定义

| 列 | 类型 | 规则 |
| --- | --- | --- |
| 编号 | text | `TC-` + 三位序号（001 起），按深度优先顺序连续编号 |
| 一级模块 | text | 行节点路径第 1 段 |
| 二级模块 | text | 行节点路径第 2 段；不存在时空字符串 |
| 用例标题 | text | 行节点的规范化标题 |
| 备注 | text | 节点 note；无 note 时空字符串 |
| 层级深度 | number（整数） | 行节点深度（根 = 0） |
| 路径 | text | 从根下一层起、到本节点的规范化标题以 `/` 连接 |

成行规则（冻结）：根节点与一级模块节点不成行（只作分组）；深度 ≥ 2 的每个主题一行。首行为表头，内容与列名逐字一致。

### 3.3 空值与类型规则

- 文本单元格缺失值一律为空字符串，**禁止**写入 `null`、字符串 `"null"`、`N/A` 等占位符冒充空。
- 层级深度必须是数值单元格（整数），不得写成文本。
- 标题为空（规范化后为空串）的节点属于输入错误，按 3.5 处理，不得静默丢弃或生成无标题行。

### 3.4 `说明` 工作表

两列（`项` / `值`，均为 text），至少包含：源文件 SHA-256、输入格式描述、本契约版本（Excel 输出契约 V1）、映射规则版本（与本文件版本一致）、源文件标题（根节点标题）。生成时间可记录为文字，但不参与工作簿等价判断。

### 3.5 失败与部分完成

- 输入不可解析或 IR 校验失败：整体失败并给出结构化错误，不产出工作簿。
- 输入中存在无法映射的元素（如未知扩展节点）：产物状态为 `partial`，未映射清单写入 `说明` 表并在响应中列明；**禁止**静默丢弃后声称完整成功。
- 生成的工作簿必须可被重新打开解析校验（往返校验属于实现期程序核验，见五条链验收 V05）。

## 4. 与冻结样本的对应

- SMP-V05-01（主题树 + content.json）是本契约的输入样本；SMP-V05-02 是输出期望：按第 3 节规则编译 SMP-V05-01，必须逐单元格得到 SMP-V05-02 的 8 行期望（含编号、路径、深度、备注）。该对应关系已在 P1-4 制备时以程序核对过结构层一致性；生成真实 .xlsx 并逐单元格比对属 P2 实现的一致性测试，本阶段未执行。

## 5. 明确延后（不冻结、不声称）

| 延后项 | 原因 | 解冻条件 |
| --- | --- | --- |
| XMind 确切版本范围（如 XMind 8 的 content.xml 形态是否纳入） | 无获准真实样本，未做只读解析探针（ADR 0008 第 5 条） | 取得获准真实 .xmind 样本并完成探针记录后，以本文件修订版冻结 |
| `.xmind` 二进制包的解析/生成验证 | 合成 content.json 未在真实 XMind 应用打开验证；仓库写接口不支持二进制样本入库 | 同上；探针结论回填本节 |
| 多 sheet 脑图、附件/图片节点、超链接节点的映射 | 首批样本未覆盖，避免无样本立法 | 出现覆盖这些形态的冻结样本后修订 |
| 旧项目 Excel 约定的逐项取舍清单 | ADR 0008 定为“逐项过、不自动沿用”；本契约字段已按冻结样本独立确定，旧约定与本契约冲突时以本契约为准 | 无需解冻；如需引入旧约定中的额外字段，走本文件修订 |

## 6. 版本与修订

本文件为 Excel 输出契约与脑图格式范围 V1。修订必须：升版本号、注明与冻结样本的对应变化、重跑第 4 节对应关系核对；与样本冲突时，先修订样本并重新核验，或修订本契约并记录理由，二者不得静默其一。
