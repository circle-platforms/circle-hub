# SSH 连接、显示与控制的对象归属 V1

日期：2026-10-10。状态：SSH 的职责细化计划；职责按 [ADR 0004](decisions/0004-runtime-object-boundaries.md) 和[对象 V1](object-boundaries-v1.md)展开，具体接口、模块与交接实现为提案，未实施。

Web 全过程可见与 Otty 并排/外部 Chrome 布局要求继续有效，见[可见性需求决定](decisions/0014-operator-visibility.md)。设备管理范围以 SSH 与 Web 为准，见 [范围修订](decisions/0021-ssh-web-interaction-scope.md)。

## 1. 逐项归属

| 能力/状态 | 主归属 | 协作与边界 |
|---|---|---|
| Circle 工具/命令接入、模型交互与结果呈现 | A | 通过 F 的客户端访问平台；保留任务/操作/SSH 会话引用，不持有真实连接 |
| Otty 面板/外部 Chrome 打开与重新关联、终端视图组件、操作进度显示 | A | 终端 UI 可评估 xterm.js；消费 D 的同会话输出与状态，不另开 SSH 登录 |
| scope 成员、允许目标/作用、谁能观察/执行/接管、截止时限与预算 | C | 政策与授权归 C；每次释放输出或发送输入前由 D 核对当前授权，不只检查打开页面时的身份 |
| 任务、run、计划/输入修订、待人工响应、完成准入与业务审计 | C | 保存 D 操作和 B/E 记录引用；Temporal 候选只承担持久编排，不保存活跃 socket 或终端对象 |
| 运行目标注册、SSH endpoint/路由引用、发现的设备身份与当前版本 | D | 稳定资源身份绑定实际 endpoint 与观察时刻；C 管范围，B 保存观察证据；产品规格不是现场注册表 |
| 私钥/口令的执行时解析与注入、SSH host key 核验、认证/连接故障 | D | C 决定凭据引用的可用范围，秘密存储是基础设施；凭据不进入 A 上下文、B 原件、E 包或 Git |
| SSH 连接、交互式 shell/PTY、会话状态、keepalive、断连/重连与释放 | D | 使用成熟连接库的公开接口；重连先核对身份/状态，不把上一条写命令直接重发 |
| 操作/attempt、真实收发、超时、取消、unknown 与现场对账 | D | E 解释产品含义，C 决定任务后续；本地停止等待不能签发远端已停止 |
| 设备配置写租约、当前输入控制者/控制修订、派发队列与陈旧输入拒绝 | D | C 授权接管，D 在实际发送出口完成切换；SSH 与将来的 Web 写入共用设备资源协调 |
| 输出流、序号/时刻、断流与重放缺口、查看服务后端与会话附着 | D | 服务端按 C 政策核验；实时缓存用于会话服务，持久证据内容/修订归 B；显示组件归 A |
| 产品 CLI 方法、命令语法/适用版本、提示符/权限/配置模式、分页及输出含义 | E | D 通用终端层执行收发/超时；产品特有模式和解析规则归版本化能力包，不写进通用 SSH 内核 |
| 产品命令作用声明、配置步骤/清理方法、预期和业务核验 | E | 从 B 的固定来源取得依据；C/D 在权威路径核对作用与执行许可，不能只信任模型或 readOnly 提示 |
| 手册/型号/版本规格、不可变证据原件与引用、脱敏输出、报告和回放修订 | B | D 现场采集，E 产生核验/判断，C 关联任务，A 显示；归档不持有活跃连接或签发任务完成 |
| 身份/操作/会话/输出事件契约、错误词表、SDK、协议适配与兼容策略 | F（横切） | 各对象执行运行时检查；MCP/CLI/HTTP 是接入方式，不增加业务拥有者 |
| SSH 协议夹具、断连/丢回执/并发/显示/接管/隔离的回归与有效回执 | G（横切） | 使用独立隔离输入，测真实收发/作用；生产判据仍由 E，生产授权/执行检查仍由 C/D |

这里的“主归属”表示负责写入权威状态或维护规则的对象，不要求每行成为独立服务、MCP 或仓库。现有 platform 包物理合并 C/D 不改变这些职责；后续拆包应按生命周期和隔离需要决定。

## 2. 三个需要拆清的组合能力

### 终端显示

A 保存布局、选择的查看目标、窗口与显示状态，并渲染终端；D 提供同一 SSH 会话的真实输出流、当前状态和受控输入出口。通用序号与重放字段由 F 定义，重要内容交 B 作为不可变证据保存。查看页在 A，查看服务的会话/输出后端在 D，不把前后端都归成一个额外运行对象。

Circle 关闭或查看页断开只影响入口/显示；真实 SSH 是否存活由 D 检查。重新打开附着原会话或读取明确的终局记录，不能让显示组件重新登录设备来伪造连续过程。最近画面/输出时间、缓存重放与缺口分别标注。

### 人工接管

A 接收“暂停/接管/交回”并呈现结果；C 核验主体、任务范围与操作许可，记录请求/决定；D 停止派发下一动作、核对在途操作，在实际输入出口切换唯一控制者并拒绝旧控制修订的输入。

人工仍在原会话中操作。交回时 D 提供当前设备/终端状态，E 检查权限/配置模式与产品条件是否变化，C 重新评估受影响的计划/审批。任务目标、输入修订、设备写租约和会话输入控制是不同维度，不用“接管”一个词同时覆盖。

交互式输入本身须在授权范围内执行并留可核对记录；前端允许打字不代表取得设备写权限。是否允许任意人工命令、怎样标记作用和限制范围，在 SSH 操作契约中确定。

### 连接与产品操作

D 处理 SSH 协议和通用终端传输；E 提供“这个产品如何进入配置模式、命令何时结束、输出怎样解释、怎样保存/回退与验证”的规则。B 提供规则的来源与适用版本。连接库不能判断产品业务正确，产品包也不自建长连接、租约、控制队列或凭据管理。

## 3. 一条 SSH 配置任务

1. A 接收目标并调用 C，保留 task/run 引用；C 固定输入、范围、所用 E 包和 B 知识版本。
2. C 准入并委托 D；D 解析目标/凭据引用，核对主机与设备身份，取得租约，建立交互式 SSH 会话。
3. D 返回会话/查看引用与实际状态；A 在 Otty 面板或 Chrome 查看页显示原会话输出。显示路径无需再认证一次设备。
4. E 生成带依据的配置步骤与核验方法；D 在受控输入出口复核权限/作用/租约，执行并记录现场收发。
5. E 在固定规范下核验配置读回和业务结果；D 采集证据并处理连接/租约/残留；B 登记内容和记录修订。
6. C 从实际记录解析完成清单后决定交付；A 呈现结果和未完成项。命令返回提示符或用户看见输出都不自动构成任务完成。

## 4. 首期讨论与后续验收

首期 SSH 建议包含目标/身份、认证、交互式终端、实时观察、作用声明、配置读回、断连对账及明确释放；暂停/人工接管按控制出口能力继续细化。Web 的已确认实时可见性保留，不由 SSH 通过推出 Web 已支持。

| 边界样本 | 未来必须验证的结果 |
|---|---|
| Circle/查看页退出与重新关联 | D 原会话事实可查；输出回放/缺口真实，显示端不重新建立设备连接 |
| 两用户观察、一用户/agent 输入，随后接管/交回 | C 权限与 D 唯一输入控制共同有效；陈旧输入不能发送到设备 |
| SSH 断连发生在写命令送出后、回执前 | D 保留 unknown 并对账，测实际作用次数；不直接重发 |
| 产品模式/提示符/分页变化，错误版本方法 | E 适用范围和方法检查有效；D 保留原始收发，不为方便跳过核验 |
| 欠权限读取、凭据回显、显示流串到另一 scope | D 输出/输入出口拒绝越权；普通记录不留凭据，B 仅登记允许保存的证据 |
| 输出/命令成功但业务核验失败 | E 分别记录事实与判据，C 不完整交付，A 显示真实结论 |

全部为待执行计划。本轮仅在固定平台提交 `37f2ec3` 上阅读文档并更新责任划分，没有修改业务代码、安装依赖或启动 SSH/显示/设备实验。相关：[可见性计划](operator-visibility-plan-v1.md)、[共同契约](common-contracts-v1.md)、[C/D/E 讨论](cde-implementation-discussion-v1.md)。
