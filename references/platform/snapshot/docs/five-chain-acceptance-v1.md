状态：**已接受为验收基线（用户于 2026-10-10 接受，见 ADR 0006）。全部验收均未执行。** 本文件把[基础验证计划](foundation-validation-plan.md)第 3、4 节的最低要求展开为可执行的验收条目、样本要求与证据包清单；不替代该计划的全功能迁移部分（第 7 节行为账本仍是 L6 的入口）。本阶段未编写业务代码、未连接设备、未操作真实 Web、未部署。

共同契约引用：[A–E 共同契约 V1](common-contracts-v1.md)（下文简称“契约”，条款号如 COM-02、RC-03 直接引用该文件）。验证层 L0–L6 与回执字段沿用基础验证计划第 6 节；本文件每条链标注其目标层级，未达到的层级不得用低层结果冒充。

## 0. 通用验收规则（五条链共同适用）

- `ACC-G01` 每条链的每次验收运行都是一份独立回执：含代码/构建版本（实施后）、依赖与模型版本、样本与输入身份及 hash、knowledge snapshot 与 pack 版本、harness 与传输路径、目标与环境修订、task/run/operation 身份、逐项判据结果（pass / fail / unknown / skipped / not-run）、证据 hash 清单、清理与残留状态、耗时与成本（单列，不替代正确性）。
- `ACC-G02` 程序核验与语义判断分别判定、分别记录（契约 VER-01/02）。机械项 fail 即该链 fail；语义项按该链标注集阈值判定，阈值必须在实验前冻结并写入回执。unknown 与 skipped 不计入通过。
- `ACC-G03` 每条链都必须包含至少一个失败样本与一个未知/越权样本。只跑 happy path 的运行不构成验收。
- `ACC-G04` 样本分三级管理：合成样本（可入验证仓库，人工核验过）、脱敏真实样本（按授权固定版本，不入本设计仓库）、专用环境样本（仅在 P4 授权环境内使用）。每条链的样本清单（ID、来源、版本、覆盖目的、预期）在运行前冻结；运行后替换样本重跑必须生成新回执，不得修改旧回执凑绿。
- `ACC-G05` 清理是验收的一部分：每条链结束时核对 lease 已释放、临时配置/会话/文件已按声明清理、遗留项已登记。清理未核对的运行最高只能记 partial。
- `ACC-G06` 同一条链必须在 Circle、Pi、OpenCode 三种 harness 上各完成至少一次（L3），且完成一次跨 harness 接管序列（契约 HAND-02，实验 R06）。三 harness 的结果分别记录；某 harness 能力降级时按契约 HAND-01 标注降级内容，降级链的结果不得与完整链混报。

## 1. V01 产品知识问答

目标层级：L2（隔离端到端）→ L3（真实 harness）→ L4（真实模型质量）。L5 不适用（无专用设备目标），但获准真实资料的问答质量在 L4 用脱敏真实样本集判定。

链路归属：A 理解与呈现；B 来源/实体/声明/快照/检索；C 身份、范围与任务登记；D 来源导入操作；E 检索与答题方法（pack）。

### 1.1 验收条目

| 编号 | 条目 | 判定方式 |
|---|---|---|
| V01-A01 | 每条事实性结论可回溯到固定 source revision 与 evidence 定位（页/行/节点/片段），引用正文实际支持结论 | 程序核验引用存在与 hash；人工/标注核验支持性 |
| V01-A02 | 回答绑定并回显产品、版本、snapshotId、pack 版本；版本不适用时明确说明而非套用他版结论 | 程序核验绑定闭包 |
| V01-A03 | 多来源冲突时并列呈现冲突与各自依据，不擅自选边；来源撤回/更新后旧结论按失效规则处理 | 标注集判定 + 程序核验失效传播 |
| V01-A04 | 无答案/证据不足时弃答或明确标注未知，不编造参数、命令或结论 | 标注集判定（错误确信单列统计） |
| V01-A05 | 不跨 tenant/scope 检索；越权问题返回拒绝且不泄露他 scope 内容存在性细节 | 程序核验 + 越权注入 |
| V01-A06 | 现场 actual、XML/catalog/footprint 等派生材料不被当作规范 expected 引用；来源性质在回答中可区分 | 程序核验来源性质字段 + 抽检 |
| V01-A07 | 快照切换期间已固定 snapshot 的运行结果不受影响；新运行使用新快照并可区分 | 程序核验（并发实验） |
| V01-A08 | 普通事实查询可不经模型给出证据包；语义综合回答的 Assessment 记录含方法/模型版本与依据 | 记录抽检 |

### 1.2 样本要求

- 合成多版本产品资料集（人工核验）：至少覆盖功能说明、CLI 方法、Web 方法、架构/代码关系、测试要求、型号差异；同一功能至少两个版本且结论不同。
- 冲突集：同一问题至少两份来源结论冲突，且各自定位明确。
- 无答案集：问题在本资料范围内确实无依据，预期行为为弃答。
- 误导集：引用正文不支持常见结论、同名不同产品、已撤回来源各至少一例。
- 越权集：问题指向另一 scope 才有的资料。
- 脱敏真实样本（P3 后，授权固定）：从真实产品资料脱敏抽取，标注集由人工给出预期结论要点、必需引用与不可接受结论。

未验证披露：当前无任何 V01 样本已制备或运行；资料范围细节（商务/报价类内容的绑定方式）为契约 OPEN-03/04 关联待定项，不在本文件定案。

## 2. V02 APV 设备操作

目标层级：L2（本地协议 fixture）→ L5（指定专用 APV 实测）。**fixture 通过不得表述为 APV 真机通过**（基础验证计划第 4 节）。

链路归属：A 请求与呈现；B 规范与证据；C 准入、任务与预算；D 租约与 SSH 执行；E APV 规则与业务判据。

### 2.1 验收条目

| 编号 | 条目 | 判定方式 |
|---|---|---|
| V02-A01 | 执行前核对目标身份：设备别名解析、序列/型号、固件版本与任务绑定一致；不一致时在产生副作用前拒绝 | 程序核验 + 身份不符注入 |
| V02-A02 | 只读采集：实际通道收发留痕，采集结果与设备当时状态一致，采集 operation 的效果声明如实含连接与 lease 占用（EFF-01） | 程序核验回执与效果 |
| V02-A03 | 受控变更：变更前后状态分别采集并对比，仅目标项变化；变更的业务判据（E）与执行成功（D）分别记录 | 程序核验 + E 判据记录 |
| V02-A04 | 两任务抢占同一设备时仅一方持有可写 lease；过期 fencing 的写入被设备端/网关拒绝并留痕 | 故障注入 + 程序核验 |
| V02-A05 | 长输出、CRLF、分页、prompt 变体下采集不截断、不误判结束；截断发生时显式标记 partial | fixture 协议样本 |
| V02-A06 | 断连后已执行但回执丢失：状态落 unknown，经 reconcile 核对实际状态后才可继续；禁止直接重跑变更（RC-03） | 故障注入 |
| V02-A07 | 取消四段可区分（RC-04）；取消后远端仍存活时如实报告并给出残留处置 | 故障注入 |
| V02-A08 | 清理：测试配置、临时对象、会话与 lease 按声明清理，遗留清单为空或已登记处置 | 程序核验 + 现场复查 |
| V02-A09 | 通道不可替代：任务要求 Web 操作验证时，SSH 成功只能补充设备侧证据，不能替代页面提交和页面读回结论；SSH 路径同样单独验证 | 回执审查 |
| V02-A10 | 业务效果与配置变更分开：涉及流量/业务验证时，独立记录业务结果，不以配置已下发冒充业务通过 | 专用环境实测（L5） |

### 2.2 样本与环境要求

- L2 fixture：可编程的本地 SSH/HTTP 模拟端，能注入断连、延迟、长输出、prompt 变体与回执丢失；fixture 本身用 TS 实现（属 G/D 测试资产，不是旧 executor 的封装）。
- L5 专用环境（P4 单独授权）：指定 APV 型号、固件、拓扑、账号权限与允许通道清单在运行前冻结并写入回执；初始化、破坏性操作、升级不包含在本链，通过本链不代表 those 能力通过（EFF-02）。
- 样本集：身份不符、只读采集、受控变更与清理、抢占、过期 fencing、断连未知、取消残留各至少一例。

未验证披露：当前未连接任何 APV 设备，未制备 fixture；型号/固件/通道优先级为契约 OPEN-06 待定。

## 3. V03 Web 登录与操作

目标层级：L2（全新本地测试站点）→ L5（指定专用产品 Web）。本地站点通过不得表述为产品 Web 兼容。

链路归属：A 目标提出、视觉信息（具备时）与接管；B 操作知识与证据；C 身份、任务与人工输入；D browser session 与隔离上下文；E 页面方法、参数化 TS 脚本与断言。

### 3.1 验收条目

| 编号 | 条目 | 判定方式 |
|---|---|---|
| V03-A01 | 真实登录：以测试账号完成登录并访问受保护页面，受保护业务结果（而非仅页面跳转）作为成功依据 | 程序核验业务结果 + trace |
| V03-A02 | 错误密码/无权限账号登录失败被正确识别为 failed，不误报成功、不锁定外溢到其他样本 | 程序核验 |
| V03-A03 | 浏览器上下文隔离：两账号/两任务的 Cookie 与存储不串用；跨上下文复用认证状态被阻止 | 程序核验 + 注入 |
| V03-A04 | 凭据只由可信执行环境注入（AUTH-04/HUM-04）；会话历史、截图、trace 与证据中无明文凭据 | 证据抽检 + 扫描 |
| V03-A05 | 代表动作可重放：参数化 TS 脚本在相同前置条件下重复执行结果一致；页面变化时脚本失败留痕并进入修复流程，不跳过断言变绿 | 重复运行对拍 |
| V03-A06 | 动态元素、iframe/弹窗、页面刷新、会话过期场景有明确结果；会话过期进入重新认证或 waiting-input，不静默失败 | 站点样本覆盖 |
| V03-A07 | MFA/验证码场景进入 PendingInput 等待人工，超时按未知/未完成处理，不伪造通过 | 流程注入 |
| V03-A08 | 三组方法对比留记录：结构/DOM、结构+视觉、稳定脚本各自的适用样本、成功与失败模式分别报告；无视觉能力的 harness 结果标注为结构路径 | 对比实验回执 |
| V03-A09 | 下载与文件产出绑定 artifact 登记；下载内容 hash 与页面声称一致 | 程序核验 |
| V03-A10 | 失败可定位：失败回执含步骤定位、网络/控制台摘要、截图/trace 引用（脱敏后） | 回执审查 |

### 3.2 样本与环境要求

- 本地测试站点（TS 实现，全新）：含登录、受保护页、动态按钮、iframe/弹窗、下载、会话过期与权限分级；账号与数据均为合成。
- 视觉有意义样本：至少一组仅靠 DOM 难以判定的页面（如状态靠颜色/布局表达），用于区分 V03-A08 三组方法；普通表单样本不能替代。
- L5 产品 Web（P4 单独授权）：目标产品、版本、账号权限、允许动作清单运行前冻结。

未验证披露：当前未创建测试站点、未操作任何 Web 产品；视觉模型选择与 MFA 通道为契约 OPEN-07 待定。图片理解不得假定当前 Jev 形态可直接读图，需在 P3 实测后定案。

## 4. V04 用例评审

目标层级：L2（固定用例集与缺陷集）→ L4（语义评审质量）。

链路归属：A 交互与呈现；B SPEC、原件与 Assessment；C 返工、人工响应与修订管理；D 文件读取与隔离 worker；E 检查规则与评审方法。

### 4.1 验收条目

| 编号 | 条目 | 判定方式 |
|---|---|---|
| V04-A01 | 结构检查可复现：同一输入修订多次运行，机械 findings 集合一致 | 程序核验重复运行 |
| V04-A02 | 每个 finding 绑定：输入修订、原用例节点/字段定位、规则或来源引用、影响说明、性质标记（机械缺陷 / 语义建议 / 证据不足） | 程序核验字段完备 |
| V04-A03 | 规范冲突类 finding 的依据可回溯到固定 SPEC 来源修订；版本不适用时不误报 | 标注集判定 |
| V04-A04 | 评审不直接修改原件；修改产生新修订，新修订必须重新评审，旧评审结论不自动迁移（BIND-01） | 流程核验 |
| V04-A05 | 人工决定绑定 requestId 与修订（HUM-01/02）；关键语义解释经人工确认后才进入收口清单 | 流程注入（迟到/冲突响应） |
| V04-A06 | 单 case 与批量评审结果一致性：同一 case 单独评与批量评的 findings 不矛盾，批量 partial 时逐条列明 | 对拍 |
| V04-A07 | 评审报告明确其证据边界：报告通过不表述为“整个用例集绝对正确”，未覆盖维度显式列出 | 报告审查 |
| V04-A08 | 语义建议保留未知与分歧：模型不确定项标注为建议/未知，不以机械缺陷口吻呈现 | 标注集判定 |

### 4.2 样本要求

- 正确用例集：人工确认无已知缺陷，覆盖不同协议/算法/产品形态各至少一例。
- 注入缺陷集：与正确集同源派生，缺陷类型至少含结构缺项、条件/步骤不一致、预期与 SPEC 冲突、版本不适用、来源缺失、含混或不可观测判据、覆盖遗漏、重复问题；每类至少一例且有人工标注的预期 finding。
- 修订集：对缺陷集修改后的新修订，用于验证 V04-A04 的重新评审路径。

未验证披露：当前未制备用例样本；SPEC 的具体来源与版本绑定方式随 P1 样本议题定案。

## 5. V05 人工脑图编译为 Excel

目标层级：L2（固定脑图样本与独立 reader 核验）。Excel 生成成功不等于用例已在设备执行通过，二者严格分开（契约 14.4）。

链路归属：A 澄清与确认；B 原件、来源与制品；C 阶段、返工与收口；D 文件处理与 worker；E 解析、重组、编译与工作簿规则。

### 5.1 验收条目

| 编号 | 条目 | 判定方式 |
|---|---|---|
| V05-A01 | 节点完整性：原脑图节点不漏、不重复进入 IR；节点 → case → sheet/row 映射可逐条追踪 | 程序核验映射闭包 |
| V05-A02 | 未解释节点/不支持内容显式列出并阻断静默交付；超出支持格式范围的输入在受理前拒绝并说明 | 程序核验 + 范围外注入 |
| V05-A03 | 步骤、命令与预期依据绑定来源修订；无依据的生成内容标注为待确认，不冒充规范结论 | 依据抽检 |
| V05-A04 | 产物为可被独立 reader 打开的真实 .xlsx；表头/工作表/单元格类型符合输出契约版本 | 独立 reader 程序核验 |
| V05-A05 | 中文、嵌套层级、笔记、关联与附件引用按支持范围正确处理；重复 ID 有明确处置（拒绝或重命名留痕） | 样本覆盖核验 |
| V05-A06 | 含混产品语义经澄清流程确认（PendingInput）后才编译；未确认项不进入正式 sheet 或按契约标注隔离区 | 流程核验 |
| V05-A07 | 返工后引用旧输入、重复编译、进程重启后恢复等场景不产生重复行/重复 case；幂等键生效（RC-01） | 故障注入 |
| V05-A08 | 截断与超限（超长文本、超多节点）有显式失败或分批策略，不静默截断交付 | 边界样本 |

### 5.2 样本要求

- 格式样本：先以获准样本确定真实格式与版本（候选为 XMind 原文件），记录接受/拒绝范围；随意 JSON 提纲不得命名为“已支持人工脑图”。图片脑图不在本链范围（需 OCR/视觉另链）。
- 内容样本：至少含多 sheet 预期、深嵌套、中文标题与内容、笔记、关联、附件引用、重复 ID、含混语义各一例。
- 输出契约样本：与样本一一对应的预期工作簿结构说明（表头、工作表划分、单元格类型），由人工确认，作为 V05-A04 的判定依据。
