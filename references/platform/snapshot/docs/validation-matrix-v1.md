# 验证矩阵与后续实施顺序 V1（第一阶段设计收口）

日期：2026-10-10。

状态：**已接受为设计基线（ADR 0006）。P1 已有用户裁定通过的收口记录；P2-1..P2-6 已有有限范围代码与本地执行记录，P2 已经用户裁定收口（ADR 0015）。** 本页同步可查记录，不签发本轮新的通过结果。本轮仅静态检查设计/所列源码，没有安装依赖、运行包测试、连接设备/浏览器或部署。矩阵表示必测关系，不是勾选结果；没有逐项对应回执的单元格不得自动判 pass。

依据：[共同契约](common-contracts-v1.md)、[五条链验收方案](five-chain-acceptance-v1.md)、[基础验证计划](foundation-validation-plan.md)第 6 节（验证层 L0–L6 与回执要求）。

## 1. 验证层（复述基础验证计划，不重新定义）

| 层 | 范围 | 不能越界的结论 |
|---|---|---|
| L0 | 静态设计与来源检查 | 不证明新功能运行 |
| L1 | 契约与故障语义：TS schema、scripted model、协议客户端 | 不证明模型判断或真实 harness 可用 |
| L2 | 隔离端到端：真文件、新测试服务、本地协议/浏览器 fixture、重启恢复 | 不证明 APV 真机或产品 Web 兼容 |
| L3 | 真实 harness：固定 Circle/Pi/OpenCode 版本与本地模型 gateway | 通用 MCP client 通过不能替代 |
| L4 | 真实模型质量：固定模型/参数、人工标注集、预算与分布 | 机械通过与语义质量分别计量 |
| L5 | 专用产品环境：指定 APV/Web、版本/拓扑、实际业务效果 | 只对所测范围成立 |
| L6 | 全功能迁移：全部保留行为逐项有当前证据 | 五条链通过不能推出 L6 |

## 2. 契约 × 功能链验证矩阵

图例：● 必须在该链验证；○ 相关时验证；— 不适用。方法缩写：对拍 = 协议/多路对拍；注入 = 故障/越权/伪造注入；标注 = 人工标注集判定；实测 = 隔离或专用环境实测；审查 = 回执与证据人工审查。

| 契约组 | V01 问答 | V02 APV | V03 Web | V04 评审 | V05 编译 | 主要层级 | 主要方法 |
|---|---|---|---|---|---|---|---|
| COM 结构化 IO 与状态区分 | ● | ● | ● | ● | ● | L1→L2 | 对拍、注入 |
| BIND 来源与版本绑定 | ● | ● | ○ | ● | ● | L1→L2 | 对拍、注入（错配引用） |
| AUTH 权限与身份链 | ● | ● | ● | ● | ○ | L1→L2，L5 复核 | 注入（无权/过期/自报身份） |
| EFF 效果与副作用 | ○ | ● | ● | ○ | ● | L2，L5 复核 | 实测、审查（回执比对声明） |
| STATE 失败与未知 | ● | ● | ● | ● | ● | L1→L2 | 注入（断连/丢失/超时） |
| RC 幂等、重试、取消 | ○ | ● | ● | ● | ● | L1→L2 | 注入、重复提交对拍 |
| LONG 长任务与恢复 | ● | ● | ● | ● | ● | L2（R01–R03） | 重启/退出注入 |
| HAND 跨 harness 接管 | ● | ● | ● | ● | ● | L3（R06） | 三 harness 实测 + 接管序列 |
| VER 双轨记录与完成准入 | ● | ● | ○ | ● | ● | L1→L4 | 审查、标注、R08 注入 |
| EVD 证据与制品 | ● | ● | ● | ● | ● | L2 | 程序核验（hash/闭包）、抽检 |
| HUM 人工决定 | ○ | ○ | ● | ● | ● | L2→L3 | 流程注入（迟到/冲突/过期） |
| A 薄适配禁止项 | ● | ● | ● | ● | ● | L3 | 三 harness 对照审查 |

读法：任一 ● 单元格未取得对应层级的有效回执，该契约组不得宣称“已在该链验证”；任一链的全部 ● 未齐，该链不得宣称通过。矩阵后续随评审增删行列时，必须保留变更记录，不得直接改写历史回执的判定。

## 4. 回执与状态管理规则

- 每份回执字段沿用[五条链验收方案](five-chain-acceptance-v1.md) ACC-G01。回执保存在 G 的验证资产中（后续阶段确定具体仓库位置），不回写进设计文档冒充结论；设计文档只引用回执身份与结论摘要。
- 状态词只用：未执行 / 执行中 / pass / fail / unknown / partial / blocked（缺前置条件）。blocked 必须写明缺什么、由谁定案。禁止使用“基本通过”“应该没问题”等不可判定状态。
- 同一验收条目在修复后重跑产生新回执；旧 fail 回执保留。汇总表引用最新有效回执，同时保留历史失败计数。
- 语义阈值在实验前冻结写入回执计划；实验后修改阈值必须新开一轮并说明理由（契约 OPEN-04）。

## 5. 后续实施顺序（提案，逐段过门禁）

每段含：目标、主要产出、进入条件、退出条件（门禁）。**未过门禁不得进入下一段的实施**；讨论与样本制备可按标注提前，但不得以“已讨论”为由跳过门禁宣称完成。

| 阶段 | 目标与产出 | 进入条件 | 退出条件（门禁） |
|---|---|---|---|
| P0（已完成） | 对象边界、适配与验证计划、契约/验收/矩阵收口文档 | 用户授权计划阶段 | 已满足：文档已提交 GitHub，用户于 2026-10-10 接受三份文档与 ADR 0006 为基线，P0 门禁通过 |
| P1 契约与样本冻结（已有收口决定） | F 的 TS schema/SDK 骨架（仅契约层，无业务逻辑）、五条链样本清单与合成样本、Excel 输出契约与脑图格式范围、错误码表与状态词表冻结版 | P0 评审通过；OPEN-01/05 有结论或明确的延后清单 | 原 [P1 收口评审](p1-closing-review.md)与 [P1 收口 ADR](decisions/0010-p1-closing.md)为准，延后登记保留 |
| P2 完整纵向链（已有局部记录，未整体收口） | B 知识 V1 最小实现、C 最小持久任务、D 的 fixture 执行（本地协议/浏览器/文件）、E 首批方法；五条链 L1/L2 与 R01–R05、R07、R08 | P1 门禁通过；样本就绪 | 五条链 L2 回执齐备（含失败/未知样本），清理核对完成；持久任务仍是待验证要求，不能由内存阶段机代替；任一链缺回执则该链停留在 P2，不进入 P3 的对应宣称 |
| P3 替换与语义质量 | 三 harness 固定版本薄适配、能力协商与降级标注、R06 接管序列、真实模型 L4 标注评测（V01/V04 为主，V03 视觉对比） | P2 对应链通过；模型与 gateway 选型经单独议题定案 | L3/L4 回执齐备；三 harness 差异清单公开；语义指标按冻结阈值判定 |
| P4 专用环境 | 指定 APV（V02 L5）与指定产品 Web（V03 L5）的验收 | 单独授权：目标、版本、拓扑、账号权限、允许动作与清理方案逐项确认 | L5 回执只覆盖所测范围；未授权动作一律不在范围内执行 |
| P5 全功能迁移 | 403 条行为账本逐项处置与验收、产品研发/发布/维护扩展链 | P2–P4 基础链稳定；行为账本评审完成 | L6 条件（见基础验证计划第 7 节）全部满足才可宣称全量替代 |

顺序说明：

- P1 只做契约层与样本，不做 B/C/D/E 业务实现，避免在契约未冻结时写出返工代码。
- P2 强调“完整纵向链”而非先把某一层做厚：每条链都要真实穿过 C 的任务、D 的执行（fixture）与 B 的证据登记，禁止用 stub 冒充关键对象（基础验证计划 P2 原意）。
- E 的方法随链进入 P2，不单独先行造“大而全能力包”；pack 版本从 P2 起纳入绑定。
- 多 agent 协作、缓存复用、脚本自动修复等增强项一律在 P3 之后以对比实验评估，无测量不预设收益（基础验证计划第 5 节）。

## 6. 风险与明确不做的事

- 不以官方 MCP 测试客户端或单个 harness 的通过，推及三 harness 兼容（L3 定义）。
- 不以 fixture/模拟协议通过，推及 APV 真机或产品 Web（L2 与 L5 严格分开）。
- 不以 Excel 生成、报告生成或制品存在，推及业务通过或已交付（契约 COM-03、EVD-03）。
- 不在本计划阶段的任何后续段落中默认包含：初始化、升级、破坏性设备操作与产品发布/回退；这些按 EFF-02 单独成链、单独授权。
- 排期与人力不在本文件承诺；选型（框架、存储、模型、gateway）按议题逐项定案，不在本矩阵预设。

## 7. 待定与未验证汇总

- ●/○ 表达必测关系；已有局部记录列于第 1 节，其余未取得回执的项继续未验证，本轮不重跑或补判。
- P0/P1 按已有收口决定阅读；P2-1 至 P2-6 已有各自有限范围记录，但五链、浏览器可见性和横切恢复未整体收口。本轮未重跑；不宣称 P3–P5 已启动或通过。
- OPEN-02/03/04 已由 ADR 0011/0012/0013 定案；其余待定与延后统一见[共同契约第 16 节](common-contracts-v1.md)。C/D/E 实现提案见[讨论稿](cde-implementation-discussion-v1.md)，本矩阵不另设选型决定。
