# 插件化前端检查

2026-10-11。范围是共享前端与随应用打包的第一方插件。产品分工与实际 Circle 接入限制见[设计说明](../design/pluggable-workbench.md)。

本轮把四个管理页和会话组件拆成独立模块，增加注册器、插件页、Circle / InfoSec 两种组合、启停反馈及渲染错误边界。数据仍来自前端预览适配器，没有实际连接 Circle 或平台服务。

## 实际结果

- TypeScript 类型检查、Vite 生产构建与格式检查通过。
- 7 个注册器检查通过，覆盖新页面/面板注册、重复与保留位置冲突、接口版本、依赖闭包与循环、多产品共享对象、停用与角色限制、空组合和旧偏好恢复。
- 14 个隔离 Chromium 场景通过。包含上一轮的 10 个会话与对象交互场景，以及本轮新增的 4 个插件场景。

| 新增场景 | 实际观察 |
|---|---|
| 停用知识插件 | 导航、输入区引用操作、全局资料搜索与记录入口随之收起；固定修订和工具原始输出仍在，启用后可继续查看 |
| 切换 Circle / InfoSec 组合 | 偏好经过刷新保留；基础会话仍能保存输入；长期工作与执行资源记录逐项保持原值；重新启用恢复相关组件 |
| 停用当前执行面板 | 会话侧栏回到上下文；重新启用知识插件也没有给平台运维角色增加业务读取权 |
| 注入插件渲染错误 | 在隔离浏览器中把样例长期工作项改为无效记录，C 的侧栏与页面分别显示局部失败；A 的输入区和 B 的资料页仍可使用 |

最后一项有意触发渲染异常。[机器回执](workbench-plugins-20261011.json)分别记录预期异常数量与非预期错误；非预期错误为空。它还记录浏览器版本、时间以及源码/构建文件摘要。

[插件页截图](../design/assets/workbench-plugins/plugins-light.png)与[Circle 组合截图](../design/assets/workbench-plugins/circle-composition.png)使用合成数据。当前预览仍监听本机 4192 端口。

## 未由这些结果证明的能力

渲染错误边界只检查了 React 渲染故障。它不是进程隔离，不能阻止恶意代码、无限循环、异步错误、网络访问或凭据访问。插件启停也不等同于卸载运行代码。本轮只允许明确导入、随应用打包的第一方模块。

没有检查真实 Circle 会话、工具效果、审批往返、MCP/扩展加载、桌面 IPC、SSH 或设备浏览器。Circle 仅核对了 1.0.4 的源码与官方仓库文档，没有修改或运行它。上一轮验证记录保留为历史结果，不当作当前源码的通过凭证。
