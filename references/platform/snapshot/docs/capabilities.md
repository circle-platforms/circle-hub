# 能力分类与扩展机制

状态：机制分工说明。主归属以[运行对象 V1](object-boundaries-v1.md)和 [ADR 0004](decisions/0004-runtime-object-boundaries.md) 为准；不是已实现接口。逐项映射见[能力盘点](research/project-capability-audit.md)。

## 两个分类维度

业务领域与实现机制分开分类。一项故障修复任务可以同时使用知识、设备、观测、代码和测试能力；不按业务名词机械地各建一个 MCP 服务或 agent。

| 机制 | 承担的职责 | 示例 |
|---|---|---|
| Skill | 方法、适用条件、专业判断与推荐步骤 | 需求评审、故障诊断、CLI 开发、用例编译 |
| Tool | 输入、作用和输出明确的可调用能力 | 查询能力、取得快照、启动测试、读取证据 |
| MCP | 跨进程、跨语言、跨客户端暴露能力的协议 | 暴露共享工具、资源和受支持的长任务接口 |
| Resource | 有身份和版本的资料或产物 | 手册、命令定义、拓扑、制品、报告 |
| Hook / middleware | 在确定的运行节点观察、校验或拦截 | 检查目标和权限、登记回执、验证完成条件 |
| Validator | 执行独立的可复现检查 | 命令结构、产物结构、预期与实际结果对照 |
| 任务运行层 | 目标、依赖、等待、恢复、取消和预算 | 跨会话、跨系统推进一个长期任务 |

MCP 与 tool 不互斥：同一个 tool 可经本地扩展、CLI 或 MCP 暴露。业务实现应尽量共享。Skill 可以携带脚本，但文字说明不能替代运行时必须保证的约束。

Circle/Pi/OpenCode 属于可替换 A；其余四类的契约和权威状态独立。接入差异与能力协商见[harness 适配计划](harness-adaptation-plan.md)。没有 Tasks/媒体支持时要提供明确兼容路径或声明限制。

## 业务能力领域

| 领域 | 内容 |
|---|---|
| 产品知识与需求 | 按版本查询、答疑、需求和规格评审、兼容性分析 |
| 代码与工程协作 | 代码检索、隔离工作区、修改、评审、仓库与 CI 集成 |
| 设备与实验环境 | 设备身份、能力、拓扑、租约、配置与通道操作 |
| 观测与诊断 | 日志、指标、抓包、连接状态、崩溃信息、时间关联 |
| 测试与验证 | 用例评审、编译、单元/集成回归、流量与性能验证 |
| Web 与交互 | 浏览器会话、DOM、视觉、网络和控制台、重复脚本 |
| 发布与维护 | 制品、版本关系、升级回退、发布条件、维护分支 |

领域划分不预设部署单元。独立服务的理由应来自共享需求、资源生命周期、权限与网络边界。

## 操作契约需要表达的内容

| 部分 | 候选内容 |
|---|---|
| 请求 | 任务身份、目标、基线、动作、参数、适用产品版本 |
| 约束 | 授权范围、资源归属、超时、重试条件、幂等或去重方式 |
| 回执 | 操作身份、受理/运行/完成/结果未知、观察到的实际影响 |
| 验证 | 判据、通过/失败/证据不足、适用范围 |
| 证据 | 原始输出、截图、抓包、日志、产物、来源和时间 |
| 恢复 | 外部任务身份、可恢复位置、取消状态、核对方式 |

通用信封、身份、状态和错误已有 [contracts](../packages/contracts/README.md) 冻结记录（当前契约 v1.2）；各链的具体操作 schema、能力包清单和运行可用性仍需逐项确定，见 [C/D/E 实现讨论](cde-implementation-discussion-v1.md)。身份和权限从可信运行环境传递；不能依靠模型自行声明。工具返回成功、产物生成、测试通过和业务恢复需要分别表示。

## Hook 的不同语义

- 观察回调：界面更新、普通统计等，可以记录回调错误后继续。
- 强制检查：授权、目标、基线、租约、发布条件，检查未完成时不能继续对应操作。
- 关键结果登记：回执和关键证据需要明确持久化保证及失败处理。
- 外部事件接入：CI 或设备事件唤醒已有任务，必须处理事件身份、重复和时序。

关键操作应在真正执行副作用的服务上做最终校验。通过 CLI、MCP 或脚本进入时都应遵守相同边界。不能用工具自报的只读提示代替执行端保证。

## 产品扩展包

候选内容包括多个 SKILL.md、TS 工具与适配器、验证器、能力与版本描述、样例、回归用例和引用规则。暂不新增私有的 skill 文档标准。

同一 skill 可以被不同角色使用，一次任务也可以组合多个 skills。产品命令和判据保留在领域组件内，通用任务机制不写死任何单一产品线的资源对象、命令、判据或案例编号；负载均衡实践用于验证这套跨产品线抽象。
