# ADR 0006：第一阶段设计收口——共同契约与五链验收基线

日期：2026-10-10。

状态：**已接受，为第一阶段设计基线。** 用户于 2026-10-10 回复“接受继续”，接受本 ADR 与三份收口文档作为基线并授权进入下一阶段（P1）。本 ADR 记录收口的范围、产物与未定事项；接受基线不等于已实现或已验证。本轮没有业务实现、设备连接或部署。

接受说明：接受范围为三份文档的整体框架与编号条款作为 P1 冻结工作的起点。OPEN-01–08 仍为未定事项，不因整体接受而视为已定案；P1 中对它们的定案需另行记录。个别条款若在 P1 冻结时需要修改，按纠正记录修订并保留历史，不静默覆盖。

## 背景与用户要求

用户要求接手私有仓库 infosec-platform，在已读 AGENTS.md、运行对象 V1、harness 适配计划与基础验证计划的基础上，完成第一阶段设计收口：明确 A（可替换 harness）、B（产品知识、证据与制品）、C（任务与协作治理）、D（操作执行与资源）、E（能力包与业务规则）的共同契约，并为知识问答、APV 设备操作、Web 登录操作、用例评审、人工脑图编译为 Excel 五条功能链制定完整验收方案。

用户同时重申：Circle、Pi、OpenCode 应能通过薄适配使用同一套 B/C/D/E，任务和执行状态不能依赖某个 harness；新自研实现全部采用 TypeScript，旧项目仅作为需求、数据和行为参考，不复制、包装或调用其代码。重点为结构化输入输出、来源与版本绑定、权限、真实副作用、失败与未知状态、重试取消、长任务恢复及跨 harness 接管；程序核验与 Jev/LLM 语义判断分别记录。本阶段只做调研和计划，待定与未验证内容必须明确披露。

## 本轮确认沿用的决定（不重新打开）

1. ADR 0003 的知识库 V1 基线（六类记录、PostgreSQL + 对象存储、不可变快照与发布规则、程序/模型分工）继续有效；共同契约的 B 部分与之对齐，不另造知识模型。
2. ADR 0004 的五类运行职责与 F/G 横切划分继续有效；本轮只在其上收口共同契约，不调整归属。
3. ADR 0005 的 harness 可替换、禁止复用旧代码、本轮仅做计划继续有效；本轮产物全部为计划文档，未越界实施。

## 本轮决定（已接受）

1. 以编号条款作为后续 P1 契约冻结的评审单位：整体接受为基线后，P1 冻结时仍按条款核对，修改需留纠正记录。
2. 以 `ResponseStatus` 多值状态、效果描述符、四段取消、unknown 正式终态与 reconcile 唯一出口，作为全平台统一语义（契约 COM/STATE/EFF/RC）。
3. 以完成准入清单（VER-03）作为任务 `delivered` 的唯一产生方式；执行成功、核验通过与交付完成严格三分（COM-03）。
4. 以薄适配禁止项清单约束每个 harness 的适配器实现与验收（契约 14.5 与 HAND 组）。
5. 以 P0–P5 顺序与门禁作为后续实施推进方式（验证矩阵第 5 节），其中 P1 只做契约层与样本，不做业务实现。

## 明确未定（OPEN）

共同契约第 16 节 OPEN-01–08 集中管理：wire 协议与 Tasks 扩展细节、幂等窗口与租约参数、tenant/scope 划分、语义模型与阈值、Excel 输出契约与脑图格式范围、APV 专用环境、Web 目标与 MFA 通道、各链完成清单的精确构成。本 ADR 不对上述事项作答；它们按验证矩阵的阶段安排逐项定案，定案时追加或更新 ADR 并同步受影响文档。
