# ADR 0009：ResponseStatus 增补 cancelled（OPEN-09 定案，契约 v1.1）

日期：2026-10-10。

状态：**已定案。** 用户于 2026-10-10 选择“给 `ResponseStatus` 增补 `cancelled`，走 v1.1”。本 ADR 关闭 [P1-3 记录](../p1-3-pairing-record.md) 发现的 OPEN-09。

## 决定

1. **`ResponseStatus` 由八值增为九值**，新增 `cancelled`：操作因取消而终止的**最终**状态。凡操作状态到达 `stopped-observed`（无论取消发生在执行前还是运行中），其最终响应状态一律为 `cancelled`；此前桩中“未执行即取消 → `not-run`”的临时映射废止。`not-run` 收窄为：被准入/校验明确拒绝、从未被受理执行的操作。
2. **CLI 退出码**：`cancelled = 5`（接在既有最终态 0–4 之后；中间态 10–12 不变）。
3. **契约版本升为 1.1.0**（`CONTRACT_VERSION`）。枚举增补对穷举消费方是破坏性变更：所有按 V1 八值写穷举分支的消费方必须显式处理 `cancelled`，不得落入默认成功/失败分支。npm 包版本（0.1.0）是制品编号，不随契约版本变化；契约版本以 `CONTRACT_VERSION` 与信封 `schemaVersion` 为准。
4. **生效方式**：契约包与服务桩在同一次变更中更新并重跑全部回归（契约测试 + 三路对拍）；P1-2 冻结记录与 P1-3 记录保留原文并加修订注记，不回改历史结论。共同契约 COM-02 的状态枚举同步增补 `cancelled` 并注明出处为本 ADR。

## 理由

- 取消是用户主动终止的正常结局，不是失败、不是部分完成、更不是未执行；用既有值冒充会在回执、统计与审计里系统性说谎（与 STATE 组的诚实原则冲突）。
- 在运行中取消与执行前取消之间维持同一最终状态，避免同一用户动作因取消时机不同得到不同结局词；时机差异由操作状态（`stopped-observed` 的前置路径）与证据表达，不由响应状态表达。

## 影响

- FZ-01 冻结版更新为九值；FZ-02 的操作状态词表不变（取消四段仍在操作状态空间内）。
- 验收侧后续动作：R06/RC 类场景在 P2 起按 `cancelled` 断言；V02/V03 的取消类验收条目在逐链评审时引用本 ADR。
- OPEN-09 关闭。本决定不涉及 OPEN-02（幂等窗口与租约参数）等其他未定项。
