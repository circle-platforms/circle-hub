# ADR 0003：知识库 V1 设计基线

日期：2026-10-10

状态：按用户本轮要求收敛的设计基线，供逐项实现；不是实现完成记录。

## 本轮要求

用户要求查看 Claude 最近发布的 mods 和 InfoTest 的发布过程，提出“可确定的东西交给程序，不可置真 100% 的内容交给 LLM”，并要求先定本版本知识库方案。

## 采用的设计

1. 全产品知识范围沿用 ADR 0002，以对象、声明、关系、来源和适用范围组织。
2. 六类核心记录为 SourceRevision、Evidence、Entity、Claim、Assessment、KnowledgeSnapshot；关系是一类有依据的 Claim。
3. TS 程序处理可重复的解析、核验、范围/权限、存储、索引、依赖失效和发布；Jev/LLM 处理语义判断并保留状态和依据。
4. 机械核验、来源性质、语义判断、实际验证和发布状态分别表达。
5. PostgreSQL 管事务与结构化知识，关系表与版本化 JSONB 共存；对象存储保存原始字节和产物；索引作为可重建投影，不先引入独立图数据库。
6. 精确、全文、关系和可选语义召回组合，返回共用证据包，不把模型相关性变成事实权威。
7. 不可变快照、candidate/stable、原子切换、并发保护、回滚、任务固定快照作为发布/消费基线。
8. 普通查询与机械解析可不调用模型；语义判断按具体输入和问题缓存并依赖失效，阈值在本产品样本上校准。
9. Circle/mod 类扩展组织接入与界面；知识服务负责权威数据、发布和权限规则。

详细模型、流程与验收见[知识库 V1](../knowledge-v1.md)。

## 对原则的解释

程序能够证明某个引用存在、某个哈希匹配或某个快照满足发布契约，但这些证明有明确对象与范围。模型可以判断含义并表达概率和未知；这类输出仍是 Assessment，不自动签发产品事实。

未决和冲突可带状态发布供研究与检索，不能为完成状态而强行归因或补造知识。
