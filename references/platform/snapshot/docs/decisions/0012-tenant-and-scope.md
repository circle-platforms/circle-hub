# ADR 0012：租户与 scope 划分基线（OPEN-03 定案）

日期：2026-10-10。状态：**已定案（用户于 2026-10-10 按建议确认）。**

## 决定

1. **单租户先行，多租户预留**：首期部署只有一个租户（本组织），但 `tenantId` 从第一天起就是所有信封、存储键与索引的强制组成（FZ-04 已含），禁止出现无租户的数据路径，避免日后 retrofit。
2. **scope 是授权与数据分区的基本单位**：一个 scope 对应一条产品线或一个独立项目；知识来源、快照、样本、任务、证据与产物全部按 `(tenantId, scopeId)` 分区存储与检索。
3. **跨 scope 默认拒绝**：快照不得混合多个 scope 的来源；跨 scope 读取需要对 principal 的显式授权记录（谁、何时、哪两个 scope、只读），无授权时按 `FORBIDDEN_SCOPE` 拒绝（样本 SMP-V01-04 是该规则的校准集）。
4. **角色最小集**：principal 在 scope 内的角色四种——requester（发起）、operator（执行）、approver（批准高风险/不可逆）、reviewer（评审签字）；一人可兼多角色，但不可逆操作的批准者不得是其发起人（职责分离只卡这一处，其余不设）。
5. scope 的创建与成员变更由 C 治理并留痕；已冻结样本中的 demo scope（scp_demo_a 等）只作校准，不是生产 scope 注册表。

## 理由

- 用户场景里“串项目”是真实风险（V01-04 样本即源于此），scope 先做硬分区、后谈共享，比先共享后收紧便宜得多。
- 单租户先行避免过早为多租户付复杂度税，但所有键预留租户维度，保住演进路径。

## 影响

- P2 的所有存储与查询接口按 `(tenantId, scopeId)` 设计；跨 scope 授权记录的数据形态在 P2-1 落定。
- AUTH 组条款在实现时按第 4 条角色集校验；角色扩展需修订本 ADR。
