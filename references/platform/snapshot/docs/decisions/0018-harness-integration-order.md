# ADR 0018：harness 接入顺序与版本固定（DEC-P3-03）

日期：2026-10-10。状态：**已定案（用户确认）**。

## 决定

P3-4 三 harness 薄适配按以下顺序接入：**OpenCode → Circle → Pi**。每家在接入开始时固定其当时的稳定版本并逐一记录（产品名、版本、安装来源）；接入产出两份必备记录：

1. **能力协商记录**：含 MCP 协商版本的实测断言（关闭 P1-3 以来“基线目标未核”的登记项）、可用传输与工具面、与 ADR 0007 基线（普通工具 + CLI 六调用同语义）的符合点与降级点；Pi 走扩展/CLI 路径的，按降级标注如实记录，不冒充原生 MCP。
2. **差异清单**：三家之间的行为差异集中成文公开（矩阵 P3 退出条件）。

R06 接管序列按验证矩阵定义执行：同一 task 由 **Circle 提交 → Pi 接管 → OpenCode 交付检验**，接管者为不同 actor（R05）。任务与执行权威状态始终在 C/D，harness 只经薄适配接入（常设约束）。

## 影响

任一 harness 的单独通过不得推及三家兼容（矩阵第 6 节）；版本固定后升级须重跑协商记录与 R06。
