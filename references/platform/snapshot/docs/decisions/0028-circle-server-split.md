# ADR 0028：Circle 客户端与 circle-server 分工

日期：2026-10-11。

状态：用户已明确下列产品分工。共同代码的具体取用、同步方式、发布门禁和 GitHub 调整见配套提案，尚未实施。

编号说明：未合并的前端迁移 PR #22 已使用 ADR 0027，本记录顺延为 0028，不覆盖原提案。

## 用户明确的方向

1. Circle 保留通用 harness 属性，企业平台能力由派生的 circle-server 项目承担。
2. 普通用户使用 Circle，通过连接插件访问 circle-server；配置服务端 IP 或域名后完成认证，使用获准的能力。
3. 连接插件放在 Circle 默认插件库，按需启用；不单独创建插件仓库或插件 Project。
4. B/C/D/E 的管理与运维由 circle-server 提供，不另外建设 Web 管理站点，也不把企业管理功能加入 Circle 的通用核心。
5. 客户端与服务端可以复用共同代码；要一起考虑 GitHub 工作组织、代码同步、兼容和发布。

## 职责和运行边界

Circle 和连接插件负责交互、连接、展示及用户回应。circle-server 持有 B 的产品资料与证据、C 的任务和权限、D 的实际执行资源、E 的方法与业务规则。显示或隐藏插件不改变权限。

服务端后台 Agent 可以复用 Circle 的 TypeScript 运行内核。这部分仍属于 A 的运行职责；会话记录不能代替 C 的任务、D 的实际操作或 B 的证据。长期任务由服务端持久受理和推进，客户端断开后仍可查询同一任务。

circle-server 的常驻后台和它自己的管理入口分别运行。复用 Circle 界面框架建设专用管理控制台是当前建议，具体复用基线和管理端形态仍需核验。关闭管理窗口不停止后台；后台可部署在无图形桌面的主机，管理入口通过受认证的接口访问它。

## 与已有决定的关系

- 保留 A–E/F/G 的职责与状态身份，不增加一个包办所有状态的 server 对象。
- 保留其他兼容 harness 的接入方向；插件是 Circle 的接入方式，不定义唯一业务实现。
- 允许按选定版本复用 Circle 的 TS harness 和界面基础；不取消旧 InfoTest、compile 或 Python 运行链的重写边界。
- C 的持久运行继续按 [ADR 0022](0022-durable-runtime-selection.md)使用 PostgreSQL 任务表基线，本次没有重选运行框架。
- SSH、产品 Web 操作的全过程可见、人员权限及输入输出披露继续有效。不建设 Web 管理站点，不表示取消 HTTP API 或产品 Web 操作。
- 旧工作台组合和 Web 管理提案保留为历史材料；正式产品的入口分工以本页为准。
