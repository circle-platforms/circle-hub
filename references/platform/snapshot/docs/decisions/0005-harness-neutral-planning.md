# ADR 0005：Harness 可替换与本轮仅做计划

日期：2026-10-10。状态：用户明确的方向与执行范围；详细契约/实施选型仍是提案。

## 用户要求

本轮有两项：调研类似项目经验；按已划分的五类对象计划全新 TS 基础验证，最终覆盖已有功能。Circle 是通用 harness，理论上可由 Pi/OpenCode 等替换，其余四类对象需适配。

最低功能包括知识问答、APV 设备操作、Web 登录操作、用例评审、人工脑图编译为 Excel。用户随后明确：**先都只做计划放到 GitHub 上，不实施。**

## 已确认

1. A 是可替换入口与 agent 运行职责，Circle 只是当前候选实现。平台不以 Circle 专属生命周期或内部数据格式定义 B/C/D/E。
2. 其余四类共享业务逻辑和权威状态，通过统一契约/薄适配服务不同 harness。F/G 保持横切工程，不增加运行对象。
3. 新平台不使用旧项目代码或旧执行后端；旧工程是需求、数据、行为与失败经验参考。相关自研执行实现全 TS。
4. 五条功能链是最低验证范围，不缩小产品级平台方向，也不表示通过五条即覆盖全部历史功能。
5. 当前仅调研、设计、计划、文档校验及 GitHub 记录；没有授权在本轮创建业务代码、启动验证服务、安装平台依赖或做设备/Web 实验。

## 本轮提案

- [同类项目调研](../research/comparable-platforms.md)：可借鉴的具体机制、责任和不能照搬的边界。
- [harness 适配计划](../harness-adaptation-plan.md)：统一状态/契约、最低兼容面、接入差异、跨 harness 接管实验。
- [基础与完整迁移验证计划](../foundation-validation-plan.md)：五条链、恢复实验、验证层、行为账本和实施前议题。

三种客户端的具体兼容性、模块/API 命名、MCP 版本、框架、TS 库与部署方式尚未定案。理论上可替换须经实际客户端和业务效果验证，不由 MCP 配置文件存在推断。

## 对之前记录的澄清

“Circle 保留”意味着不重写/改造 Circle 来承载本平台全部领域逻辑，不意味着其他客户端被排除。“后续逐项实现”是讨论方向，不是本轮开始实现的许可。知识库 V1 与运行对象 V1 继续有效。
