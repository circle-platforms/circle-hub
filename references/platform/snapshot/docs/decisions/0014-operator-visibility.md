# ADR 0014：操作全过程可见与两种入口布局

日期：2026-10-10。状态：**用户明确的需求与布局选择。** 具体显示协议/组件、Circle 适配、控制接管与验收数值仍为提案；未实施。

## 背景

讨论 SSH 和 Web 配置之后，用户指出上述方案都涉及显示：Circle 作为入口，必须让人看到 Web 的整个操作过程。用户进一步说明，两种方式都可行：Otty 这类终端自带浏览器可并排操作；Windows 普通终端可以打开 Chrome。

## 已确认

1. Web 操作须支持用户实时看到整个实际执行过程。模型日志、几张截图或事后报告不足以满足该要求。
2. 支持两种入口布局：具有浏览器面板的终端中并排显示；普通终端关联外部 Chrome 等浏览器显示。不把内嵌浏览器作为 Circle 或平台的唯一使用前提。
3. 本次是设计要求补充，只做计划和 GitHub 记录，不修改 Circle/平台业务代码或运行实际浏览器/设备实验。

## 对原范围的澄清

此前“Circle 本轮不展开”继续约束其核心运行实现；本次用户明确要求讨论入口的显示关系，因此 A 的薄展示/会话关联契约进入讨论。可替换 harness 和 C/D/E 权威边界继续有效，知识库设计不重开。

实现与验收提案见 [操作可见性计划 V1](../operator-visibility-plan-v1.md)。同一执行会话的显示、暂停/接管、输入出口校验、断流策略和具体组件均须在对应实现议题确定，不因本 ADR 自动成为已实现功能。

## 后续范围修订

设备管理范围以 [ADR 0021](0021-ssh-web-interaction-scope.md) 的 SSH 与 Web 为准。Web 全过程可见与两种入口布局仍有效，SSH 责任分工见 [SSH 职责计划](../ssh-responsibility-plan-v1.md)，用户交互与对象通信见[讨论稿](../user-interaction-and-object-communication-v1.md)。本次没有扩大为业务实施或设备实验。
