# ADR 0002：产品级知识库范围

日期：2026-10-10

状态：已确认的内容范围；索引设计后续收敛为 ADR 0003，业务实现尚未开始。

## 用户澄清

用户强调知识库要覆盖产品知识、测试知识、产品底层架构、代码、商务、型号、产品报价、Web 操作、友商知识等一切产品相关内容。仅靠现有 CLI 命令只能解决部分内容，并再次确认这是产品级 platform。

## 决定

1. 知识库的内容范围按产品全生命周期和相关业务确定，保持可扩展，不局限于当前 CLI、编译或评审资产。
2. CLI/XML 命令树和 footprint 是重要的现有知识来源与结构，但不能成为覆盖全部产品知识的唯一主体。
3. 既有分类目录统一不代表知识语义、来源性质、时间或适用条件相同。

## 用户提出的研究动机

Jev 的结构化判断能力值得用于研究跨用户与 agent、agent 与程序、agent 与 agent 的沟通和快速迭代。TS 的共用数据类型与接口是重构的重要理由之一。

该动机不等于已经决定所有索引依赖 Jev，也不表示结构化返回或置信度能够保证事实正确。

## 待讨论

- 如何定义产品、型号、功能、架构、代码、测试、许可、报价等对象身份。
- 关系、来源引用、适用范围和验证状态的表示方式。
- 原始目录/章节树、产品视图、设备命令树的关系。
- Jev 在入库、实体对齐、检索与判断复核中的具体角色和评测。
- 商务与报价的时效、条件、权限及跨用户共享范围。
- 多种索引与存储技术，以及更新、失效、冲突和未知的处理。

实现仍遵守 [ADR 0001](0001-project-direction.md) 的全 TS 新建边界。

## 后续收敛

本轮用户进一步要求先定知识库设计，以上对象、关系、职责、索引和发布流程已形成 [ADR 0003](0003-knowledge-v1-baseline.md) 与[知识库 V1](../knowledge-v1.md)。具体模型阈值、查询分析器、适配器与部署参数仍按实现议题确定。
