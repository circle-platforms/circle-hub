# ADR 0024：确定内容交给脚本，其余内容由 LLM 判定，完整披露输入输出

日期：2026-10-10。状态：用户确认的全平台设计原则；本次只更新设计，不宣称实现已经符合。

## 决定

用户明确平台的设计原理风格：**将 100% 置真内容交给脚本，其他非置真内容使用 LLM 判定，完整披露输入和输出结果。**

这条原则适用于知识处理、需求与代码分析、设备操作、测试、网络排障和交付。详细说明见[判断与披露原则](../design/truth-and-disclosure.md)。

“100% 置真”需要有明确的规则、适用范围和可核验输入。脚本负责在这些条件内确定能确定的事情，不能把格式正确、命令返回成功、历史观察或模拟测试通过扩大成业务真相。条件不满足时，保留缺项并交由 LLM 分析，不以硬编码强迫得到成功或失败。

需要理解、解释、比较或推断的内容交给 LLM。LLM 的判定是正式结果的一部分，但应与脚本事实、实际观察分别展示，披露依据、冲突、假设和仍缺的证据。模型置信度、反复同意或多个模型一致，都不能自动变成 100% 置真。

完整披露包括实际使用的输入、处理方法与版本、原始输出、转换过程、错误与重试、实际作用及最终结果。披露面向有权限的用户，原件与可见结果可以追溯；GitHub 只保存设计及适合发布的记录，不保存凭据、原始业务资料或完整对话日志。必要脱敏须说明哪些内容被遮蔽及原因，不能把删减结果标成完整原件。

## 与现有设计的关系

A 展示过程与结果，B 保存输入输出和证据，C 保留任务、决策及交付检查，D 记录执行和实际观察，E 定义脚本规则及 LLM 判断方法。F 提供共同表达，G 分别验证规则、执行效果与模型判断质量。该决定不增加新的运行对象。

现有 scripted assessor、夹具和规则评审用于其已声明的本地验证范围；不能因为它们存在就宣布非确定性语义判断已实现。后续各模块按本原则检查设计和验收。
