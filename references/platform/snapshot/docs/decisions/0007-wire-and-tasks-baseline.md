# ADR 0007：Wire 基线与 Tasks 扩展定位（OPEN-01 定案）

日期：2026-10-10。

状态：**已定案。** 用户于 2026-10-10 在 [P1 计划](../p1-contract-sample-plan.md)第 4 节的选项中选择 A。本 ADR 只定 wire 基线与扩展定位，不冻结具体包版本，不构成已实现声明。

## 决定

1. **最低基线**：长任务与平台语义只依赖普通 MCP tools 与 CLI 的长任务调用集——`submit / status / result / input / cancel / reconcile` 六个独立调用（共同契约 LONG-01），三路（MCP / CLI / HTTP）承载同一信封语义（COM、HAND-01）。不支持任何增强扩展的 harness，只要能走最低基线，即可接入同一套 B/C/D/E。
2. **增强可选**：MCP Tasks 扩展、resources、媒体与进度通知属于增强路径。支持的 harness 可以使用以减少轮询、改善呈现，但增强路径不得引入基线没有的业务语义；同一操作经基线与增强两路必须产生一致的业务状态与判据（R07 对拍）。
3. **协商与降级**：每次 run 记录能力协商结果（harness、版本、支持的传输/媒体/Tasks/人工输入方式，HAND-05）。能力不足时在产生副作用前显式拒绝对应能力或标注降级，不假装具备（如无视觉的 harness 不得宣称视觉判断）。
4. **版本基线**：MCP 以实现时三家目标 harness（Circle / Pi / OpenCode）当前正式版共同支持的官方规范版本为基线，确切版本号在 P1-2 启动时以三家实际版本核对后写入 P1 收口记录；在此之前不写死未经核对的版本号。schema 自身版本与兼容策略按 COM-05 执行。
5. **错误与退出码**：传输层错误必须映射到 FZ-03 的结构化错误（category + code），不得在任一路丢失语义；CLI 退出码与 `ResponseStatus` 的映射表随 P1-2 冻结（COM-06）。

## 理由

- 与已接受的三档兼容（适配计划第 5 节、HAND-01）一致，保证可替换性不被单一扩展的成熟度绑架。
- 选项 B（强制 Tasks）可能直接排除一家目标 harness，与“任务和执行状态不能依赖某个 harness”的已确认方向冲突。
- 选项 C（仅 HTTP）把集成成本转嫁给每个适配器，并与既有 MCP 生态脱节。

## 影响与后续

- 共同契约第 16 节 OPEN-01 标记为已定案（本 ADR）；FZ-01/FZ-04 可以在 P1-2 据此落 schema。
- 仍未定：确切 MCP 版本号（P1-2 核对）、幂等窗口与租约参数（OPEN-02，P2 数据定案）、错误 code 的逐项清单（P1-2 冻结）。
- 本决定不改变任何业务语义；若 P1-2 核对发现三家共同支持面与本基线冲突，按纠正记录修订本 ADR 并说明影响，不静默偏离。
