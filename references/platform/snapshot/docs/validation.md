# 全 TS 重写与验证

状态：方法提案；本轮用户要求只做计划放到 GitHub，不实施。没有运行业务测试、模型实验或设备验收。

具体五条链、长任务/更换 harness 实验、分层证据与全功能迁移条件见[基础验证计划](foundation-validation-plan.md)。Circle/Pi/OpenCode 的接入事实与共同契约见[harness 适配计划](harness-adaptation-plan.md)。

## 重写原则

新自研执行代码统一 TS。旧 Python 源码可以帮助确认行为、定位历史缺陷、构造对照输入，但不能被复制进新生产运行链或作为新 TS 服务的隐式执行后端。

旧系统行为分为三类记录：确认要保持的行为、已知缺陷、尚待澄清的行为。对拍相同不必然说明正确，差异也不必然说明回归。

新系统也不能复制旧 TS 自研运行模块；相关后端与适配器均从新设计实现。允许借鉴行为、获准数据与独立验收契约，并使用适合的公共 TS 库；旧代码不进入新运行链。Circle 仅作为已有通用 harness 使用，平台应可更换客户端。

## 分层验证

| 层次 | 观察对象 |
|---|---|
| 契约 | 输入输出、状态迁移、版本、错误和边界语义 |
| Harness 行为 | 下一次模型请求、原始历史、取消、恢复、预算和协作 |
| 执行效果 | 文件、进程、外部任务、设备和浏览器实际状态 |
| 业务正确性 | 基于来源的判据、产品预期、覆盖范围和真实结果 |
| 交付 | 制品与验证身份一致、未完成项如实保留、报告与事实一致 |

开发时使用脚本化模型、本地 HTTP 网关和隔离资源验证运行语义。模型质量实验与真机验收另行安排，记录模型、版本、环境和预算。

## 应保留的故障样本

- 模型宣告完成，但没有有效提交或产物。
- 工具已执行，回执丢失；恢复时发生重复副作用。
- 取消本地调用后，远程进程仍然运行。
- 历史通过结果被用于改变后的输入、代码、设备或拓扑。
- 退出码成功，但响应语义或实际流量不符合要求。
- 日志换行、裁剪窗口或编码变化导致判据读取不同输入。
- 同一轮的多条拒收记录被错误计作多次独立尝试。
- 规则已生效但报告或其他执行入口没有消费该规则。
- 证据不足时强行给模型、环境或产品归因。
- 通过跳过、削弱断言或根据实际输出来改写预期取得绿色结果。

这些类别来自既有工程经验。迁移具体样本前要核验来源、脱敏、固定原始输入，并标明预期和实际观察；不能编造缺失身份。

## 三组研究实验

1. 长任务：在等待、上下文切换、重启、外部状态变化后检查恢复和进展。
2. Web：比较结构化、视觉与程序执行的组合，检查页面变化、重复执行和实际业务结果。
3. 经验与协作：比较经验复用或额外角色的收益、成本及失效识别。

固定模型、环境、任务和预算，保留单 agent 与无经验复用的基线。公共 Web 基准可补充研究，不能替代本产品环境的验收。

## 每项实现的完成证据

开始前明确问题和可复现样本；实现后证明目标行为、相关边界和必要的消费者都得到验证。需要时检查原故障、修复后结果、重新注入故障的边界，以及合法输入不会被误拒绝。

报告区分静态检查、本地测试、离线对拍、真实模型实验和设备验收。失败、跳过、资料缺失与未执行项目分别记录。旧测试总数不能被引用为当前提交已通过。
