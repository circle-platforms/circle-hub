# P2-2 完成记录：V05 脑图编译器纵切

日期：2026-10-10。本记录是 P2 隔离纵切规划 P2-2 的出口证据。执行环境：助手自有计算机本地，未连接任何外部系统；输入样本为仓库内已冻结的合成样本。

## 1. 交付内容

`packages/chain-v05`：按已冻结的 Excel 输出契约 V1 实现——两路输入解析（主题树 JSON、XMind content.json）→ IR（主题树、标题规范化、SHA-256）→ 行编译（深度优先、深度 ≥ 2 成行）→ ExcelJS 生成 .xlsx（`用例清单` + `说明` 两表）→ 往返读取校验。纵切测试同时跑通平台核心（TaskService 清单门禁 + Registry 产物登记）。

## 2. 本地实测（执行时验证）

| 检查 | 结果 |
| --- | --- |
| chain-v05 typecheck + 测试 | 通过，**8/8** |
| 平台核心回归（含下述缺陷修复后） | 通过，**12/12** |

8 项测试要点：

- **一致性（契约第 4 节锚点）**：主题树与 content.json 两路输入编译冻结样本 SMP-V05-01，逐格等于 SMP-V05-02 的 8 行期望；两路 IR 哈希相同。
- **往返**：生成的工作簿重读后，表名顺序、表头、8 行内容、深度数值类型、`说明` 五项元数据（源 SHA-256、输入格式、契约版本、映射规则版本、根标题）全部与期望一致；同输入同元数据重复编译结果一致（确定性）。
- **partial**：非对象子节点、空标题节点、非字符串 note 三类不可映射元素被列明（响应 + `说明` 表），状态 partial，其余行正常生成；content.json 第二张 sheet 报告未映射、不编译。
- **失败**：不可解析输入整体失败（INVALID_PAYLOAD），不产出工作簿。
- **纵切**：编译产物经 Registry 登记（跨 scope 读取被拒），任务挂三项必需核验的完成清单后经门禁交付成功。

## 3. 本步发现并修复的一处既有缺陷

平台核心 `src/result.ts` 构造的错误对象与冻结的 StructuredError schema 不符（`userActionRequired` 不是 schema 字段，且缺失必填的 `userAction`/`evidenceRefs`；平台测试未对错误对象做 schema 校验而漏检）。已改为经 `StructuredErrorSchema.parse` 构造，平台 12 项测试复跑通过。传输桩的错误构造经复查符合 schema，未受影响。

- 仍只处理结构层：`.xmind` 二进制、真实 XMind 版本范围、多 sheet 编译均按契约第 5 节延后，不在本步声称范围。
- 测试从仓库 `samples/v05/` 读取冻结样本（`V05_SAMPLES_DIR` 可覆盖路径）；本地运行时经等价目录提供同一批冻结文件，哈希与登记表一致。
