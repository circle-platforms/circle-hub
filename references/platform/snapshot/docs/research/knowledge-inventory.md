没有上传、编辑或删除资料，没有运行导入、转换、迁移或设备任务，没有修改配置或重启服务。SSH 会话已退出。记录是现场观察，不是冻结全盘备份，也没有对全部资料做语义复核。

## 已观察到的服务与资产

- Apache 提供分类资料的 WebDAV 入口；根目录 HEAD 返回 200。
- 一个 Python/Flask 文件管理服务在线，未认证访问返回 401。源码包含文件和文件夹上传/下载、查看、编辑、保存、删除、新建等路由；本轮未实际调用写接口。
- 文件管理服务的上传根与分类分发根不是同一个目录或简单符号链接。
- 文件管理服务 app.py 共 441 行；检查前后 SHA-256 均为 40068c700bda075b2b6934641a50285ba95b5e6dba6849249f47820e8bc0377d。
- 分发目录存在 docx2md/pdf2md 状态文件及转换失败排除记录。
- 部署的 InfoTest 消费目录有按版本的 manual、product/qa Markdown，以及 spec 的 active.json 与 generations。
- spec 的活动记录包含 generation_id、manifest_sha256 和 schema；本轮未验证整个代际的文件闭包。
- 同机还运行已有 compile 数据服务与其他应用。没有把这些现有服务作为新平台已实现能力，也未修改它们。

## 对新 TS 知识服务的启示

已有资料不只是待搜索的文本：版本、结构化命令、参数、示例、图片与来源都值得保留。新系统优先明确资产身份、来源关系、版本与引用，再讨论检索技术。

需要进一步研究原件到转换件、转换件到分发件、分发件到消费者快照的关系，以及重复、更新、删除、转换失败和版本冲突的处理。原始资料迁移与新的 TS 实现是两个不同工作面。
