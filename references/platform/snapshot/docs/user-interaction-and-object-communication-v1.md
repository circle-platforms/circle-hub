# 用户交互与对象通信 V1

日期：2026-10-10。状态：**讨论提案，未冻结接口或实施。** 当前设备范围按 [ADR 0021](decisions/0021-ssh-web-interaction-scope.md) 为 SSH 与 Web；沿用[对象 V1](object-boundaries-v1.md)、[共同契约](common-contracts-v1.md)、[可见性要求](decisions/0014-operator-visibility.md)和 [SSH 责任计划](ssh-responsibility-plan-v1.md)。

本轮讨论怎样表达目标、响应问题、观察/干预实际操作，以及对象间如何传递请求、状态、决定和证据。五类对象是逻辑职责，可先以模块组织；对象间通信不等于新建五个独立 agent 或五套会话。

## 1. 用户看到四种交互入口

| 交互 | 用户能做什么 | 负责对象与权威记录 |
|---|---|---|
| 聊天 | 提目标、问进展、补充资料、纠正理解、改变方向 | A 保存原始会话并理解意图；C 接收影响任务的明确变更，形成输入/计划修订 |
| 结构化回应 | 澄清选项、确认具体变更、评审签字、处理分歧 | A 显示问题及其对应任务/输入；C 持有 PendingInput/Decision 并验证响应身份和有效性 |
| 实时操作视图 | 看 SSH 终端或真实 Web 页面，请求暂停、接管、交回、取消 | A 打开同会话视图；C 核验许可和记录决定；D 持有实际会话/控制者并执行输入或停止 |
| 产物与证据查看 | 打开配置差异、报告、用例、运行输出和引用，定位问题并发起修正 | B 保存不可变内容及修订；A 呈现与展开；E 提供专业解释/核验；C 管相关评审和交付 |

可以继续在 Circle 中完成普通聊天和明确的回应；Otty 面板或外部 Chrome 提供实际操作/证据页面。具体控件和布局逐项确定。显示任务目标、当前动作、真实连接/等待/未知状态和下一项用户输入，避免让用户根据模型文字猜设备是否还在执行。

“同意”可以作为交互输入：A 将用户对一个已明确问题的答复绑定到对应 requestId 和当前输入，交 C 核验。存在多个请求、作用不清或输入已改变时不能自行选一个审批对象。文本选项/按钮是输入形式，真正决定效力来自 C 的身份和修订检查；不要求每次都重复确认既有授权。

## 2. 一项任务如何交互

示例：用户要求“把设备 X 的某参数改为指定值，并验证结果”。

1. A 理解目标，展示可核对的设备、期望值和已有上下文；存在关键歧义时提出具体问题。E 的方法和 B 的规范帮助解释，模型解释保留为解释。
2. C 固定任务/输入/方法版本，核对已有授权与作用；需要补充决定时创建明确 PendingInput，而非由聊天末尾的泛化“可以开始吗”充当准入。
3. D 建立或核对执行会话；A 关联原会话显示。在实际动作前保证所需查看路径就绪，真实操作和动作时间线同步呈现。
4. 用户观察期间可继续聊天、补资料或请求干预。A 区分询问、目标变更、暂停、取消和接管，分别路由，不把这些动作都实现为中断本地模型调用。
5. D 产生执行事实与现场证据；E 在固定依据下核验；B 登记结果。C 核对完成清单后给出可交付结果，A 展示已完成、未完成与可展开依据。

首期不必为普通只读问答创建复杂流程：A 可在可信 scope 内调用 B/E 查询。需要副作用、跨会话等待、人工决定或交付追踪的工作进入 C/D 持久任务路径。

## 3. 对象间采用三种沟通方式

| 方式 | 用途 | 权威约束 |
|---|---|---|
| 短请求/响应 | 读取知识、获取方法、查询任务、提交决定、取得会话引用 | 共用 TS/runtime 契约；进程内调用模块，跨进程通过共同 facade/SDK；接收者核对身份/绑定，不各写业务分支 |
| 持久工作调用 | 长操作提交、等待、查询结果、人工响应、取消、对账 | 沿用 submit/status/result/input/cancel/reconcile；完成持久受理才返回 accepted；C 与 D 分别持有任务和执行状态 |
| 事件/实时流 | 任务进度、待输入通知、SSH 输出、浏览器画面、连接变化 | 从拥有者产生并带身份/序号/时刻；事件用于唤醒和显示，最终状态回到拥有者查询；漏事件可重新获取状态并披露流缺口 |

MCP、CLI、HTTP 是已有接入面；新实时订阅/流的传输后续选型。不同入口都消费同一 B/C/D/E 语义。暂不要求所有模块跨进程，也不先新增一个全平台消息总线。

## 4. 谁向谁传什么

| 路径 | 传递内容 | 返回内容 |
|---|---|---|
| A → C | 用户目标、任务引用、输入/参数变更、人工回应、干预请求 | task/run、当前修订、待输入、关联操作、完成清单与授权拒绝原因 |
| A → B/E（普通查询） | 可信授权范围内的知识/方法查询与版本引用 | 可展开来源、判断/未知和方法说明；不自动授权执行 |
| C → E | 固定输入/知识/能力包版本、需执行的方法或核验 | 步骤/作用建议、Verification/Assessment/findings、待澄清内容与制品引用 |
| C → D | 已准入的操作、目标/输入/作用/期限、任务委托引用 | operation/attempt、实际执行状态、会话/查看引用、现场证据和遗留 |
| D → B | 现场产生的输出/截图等内容、hash、来源位置、目标/运行/时间绑定 | evidenceId/修订与登记核验；内容上传失败不改写为操作未执行 |
| E → B | 固定方法产出的核验/判断、候选产物及其依据 | 记录/制品修订与引用闭包检查；语义判断不自动签发产品事实 |
| C → B/D | 交付前读取当前绑定的记录、执行终局/对账和产物身份 | 可核对的记录与缺项；C 据此推进任务，不能凭事件摘要收口 |
| D → A（查看流） | 同一 SSH/浏览器会话的实时内容、状态、控制者和缺口 | 显示附着/断开信息；不改变执行终态 |
| A → D（获准操作视图） | 当前控制授权下的人工输入或敏感通道提交 | 实际输入受理/拒绝与当前控制修订；每次在 D 的真实出口核验 |

E 的方法可作为库在 C 的步骤或 D worker 中执行，无须为表中每一行新增 HTTP 服务。C 提供政策，D/B 等实际作用端做最终核对。F 提供类型/schema/错误/兼容材料，G 负责这些路径的独立回归，不成为运行中的授权或交付拥有者。

## 5. 交接内容与一致性

共享的是所需引用和结构化记录：task/run、inputRevision、operation/attempt、resource/session、scope、具体方法/包/知识版本、evidence/artifact 引用。自然语言用于目标、解释、理由和建议，不作为权限或终态字段。模型负责意图/语义判断，确定性的身份、状态、作用和引用检查由程序执行；格式正确不证明内容真实。

可信身份来自已认证通道，服务端构造上下文；模型或请求体填写 principal/tenant 不能扩权。对象读取其所需原件/片段和记录，不广播整段私人聊天或要求用户向每个对象重复描述任务。会话历史在 A，任务在 C，实际执行在 D，产品资料/证据/制品在 B，方法与规则版本在 E。

变更请求绑定预期输入/计划修订；重复请求按已定幂等契约处理，旧决定、乱序事件和陈旧控制输入拒绝推进当前任务。对象不直接改其他拥有者的存储。C 的业务持久存储已由 [ADR 0017](decisions/0017-postgresql-baseline.md) 固定 PostgreSQL 基线；领域变更与可靠待发送记录放同一事务，接收端按事件身份幂等消费。事务隔离、消息投递、重试和恢复实现仍须在 C 的实现议题验证，本稿不重开存储选型。

实时显示与设备原始记录分开：看不到后续流不代表操作停止；缓存重放不标为实时。通知丢失时读取权威状态；关键原件按范围保存在 B，收到通知不证明已经核验或交付。

## 6. 三类用户干预分别处理（提案）

| 用户意图 | 协作路径 | 必须呈现的事实 |
|---|---|---|
| 改变目标/输入 | A 提交明确变更 → C 新修订和影响分析 → D 核对在途作用 → E 重新生成/核验受影响步骤 | 已发生作用、旧结果/审批哪些失效、剩余工作；不能自动回滚所有已执行内容 |
| 暂停或取消 | A 明确 task/operation 范围 → C 记录请求 → D 停止后续派发/送达取消并核对实际状态 | 已请求、已送达、是否实际停止、残留；保持现有状态词表，不能凭入口响应判停 |
| 人工接管/交回 | A 请求 → C 核验 → D 达到可交接位置并切换输入控制 → E 检查当前模式/条件 → C 继续计划 | 当前控制者、在途未知、交回后的有效绑定；同会话不双输入 |

口令/MFA 使用专用敏感通道进入 D；C 只登记相应待输入和处理结果，A 的普通聊天、模型请求、事件摘要和 B 证据中不携带秘密值。

## 7. 下一步讨论与验证

建议先确定用户意图到平台动作的映射，以及每种动作的完成反馈，再冻结具体字段和页面。主要议题：聊天怎样绑定当前任务/未决请求；暂停/取消/接管怎样区别呈现；多任务怎样选择当前目标；断连时怎样查询和显示真实状态；证据怎样展开；能力不足的入口怎样明确降级。

未来验证分别覆盖自然语言歧义/多请求、旧修订响应、目标改变时仍在执行、通知重复/乱序/丢失、显示断流与重新附着、跨 scope 读取/控制、并发接管、敏感通道、伪造完成与引用。冻结提交/输入/身份/运行/目标后，检查实际动作、权威记录和下一次消费行为，不能只检查界面文字。

本轮仅更新文档和 GitHub 记录：无业务代码、依赖安装、服务启动、设备/浏览器或模型实验。当前候选通信面和用户干预方案不因写入本稿成为已接受实现。
