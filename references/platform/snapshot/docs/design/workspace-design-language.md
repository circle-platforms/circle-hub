# 工作台的视觉与交互

2026-10-10。以下记录的是已被用户否定的旧方案及其演变，不再作为界面基线。当前入口方案见[Harness 五方案](harness-interface-alternatives.md)。第一版把平台收窄成网络排障后台，用户指出定位和审美不符；后续改为产品与完整任务，并按用户要求联网检查成熟产品界面。

## 参考和取舍

看了 [Linear 项目界面](https://linear.app/docs/projects)及其官方截图；它把目标、资料、属性和任务放在同一项目上下文。参考 [Vercel Geist](https://vercel.com/geist/introduction)的统一组件、[颜色](https://vercel.com/geist/colors)与[字号](https://vercel.com/geist/typography)，以及 [GitHub Primer 导航](https://primer.style/product/ui-patterns/navigation/)和[图表](https://primer.style/product/ui-patterns/data-visualization/)规范。本平台的布局与交互是根据自身需求设计，没有复制第三方源码、品牌或截图作为产品素材。

首页服务于选产品、提目标和继续任务。答疑、评审、开发、测试、设备操作和发布是快捷起点，工作仍可自由组合。任务页以对话推进，按需展开变更、执行、输入输出和交付；管理入口提供资料、资源、方法与人员权限的维护。

## 统一表达

浅色背景、中性色文字与边框，少量强调色用于可操作和当前状态。成功、警告和失败分别有文字，不只靠颜色。图标使用统一线条；步骤图、拓扑与详情共用节点、连线、字体和状态规则。图表用来解释工作与证据，不填充没有数据依据的百分比或统计。

文案写用户能直接理解的动作，例如开始工作、查看依据、暂停、接管、检查结果。规则、原始记录和限制放到详情，默认页面不堆设计术语。涉及 demo 的说明在固定入口可见；不能用精简文案掩盖没有实现的后端、鉴权、模型或设备操作。

导航保留返回路径，页内标签围绕同一任务切换。搜索、输入保留、键盘操作、空结果与受限权限有明确反馈。界面支持窄屏；重型网络图可以在自己的区域滚动，不导致整页横向溢出。

当前 [demo](../../demo/workbench/README.md)使用合成内容，浏览器检查只证明其前端交互，不证明实际平台或安全机制已经完成。
