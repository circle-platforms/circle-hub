# 哪些人能看什么、做什么，以及哪里必须检查

2026-10-11 补充：用户通过 Circle 默认插件认证并使用获准能力；成员、政策、服务和资源维护从 circle-server 管理入口发起。服务端实际作用路径检查权限，不因插件安装或管理员页面可见而扩权，见 [ADR 0028](../decisions/0028-circle-server-split.md)。

2026-10-10。用户明确提出人员区分、鉴权和安全划分。本页形成设计方案；角色名称、组织身份接入、具体策略与实现仍需按任务冻结。demo 只有前端权限反馈，不能作为鉴权实现。

## 人员角色与业务范围共同决定权限

登录使用可信身份来源，浏览器、Circle 和 CLI 都不能靠请求体自报管理员身份。组织/项目是资料和任务隔离的基础，再按产品、环境、目标资源、具体动作及有效时间限定权限。单组织部署也要保留项目与环境隔离。一个人可以在不同项目承担不同角色，不能把角色变成全平台通行证。

| 人员职责 | 可以承担的能力 | 默认不包含 |
|---|---|---|
| 观察与业务阅读 | 项目内资料、任务、允许的现场与结果 | 设备控制、变更、方法发布 |
| 研发/测试/操作人员 | 授权项目中的任务、工作区与测试环境操作 | 生产环境、其他项目、全部凭据、权限策略修改 |
| 产品/方法专家 | 规则与方法编辑、验证、支持范围评审和获准发布 | 其他产品的方法、任意生产变更、扩大本人权限 |
| 业务审批人 | 对指定项目和作用范围的请求作决定 | 通过审批获得任意设备或资料访问权 |
| 审计人员 | 授权范围内的审计记录及必要证据 | 操作资源、修改审计、读取所有秘密 |
| 安全管理员 | 成员、角色、策略和安全域管理 | 自动读取全部业务资料、控制所有设备 |
| 平台运维 | 服务健康、排空 worker、备份与恢复等维护 | 自动读取资料正文、设备业务变更、使用他人账号 |

查看、执行、控制会话、审批、发布方法、维护服务是不同权限。测试域授权不继承到生产域。审批要求由明确的操作策略决定，授权内的常规工作自动推进，不对每一步反复征求确认；需要审批时绑定具体输入、目标、动作和版本。

## 每个实际作用端都要强制检查

A 显示可用动作并处理登录与交互；C 检查任务、委托、输入修订及决定；B 在查询、原件和引用访问时检查范围；D 在连接、每次实际作用、接管和结果读取时检查；E 检查方法修改、使用与发布权限。隐藏按钮、普通 hook 或模型判断都不能承担强制鉴权。

服务账号与 worker 不借用人员的全部权限。委托绑定发起人、任务、项目、目标、动作、期限和策略版本；有效权限不得超过人员授权、服务权限及本次委托的共同范围。租约协调资源使用，不替代授权。接口、MCP、CLI、Web 和后台恢复路径都执行相同规则。

权限被撤回或任务输入变化后，拒绝下一项失效动作，检查在途操作并如实呈现停止是否确认；不能因为本地请求中断就宣布远端停止。生产部署与真实目标仍按原授权范围处理。

## 数据与控制通道分别保护

完整披露面向有权限的人员。原始业务资料、代码、截图、浏览器状态、模型上下文、日志与导出的报告都沿用项目和内容范围，不能通过搜索摘要、事件流或产物链接绕过。派生结果不能丢掉来源的访问限制，跨范围组合需要检查所有来源。

口令、MFA、密钥及连接凭据由受控通道与秘密管理设施处理，不放入普通聊天、模型上下文、代码库或常规审计日志。具体设施选型后续确定。会话查看链接需要短期授权并绑定可查看范围，原始 SSH/浏览器调试端口不向普通用户开放。

代码执行、产品方法和上传文件是实际执行边界。D 使用任务专用工作区与运行资源，按授权限定网络、文件与进程作用；正式隔离方式单独验证，本地进程目录隔离不等于安全沙盒。资料中的命令或模型输出不能扩大权限，方法发布与运行分别受控。

备份包含敏感内容，维护任务只取得必要范围；恢复前核对目标与版本，恢复后核对权限及业务记录。管理员读存储、调试或紧急访问需要明确范围与审计，不能靠数据库手改权限或结果。

## 安全验收从首个可用任务开始

至少覆盖：未登录访问；跨项目/环境读取；伪造人员或服务身份；越权执行/接管；搜索、引用、导出与实时流泄漏；失效委托、旧审批和权限撤回；方法修改/发布分离；敏感输入与日志检查；worker 作用范围和恢复路径。

正常授权场景和拒绝场景都要检查真实接口、返回内容与实际作用，不能只看页面。安全策略说明与当前运行权限分别记录，demo 或静态清单不签发安全通过。
