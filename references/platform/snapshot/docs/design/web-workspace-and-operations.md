## 用户直接与 Agent 工作

2026-10-11 后续：前端开始按[通用工作台与可选插件](pluggable-workbench.md)组合，既研究 Circle 的图形入口，也保留 B/C/D/E 的独立接入。初始布局继续采用，插件接口和完整运行集成继续评审。

A 提供持续会话、模型、上下文、工具与技能加载、调用过程、中断和继续。用户自由表达目标、补充现象或引用前文，由 A 结合当前工作区和授权范围处理。产品、版本和环境是上下文，需要时取得或澄清，不是每次输入前必须填写的表单。

答疑、开发、测试、设备操作和发布是可完成的工作，不能直接堆成固定首页流程。C 的长期工作与 A 的会话分开，只有符合长期运行、交接、人工决定或交付跟踪要求时，才通过契约持久受理；聊天本身不自动变成预定义任务。

B/C/D/E 分别有观察和维护入口，也能从 A 的工具、来源或运行记录直接关联。用户不必在每个对象中重复解释目标；管理员需要的维护操作则按对象与权限展开。

## 历史提案：A 可以直接在 Web 中提供

没有 Circle、Pi 或 OpenCode 的用户，直接在 Web 发起和完成任务。正式版本需要服务端的对话/agent 运行能力，复用适合的公共框架或兼容运行组件；具体选型尚未确定。浏览器不保管模型密钥，不直接连接设备或直接读业务数据库。

Circle 等是可选入口。Web 与它们调用同一 B/C/D/E 契约，关联同一任务、权限、输入版本与证据。会话可以变，任务不因此重建。Web 对话、执行可见性与管理界面同属 A 的展示和交互职责，不新增一个持有业务真相的管理对象。

## 四个对象怎样观察、操作和维护

| 对象 | 日常观察 | 获准操作 | 专门维护 |
|---|---|---|---|
| B 知识、证据与产物 | 来源、版本、冲突、引用、原件、导入与查询状态 | 导入资料、登记结果、发布/撤回资料修订；按权限查看原件 | 重建索引、处理导入失败、备份恢复和存储核对；索引不替代原件 |
| C 任务与决策 | 目标、步骤、输入修订、等待、阻塞、关联操作及交付缺项 | 补充输入、修改目标、回应问题、请求暂停/取消/继续、交接任务 | 查询运行积压、恢复任务、处理失效通知；不能直接改数据库宣布完成 |
| D 执行与资源 | worker、资源、租约、实际会话、命令、浏览器、在途作用及残留 | 获准的采集与操作、控制接管、重连、停止请求、远端对账 | 排空/重启 worker、核对孤立操作、凭据轮换与资源清理；维护权不等于设备业务权限 |
| E 产品方法 | 产品/版本支持范围、脚本规则、LLM 输入输出、测试与方法版本 | 运行获准方法，提交改进候选，复核判断 | 测试、发布、停用和回滚方法；旧任务固定旧版本，晋级需要独立核验 |

在一个任务中看这四部分的关联，避免让用户去四个后台重新解释问题。维护视图另行展示服务健康、积压、延迟、错误、存储与恢复状态；人员能看到的范围由[权限方案](identity-and-security-boundaries.md)限制。

## 历史提案：桌面为主，Web 与 CLI 作为补充

独立桌面应用提供会话、工作区、终端、浏览器及平台管理。Web 可保留为补充查看和管理入口，CLI 用于自动化、批量查询和故障恢复。各入口使用相同的身份、权限和状态规则。

复杂网络内的 worker 保持独立运行，可以部署在能接近目标的位置。管理页面通过受认证的服务查询和控制它，不能暴露原始调试端口或用一个可转发链接代替会话授权。查看与控制同一 SSH/浏览器会话分别授权，敏感输入走专用通道。

## 分阶段交付

第一阶段提供一个产品上下文、原生任务交互、有限的 B/C/D/E 关联视图，以及人员登录和项目/环境范围检查。后续补齐真实模型、跨层调查、方法维护、跨入口接管和多人运行。备份恢复、故障处置和诊断导出需要独立验收，不能由一个健康灯或管理按钮推出已经实现。
