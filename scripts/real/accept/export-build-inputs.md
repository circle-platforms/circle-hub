# 构建验收输入导出

由集成者在部署主机运行。开发和测试只用合成数据，不会启动同步、模型、派发或连接真实业务系统。先让管理员完成知识生产和原件读取，再导出已保存的快照。

```sh
node scripts/real/accept/export-build-inputs.ts \
  --token-file <管理员令牌文件> \
  --product <产品> --build <构建> \
  --out <仓库外空目录>
```

令牌文件以 UTF-8 读取并去掉首尾空白；令牌不进入命令行、输出或证据文件。管理员 CLI 使用 `bin/circle-hub`，仅给该子进程设置 `CIRCLE_HUB_TOKEN`。它使用部署主机的现有数据库配置；脚本自己不连 MCP、不开端口，全部读取走这一个 CLI，因此也不会读到另一套部署。

读取路线：新增的通用只读命令 `circle-hub knowledge view <knowledge外部标识> [--only <取值列表>] [--as <管理员>] --out <新文件>` 调用现有知识视图读取器，保留它的 JSON 字节。单独的 --only 使用与引用查询参数相同的逗号分隔、URI 百分号编码写法，不能与引用内的 only 重复。屏幕仅输出字节数、SHA-256、totals 数字计数和截断/跳过情况。无令牌且启用管理员不唯一时可用 --as 选择管理员；有令牌时 --as 必须与令牌账号一致。它只允许启用中的管理员，不加 MCP 工具，不借用业务包创建运行，也不生产知识。普通 `knowledge sync` 没有被调用。视图读取会保留现有的读取凭据和派生记录。

导出索引是 `knowledge:index:<产品>:<构建>?kind=case&key=document&fields=commands,document,node`。首页就是完整视图（`truncated` 为否、`next` 为空）时直接保存为 `index-1.json`；否则脚本按视图自己给出的 `next` 续页标识一页页读下去，直到没有下一页，收齐全部文档键，再逐文档用 `only=` 补取完整分片，保存为 `index-*.json`（比较器要求每份视图自己完整，分页本身不能直接当输入）。续页读不出时不算完：通常是该页条目有未受理的凭据命中，Hub 不按 `after` 续读（首页有命中时它直接把 `next` 置空），脚本记下次数、改由分面视图补齐键集，并在屏幕上写明这一事实。

分面视图 `knowledge:facets:<产品>:<构建>?kind=case&by=document` 是交叉核对，不是枚举路线：它数的是同一批条目（挂树的、留在根下未归位的、产品级根的都算），一行一个取值，`null` 那一行是没有文档键的条目（索引不为它们建键），不是字符串的取值按 Hub 的规范 JSON 文本映射成键（数字、布尔就是它们的字面文本）；它自己也按 `next` 翻页。两个恒等式必须成立：`total_keys` 等于分页列出的键与分面非空取值行的并集，`total_entries` 等于分面 `total` 减 `totals.empty.document`；对不上就停下，报出两边的计数（索引几个、分页列出几个、分面几行、合计几个、读不出的续页几次）和下一步。空字符串键和 `__proto__` 键各自准确拒绝：前者 `only=` 表达不了，后者索引不为它列出任何键。所有读取必须保持同一产品、构建根、不分版本根及其组成和两个总数；另外逐页逐分片核对 `totals.entry_counts`（按内容去重的条目总数、已挂到树上位置的、未挂到树上位置的），不一致就是快照在导出中移动过；比不分版本摘要时只比根和组成，因为索引会按自己的 `only` 过滤那份摘要的总数。某个文档的条目全部被排除、来源未读或快照漂移均拒绝，不把截断的视图混进可供比较的索引文件。

不分版本的根可以合法地为空。文档键为零时，只有回答自己声明“完整且为空”才接受：索引首页 `truncated` 为否、`next` 为空、`skipped` 为 0、`total_keys` 为 0，且分面视图零行、`truncated` 为否、`skipped` 为 0、`total` 为 0；有用例但没有文档键时（分面只有 `null` 那一行）同样接受，屏幕写明“有 N 条用例没有文档键”。续页读不出、读了不止一页、任一视图声明截断，都不是空的证明，一律拒绝并写明下一步；说明文字（例如“不分版本的根为空（清单完整…）”）从不作为证据。

文字有凭据扫描命中的条目：Hub 把它们计入总数，却不放进任何列表，分片拿不到它们。脚本按每个分片 `total_entries` 与列出条目数的差额算出这个数，屏幕首行写明“另有 N 条被凭据扫描排除，没有进输入”，导出仍然成功；要它们进输入，得由管理员受理这些命中或修复来源文字后重新生产。若某个文档的条目全部被排除，它的分片列不出键，脚本拒绝并说明。

文档原件用 `original list --external agile:case:<文档>` 查找，再严格比较完整标识，只取最新记录，使用 `original export` 导出为顺序编号的 `original-map-*.json`。命令树按 `buildsite:file:` 和 `/command_tree-<构建>.xml` 后缀定位。新增的通用 `original list --suffix` 在数量上限之前筛选，避免其他构建的原件占满列表；多个不同路径匹配同名命令树时拒绝猜选。每份原件导出后重新核对字节数和 SHA-256。

输出目录必须在所有 Git 仓库之外且为空，父路径经真实路径核对。文件权限为 0600，新建目录为 0700，不覆盖既有文件。产物：

- `index-*.json`：直接供 `command-index.ts --index` 使用，每份各给一次参数。
- `original-map-*.json`：平台回答的原件字节，摘要和 CLI 导出一致。若回答含 `data` JSON 字符串，确定性解码为 UTF-8，另存 `map-*.json`；若原件本身已含顶层 `root`，两份字节一致。解码后必须含脑图 `root`，不改写节点或数值文字。屏幕分别给原件和解码文件的摘要。
- `map-*.json` 和 `maps.txt`：清单每行是原件绝对路径和文档编号，以冒号分隔，直接供 `case-commands.ts --maps` 使用。
- `command-tree.xml`：直接供 `case-commands.ts --tree` 使用，保持原字节及编码。

屏幕只输出计数、字节数、SHA-256，以及缺失的事实和下一步（事实里只带计数，不带编号或标题），不输出编号、标题、原件内容、子命令原始输出或异常消息。任一输入不完整、原件缺失或两个视图的计数对不上均非零退出；只有凭据扫描排除的条目是例外，它们由 Hub 扣住，脚本报出条数后照常退出 0（见上）。失败时目录可能留有部分证据，不能作为完整输入使用；按报出的下一步修正后换空目录重跑。零文档索引可导出，但 `case-commands.ts` 本身要求至少一份脑图；该情况不能用于它的用例抽取验收。
