# Changelog

All notable changes to circle-hub are listed here, newest first. Repository releases start at 0.1.0. Changes after the latest release are listed under Unreleased.

## Unreleased

- case-compile 3.26.1 (2026-11-21): two places take their words from the generated vocabulary. The device history a writer reads labelled an earlier verdict with words written by hand (失败, 无判定, 未完成) where the vocabulary says 未通过, 无结论 and 检查未完成; the outline of the plan fields listed the two slot scopes by hand. Both were added on 2026-11-20 and failed the repository's check for hand-written axes, which the pack's own suite does not run. The pack's vocabulary snapshot gains the `target` axis.
- Two identities of a runner rule: case-compile 3.26.0, runner-workbook 1.0.1 and bed-side cell runtime 1.3.0 (2026-11-21, decision 184; not installed or published yet). A rule's identity was its whole digest, which takes in the digest of each of its 22 source files, and that identity was copied to the gateway pin, the workbook identity row, the two rule documents and twice into the runtime profile. Runtime 1.2.0 and 1.2.1 each changed one file of the component, and each time the three documents were replaced and every compiled workbook became invalid. (1) The workbook identity row, the private entry's pin and the runner's comparison now use the rule's interface identity: the digest of the rule without the members that only say which bytes run (its own digest, the source digests, the certification and snapshot records, the runner's file and digest, the line of each declaration and the receipt set behind a certified status). The whole digest is still held against the loaded files when the private entry starts and before every task. A repair that changes a source and no declaration leaves compiled workbooks valid. The Hub rule declares the interface identity as `original.interface_sha256`; the pack recomputes it and refuses a rule whose declaration differs, and keeps working with a rule that does not declare it. Three real installs with three different whole digests give one interface identity, in both implementations. (2) The identity is kept in one place: the generator writes the runtime and the identity into the workbook's first row from the contract the run locked, `runtime.contract_sha256` of the profile is retired (a profile that carries it is refused and told to delete it), and the identity row of the workbook template is compared with nothing. The runtime profile no longer changes when the runner's files do. `hub-documents.ts` writes the two rule documents and reports both identities and whether compiled workbooks stay valid; the template rebinding tool is removed. Workbooks compiled before the step from 1.2.x to 1.3.0 are compiled once more, because the pin itself changes.

Only a step the service refuses with nothing but itself is refused to the writer, by name, with what to change. Replayed on the refused plan of that case with the real service: the installed tool gives the recorded refusal word for word, the fixed one passes with five questions asked again.

- Bed-side cell runtime 1.2.0 (2026-11-21, from round 50): the runner's note of a device session's mode follows the prompt the device shows. The framework's cleanup and close call the senders from inside and are covered. A missed read window of an enable-mode command is reported under that command (it was reported under the configuration command before it). The framework's files are not changed. Both recorded failures were replayed against the framework's own classes with a scripted session: without the wrapper the two marker lines come out word for word as recorded, with it neither occurs.

- case-compile 3.25.1 (2026-11-20): (1) the loop script does not charge a case for a model service that is down. - case-compile 3.24.1 (2026-11-20, from the end of rounds 44, 46 and 47): the delivery volume is opened by code. When a case has used its three device rounds, `pipeline.ts rework` no longer answers "write the conclusion and assemble by section 5" and leaves the rest to the delivery guide; it excludes what did not pass, opens the new plan run with `--exclude`, carries the plans that passed as they are (no briefs options, so each plan's fidelity judgment stays where the new run's brief is the one it was judged against), marks the excluded cases in the state and tells the lead the one next step: collect and merge with the open file it names. Called again with the volume's returns it says the volume passed as a whole, or excludes what failed and opens it once more, or — after the second — that the device runs are over. `collect` copies the volume's plans only and names the excluded cases; a verification of the volume charges no case a round; nothing is written again. The history of a case now shows, in the task text itself, what each step of the newest run that passed sent (who, in which mode, the command by its beginning; one line a step, the runner's own clock and clearing lines left out): in round 48 all sixteen writer tasks listed six earlier verifications with the paths of their logs, and no writer opened one. It stays a statement of what was recorded.

- case-compile 3.24.0 (2026-11-20, from rounds 43 to 47; it reads the run history of decision 182 and works without it): a compile sees what the device answered when the same document was verified before. Rounds 43 to 47 compiled the same seventeen-case mind map from scratch each time; the first device round passed eleven or twelve and the same few cases needed a correction only the device teaches (a listing prints two rows for each key, a record type cannot coexist with another, a sync takes minutes), which three device rounds a case are often not enough to find again. `download-run.ts` now asks the Hub once, with the first plan run of a compile, for the earlier verifications of the document (`GET /run-export/<run>/history`, six runs at most), saves the answer and where the files are to `history.json` in the run directory and the returns of each listed run to `history/<run>/` beside it (the code of `download-returns.ts`, no waiting for a job), within four minutes in all. - Run history (2026-11-20, decision 182, model 86; not published, not deployed): `GET /run-export/<run>/history` lists the earlier runs that verified the same subject on a target, so a client that writes for a document again can read what the device answered before. A run's subject is named by its subject source: the external object identity without its revision, or the reference of bytes bound directly. A run is listed when the reader may export it by the rule of the other run-export routes (its runner or an administrator, and the run visible to them) and when a job of it ended and took effect; each lists the build it locked and, per job, the plan run, when the journal recorded the end and each report row's item and verdict, from the same checked projection the jobs export reads at the reader's tier (null when it cannot be shown). Newest first, eight runs at most, `?limit=<1-8>` lowers it; a subject nothing verified answers an empty list. It reports recorded facts only: nothing is compared, judged or stored and no model is called. The runs are found by a bounded scan of the dispatch reservations and the run records (no index, no migration): with 300 dispatched runs, eight found among the oldest cost 38 queries and about 120 ms on a temporary PostgreSQL. Also fixed: since 2026-11-15 `/run-export/<run>/jobs` answered 500 to a runner who is not an administrator once the run had a job, because the job list was read from the dispatch service as the reader and that service answers administrators only; the journal is now read as a named administrator and the projection still at the reader's own tier.

- Device read on request (2026-11-19, decision 181, model 85; on the acceptance Hub only): a writer who holds a booking can have the Hub send one read-only command line to a booked device and get the device's own output back, instead of guessing how a listing is laid out or what a cleaned device shows and losing device rounds on the guess. The read goes through the per-seat read every precheck already uses (`probes.call`, `probes.command_pattern`, `probes.output`), so no premise is certified; the whole line must have the declared command shape, and no word is compared with any list. The words are no source of the run and no basis of an expected value. An executor without `probes.read` says so; an administrator adds it with `executor update` after checking that the declared command shape lets only read-only commands through.

In knowledge-contribution 1.3.1 and earlier, the first waiter then failed to remove its own quarantine (ENOENT), or met a lock file that was being removed (no links left) and took it for an invalid owner. - **defect-to-case compares a case whose command takes an IPv6 address or a prefix length by its declared structure.** The product's command-tree producer publishes a union-typed argument (IPADDR is IPv4 or IPv6) as several catalog signatures under one signature reference. defect-to-case 1.6.20 checked a command identity against the first of them only, so an argument of any later alternative (an IPv6 address, or a prefix length where the mask comes first) never matched: a draft with one stayed unknown in the duplicate check, and an indexed case with one was counted as lacking its author's structure declaration, which left every other draft checked against that index unknown unless it duplicated another case. defect-to-case 1.6.21 accepts an identity that is complete under one of those signatures. - **A configuration command with an address argument no longer leaves a case-compile plan pending.** The product's command-tree producer publishes a union-typed argument (IPADDR is IPv4 or IPv6) as several catalog signatures under one signature reference. When the product declared inverse enum pairs, case-compile 3.8.5 read any such command as an ambiguous enum inverse, even with no enum in it, so its plan checks stayed pending with "声明的枚举互逆不能在同一签名中得到唯一完整身份". case-compile 3.8.6 reads a declared pair position by position across those signatures: a position where none of them declares an enum holding the pair is no alternative, and the declared prefix inverse applies as before. Signatures that disagree on such an enum still stay unknown.
- **The start-up sweep finds orphaned sandbox processes when the Hub lives under a path outside ASCII on macOS.** The sweep ran `ps` with an empty environment; in that C locale `ps` prints every byte outside ASCII in `vis` notation (a folder named `开发` as `M-eM-<M^@M-eM^OM^Q`), so the bootstrap path never matched and sandbox processes an earlier Hub process left behind kept running. `ps` still gets a fixed environment, now holding only `LC_CTYPE=UTF-8`. Linux reads the argv from `/proc` and was not affected.
- **Pack extraction works on macOS 15.** A pack's read-only tree is built under a temporary name and renamed into place; macOS 15 refuses to rename a read-only directory (macOS 26 and Linux allow it), so every pack function failed there with `EACCES`. When that rename is refused and no tree is in place yet, the directory is made writable for the move and read-only again at its new name.
