# Hub R5 简报：分工与顺序

依据：决定 71–73（docs/hub-r4-progress.md），三方对比与三份分解报告（本机工作目录 review/，不进 Git），能力 7 真实重跑记录。

## 原则

1. 信息归 Hub，操作归 Circle。Hub 不加任何执行器；已核验工作簿经 Hub 派发给网关的受控移交保留。
2. 四层：核心只放真相保证所需；通用技能包解释公司工件格式，可安装不随 Hub 发布；产品包只放事实；工作技能包只放单一工作的规则；系统包保留。
3. Circle 做过的事以"声明"等级进喂入层，团队可检索，不单独作 Hub 判定依据。
4. 规矩不变：不许关键词匹配；仓库只用合成数据（产品 ORBIT/COMET（同一产品两个名字，见 tests/fixtures/README.md）、lumen-api，地址 192.0.2.0/24）；未知必须写缺的事实与下一步；`git commit -s`，只暂存显式路径，英文祈使句；测试并发不超过 2；改包内文件同提交升版本重签；合并用 wf/merge-locked.sh；不碰钥匙串、环境配置文件和任何真实系统（本机 Hub 除外）。
5. Bot 不做。

## 分角色说明

### codex

- A1 先定机制再移模板：技能包的发布与安装（管理员安装，不按用户分配）、工作包 pack.json 的依赖声明、运行锁定依赖摘要、registry 装载；KityMinder 解析器移出后，旧运行里的 `src:…/kityminder@1/…` 引用仍能按锁定摘要复核，补对应测试。
- B1 块模型是能力 7 正确结果的前提：计划要能表达"先捕获再比较""先建记录再查询""断言针对上一步输出"。断言仍在原文上逐字搜索，不解析回显。
- B2 等 pi 的规格；重组是独立阶段，输出带来源身份的契约，标欠定与冲突，评审记录不能替代。
- C1 推送：从 origin/main 开 hub-r6，同一套脱敏与改名，扫描后开 PR 并合并。

### cursor

- A2 修派发顺序和原因披露；B3 做喂入层对象与检索；C1 驱动真实重跑：清理台架、登记基线、逐例派发、读结果，记录到本机 plan.md。
- 真实运行只用 Hub 命令行与技能会话，不 SSH 跳板机，不读环境配置。

### pi

- 只写本机工作目录。A3 的三份文件都要离线用主线代码校验后再交；B6 的规格只用合成例；孪生数据集：每份真实文档对应一份结构相同、内容合成的文件，供合成层测试。
- 允许读真实内容，但报告与规格不抄真实取值。

### kimi

- A4 每项先判是实现回归还是期望落后，再改；规程以 InfoTest 的 test-list-review 与 review-verifier 为正本。
- B4 在 Circle 仓库做：钩子不经模型；共享范围按用户设置；提交按回注契约，引文逐字。

### agy

- A5 不改核心；B5 严格照 codex 的模板移，每移一个解析器补"旧引用仍可复核"的测试。
- 每条结论附文件行号并自行核对。

## 阶段与顺序

- A：五项并行，各自合入后部署一次。
- B：A1 合入后开 B1、B3、B4、B5；B6 与 A3 同时做；B2 等 B1 与 B6。
- C：全部合入后一次部署、发布、重跑、全量检查、推送。
- 测试阶段：见 docs/hub-r5-tests.md，五个角色改做测试。
