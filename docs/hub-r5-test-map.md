## 发现的问题

1. **同一请求编号在已认证重试时会再投递。** 事实：`hub/dispatch/retry-policy.test.ts`「duplicate_tolerant loses one response with retry premises certified true」断言两次 `send_blob` 参数 `deepEqual`，且 `possibly_duplicated === true`。成功后的另一次派发才会被拒绝（`rounds.test.ts`，以及本轮 32 号对账之后的再次 `dispatch`）。影响：T7-5「同一请求编号重复 → 拒绝」对这种重试不成立，重试被记成可能重复而不是拒绝。建议归派发治理，不在本分支改。
2. **平台不可达的失败没有下一步。** 事实：`hub/connectors/http.ts` 把连不上记为 `SOURCE_UNREACHABLE`，消息是「路由 … 连不上来源」；`hub/connectors` 下的测试没有断言下一步。影响：T9-1 要求的「带下一步的失败」现在给不出。建议归 A5 的来源读取说明，不在本分支改。
3. **床面恢复没有逐字节比较两份探针原文。** 事实：`bed-state.test.ts`「post-run match restores bed…」在回显与基线逐行一致时断言 `recovery === 'restored'` 且 `differences` 为 `[]`，没有把跑前、跑后两段捕获做字节相等。影响：T4-1 预期里的「逐字节相等」比现有逐行差异更强，空差异不能代替字节比较。建议仍归 T4 派发，不在本分支改。
4. **同模型族复核被标成不独立，提交仍然受理。** 事实：`independence.test.ts` 断言同族为 `not_independent`；`packs/workflow/case-review-verify/end-to-end.test.ts`「the verification from the draft's own session and model is not independent」断言 `acceptance === 'accepted'`，同时 `unsatisfied_reason === 'independence_unknown'`。影响：T1-2 与 T7-1 要求的「拒绝」没有发生，整份提交仍被收下。建议归 A4，不在本分支改。
5. **缺修复说明是投影错误，不是未知。** 事实：`packs/workflow/defect-to-case/functions/fix-text.test.ts`「a missing, non-text or blank configured fix field…」断言错误码 `defect-to-case.fix_text_missing`，`error.fix` 指向 `settings.bug_fix_field`。影响：T2-3 反例要求未知并给出具名请求，现有结果是投影失败。建议归缺陷转用例包，不在本分支改。
