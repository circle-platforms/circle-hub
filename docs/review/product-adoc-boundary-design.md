# 核心对产品 adoc 实现依赖的迁移设计（问题 11）

本页只给设计，不迁移实现或新增词表。依据所有者四层划分：Hub 核心仅平台机制；可复用的领域解析做按需安装的通用技能包；产品包保留产品数据；工作技能包消费结果。案例仅 ORBIT/COMET 与 lumen-api，不涉及真实源。

## 当前依赖与问题

hub/knowledge/directory-sources.ts:4 直接导入产品包的 ADOC_LIMITS、ManualSourceError、booksOf、directoryOf、listedSources、mainsOf、rootId。:16–24 根据 meta 槽和 many 字段识别目录输入，:36–40 的接口又固定了 cli/app 两本主文件。seed.ts:15 调此绑定器。

这既是直接模块耦合，也是语义耦合：只把 import 复制进核心仍会让核心知道手册目录、主书名与目录命名规则。另一产品即使不叫现有产品名，也不能得到真正独立的读取机制。

## 归位与建议方案

| 层 | 保留/迁移的责任 |
| --- | --- |
| 核心 | 校验包和技能包摘要，授权读取，锁定原件、读取清单与版本；限制文件数/字节/深度，保存受理/未知/失败；执行声明的有界读取计划，不识别 adoc、主文件名字、产品槽名或文件扩展名 |
| 通用技能包 | adoc 文档组结构：引擎 AST、include 图、块/行内结构、两次产出确定性、恢复诊断。包按需安装，未安装明确点名；运行按摘要锁定，旧引用按固定摘要复核 |
| 产品包 | 目录模板、版本线到目录名的声明语法、名称族属性闭集、CLI/APP 主文件、来源 parser 声明、品牌条件及命令树格式/绑定数据。不把这些写进核心或通用技能 |
| 工作技能包 | 评审/编译规则；只通过既有引用和锁定目录消费结构模型，不直接导入某产品或 adoc 引擎 |

建议先采用“包声明绑定计划，核心执行机械读取”方案：由产品声明（可调用安装的技能包中的结构函数）给出每组入口、所需原件引用和引擎输入关系；核心校验这些引用确实在授权来源和冻结修订内，按统一预算执行并保留完整读取凭据。不得按槽名 meta、adoc_*、后缀或正文关键词选解析器；只用明确声明和已安装 parser@version。

需要的最小机制是包/技能包可声明的有界预读取接口及其冻结回执；应先对照现有 Producer inputs/many/parser 与规则 reads 能力确定复用面，再由所有者审定是否扩展契约。不在本设计中捏造新全局枚举或把格式私有对象发布成核心类型。

## 实施顺序与兼容

1. 为当前目录绑定冻结合成对照夹具：双书、嵌套目录、同修订、包含依赖、成员改动、声明 parser 与服务器媒体类型不同、NUL、少格、未闭合块和其他 ERROR。
2. 提炼可复用文档组解释器到通用技能包，保留当前产品数据声明；迁移等价测试比较结构模型和生产报告摘要，不复制产品规则到核心。
3. 核心增加/复用通用有界读取计划校验，绑定源记录与 parser/技能摘要；由产品声明调用，seed/sync 使用同一机制。消除 cli/app、目录命名和 meta 槽的隐式识别。
4. 原子替换 directory-sources 的调用边界，移除产品直接 import。旧运行和旧原件不改；新运行冻结新技能/包摘要。旧 parser@version 若保持则必须有逐字节等价证据，否则发新版本。
5. 在另一合成产品上用另一种来源布局运行相同平台机制；接口依赖、错误与读取清单均须无产品名分支。

## 验收与取舍

- 核心生产代码不能导入任何产品目录；AST/import 边界检查应单独于“产品身份字面”检查，后者不足以发现本问题。
- 文档组按声明批量处理，摘要去重键包含技能/产品包摘要；失败可随包升级重试，start_run 不因投影阻塞。
- 跨修订、越权引用、超预算、缺文件、缺 parser/技能包均 fail-closed 并给缺失事实和具名出口；不得复用上一修订缺失文件或猜媒体类型。
- 保留内容摘要身份与多来源出处合并，按本次读取捕获绑定，不能全库择一。
- 不选择“把现有产品目录工具挪到核心”的快捷方案：它仅消除 import，未消除产品/手册语义。若首期只做接口隔离，必须标明技能迁移仍未完成。

待所有者审定：预读取接口是否复用现有 reads；通用技能包如何承接多原件文档组输入；原解析器版本的等价证据范围。审定前不动核心/产品实现。
