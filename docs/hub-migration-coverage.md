# Hub 迁移需求覆盖与验收附录

状态：迁移方案，尚未实施。与[完整方案](hub-migration-plan.md)一起阅读。以下保留既有需求研究的 75 个编号，编号表示待满足的用户效果，不表示旧系统已全部实现，也不表示 Hub 当前可用。迁移承接需求与输入输出语义，不复制旧业务代码、部署配置或业务数据。

“Circle”负责本地交互与运行；“Hub 宿主”负责共享身份、资产、受托工作、采用依据与操作责任；“pack 能力”负责专业语义、方法、验证和格式；“系统适配”负责外部系统协议。多方归属表示职责协作，不要求新增同名服务。普通编辑、检索和能力调用可独立使用；进入受托工作后才适用相应工作合同。

阶段表示该需求的最终验收主批次，公共基础随使用批次提前建设；身份、权限、原件保护和证据关联从首次接入即生效，不能推迟到生产接入阶段。各批次验收均包含正常、失败、缺证据、恢复和越权样本，且分别记录静态检查、离线回放、合成运行、授权真环境验证；前一层通过不代替后一层。

| 阶段 | 主批次 |
| --- | --- |
| 0 | 合同与样本基线 |
| 1 | 资料与 PLM 查询 |
| 2 | 评审与脑图编译 |
| 3 | 受管执行与工作接续 |
| 4 | 发布渠道与知识回填 |
| 5 | 生产接入与迁移收尾 |

## 十二类工作组合

这些是端到端验收场景，不是十二个独立产品或强制流程。同一能力可直接调用或被多项工作组合；PLM 查询在问答、规格形成、评审等场景中复用，脑图只是编译的一种输入。

| 工作 | 组合目的 | 主要需求 | 必须保留的边界 |
