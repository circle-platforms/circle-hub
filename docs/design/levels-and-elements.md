# 层级与元素

> **已被取代**（2026-10-21）：Circle 里的五层界面、工作队列和登记簿已随旧服务器退役。Circle 里不出现 Hub 专用界面；Hub 的控制台是只读的四页（规划中），记录页按五要素布局，见[对象标准](object-standard.md)。本文只作记录保留。

先设计 hub 的入口，再逐层深入；每一层固定用什么图、表、描述、按钮，现有工作只往里填内容。取自 Claude Code 桌面版和 Codex 桌面版的共同做法，不抄它们的皮：会话是入口，左栏是工作清单，需要人的事以内联卡片出现并在左栏聚合，证据在旁栏，动作少而固定。

## 五层，逐层深入

| 层 | 是什么 | 进入 |
|---|---|---|
| L0 会话 | Circle 的会话就是入口。hub 的工作在这里交出去，进度、证据、需要人的事以卡片回到这里 | 登录 hub 后的任一会话 |
| L1 工作队列 | 待我审批 / 待我回应 / 我提交的 / 我负责的 / 异常。按年龄排序，逐条审阅 | 左栏「需要我」的计数 |
| L2 登记簿 | 一个对象的记录：分面 + 计数 + 搜索。四个对象同一个模板 | 左栏菜单项，或队列行的对象 |
| L3 记录详情 | 五格：资产 · 内容 · 审批 · 证据 · 扩展点。决定在这里做，也能在 L0 的卡片里做 | 登记簿一行，或卡片的「打开」 |
| L4 证据原文 | 平台原样保存的返回：sha、谁、何时、哪个工具；可引用，不可改 | 任何 evidenceId |

任何一层都能回到会话。

## 每层用什么

| 层 | 图 | 表 | 描述 | 按钮 |
|---|---|---|---|---|
| L0 会话 | 无；只有内联卡片 | 无 | 事件一句话（受理 / 证据 / 过闸 / 平台核验）；报错卡：错误码 + 事实 + 申请人的选择；审批卡：变更集 + 绑定三项 + 资格 | 批准 · 驳回 · 回应 · 打开 · 跟随 |
| L1 队列 | 计数条；年龄与超 SLA 的分布 | 队列表：对象 · 申请 · 流程@版本 · 范围 / 产品线 · 申请人 · 年龄 · 过期 · 状态 · 资格 | 统计一行；资格原因 | 上一条 · 下一条 · 批准 · 驳回 · 保存视图 |
| L2 登记簿 | 无；分面代替 | 登记簿表：名称 · kind · version · lifecycle · owner · 更新 | 对象一句话；平台约束四条 | 登记 · 上传 · 推送 · 交活 · 打开 |
| L3 详情 | 绑定图：请求 ↔ 输入修订 / 目标身份 / 动作摘要；数据流中的位置 | 文件表 · 证据表 · 决定表 | 资产条；平台核验 vs 申请内容；资格 | 批准 · 驳回 · 新版本 · 停用 · 核对 |
| L4 证据 | 无 | 原样返回（只读） | sha · 谁 · 何时 · 工具 · 输入摘要 | 复制 id · 引用 · 下载 |

不在表里的元素不出现在那一层。

## 图只有四种

- **数据流图**：一件工作怎么走过 A C E B D，带 id。
- **绑定图**：一条审批请求钉住的三项，和它们各自指向的记录。
- **执行拓扑**：hub → worker → 资源，谁持凭据、谁碰外部系统。
- **生命周期图**：资产 draft → approved → running → retired，与审批状态的对应。

别的都用表和计数表达；不画示意性的架构图。

## 动作词固定，哪一层都是这几个

| 动作 | 对什么 |
|---|---|
| 批准 / 驳回 | 一条审批请求；绑定其摘要；被取代的也可驳 |
| 回应 | 任务等我的输入 |
| 打开 | 到下一层 |
| 跟随 | 把任务事件接回会话 |
| 核对 | 未知结果的 reconcile |
| 登记 | 来源、资源、服务客户端 |
| 上传 | 原件，带 role |
| 推送 | 技能包，带试跑记录 |
| 交活 | 把工作交给 hub |
| 新版本 | 资产换字节 |
| 停用 | 资产 retired |

没有「确认」「提交」「保存」这类不指向对象的词。
