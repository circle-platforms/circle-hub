# 个人与团队知识库整合调研（已被取代）

**本草稿已被[决定 84](../hub-r4-progress.md)取代（所有者 2026-11-02）。个人知识不再只留在 Circle 本机。**

所有者已决定：个人知识在 Circle 本机和 Hub 两边都放，双向同步，多客户端共用，方式由本人选择；提交共享不审核；个人空间由本人设权限，可共享给管理员或其他人。所有者原话：“用工作流”“工作流标签里面分为两种，一种是通用的skill 一种是我们的packs”。工作流页面分为通用技能（不验收）与工作流（现有 packs，有验收）。产品包和系统包的展示位置仍待定：建议分别放在知识库的“产品知识来源”和连接的“业务系统接入”，这些只是建议，尚未决定。本轮不实现改名，另立任务。完整方案与其余待定问题在所有者的方案文档中，定稿后再写入 `docs/design/`。

下文原样保留为第一轮的调研记录，包含当时尚未获批准、现已被取代的建议。保留理由：需求核对与同类项目的资料来源仍可追溯；其中“个人只放 Circle 本地”等建议不再作为现行方案。本次没有修改知识模型、协议、数据或 Circle 代码。

## 需求与现状核对

调研依据为当前 `contracts/model.json` 的 B01–B03、K01–K05、R01–R02，以及 `hub/knowledge/README.md`、`hub/refs/README.md`、控制台知识入口、搜索与引用次数实现。下面覆盖采集、保存、组织、读取、共享、修订和维护；不是对真实业务数据的验收。

| 需求 | 当前能力或限制 | 整合要求 |
| --- | --- | --- |
| 个人与团队使用相同知识形态 | 团队已有条目、树、组成记录；个人候选留在 Circle | 共用陈述、出处、路径与内容身份格式；可见范围单独管理 |
| 不依附产品包也可使用 | 无产品线原件可保存和引用，尚不能形成通用知识库；团队树目前按产品线组织 | 先有通用知识空间，再可选关联产品线、版本、构建；保留现有产品树读取路径 |
| 个人隐私 | 个人候选不进 Hub；Hub 管理员可以管理团队记录 | 默认在 Circle 本地保存和索引，管理员无法从 Hub 列出个人条目或读取次数 |
| 导入与采集 | 团队导入使用产品包声明来源，经只读连接器、解析器与生产器 | 区分“导入到个人”和“导入到团队”；目标、来源、范围和读权提交前明确显示 |
| 原文与出处 | 源文件片段精确定位、逐字引文核验、凭据扫描已有；个人原文归档尚在规划 | 原文、陈述、模型归纳分别保存；来源可得性、修订和核验结果可查，不把摘要当证据 |
| 浏览与索引 | 有层级树、索引、分面、影响视图与有界分页；并非任意全文搜索 | 统一条目索引字段与游标；个人、团队各自分区，合并结果明确范围与截断 |
| 搜索与任务依据 | 控制台是有界搜索；K04、K05 禁止用关键词结果自动挑选任务依据 | 可以查找候选，采用时仍由精确引用或经核验的带引文提议绑定；检索命中不证明查全 |
| 被引用次数 | 团队已按受理提交中的引用统计近 30 天，回填期间给下限 | 个人采用同口径的本地使用记录；分别显示统计窗口、覆盖范围、是否下限，不泄露个人使用 |
| 版本与差异 | 内容寻址、旧根保留、组成记录分离、指针比较并交换、运行锁定版本与不分版本两根 | 个人也有不可变修订与当前指针；通用空间无需虚构产品版本；差异不自动触发全量回归 |
| 适用条件与冲突 | 条件带出处、声明与判断分开；未判断与未声明不同；矛盾只标记 | 统一继承这些规则，未知保留缺失事实及下一步，不用模型相似度裁定真假或重复 |
| 提交共享 | K03 只接收限定范围内有据的回注；模型与判断在 Circle 侧 | 显式提交副本和必要出处，Hub 做确定性核验；个人内容不自动上传或改变可见范围 |
| 收回、停用与删除 | 团队记录只追加，撤回不改历史；停用账户不删除记录 | 区分撤回当前读权、撤回条目和物理保留策略；已被他人读取的副本不能声称已远程删除 |
| 导出、离线与恢复 | 团队有部署级备份，个人知识尚无同构恢复方案 | 可携带原文、出处、组成和历史导出；个人离线可读；以后按改动范围设计恢复验证 |
| 大规模与维护 | 当前有分块、缓存、范围清单、增量观察；部分构建/比较接口仍由调用方做读权检查 | 所有入口统一先校验空间读权，分页固定快照；不按猜测的目录、名称或主题扩大范围 |

## 同类项目的可借鉴部分

只核对官方文档，没有安装、调用账号或验证这些产品的实际部署。下列设计取舍是建议，不是外部项目对本方案的背书。

| 项目及资料 | 核对到的行为 | 本方案取舍 |
| --- | --- | --- |
| [Outline 个人文档](https://www.getoutline.com/changelog/personal-documents) | 个人空间仅本人可见，管理员不能列出；可主动分享或移入集合 | 个人入口与团队入口清晰分开；分享必须显式。为保留当前边界，个人存储仍放 Circle |
| [Outline 安全说明](https://docs.getoutline.com/s/guide/doc/security-DlJBglbImQ) | 集合承担权限边界；有文档修订历史与可移植导出 | 用空间管权限，用条目格式表达内容；历史与导出作为基本能力，不把产品线当权限主体 |
| [Joplin 笔记本共享](https://joplinapp.org/help/apps/share_notebook/) | 邀请接收人后同步共享笔记本；团队方案可分别授予查看和编辑权限 | 可见范围与编辑权分别处理；同步撤回不能被描述为消除已经复制的内容 |
| [Joplin 历史版本](https://joplinapp.org/help/apps/note_history/) | 修订可跨设备同步；恢复时建立副本，不覆盖当前笔记 | 沿用不可变历史，恢复产生新的选择或修订，避免破坏已有任务的引用 |

这些项目帮助回答空间、权限和历史的交互问题；它们的普通文档分享不能直接替代 Hub 的出处、依据等级、固定组成和边界核验规则。个人与团队共用格式也不等于必须共用服务器或共享物理索引。

## 建议的对象与边界

建议采用“空间 → 固定快照 → 树路径 → 条目”的统一组织方式。个人空间由 Circle 持有，团队空间由 Hub 持有；空间身份和权限不计入陈述内容摘要。产品线、版本与构建是可选组织信息；现有产品树保留既有绑定和组成依据，不把未声明的构建填成默认版本。

条目保持规范化陈述与内容身份；出处、作者、时间、适用条件、来源类型、归位判断和核验回执由组成及附属记录表达。同一陈述可以在个人与团队各有一份授权关系；相同内容摘要不能授予读取权，也不能跨空间共用未经授权的缓存、来源或引用次数。上传前不以全局查重接口透露团队是否已有某份私人内容。

个人搜索与引用统计在本地进行，团队查询在 Hub 的当前读权内进行。Circle 可以并列展示两边结果并标明来源范围。Hub 不接收个人搜索词和个人命中内容。共享条目进入团队后，团队使用量与个人使用量分别显示；避免把两者合成一个会透露个人活动的数字。

共享是一次明确提交：选择条目和目标空间，列出将上传的原文片段、必要原件与个人信息；凭据扫描后提交。团队无法取得或无权读取的出处不能标为已核验。Hub 继续只做结构、引文、可解析路径、权限和版本绑定等确定性核验，不调用模型。未满足当前 K03 根据范围的通用条目，须先由所有者批准模型扩展，不能在实现时借用现有回注入口绕过。

## 入口与“导入知识”

当前按钮仍名为“导入知识”，只增加所有者要求的悬停说明。未来知识入口建议分为个人、团队两个范围；个人由 Circle 的通用知识能力承载，网页控制台展示团队知识。页面先明确目标空间，再选择来源和组织方式。团队无产品包时仍可创建通用空间；关联产品线时才出现产品来源与版本选项。

命名建议保留“导入知识”为操作总名，在确认步骤写明“个人知识”或“团队知识”及可见成员。是否采用范围切换器、独立入口或改按钮名称，留给所有者看交互稿后决定。本次不改变名称，不添加不存在的个人网页数据，也不把“所有人可见”解释为绕过现有任务包分配。

## 分阶段实施建议与待定事项

1. 由所有者确认空间及隐私边界、个人原文保留位置、团队默认受众、通用来源的核验规则和导入交互。模型负责人再列出 K01–K05、R02 与协议的精确变更；此草稿没有注册新记录种类或词表代码。
2. 先交共同格式、空间权限和固定快照协议及迁移方案。旧产品树按现有读法继续工作，新增空间映射；不重写旧摘要或迁移记录。跨空间引用须带可验证的授权与出处，不能仅持摘要读取。
3. Circle 在独立授权任务中实现个人归档、搜索、版本和本地计数。Hub 实现通用团队空间、明确导入与共享回执；两边使用同一结构与边界测试样例，运行时保持分离。
4. 补齐撤回、离线冲突、导出恢复和分区缓存。验证覆盖本人/他人/管理员、授权改变、同内容不同空间、缺出处、凭据命中、旧引用重放、分页和大规模上限；每阶段只跑受影响检查，不默认增加 SHA 扫描或全量回归。

实施前还须决定：个人是否支持可选加密同步及其密钥归属；团队是否允许细分成员组；个人账号离开团队后的本地保留与团队贡献归属；删除与审计保留时长。以上没有在本次代码中做默认选择。定时任务与机器人只作为将来的知识更新触发者讨论，不在本次加入功能或页面。
