## 已核对的源码缺口

| 边界 | 当前源码证据 | Windows 工作 |
| --- | --- | --- |
| 数据库包 | `package-lock.json` 固定 embedded-postgres `18.4.0-beta.17`；列有 `@embedded-postgres/windows-x64`，没有 Windows arm64 包 | x64 包存在于锁文件不证明能启动、完整或可重新分发；arm64 原生包缺口待解决 |
| 包解析 | `hub/platform/postgres.ts` 的 `binaryPackage()` 拼 `process.platform-process.arch`，Windows Node 的平台名与锁内 `windows-x64` 名称不对齐；工具名没有 `.exe` | 显式平台映射、工具与 DLL 清单、绝对路径解析和摘要检查；不能依赖 PATH 恰巧找到工具 |
| 认证与传输 | 同文件用 Unix socket、`peer`、`listen_addresses=''`；`hub/platform/sql.ts` 把 socket 目录作为 `pg` host | 不能原样搬到 Windows；需要独立传输、认证与秘密供应设计 |
| 密钥 | `hub/platform/keychain.ts` 调 `/usr/bin/security`，缺失或格式错即失败 | 无交互服务身份可访问的 Windows 后端，保持不自动创建、不覆盖和读回校验 |
| 持久服务 | `context.ts`、`launchd.ts`、`deploy.ts` 直接接 LaunchAgent | 平台服务抽象与 Windows SCM 接线；不是把 Node 命令直接登记就算服务 |
| 备份 | `backup.ts` 默认 Homebrew libpq 路径，工具名无 `.exe`；按服务器主版本检查 | 发布内提供同主版本工具及 DLL，不依赖机器已有 PostgreSQL |
| 文件和中断 | `files.ts` 依赖 chmod、硬链接锁、symlink+rename；`deploy.ts` 依赖 Unix 信号与 detached 进程组 | ACL、重解析点、文件锁、原子切换与服务停止语义必须重做实测 |
| 包函数隔离 | `hub/rules/sandbox/isolation.ts` 只有 darwin/Linux 分支，最终启动 `/bin/sh`；Windows 探测返回不可用 | Windows 专属 OS 启动器与探测，禁止降级为 Node 权限模型 |

本设计不改既有迁移，不把分类声明、跨平台编译或 x64 模拟启动写成平台支持。

## 数据库选择与 Windows ARM64

优先保持 PostgreSQL 的 SQL、事务、只追加触发器和权限边界，保留管理员拥有数据库、运行角色无所有权且无超级权限的分离。不得改用内存数据库或应用逻辑代替数据库约束。

Windows x64 的首个候选是锁文件中的原生包。先静态列出 `initdb.exe`、`pg_ctl.exe`、`postgres.exe`、`pg_dump.exe`、`pg_restore.exe`、依赖 DLL、许可证和来源摘要，再在干净 runner 检查架构、版本与装载。包中是否含 dump/restore 当前未知，不能假定存在。

Windows arm64 有两条候选，均未获支持结论：

1. 选择有可追溯来源的原生 ARM64 PostgreSQL 发行，或建立可复现的原生构建与安全更新链；当前锁文件没有它。必须先确认源码、构建工具链、扩展与客户端工具兼容性、许可证和维护责任，再请求依赖/供应链决定。
2. ARM64 Node/Hub 配合 x64 PostgreSQL 子进程模拟运行。它是混合架构方案，不是原生 ARM64 PostgreSQL。先核对目标 Windows 版本与 runner 镜像的 x64 模拟条件、DLL 装载、服务身份和升级行为，再在原生 ARM64 runner 完整验收。不能自动使用 x64 Node 伪装原生 Hub。若批准混合架构，发布清单必须明确每个组件架构及模拟依赖。

两者都不满足时，六平台发布仍未完成；不得把 arm64 任务 skip、下载 x64 包或只跑 `--version` 解释为通过。包选择失败应给出缺少的组件和下一步，不回退到系统 PATH、系统数据库或网络安装。

Windows 认证候选是仅 `127.0.0.1` 的 PostgreSQL TCP 加独立角色的 SCRAM 凭据。必须核对 PostgreSQL Windows 构建是否提供其他可保持同等本机身份约束的传输；不可凭空声称支持 Unix socket/peer 或命名管道。若使用 TCP：只绑定显式回环地址，HBA 按数据库和角色精确允许，其余拒绝；管理员和应用凭据分离，清空 PG 环境继承，密码不进入参数、日志或普通配置。端口冲突失败，禁止连上别的数据库或自动换口。连接还应校验部署身份，单纯端口回答不证明属于本 Hub。回环只限制远程访问，不能替代本机认证。

## 无头密钥与文件权限

候选为专用低权限服务账户下的 DPAPI 用户范围保护，或适用服务账户的 Windows Credential Manager；二者都需验证无登录桌面、用户配置文件加载、重启和账户恢复条件。不能直接把交互用户凭据搬给服务，也不能默认 LocalSystem、管理员账户或机器范围 DPAPI 就等价安全。机器范围方案若被提议，必须说明本机其他身份解密风险及额外边界，独立审查前不接受。

需要可信的本机辅助程序调用 Win32 API；Node 当前依赖没有这样的桥接能力。引入辅助程序及构建依赖要先由所有者/集成者决定，不借 shell 明文命令、环境变量或 PowerShell 历史保存密钥。输入仍只经标准输入或受限匿名管道；确保管道句柄不被无关子进程继承，读取内存与崩溃转储策略进入复核。

数据、vault、备份、运行目录与服务配置用显式 DACL：仅指定服务身份及明确授权的运维身份可访问，按用途区分只读/写入；移除宽泛继承并读回验证 SID 和有效权限。管理员是受信任运维边界，不宣称能抵御本机管理员。运行服务不能修改发布二进制；包函数不能读 vault。`chmod(0600/0700)` 在 Windows 不能当作 ACL 验收。拒绝重解析点越界、UNC/远程共享和未经验证的文件系统；ACL 设置、检查或密钥解封失败都停止启动。

备份不携带可明文使用的主密钥；跨账户或跨机器恢复需要单独的受控密钥恢复方案和所有者决策，不能静默生成新密钥。临时账户验收覆盖缺项、损坏、错账户、交互会话退出、重启和账户恢复后解封，输出只记存在、长度及结果。

## 持久服务、更新与恢复

采用真正接 SCM 的服务宿主候选，运行固定绝对路径和受控环境；可用原生宿主或经审查的服务包装器，必须解决新增二进制的来源、许可证、签名、构建与更新责任。当前没有实现，不能把 `sc create` 当作 Node 已支持服务控制协议的证明。

安装阶段显式设置专用身份、服务 ACL、启动顺序、失败恢复与重启节流；日常运行不授管理员权限。登录前启动、注销不退出、服务停止状态和数据库停机顺序需要原生测试。停止必须拒绝新请求、等待或中止当前操作、保存可恢复进度，再确认全部自有子进程终止。超时和父进程死亡不能只凭本地 Promise 返回认定清理完成。

发布目录不可变，运行数据分离；服务绝对定位发布，切换使用独立版本指针候选，避免要求用户开启符号链接特权。NTFS rename/替换、运行中 EXE/DLL 锁、杀毒软件占用和断电恢复都要有明确状态机，不能用删除旧版强行更新。部署锁要绑定身份与进程创建时间，防止 PID 重用误破锁；本地文件原子性和锁语义必须通过 Windows 故障注入。SCM 停止通知替代 Unix 信号接线，保留平台锁、备份、迁移、健康检查和回滚日志语义。

迁移只由受控运维操作以数据库拥有者执行；服务启动不迁移，运行角色不获触发器修改、DROP 或 COPY PROGRAM 权限。升级前备份、校验、停服、切换、迁移、核对运行角色、启动、校验发布身份；失败按持久化步骤恢复。应用二进制回滚不等于数据格式可回滚；已迁移的数据只能按可证明兼容策略或已校验备份恢复，不能直接拿旧版运行未知 schema。

备份保留 exported snapshot、数据库与对象/vault 的一致性、文件清单摘要、表行数与摘要校验；临时目录全部完成才公布。备份用与源 PostgreSQL 同主版本 `pg_dump`，还原用与目标同主版本 `pg_restore`；跨主版本到新空目录，不原地改 PG_VERSION。测试 Windows 路径空格/中文/长路径、大小写碰撞、重解析点、打开句柄、权限保留和中断；备份密文与密钥恢复须分开验证。保留最后两次部署和未完成操作所需备份，不因清理失败抹去恢复证据。

## 包函数的 OS 级隔离

要求同时成立：无网络（含回环、IPv4/IPv6、DNS、UDP/TCP）、无文件系统写入（包括临时目录、ADS、注册表等持久写通道需明确界定并验证）、不能执行其他程序、只读声明文件、资源限制、父进程死亡后无遗留进程。Hub 自己连接数据库与只读业务来源的权限不能传给包函数。

候选组合是 AppContainer/受限令牌、精确只读文件 ACL、无网络 capability、启动时的子进程创建限制，以及 Job Object 的资源与生命周期限制。这里没有声称这些 API 可无条件组合：需分别核对桌面 Node 启动兼容性、初始可信启动与后续禁止子进程的区分、Job 嵌套、继承句柄、退出限制和 Windows 版本支持。Job Object 本身不是无网络/无写安全沙箱；Node `--permission`、静态导入检查、冻结 JS 对象或进程数量限制也不是 OS 禁止执行其他程序的替代。

实现应先创建挂起子进程，在加载包字节前完成身份、权限、Job 和缓解策略，再恢复；任一步失败即终止并确认回收，绝不先运行再补限制。具体 API 与启动顺序需经原生原型及独立安全复核，不能在此认定成立。若 AppContainer 默认可写私有存储无法满足无写要求，或不能阻断同进程替换/子进程执行，就否决该方案，研究满足边界的更强执行环境；不得豁免“只是临时目录”。不能把只能运行 wasm 或另一个解释器的方案直接称为兼容现有 Node 包。

每次使用真实策略执行可信启动探针，验证身份和限制确已生效；策略摘要、宿主版本、OS 构建和架构绑定结果。缺少 API/策略、权限不足、探针错误、宿主不受信任或清理失败均返回现有不可用边界，函数不执行。未知能力不得被缓存成成功；不新增 Windows 专属绕过开关，不接受 `os:false` 降级作为发布支持。

## Circle 同款六平台发布门槛

Circle 当前 `.github/workflows/release.yml` 的 CLI/runtime 矩阵与候选对应如下；这是本地源码声明，runner 当日可申请性、权限与镜像能力仍需上线任务核实，不是本轮已跑的事实。

| Hub 目标 | Circle 当前 runner 声明 | 必须证明 |
| --- | --- | --- |
| linux-x64 | ubuntu-24.04 | 原生运行、发行与 Linux OS 隔离 |
| linux-arm64 | ubuntu-24.04-arm | 原生 ARM64 Node/数据库与隔离 |
| darwin-x64 | macos-15-intel | 原生运行、密钥与服务、隔离 |
| darwin-arm64 | macos-15 | 同上及 ARM64 原生依赖 |
| windows-x64 | windows-2025 | 原生 x64、无头密钥/SCM/ACL、隔离 |
| windows-arm64 | windows-11-arm | 原生 ARM64 Hub；逐组件架构与模拟依赖如实披露 |

Circle 六平台指 CLI/runtime 标准；其 desktop 是不同矩阵，Hub 是无头服务，不复制 GUI/MSI 的产品功能。继承标准是固定 Node runtime 和组件摘要、每平台原生构建与已打包产物实跑、安装/搬迁/升级/摘要拒绝/默认路径、真实工具回合以及完整资产集合后才发布。Hub 的等价“工具回合”是合成 MCP 客户端对打包服务执行请求、落下可检查记录并独立读取核验，不调用真实模型或真实系统。

将来工作流须经所有者授权，先最小权限的只读 CI，发布另行授权。每目标运行 types、contracts、unit、docs、acceptance、references 适用全套并报告通过/失败/跳过数量和原因；数据库、隔离、密钥、服务这些平台支持必需项不准以 skip 完成。源码测试和打包产物验收分开留证，发布要求精确提交全矩阵成功，缺 runner/取消/零测试/旧提交结果都是未完成。只跑 x64 runner 上的交叉打包不能替代 ARM64 实跑。

Windows Actions 用临时服务账户、临时 vault/数据库/数据根与合成数据；不使用 GitHub 真实业务 secrets。runner 管理员权限若用于安装服务或策略，验证进程必须降为目标身份；记录实际 token/权限事实，避免管理员测试掩盖 ACL 缺口。Hosted runner 的单次任务不能证明重启持久化；需明确安排允许重启的隔离 Actions runner/VM 验收，完成前该项未知。工作流不得因 hosted 限制放宽生产安全，runner 能力不足时任务失败并提出补充设施决定。

## 可复现验收与移交

后续按失败先行的合成用例接线；每个收据绑定源码 SHA、打包 SHA、Node/数据库/宿主架构、OS 构建、runner 镜像、策略摘要、实际命令、退出码、计数和缺项，不存密钥、业务字节或机器内部地址。

1. 数据库：空目录初始化、停止/重启、错误架构/缺 DLL/工具主版本错/占用端口拒绝；非授权本机身份、错凭据、非回环连接失败；运行角色不能修改或删除历史、禁用触发器、改 schema、创建高权角色或执行程序，正向 append 可复核。
2. 密钥/ACL：第二个临时普通账户不能读取目录和解封密钥；服务账户能无头启动；配置/发布不能被运行账户篡改；丢失密钥不自动重建；句柄继承与错误输出不泄漏秘密。
3. 隔离：以可信原生探针绕过 JS 层分别尝试 IPv4/IPv6、回环、DNS、UDP/TCP、文件创建/改写/删除/改名、ADS、越界读取和启动 node/cmd/PowerShell 等无害程序；检查外部见证服务器无请求、哨兵无变化、OS 拒绝码与进程事件。每一负向检查同时有非沙箱正向对照，排除环境本来不可用；探针与现有包入口分别覆盖。网络/写入/执行任一漏过即红。
4. 生命周期：启动失败、超时、内存/CPU 超限、Hub 强杀与正常停止后检查 Job 与进程树真实消失，等候资源释放；PID 重用不能误杀别人的进程。不能用“取消回执”证明停止。
5. 部署恢复：任一步骤边界强杀、磁盘满、文件锁和健康检查错身份；重新进入恢复状态机，旧发布/备份不丢；迁移失败不能留下半服务。从空根还原后核对逐表摘要、对象、vault、角色约束、引用完整性及追加行为。
6. 发布产物：无开发工具的临时环境，解包、安装、搬迁、升级、篡改摘要拒绝、卸载保留数据；离线启动不临时下载依赖。六目标分别使用自己的最终资产，资产缺失、额外资产或摘要不符都不能发布。

待源码接线包：platform（数据库传输、密钥、ACL、SCM、部署/备份/文件）、rules（原生隔离宿主与探针）、testing/records（临时 Windows 数据库与约束）、server（只经 api.ts 接入平台能力）、发布 tooling/CI（六目标供应链与产物回合）。本页不授予这些路径的修改权；集成者后续逐任务列路径与验收。

独立复核必须覆盖威胁边界、Windows API 版本条件、辅助程序供应链、服务身份与密钥恢复、TCP 认证、文件原子性及模拟架构声明。真实 Windows x64/ARM64 Actions 验收在源码接线和独立复核后进行；静态阅读、macOS 结果、成功打包、模拟可启动或少量 smoke 均不能替代。六平台全部满足前保持“待实现/待验证”，不得宣传全部支持。

本轮验证：仅只读源码与 Git 状态/diff 检查；按任务指示未运行 typecheck、contracts、docs 或任何测试，没有新增平台通过数，也没有真实 Windows 运行证据。
