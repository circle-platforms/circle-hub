# 任务：核心的 xlsx@1 解析器（上真实台架第 2 件的通用部分）

依据：`docs/hub-r4-device-run.md` 第 3 节第 1 条，以及第 8 节第 2 件。

Hub 要回读 Circle 上传的工作簿。核心加一个通用的 xlsx@1 解析器：只给出单元格、定义名、隐藏行、公式、最后一行这些结构，不带运行器的任何字。按运行器的写法解释单元格，是 case-compile 包的读取器的事，不在这一件。

- 分支和工作树：`xlsx-parser`，目录 `circle-hub-xlsx-parser`（从 hub-redesign 开出，依赖已装好）
- 可以改的路径：
  - `hub/refs/parsers/xlsx.ts`（新文件）和它的测试；
  - `hub/refs/parsers/index.ts` 里注册的一行；
  - `hub/server/upload.ts` 的扩展名和媒体类型表加 xlsx；
  - `hub/refs/README.md` 加一节。

  别的路径不动。不加任何 npm 运行依赖：解压用 Node 自带的 zlib，XML 用现有的 xml@1 解析器。
- 规则：同前（不推送、不建 PR、不发布、不部署；不碰 7420、钥匙串、环境配置文件和任何真实系统；测试只用合成的工作簿，在测试里现生成；`git commit -s`）。所有者的规矩：未知只能是过渡状态，写明缺的事实和下一步动作；Hub 只核验，不生成内容。
- 验证：`npx tsc --noEmit`；`node --test --test-concurrency=1` 对 `hub/refs/**`、`hub/server/**`。

## 要做的

1. **zip 安全上限**，超过就整份拒绝并写明是哪一项：
   - 总字节数；
   - 成员数；
   - 解压后的总量和解压比；
   - 成员路径（不许绝对路径和 `..`）；
   - 加密。
2. **只认生成器会写的那个子集**，不在子集里的整份拒绝并写明原因：
   - 一张可见的表；
   - 没有隐藏的表和行；
   - 只有内联字符串，没有共享字符串表也可以；
   - 没有公式，没有以 `=` 开头的值。
3. **模型**：
   - 表名；
   - 每个单元格（行、列、文本）；
   - 工作簿级的定义名（名字、目标表、范围）；
   - 最后一个有单元格的行。

   选择器写法照其他解析器（例如 `c/<表>/<单元格>`、`n/<定义名>`），写进 README。
4. **同样的字节给出同样的模型**；解析失败时报的是确定的原因，不是未知。
5. **测试**：
   - 合法的小工作簿；
   - 上面每一种拒绝情况各一个反例：超大、炸弹、路径穿越、加密、隐藏行、公式、`=` 开头；
   - 定义名作用域不对；
   - 两次解析的模型相同。

完成后在终端里回报：提交号、测试数量、没做完或拿不准的地方。
