## 要做的

1. **回注运行。** 一个通用工作流包，条目是四种按文档的产出（`document_output_kind`：分类、归位提议、声明、关系）。
   - 每条带引文（引用加原文）和要挂的节点路径；
   - 输入是它引用的源文件（运行绑定）和锁定的根；
   - 核心里不写任何产品名。
2. **确定性核验**，不调用任何模型，WIP 里已有的照用：
   - 引文逐字出自所引源文件，和边界用同一比对规则；
   - 路径在锁定的根里能解析；
   - 不越过声明：不改片段的来源类型，不添原文没有的适用条件；
   - 关系只记关系和双方引用，不改任何一方；
   - 根据只有会话说法的，不入层，回执写明“需要负责人署名，署名流程以后做”。
3. **入层。** 要求项全部满足的条目写进回注层：
   - 绑定节点路径、被引片段摘要和根；
   - 产品的读者可读，可见性在查询里过滤（K05 R[4]）；
   - 不计入根摘要。

   没满足的不入层，回执给修正说明。
4. **读。** get_nodes 读节点时，把回注层的条目一并返回：
   - 各带来源、提交人、时间和依据等级，标明“回注”；
   - 矛盾关系照 K3 打标。K3 的读侧在另一个分支，关系记录的形状合并时由集成者对齐，你把形状集中在一处。
5. **按任务的产出**（排序、取舍、分数）只进运行记录，测试钉住它们不进回注层。
6. **测试**全部用合成包和合成源文件，四种产出各有正例和反例。要覆盖：
   - 引文不逐字；
   - 路径解析不出；
   - 越过声明；
   - 只有会话根据；
   - 产品的读者读得到、无权的人读不到；
   - 根变了显示“被引片段已变”。

完成后在终端里回报：提交号（WIP 之后的提交，要不要压缩由集成者合并时定）、测试数量、没做完或拿不准的地方。合并前会请另一家族复核。
