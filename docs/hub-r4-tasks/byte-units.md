# B6：大小用同一种单位写法（#244 的一部分）

来源：所有者全量计划 #244/#199；基线 aded2ffd，`fix/byte-units`。

## 允许路径

- `hub/server/console/{knowledge-display.ts,memory.ts,trial.ts,size-display.test.ts}`
- `tests/acceptance/48-knowledge-console-memory.test.ts`
- 本任务页、`CHANGELOG.md`

## 决定

控制台大多数页面用 `size()`（“151 B”“1.5 KB”，1024 进制），记忆列表、记忆版本表和业务系统试读报告里却写“164 字节”，一个数字两种单位写法。新增 `exactSize(bytes)`：可见文字用同一个 `size()`，确切字节数放在悬停提示里（“164 字节”），所以精确值不丢，也不把 1024 计量改成 1000 计量。记忆列表、记忆版本表和试读报告三处改用它；负数或不是数的值仍显示“—”。

## 验收

- 单元：`exactSize` 的四种输出（164 B、0 B、1.5 KB、1.0 MB）、提示里的确切字节数、无效值为“—”。
- 验收（48）：记忆列表含带提示的 B 写法，不再含“N 字节”的可见文字；改动前失败（已实证）。

## 不做

#244 其余部分：相对时间旁就近写明时区、“知识版本／工作流版本／产品版本”的区分，涉及面更大且与其他草稿的页面改动重叠，另做。容量弹窗和团队成员元数据页里的字节写法不在这一批（有现成测试按“48 字节”断言，需要单独评估）。
