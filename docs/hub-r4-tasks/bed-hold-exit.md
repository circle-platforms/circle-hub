# 任务：床面占用结不清、说明又指错出口

依据：所有者的规矩"未知必须写明缺的事实和下一步动作，停在未知上结束的都是缺陷"；`docs/hub-r5-tests.md` T4-1、T4-3（床面恢复、未恢复阻止下一次派发）。本任务关掉真实层派发时撞到的一个缺陷。

## 现象（集成者在线上看到，数据只留本机）

某次派发在跑后床面状态未确认，留下一条 `bed_hold` 记录，状态 `open`，记着当时的探针集 `{A, B, C, D, E}`。之后执行器定义换了探针集：去掉 `D`，加上 `F`（`{A, B, C, E, F}`，探针本身都读得到）。下一次对同一自动化测试环境的派发，床面门走到"未结清占用"一支（`hub/dispatch/service.ts` 的 `gateBed`，`openBedHold` 之后）：它对当前每个探针都要在占用记录里找到当时的原文（`pre_reads`），`F` 当时没有，于是 `outstanding = null`，抛出：

> 床面探针缺失：A、B、C、E、F；只读探针 A 没有按声明解析出结构。由 bed-admin 重读 probe_show 后再开……

两处错：

1. **说明指错了出口。** 每个探针都读到了、原文也在，缺的不是探针，是"上一次占用没结清，而且探针集变了，无法比较"。让管理员"重读 probe_show"没有用。
2. **根本结不清。** 占用只会在下一次门里逐项比对相等时由门自己写一条 `clear`；探针集一变，永远比不了，没有任何管理员命令能结清它（`job dispose` 管的是作业处置，不碰占用）。自动化测试环境就被一条旧占用永久挡住。

## 要做的

1. **比较改成按交集**（`gateBed` 的占用一支，必要时 `bed-state.ts`）：
   - 占用时和现在都有的探针：逐项比原文（现在的做法）；相等才算该项已恢复，不等就是未恢复，照现在的格式列逐行差异。
   - 现在有、占用时没有的探针：按管理员登记的基线比（`bed baseline`，`getBaseline`），没有基线就算"无法比较"，写明是哪几个探针缺基线和登记命令。
   - 占用时有、现在没有的探针：忽略，在回执里写明"占用时的探针 X 现在不在执行器定义里，没有比较"。
   - 所有项都可比且都相等，才写 `clear`（现有行为）；有不等，按现有未恢复处理。
2. **无法比较时改正说明**：缺的事实写"上一次派发（作业摘要前 12 位）留下的床面占用未结清，占用时的探针集与现在不同（两边列出）"，下一步写"由管理员确认床面干净后运行 `circle-hub bed hold clear <执行器> --reason <理由>`"。只有真的有探针没读到时才用现在的"探针缺失"说法。
3. **新管理员命令** `circle-hub bed hold clear <执行器> --reason <理由>`（只有管理员；理由必填、单行）：当前自动化测试环境有 `open` 占用时追加一条 `bed_hold` 记录，状态 `clear`，带管理员、理由、被结清的占用所属作业、结清方式 `admin`；没有 `open` 占用时说明"没有未结清的占用"，不写记录；记录追加，不改旧记录。命令用法进 `circle-hub` 的帮助、`hub/dispatch` 或 `hub/server` 的 README。
4. **测试（合成）**：占用探针集 `{A,B,C}`、现在 `{A,B,D}`——D 有基线且 A、B 相等 → 结清并放行；A 不等 → 未恢复并列出差异；D 没有基线 → 说明点名 D 和登记命令；交集为空 → 说明改正后的文字和 `bed hold clear` 出口；`bed hold clear`：非管理员拒绝、无占用时的说明、追加记录并让下一次门放行、理由缺失被拒；现有床面门的全部测试保持通过（只许加法）。

## 分支、路径和规矩

- 分支和工作树：`bed-hold-exit`，目录 `cursor-trees/bed-hold-exit`（在主目录下，集成者已从 hub-redesign 开出，依赖已链接）。
- 可以改的路径：`hub/dispatch/service.ts`、`hub/dispatch/bed-state.ts` 及它们的测试，`hub/dispatch/README.md`，命令入口所在的 `hub/server` 文件（`bed baseline` 命令所在处，同一处加 `bed hold clear`）及测试，涉及派发的 `tests/acceptance/` 场景（只做加法），相关 README。别的路径要改先说明理由。
- 规则：同前（不推送、不建 PR、不发布、不部署；不碰线上 Hub、钥匙串、环境配置文件和真实系统；测试只用合成数据；`git commit -s`，只暂存明确的路径）。枚举和文字不自造词；不用关键词匹配做判断。
- 验证：`npx tsc --noEmit`；`node tools/gen-contracts.ts --check`；`node --test --test-concurrency=2` 对 `hub/dispatch/**`、`hub/server/**`、`tests/acceptance/*.test.ts` 中派发相关场景和 `.github/checks/*.test.ts`；合入前合并最新 hub-redesign 再跑相关部分并报计数。
