# Reuse the run's model declaration in submissions

Decision 82 allows a same-session submission to reuse the explicit model identity recorded at start. `model_identity` became optional, but the older top-level `model` string still remained mandatory, so the client had to repeat the model on every submission. Make that field optional at the input boundary and use an explicitly submitted identity, or the run's identity only when the observed sessions match. An older submission that already has `model` keeps its existing meaning; a different or unobserved session without its own model declaration is not attributed to the start session. Missing identity must be named with a next action, never filled from a model name or a different session.

The original submitted object and old records remain byte-for-byte unchanged. Derived evaluation input may carry the effective model; replay, carry-over, criterion requests and idempotency must use the actual validation session and the same declared identity. Add synthetic tests for same-session omission, different/missing session, explicit override, raw bytes, replay and legacy records. Update the generated tool contract and any affected model wording. No production data or services.

Scope: `contracts/src/submission.ts`, generated contracts and model documentation as needed; `hub/runs/engine` identity, submission and replay; `hub/ports.ts` and the dispatch replay call to bind the selected accepted result; server guidance, test fakes and synthetic tests; this task page, the simplification inventory and its active task guidance. Contracts are a wide change under decision 80: run the full synthetic unit, acceptance (including oracle), docs, typecheck and contract checks using adaptive concurrency.
