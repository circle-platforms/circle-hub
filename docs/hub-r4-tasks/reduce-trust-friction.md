# Simplify request authorization, identity, and Linux sandbox proof

The owner explicitly chose on 2026-10-29: a request retains the permissions established at its start and revocations apply to the next request; a submission in the same observed Circle session may reuse the explicit model identity declared at start_run; and Linux stops per-child isolation attestation while retaining OS isolation and the no-network, no-write, no-child-process boundaries. The owner explicitly approved updating the relevant model/contract and old tests that asserted the superseded behavior. These changes implement decision 81 as one batch so wide checks run once.

Implement request-local permission reuse without sharing cached authority across requests or principals; protect real credential withholding, and distinguish a failed read from a denial. Same-session identity comes only from a client declaration frozen in the current run, never inferred from a model name or from a previous run; submitted bytes and old records remain unchanged. A different or missing observed session cannot inherit the declaration. Replay and carry-over use the actual validation action of the selected result, rather than the newest action for identical submitted bytes. Preserve independent judgment and the old missing-identity behavior for old runs.

Remove the per-child Linux proof and its proof-only temporary permissions and fixtures. Keep the actual bubblewrap, AppArmor and Node permission boundaries, startup availability checks, and the real isolation tests. Do not run tests against any real system or installed production policy. Document the removed behavior and test coverage honestly.

Scope: `contracts/model.json`, `contracts/src/{tools,run,submission}.ts` and generated contracts; request-scoped permission reads in `hub/records`, `hub/runs/engine`, `hub/server/tools.ts` and the console; `hub/rules/sandbox` and its README; explicitly affected synthetic tests, `docs/hub-r4-progress.md`, the old Linux proof task's historical notice and model documentation as needed. Keep package functionality and stored history compatible. Update the old revocation and proof-only assertions to the newly approved behavior, and add tests for request boundaries, concurrent requests, identity overrides, different sessions and legacy replay.

Changes to contracts and sandbox are wide under decision 80: regenerate contracts, run typecheck, contracts/docs checks and full synthetic unit/acceptance/reference checks at the agreed concurrency; test Linux isolation only in the dedicated synthetic VM. Do not deploy, push, read credentials or access real devices without a separate instruction.
