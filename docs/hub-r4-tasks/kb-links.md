## 第一步

1. **产品包声明链接**：product@1 的知识声明加 `links`，写明三件事：
   - 从条目 data 的哪个字段取字面；
   - 链到哪个命名空间；
   - 字面怎么变成路径：按空白切成词，一个词一段；规范化只许声明的几种，没有就照原样。

   核心照声明做，不认识的声明整份拒绝。
2. **读时视图**：对锁定的根，按声明把每个条目的字面解析成目标路径。精确匹配到存在的节点算链接，没有的算漂移。视图给出：
   - 正向：某个路径前缀下的条目链到哪些目标路径；
   - 反向：给一个目标路径，哪些条目链到它。评审拿命令找手册段落用这个；
   - 漂移：解析不到的字面按字面分组，带出现它的条目引用；
   - 计数放在 `totals` 里，截断砍不掉（和 views-and-notes 的空组计数同一做法）；分页沿用视图的游标。

   同一个根、同样的请求给出同样的字节；可以按根摘要缓存。用一个约 2 万条目的合成根测时间，写进 README。
3. **漂移是确定的事实**：例如“这个根的命令树里没有 X，条目 Y 提到它”。是手册勘误还是缺陷候选，留给 Circle 或人判断，Hub 不判。
4. **绑定和渲染**：
   - 视图能作为运行输入绑定，照 facets 视图的写法；
   - get_nodes 读一个目标路径时，回答文字里列出链到它的条目：只列引用和一行摘要，不展开全文；有上限时写明总数。
5. **FAMX 产品包声明它的链接**：
   - `command_literals` 链到 `/commands`，规范化照 K1 生产时用的规则；
   - 生产器的漂移警告改成按这份声明算，保证生产时和读时是同一个规则；
   - 包升小版本，重签。
6. **测试**：
   - 链接、反向查找；
   - 漂移分组和计数（截断时计数照样对）；
   - 不认识的声明被拒绝；
   - 两次读字节相同；
   - 生产警告和读时视图对同一份合成手册给出同样的漂移集合。
