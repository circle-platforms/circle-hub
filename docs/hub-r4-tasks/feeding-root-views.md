# Preserve root-specific case projections in feeding views

A case identity is content-based and can be observed at multiple source records and locked roots. A later read without a root must not erase an earlier readable, still-valid projection under a root; distinct root projections retain their own command identities. Select a projection for the exact requested root rather than combining commands between roots. Respect the frozen feeding offset, access, retractions and source revisions.

Reproduce with a synthetic 40-case mind map: feed with a locked seedling, then re-read the same bytes without a root; a facet view over the seedling must still count all cases. Cover distinct roots, frozen cuts and withdrawal. Existing tests and assertions stay unchanged.

A separate issue discovered during this work: index entries currently require `tree:` references although fed cases are stored outside the tree; the generated synthetic tree reference cannot resolve. Before returning fed-case index entries, make their references resolve to the exact authorized feeding record with an explicit, compatible contract and update any consumers that assume every index reference is a tree reference. Do not fabricate tree membership, titles, paths or command identities. Document any fields the feeding contract does not provide as missing.
