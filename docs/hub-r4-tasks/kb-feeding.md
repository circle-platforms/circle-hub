# 任务：知识库喂入层（kb-feeding，方向 2，先不实现）

设计依据：所有者 10-24 定稿（修订 2，评审目录 `kb-design-1024.md`）。树苗（`docs/hub-r4-tasks/kb-seedling.md`，方向 1）之外的一切资料——用例、缺陷、需求/规格、构建、自由文本——都由 Circle 喂给树：Circle 实际用到什么，Hub 就按来源的 schema 把什么填进喂入层；Circle 只补程序填不了的语义，带逐字引文；Hub 只核验、登记、写账，不问人。

## 喂入层的位置与形状（照定稿）

- 挂在树苗旁，**不进根摘要**：喂入条目是独立对象，只带指向树苗（和节点路径）的引用。
- 版本绑定：出处只有来源结构和人的声明两种，状态为 已绑定 / 未声明 / 冲突；定不出版本的进产品线不分版本范围、标"版本未声明"，照常参与，单列计数。
- 运行中不问人：待办只登记在控制台（浏览器里不做弹窗确认）。
- 冲突：同一对象两种说法都保留并标记冲突，回归和巡检时能看到冲突；不自动择一。
- 伪造（顺藤摸瓜式核验）：核对引文与原件逐字一致、来源对象存在且可读、声明链完整；不一致的整份拒收并给修正说明。

## 三条硬要求的落法（照定稿）

1. **必须回**：凡经 Hub 读的都在——任务里经 Hub 读过的用例、缺陷、构建、规格都是本次运行提交的一部分，不是可选。
2. **必须按格式回**：来源 schema 由 Hub 程序填（命令树、手册等结构来源），自由文本按结构契约（逐字引文、路径、声明）。
3. **树的结构先定**：树苗布局在 `kb-seedling.md` 写死；喂入侧的结构进生成的 `knowledge-structure@1`（schema 进 `contracts/model.json` / gen-contracts）。

## 要改什么（定稿"要改什么"三部分，任务清单，先不实现）

### 模型（Circle 侧）

- 读手册和用例后提出对树苗的更新：新增节点、手册章节和命令的关联、适用条件、更正，每条带逐字引文。
- 任务提交时把用到、引用到的原件和结论按固定格式交回 Hub（必须回）。
- 只补程序填不了的语义；运行中不向人提问。

### Hub

- 喂入层对象与记录：独立于树苗根摘要，带树苗/路径引用、版本绑定（已绑定 / 未声明 / 冲突）、"版本未声明"单列计数。
- 核验管线：逐字引文与原件一致、来源存在可读、声明链完整；不合格式整份拒收并给修正说明；冲突两说并存标记。
- `knowledge-structure@1`：喂入结构的生成 schema（结构先定）。
- 树苗更新：核验通过后按血缘只追加地产出树苗新版本（`seedling@1` 的 parent 链，走现有 seedling 生产与指针移动）。
- 待办登记在控制台；不新增人机交互机制。

### 包（packs）

- knowledge-contribution 包：回注运行（现有骨架），承接喂入提交与核验结果。
- apv 包：cases / release-notes / specifications 等函数转为喂入层逐次投影使用（声明已从 product.json 去掉，函数保留）。
- 喂入读取用的 SVN / 平台连接器按来源 schema 由 Hub 程序填，不做自由文本整批解析。

## 顺序

等集成者通知后再实现；实现前先把 `knowledge-structure@1` 的结构（用例、缺陷、需求/规格、构建、自由文本各自挂哪个路径、按什么键）逐项写死在本页，经所有者看过再动代码。
