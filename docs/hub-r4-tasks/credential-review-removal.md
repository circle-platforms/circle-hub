# 凭据命中的核看、接受和撤回去掉（#194 第三步，决定 161）

所有者 2026-11-12 在问题对话里选“保持扣留，重读取得”。前两步：决定 154（模型第 44 版）不再对来源内容做凭据扫描；决定 159（模型第 47 版）加了遮盖字典。这一步去掉为扫描命中而设的整套处理，模型到第 49 版。PR #PR。

## 去掉了什么

- 命令 `circle-hub source`（held、findings、accept、withdraw、review）整个去掉。用到它的地方（文档、提示、测试）一起改。
- 待核看请求：读业务系统时不再答“X 存在，内容待核看”（`SOURCE_PENDING_REVIEW`），也不再给具名管理员发核看请求；控制台记录页的“来源核看请求”页签去掉。
- 记录层的 `scanFindings`、`acceptFindings`、`revokeFindings`、`recordUploadRefusal` 和导出时派生覆盖的计算去掉；知识层的自动接受名单（`credentialAcceptance`）和请求对账去掉。
- 知识视图不再按凭据检测器把条目标出或排除；派发只核对字节摘要。
- 测试里重新打开旧检测器的开关（`useContentDetectors`、`withCredentialDetectors`、`detectors: true`）去掉。只测这些已去掉行为的测试一起删除；只把接受当作其中一步的测试，改用旧记录夹具（`storeLegacyHeld`、`storeLegacyAcceptance`），或改测现在的行为。

## 留下的

- 此前按 credential-scan@3 只保留的记录：仍只保留，不放开，不改写。原件只有管理员能用 `circle-hub original export <sha256> --out <文件>` 取出。
- 此前已经接受的记录：仍按那次接受读（读取时核对接受绑定的扫描摘要）。没有新的接受，已有的接受也不能撤回。
- Hub 自己发出的凭据被应答回显（B02 R[6]）：规则不变，仍只保留。
- Hub 自己写下的东西（调用日志、备注、资源配置、变量、包文件）仍用旧检测器检查，不写入凭据。
- 协议码 `CREDENTIAL_IN_UPLOAD`、`SOURCE_PENDING_REVIEW`、`MEMORY_CREDENTIALS_DETECTED`、`SPACE_CREDENTIALS_DETECTED` 等仍然登记，此前存下的记录和回执里有它们；新的读取和写入不再产生。
- 引用旧记录的运行结果保持原样。

## 读取时怎么判定

新读取写下的记录（`credential-scan@4`，内容扫描）按自己存下的档位读。旧检测器扫描过的记录按原来的规则读：同一字节里最新一版检测器扫描的命中，加上绑定这次扫描的接受。新记录不参与这个判定。这一处在 main 上原来不对：重读之后，旧的已接受记录会变成只保留，而更早版本的记录反而会被放开。这次一起改正，并加了测试（`hub/records/artifacts.test.ts`）。

## 出口

要用被扣留的内容，按原对象重新读取（例如重新运行同步或读取），得到一份按现行规则存下的可读新记录，遮盖字典照常替换。运行引擎对只保留来源的请求仍发给具名管理员，文字改为“按原对象重新读取，得到可读的新记录后重新核验”；新的源文件记录写下后，维护轮次会让请求继续。

## 核对

只用合成数据；没有部署。本地跑了 TS6 类型检查、契约检查和受影响的测试：改过的和提到凭据、扣留、扫描的单元测试文件，加上三个验收测试。全量回归由合并队列跑。
