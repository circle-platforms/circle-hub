# Circle Agent 全流程回放设计

## 目标与任务边界

回放在真实 Circle Harness 中执行已经记录的模型决策，使用隔离工具替身复现主会话、子代理、工具结果、Hook 拒绝、宿主通知和后台任务。它用于复现交互与定位首个行为差异，不评估真实模型遇到新结果后会如何决策。

使用者先提出根据仍开着的脑图编译终端设计完整回放脚本，随后确认开始设计。本任务只新增本页，工作树和分支为 `design/session-replay`，基线为 `hub-redesign`。不编写回放实现，不更改 Circle、Hub 或已安装技能，不导出原始业务材料，不控制现用终端，不合并、推送或部署。

拟实现入口为 `scripts/real/replay-circle.ts`，内部模块位于 `scripts/real/replay/`；实际实施另开任务分支。实现使用 Node 24、TypeScript 和已有依赖。回放证据只保存在操作员明确指定的 Git 外目录；Git 内只保留合成测试材料。下述回放包属于脚本私有格式，不修改 Hub 模型、六个 MCP 工具或领域词汇。

## 命令与退出约定

以下命令是待实现接口；变量由操作员指向本机目录，示例不含真实位置或业务标识。

```sh
node scripts/real/replay-circle.ts capture \
  --home "$SOURCE_HOME" --session "$ROOT_SESSION" \
  --circle-app "$CIRCLE_APP" --out "$BUNDLE_DIR"

node scripts/real/replay-circle.ts inspect --bundle "$BUNDLE_DIR"

node scripts/real/replay-circle.ts run \
  --bundle "$BUNDLE_DIR" --circle-app "$CIRCLE_APP" \
  --out "$RESULT_DIR"

node scripts/real/replay-circle.ts compare \
  --bundle "$BUNDLE_DIR" --circle-app "$CIRCLE_APP" \
  --candidate-guard "$GUARD_FILE" --out "$COMPARE_DIR"
```

- `capture` 只读来源，拒绝覆盖输出目录；来源清单冻结当次截取边界。源材料目录与输出目录都必须显式给出，不读取默认个人 Circle Home。
- `inspect` 只验证私有包，输出数量、摘要和缺失事实，不展示原始消息、路径、命令或工具结果。
- `run` 默认为加速回放，不等待历史耗时。`--pace recorded --speed <正数>` 只控制呈现节奏；不改变依赖关系，不把睡眠或真实网络当作同步手段。
- `compare` 使用同一基线，逐调用重新运行候选守卫；遇到首个决定或反馈差异即停止，不自动生成后续模型回答。
- 退出 0 表示该命令要求的核验已完成，退出 1 表示明确差异或包损坏，退出 2 表示缺少完成该命令所必需的证据或版本能力。报告始终分别列出相符、不符及未知项。
- 捕获可以成功保存带缺口的材料，必须显示缺口数量；是否可执行由 `inspect` 按本页的验收范围判断，不将文件未找到转换成业务失败。

## 回放包与来源完整性

私有包由 `source.json`、`sessions.json`、`events.jsonl`、`blobs/`、`gaps.json` 组成；报告另放在运行结果目录。目录权限 0700、内容文件 0600，拒绝写入 Git 工作树、来源 Home 或来源工作目录。只读捕获不打开凭据或环境文件，不附带其他会话。

`source.json` 使用 `circle-replay-source@1`，记录捕获时间、来源数据库所选行的内容摘要、根会话及所有子会话的 head、上下文边界、应用相关模块与 Node 的版本及 SHA-256、派生索引摘要、文件读取时间和完整性缺口。数据库主文件摘要不能代表 WAL 中的记录，以只读事务选出的行字节为证据。

`capture` 用 `DatabaseSync({readOnly:true})` 和显式只读事务直接查询；禁止对真实 Home 构造 `CheckpointStore`，因为其构造过程可能迁移、修复或取得租约。读取 SQLite 中的 message 时同时取 `CAST(message AS BLOB)`，先保留来源字节和摘要，再解析生成索引。保持原始字节与派生事件分离。

`sessions.json` 保存会话父子关系、当前祖先链、分支和 task 调用绑定。若将来存在非当前分支，一并归档，但 `run` 只执行捕获清单选定的 head 祖先链，报告其他分支数量；不能把多个分支拼成单条历史。

每个派生事件有以下公共字段：

| 字段 | 约定 |
| --- | --- |
| id、kind | 包内事件身份和脚本私有事件类型 |
| session、ordinal | 来源会话及该会话祖先链顺序；不是全局请求计数 |
| checkpoint | 来源 checkpoint；合成关系事件引用其来源 checkpoint 列表 |
| dependsOn | 必须先完成的事件 ID |
| sourceCreated | 原始保存时间，用于呈现，不能独自证明跨会话因果关系 |
| payloadRef | 内容寻址的原文或结构化载荷引用及 SHA-256 |
| derivation | 使用的版本化结构规则和输入引用；歧义进入 gaps，不做相似匹配 |

载荷保留模型响应的内容、工具调用数组顺序、参数、完成原因，以及结果的状态、原文和关联调用 ID。usage、成本、thinking 和 provider_content 保留为历史证据，不当成本次回放的实际模型消耗或服务请求。

所有调用键使用 `(sourceSessionId, sourceToolCallId)`。参数另有明确序列化后的摘要，重排对象键可用于结构比较，数组顺序必须保留。原文比较使用原始字节摘要，不能用序列化后的摘要冒充原文摘要。

虚拟文件按固定版本 `projectDataDir` 与 Sandbox 的映射规则解析，仅访问声明的项目目录和本次记录明确引用的文件。当前文件标为“捕获时观察到”，不自动认定它就是历史时点的版本。文件缺失、读取时变化、历史摘要不符分别保留缺口；不通过扫描整个个人目录找一个内容相近的文件补上。

## Harness 与调度器

回放的执行链如下：

```text
只读来源 → 来源行与内容摘要 → 会话图和依赖图
                                 ↓
                       各会话的 ReplayModel
                                 ↓
                   真实 Harness 与 ReplayTools
                                 ↓
                   Hook 及宿主事件适配与调度
                                 ↓
                      实际新事件 → 差异报告
```

### 模型与请求核对

每个来源会话都有独立的 `ReplayModel` 游标。`complete(request)` 先核对本步实际消息，再返回本会话下一条记录的 assistant 响应；固定保留来源工具调用 ID，以隔离的会话映射区分新旧存储身份。禁止用 assistant 消息总数给并发请求分配答案。

只核对有来源支持的请求部分：逐条业务消息、内部通知、工具结果、上一批调用和完成原因。原始 system prompt、当时所有可用工具 schema、完整请求参数与传输重试没有完整快照，列为请求层证据缺失，不能宣称请求报文相同。模拟所需的基础系统文本和工具元数据由匹配的已安装版本及合成适配器提供，并分别标明来源。

回放模型 `sideRequests=false`，不生成标题、摘要或其他旁路回答。当前样本未发现摘要，首版不实现摘要调用重建；其他包若含摘要而适配器尚不支持，`run` 返回证据不足。来源响应一次性驱动 token 回调；不虚构原始 token 分块、SSE 节奏或推理时间。

每步核对失败后不消费下一条响应。异常记录包含事件引用与期望、实际摘要，不把历史后续回答硬塞进已经改变的上下文。

### 上下文投影与身份映射

完整消息图保留 2,610 条消息，不意味着每次请求都携带此前全部消息。80 个上下文版本必须随 checkpoint 关系保存；其中 76 个包含裁剪及移除 thinking 的状态。捕获同时保留 checkpoint ID、message.id 和 tool_call_id，三者不能混用。

每一步先按来源祖先链定位当时的有效上下文状态，再将其中的消息、checkpoint 和子会话引用转换为临时存储身份，通过 `CheckpointStore.setContextState` 写入临时库。使用该版本公开的 `ContextManager.project` 读取投影，随后由 Harness 的 `orderModeToolResults` 形成模型输入。只调用投影接口，不调用会新增提醒、重新裁剪或启动摘要的 `ContextManager.prepare`。

新生成的工具结果、Hook 通知和根输入 message.id 与来源 ID 可以不同；在它们与期望消息逐项相符后登记双向映射，才允许后续裁剪状态引用它们。脚本返回的 assistant 及其工具调用保留来源身份。状态引用未生成消息、多个来源映射到同一实际消息或消息配对不符时立即停止。

对同一 checkpoint 上的多个版本，只有能由来源版本链明确确定的状态才作为已核实输入；保存时间用于辅助排序，不替代缺失的请求边界。如果仍有多个会改变投影的候选状态，保留原始历史，标出请求层歧义，不凭时间接近选一个来宣称相同。完整请求报文依旧属于独立的证据层。本次有 3 个 checkpoint 分别保存了 3、2、2 个版本；逐字段比较后，它们各自的输入投影状态相同，不能把这种元数据更新误报成输入歧义。


### 并发与因果顺序

依赖至少包含：同会话保存顺序、assistant 到其工具调用及结果、同批全部结果到下一次模型请求、task 调用到子会话启动、子会话终态到对应 task 结果，以及后台启动到完成通知和后续读取。

调度器保存每个任务的 Promise，只释放依赖已满足的事件。没有因果约束的同时就绪事件，使用 `(sourceCreated, session, ordinal, id)` 固定顺序作为回放策略；这个顺序不宣称是历史真实开始顺序。历史时间仅控制可选呈现延迟。

子会话绑定先使用父会话关系，再在其初始输入中逐字匹配完整 task.description，并要求一对一。描述重复、多个完整匹配或无匹配时进入缺口；不按标题、关键词或时间最接近匹配。

`task` 替身启动另一个真实 Harness，使用其脚本模型、工具集合与独立存储会话。在子会话结束后才允许交付父调用结果，同时核对子会话原始最终文本是否被 task 结果完整包含。历史 task 结果还可能含包装和统计；这些包装作为替身边界的历史结果保留，不假装是原生 CircleRuntime 重新计算的统计。

两个后台 execute 不启动 OS 进程。启动替身产生登记，完成事件等到其依赖满足后才交付；为已保存完成通知建立 job 身份的显式映射。无可靠身份绑定时不按文件引用数量或耗时猜测。后台 stdout 只重放已经记录或有完整性证据的字节，缺失部分保持未知。

### 工具边界与临时文件状态

给 Harness 的工具为显式替身：保留可核实的工具名、参数与副作用类别，`prepare`、`run`、审批事实查询等可执行入口都由回放实现提供。不能注册真实 execute 或业务适配器后仅在执行末端截断；真实 prepare 可能已经访问来源文件。未知工具不为了回放成功而自动注册。

| 工具种类 | 替身行为 |
| --- | --- |
| read_file、ls、glob、grep | 精确匹配来源调用后返回历史结果；历史返回文字本身不证明当前文件状态 |
| write_file、edit_file | 在内存文件版本表中登记完整写入或精确片段编辑；只有确认成功的历史调用才改变表 |
| delete | 原调用是否真的进入工具、结果状态及效果分别处理；不能因为模型尝试删除就删除临时文件 |
| Hub、知识与技能安装 | 返回历史结果和明确记录的安装事件，不连接 Hub、知识服务或技能下载站 |
| execute、skill_run | 不执行历史命令；成功返回原文，错误按 1.17.0 Harness 的异常消息序列化路径注入 |
| question | 重放该调用的已记录结果，不打开提问界面，不伪造人工答复 |
| task、后台控制 | 调度对应依赖图；其他控制调用只有在来源存在时才支持 |

内存文件表只表示已观察或已重建的版本。read_file 的某次结果、write_file 内容和 edit_file 片段不能补全未观察到的其余文件；编辑前版本缺失时仍可重放结果文字，但必须将文件效果核验标为未知。

默认不把历史文件物化到磁盘。需要查看已知产物时，用包内文件身份映射到私有输出目录，不保留可写的原绝对路径。路径比较依据显式声明的参数槽、命令词法和绑定表，不做全局字符串替换。未能解析的命令在基线模式下仍是不可执行的原始载荷；比较模式不能证明其路径改写安全时停止。

## Hook 与内部消息

49 条拒绝采用固定版本导出的 `HOOK_DENIED_LINE` 及完整 reason 进行结构配对，匹配同一 assistant 批次的工具名，要求唯一结果。消息的 `internal` 与 `hook` 元数据决定消息种类，不从正文关键词分类。

基线模式由 ReplayHookRunner 返回记录的决定、理由及通知元数据。拒绝交给真实 Harness 的 gateTool 路径，由其生成错误工具结果，并在原批次工具结果后 flush 通知；脚本不预先把这条通知重复写入存储。active 通知只出现一次。

日志没有调用 ID，不能把 1,354 条 before_tool 日志直接按序分给全部 1,360 次调用。对没有充分证据确定 Hook 返回的调用，适配器返回 none 作为明确的模拟默认值，并在覆盖报告记录该决定缺少历史逐调用绑定；它不是“历史已证明允许”。97 条错误逐个保留，不能全部归为 Hook 拒绝。

plan-reminder、loop-guard 和 job_notice 由回放宿主在其来源位置交付，不经 Harness.queue 伪装成人工输入。使用独立的来源游标，在 prepareMessages 前校验当前存储边界，再通过临时 CheckpointStore 的公开 append 接口写入该宿主消息。Hook 通知由 Harness 自己生成，不进入这条注入路径。遇到宿主消息重复或位置不符立即停止。

全部新增存储只落到新建临时 Home，数据库、事件和检查报告不与真实 Home 共用。加载 Circle 模块之前清空继承的连接配置，显式传入临时 Home；只注入脚本模型，不构造 GatewayModel，不启用扩展、更新、模型刷新或真实 MCP 配置。

## 候选守卫比较

基线 `run` 先通过消息与边界结果核验，才执行 `compare`。候选文件必须是操作员明确指定的本地守卫入口；比较器只执行这个入口，不执行它审查的历史命令。

为候选守卫建立临时声明、技能文件及调用信息。真实凭据不复制，令牌位置使用合成值或原有占位符；来源中的地址、身份和路径若需替换，只使用清单中明确的映射。无法重建影响判断的技能版本、声明、文件存在状态或 session 类型时，该调用的候选决定标为未知，不拿当前安装代替历史安装。

逐调用保留标准输入、标准输出、退出码、超时与决定的摘要；有可比基线时比较决定和模型可见反馈原文。守卫超时由注入限额和超时结果测试，不断言绝对墙钟上限。

出现首个确定差异时停止这条固定轨迹，报告来源事件、依赖的其他会话、期望和实际决定或反馈的摘要。允许原来被拒绝的调用后，不播放假定模型仍作原决策的后续回答。缺少候选判定输入时也停止并返回证据不足，不跳过该调用继续宣称整条轨迹相符。

## 报告与验收

报告 `report.json` 和中文摘要分别列出：消息覆盖、工具配对、子会话绑定、Hook 路径、宿主注入、后台时序、文件状态、请求层材料及首个差异。每一项记录来源事件、相符或不符或未知、实际输入与输出摘要、转换和缺少的事实。退出码与过程完成不代表业务结果正确。

本样本在捕获边界不变时应满足以下轨迹验收；捕获时重新计算，不能把本页的数量硬编码成通用条件：

- 19 个会话、2,610 条当前路径消息、1,055 条模型响应和 1,360 对调用结果全部消费，无多余请求、重复结果或未消费事件。
