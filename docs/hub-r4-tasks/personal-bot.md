# 成员私人机器人

所有者批准私人机器人首版计划，并发起独立实现：身份绑定、一对一私聊外发意图与回执、成员聊天应用接口及适配器契约均以通用能力和合成验证事实为准，切换生产入口仍须部署所有者另行决定。

## 职责与边界

- 身份绑定及唯一外部成员身份表的增量迁移、授权接口与测试归 `hub/records`（`external_member_identities`）；权限变更覆盖 `hub/platform/ownership.test.ts`；管理命令跟踪名归 `hub/telemetry/names.ts`。
- 私聊外发的意图与回执由 `contracts/src/resources.ts` 定义并生成契约（`member-notification-intent@1` 与 `member-notification-receipt@1`），正反例在 `contracts/src/member-notification.test.ts`；`hub/connectors/contracts.test.ts` 核对资源契约闭集。
- Hub 服务端（`hub/server`）提供成员聊天应用接口、控制台设置页 `bot set` / `bot test` / `bot disable` 操作、`circle-hub bot` 管理命令及对应测试。
- 运行模型与保存会话的宿主、桌面客户端源码、界面与企业微信适配器归 Circle 端；客户端与宿主须保持同一 `Circle-Version`，以发起成员自己的授权凭据调用 Hub。
- `D06` 的六个 MCP 工具继续服务工作流与技能，远程私聊走经成员认证的应用接口。消息、会话、运行、文件与外发各自保留独立标识和证据。

## 能力与契约设计

### 应用接口与媒体传输

- 应用接口 `POST /api/bot/v1` 从 `Bearer` 令牌核验成员身份，并要求请求头 `Circle-Version` 与宿主版本一致；发现、按游标读取、新建、发送及停止均按消息或会话标识幂等操作。
- 成员文件接口 `PUT /api/bot/v1/files/<sha256>` 与 `GET /api/bot/v1/files/<sha256>` 在成员空间校验字节长度与 `SHA-256` 摘要，单文件上限为 `100 MiB`（六个 MCP 工具的上传上限仍为 `16 MiB`）。
- 控制台模型连接测试发往独立宿主；扫码绑定依赖已登录成员的 CSRF 校验、一次性浏览器状态、应用授权换取的成员身份以及数据库对唯一外部身份的约束。
- 私聊外发适配器使用独立凭据，仅在启用通道后连接；测试用机器人标识也须由部署所有者显式选定并配置，不预设真实租户或主机地址。

### 通知意图与回执

- Hub 在向私聊通道交出内容前先追加记录 `member-notification-intent@1`，固定成员受众、登记通道、签名方式、重试安全类、原始事件、字节数与内容摘要。
- 通道投递结果通过 `member-notification-receipt@1` 引用该意图；第三方通道 SDK 的成功应答只记为已发出（`issued`），缺少确认应答时保持未知状态，不写成已读或已触达。
- Hub 记录仅保存文件名摘要，不将成员私聊原文或私人附件暴露给非受众成员；当前路径只覆盖私聊消息与附件，报告或云文档写入契约待后续另立任务评审。

## 一对一能力核对清单

| 输入或操作 | 预期产物与隔离边界 | 核对要点与当前缺口 |
|---|---|---|
| 新成员登录客户端并发送文字 | 本人稳定的私人机器人、成员输入与模型答复 | 真实 OAuth 登录、回环 Hub、独立 Circle 宿主与脚本端点；待真实企业租户验证 |
| 发送过程中关闭桌面客户端 | 服务端继续追加终答并在重连后可见 | 在宿主等待回复时关闭桌面端，恢复模型输出后再读回终答 |
| 帮助、新会话、停止当前输出 | 帮助说明、新会话标识、终态停止回执 | 宿主执行会话级动作；远端运行或派发中止另有独立规则 |
| 桌面端与通道端交叉投递及重投事件 | 共用默认私聊、顺序号与持久消息标识 | 双成员回环 SDK 与并发重投去重；真实租户多成员验收待做 |
| 先发文件再补充说明 | 去重并合成为单次绑定输入，附字节数与摘要 | 合成回调去重、文件流式上传与 `SHA-256` 校验 |
| 回答追问或补充附件 | 绑定本人当前问题号与文件引用的输入 | 宿主重启后保留挂起问题，拒绝跨成员或过期问题号 |
| 向本人发送文字或附件 | 受众明确的占用意图记录与通道回执 | 合成通道 SDK 回环与权限隔离验证；真实租户主动消息待验 |
| 脑图评审、编译与上机相关请求 | 沿用现有 `case-review*`、`case-compile` 等工作流 | 须衔接成员委托、独立复核模型族声明与真实测试环境验收 |

## 合成验证

- **Hub 契约与服务端回归**：在合成数据库与回环服务端验证了合约模式（`member-notification-intent@1` / `receipt@1`）、唯一外部成员身份表（`external_member_identities`）、`/api/bot/v1` 及 `/api/bot/v1/files/<sha256>` 的认证、版本检查、`SHA-256` 校验和跨成员读取隔离。
- **跨仓库配对验证（合成端点）**：Circle 桌面与通道适配器在隔离 `CIRCLE_HOME` 与临时 PostgreSQL 环境下对接合成端点与本地 Hub，验证双成员隔离、重复事件幂等、断线终答保留及管理端设置桥轮换密钥；真实企业租户、正式托管服务部署与真实设备执行仍需部署所有者另行验收。
