# B1：读一条任务记录时只看任务头，不读整段历史

来源：所有者全量计划 #200/#195/#199；基线 aded2ffd，`fix/record-reader-run-header`。与 #270（实时流可见性）同类但互相独立。

## 允许路径

- `hub/ports.ts`
- `hub/runs/engine/{queries.ts,service.ts,README.md}`
- `hub/server/{readers.ts,readers-header.test.ts}`
- 本任务页、`CHANGELOG.md`

## 决定

工具层的记录读取器（`recordReaderFor`，每次 `rec:` 引用读取都经过它）对每条与任务相关的记录调用完整的 `getRun`，只为得到“是否可见”和 `runner`/`host`/`pack_space` 三个字段。新增可选内部端口 `runHeader`：沿用 `getRun` 开头的同一可见性规则（`visibleRun`），可见时只返回这三个字段，不读提交、结果正文和请求。读取器改用它；唯一需要回执列表的情形——非执行人读取提交记录——仍调用 `getRun`，因为该答案依赖回执。缺该端口的引擎保持原来的完整读取。

不改任何读取结论、权限、完整性核验、外部 schema、MCP 工具、生成协议、迁移或配置。

## 验收

- 账号 × 记录判定矩阵（执行人、管理员、成员；任务记录、生产结果、被拒结果、有结果的提交、无结果的提交、校验动作）在分享前、分享后、撤销分享后，与原读取逐项相同，且矩阵同时含可读与不可读。
- 24 条各 64 KiB 的历史结果加 1 条生产结果：旧读取加载 50 条结果正文，读取任务记录和读取结果记录各加载 0 条。
