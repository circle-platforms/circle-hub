# B5：知识列表的陈述不再整段链接蓝（#215 的一部分，叠在 #288 之上）

来源：所有者全量计划 #215；基线为 `fix/knowledge-list-context`（#288），分支 `fix/knowledge-statement-emphasis`。这是界面改动，按 #147 的规则只作为草稿提出，须经所有者看过前后截图再决定。

## 允许路径

- `hub/server/console/{style.ts,testing-knowledge-list-browser.ts}`、`hub/server/console-knowledge-list.test.ts`
- 本任务页、`CHANGELOG.md`

## 决定

按 Issue 的建议方向“保留链接可辨性，主内容结合中性文本、下划线和悬停”：

- 文件夹页条目表里的陈述用主文字色并加下划线，静止时不再是链接蓝；悬停和键盘焦点时恢复链接蓝，焦点环保留（共用设计包里已有的 `.ch-table a:focus-visible` 规则）。
- 下划线是非颜色线索：陈述仍然看得出可点击，状态、其他链接（如子文件夹）的链接蓝不再被整段陈述的蓝色盖过。
- 只作用于 `[data-statement]` 里的链接；其他表、其他链接不变。

## 验收

- 浏览器（隔离 Chromium、真实测试 Hub、合成数据）：1440、1024、390 × 浅深主题共 6 个捕获；陈述链接计算样式为带下划线、颜色等于正文色、不等于同页其他链接的链接色（浅色 `rgb(22, 25, 29)` 对 `rgb(10, 99, 189)`，深色 `rgb(232, 234, 237)` 对 `rgb(140, 200, 255)`）。去掉样式后单元测试与浏览器断言都失败（已实证），加上后通过。看了 1440 浅色一张。
- 单元：新增的样式规则断言在 `console-knowledge-list.test.ts`；控制台与知识相关的测试通过。

## 没做、需要你判断的

- 长陈述每一行都带下划线，视觉上偏重；备选是只在悬停时加下划线（但那样静止时没有非颜色线索）。这是设计取舍，没有替你定。
- **2026-11-12 所有者看过预览后选了后者**（“#215 选乙”）：陈述平时不带下划线，鼠标移上去或键盘聚焦时变成链接蓝并出现下划线，焦点环保留。静止时靠列的位置、表头和光标形状说明可以点开。上面“做了什么”一节里“加下划线”的说法以这一条为准。
- #215 提到的“技术‘查看’入口降低常驻权重”只针对其他页面的“查看”和团队表里的“来源”链接，这里没有动。
- 悬停与键盘焦点的外观没有自动化截图（只断言了静止状态与规则文本）。
