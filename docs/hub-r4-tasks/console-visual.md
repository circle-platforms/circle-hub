### 1. 由设定生成 CSS、主题切换、字体与轨道标志

1. 增加 Node 24 直接运行的确定性生成工具：读取 `tokens.json`，把颜色、阴影、字体族与字号阶梯、间距、圆角和布局尺寸转换为 CSS 自定义属性；将 `{brand-blue}` 一类引用转换为相应的 `var()`，拒绝未知引用、循环或缺项。生成文件放在控制台目录，由 `style.ts` 导出“生成设定 + 原样的 bundle.css”；运行时不依赖工作树中的设计文档。用测试对照源文件与生成结果，保证重复生成一致，不维护第二张调色板。
2. CSS 基础值为深色；未显式选主题时由 `prefers-color-scheme: light` 覆盖，显式 `data-theme="dark"` / `data-theme="light"` 优先。三档控件使用本地存储，第二块按 Claude 要求移到账号旁/登录前面板底部并改用 `ch-seg`；跟随系统时移除显式覆盖，系统变化及时生效。存储不可用或脚本关闭时仍能跟随系统，登录及首次改密页也适用。
3. 在现有固定脚本与 SHA 允许机制内实现主题初始化与事件委托；无实时模块的页面也能切换主题，不因此订阅 SSE。继续拒绝内联事件、动态 style 属性和外部资源，不增加 `unsafe-inline`、`unsafe-eval` 或外部源。测试主题样式和脚本的实际哈希与 CSP 一致。
4. 原样采用 `Circle CJK` 的 `local()` 字形、92% 调整与禁止合成粗体；控制台固定默认字号档，数字列、时间和快捷键用等宽字体，统计大数字用正文字体。轨道标志改用 `ch-hubmark` 与品牌设定，字标保持小写；`FAVICON_SVG` 与 `/console/favicon.svg` 响应保持不变。

### 5. 交互与图表

1. 表格与 ListRow 行内不放操作按钮；行选择后在 Inspector 给出操作，破坏性动作使用 danger Button 和原有确认 Dialog，团队页与其他区域一并检查。统一选择与筛选网址、行悬停、Tab 焦点、↑↓ 选择、Enter 打开、Esc 退出详情或对话框，以及 ⌘K / Ctrl K 聚焦搜索。保留链接和 GET/POST 表单的无脚本路径，不让行点击吞掉链接、勾选框或表单操作。
2. Dialog 继续支持 `:target`，脚本增强焦点进入、限制与返回；遮罩点击不丢输入。会影响他人或不可撤销的操作复用真实预检/确认，按钮写动作；仅后端已有撤销能力时提供撤销，不为演示增加写路由。
3. 提交期间显示忙碌并防重复；普通列表保留布局、加载更多不丢已有行，图表刷新保留原图并变淡。超过 10 秒显示对应等待状态；成功 Toast 3 秒后关闭、悬停暂停，失败保留并给处理办法。字段错误就地显示，空状态按权限给可执行入口。
4. 调整既有 SVG 图表与统计组件：一个数用 Stat，数量比较用柱，趋势用线，组成用细分段条。单系列用 `--area-chart`；多系列稳定占用 `chart-1` 到 `chart-4`，筛选后不换色；状态图只用状态色和文字。按规范限制柱宽、圆角、线宽、端点、网格和标注，不增加图表依赖。
5. 同一份服务端数据同时渲染图、图例和“以表格查看”的表格，无脚本仍有数据；哈希允许的脚本只增强悬停、最近日期参考线与键盘提示，不从客户端猜值。近 7/14/30 天在页头统一控制本页所有统计、图表及表格；缺少该时段数据的现有页面记录限制，不虚构趋势。
6. 共用数字、容量、日期和完整时间提示的格式化；应用 120/180/240ms 动效及减少动态效果规则。SSE 更新后主题、选择、网址、滚动、已开对话框和正在输入的字段保持正确，事件委托不重复绑定。

检查：交互与图表数据一致性测试、无脚本表格和表单路径、键盘与焦点的浏览器检查、实时刷新回归、CSP 拒绝动态 style/事件处理器的安全验收。

### 结果解读与剩余成本

默认知识主页每次最多校验/加载 100 行正文，完整规模为 37 条 SQL；我的首页为 40 条，条目详情为 29 条。不同规模的最近 100 行落在不同空间时，空间批次数也会不同。500 / 2,000 的不可变记录清单完全匹配，分别为 2,419 / 9,055 条。成员/工作流的增长回归及 5 → 20 人探针均保留同样的授权结果，连接和团队的 SQL 增长已消除。

总览仍为 **3,122.9 ms p95**，任务为 **628.7 ms**，文件夹为 **358.1 ms**，均标为慢页。总览的窗口从小规模 50 个任务增到上限 120 个，剩余批次数也随这个窗口增加；其中某个正式样本有 110 次回答/索引页批次调用。这些已受显示窗口约束，仍保留逐任务的受保护详情推导。任务主页的两规模 SQL 范围重叠，不把最大值相差 1 次解读为逐条 N+1。全局未回应请求保持完整返回，超过 500 条时仍需按批次续读；权限稀疏时也必须继续检查候选，不宣称所有数据规模下永远是一个常数。

- CPU 是服务端 request → response.end 的 `process.cpuUsage` user+system 增量（原始值分开保留），与同窗口墙钟并列。它是 Node 进程所有线程的 CPU，可因 GC 等并行而超过墙钟，包含该进程内测试客户端的同期少量工作；不含 PostgreSQL/沙箱子进程，也不是端到端浏览器时间。负载高时 CPU 也可能受内存压力影响，不能把墙钟差全部归因于代码或用二者相减推算数据库成本。
- 端口阶段记录 calls/sum_ms/max_ms；并行调用和嵌套记录端口的耗时重叠，不能相加为总耗时。CPU profile 限定在服务端总览请求区间，排除造数和其他页面。`profileClockMarker` 给 V8 profile 时钟与 hrtime 的偏移校准范围；只分析该范围校准后的请求样本，不把启动/造数热点当总览热点。全程 profiler 开启，两个版本相同。
- HTML/CSS/JS 均为未压缩 UTF-8 字节。HTML 包含其内联部分；CSS/JS 列是每页所需资源加内联字节，不能直接和 HTML 相加。旧版每页 CSS 53786 B，JS 为 24113 B（普通页）或 28896 B（实时页）；新版 CSS 仍 53786 B，JS 分别为 24369/29152 B，其中只有 bootstrap 的 256 B 内联。首次冷加载总脚本增加这 256 B，命中不可变缓存后外置资源无需再传正文。
- 每次响应要求 200 且不含错误/无权/内部错误文案；每页测前后 records watermark 一致，禁止把错误页当有效测量或 GET 追加记录。物理 SQL 在 pg.Client 边界逐条计数（包括身份核验及使用时间更新），不是查询端口的调用次数。相同记录数和 20 成员增长探针用于核对可比性。
