# 任务：运行配置转换器出复核清单

依据：决定 119。运行配置照手头用例逐台开放：10-31 的提示符与证书导入只开了第一台负载均衡设备，11-02 的读超时只开了 cmd_config；合约已声明类型的同类参数在别的方法和对象上一直被列为永不传入，几个开放了的方法合约里又没有类型权限，用到就停在类型权限核对。这些差异只能靠人逐项比对，转换器 `--check` 只核覆盖与角色，不提示。

- 分支和工作树：`profile-review-report`（从 hub-redesign 2bf73fc45 开出）。
- 可以改的路径：`scripts/real/convert/runtime-profile.ts`、`scripts/real/convert/runtime-profile.test.ts`、`scripts/real/convert/io.test.ts`（终端输出形状的断言）、`scripts/real/convert/README.md`；本页。
- 规则：同前；合成夹具，不含真实对象、地址或摘要；提示不改变检查结论。

## 做了什么

1. `reviewNotes`：按合约的类型权限和条目的 python_symbol（已解析的结构，不按名字猜）列三类——合约已声明类型、配置列为永不传入的参数；同一运行器方法在不同对象上开放的角色或永不传入名单不同；开放了但合约没有类型权限的方法。
2. 草稿和 `--check` 都在有条目时写私有的 `profile-review.json`，终端在发布命令之前只打印个数和 JSON 指针（同本目录的输出规则）。
3. 测试：终端输出的断言改成每行只能是固定标签、个数和配置指针，再接摘要行，不含对象名，复核文件权限 0600；原格式合约的每个开放都提示没有类型权限；带类型提示符的合成合约加第二个对象、只给一处开放提示符时，提示该参数永不传入和两处开放不同，开放一致后不再提示；带类型的开放取合约声明的角色（运行器选项通过、写错角色被拒），原格式条目照旧按派发表。

4. 角色核对跟上 runtime-contract@2：条目有类型权限时（按包的配置解析器的读法，排除该项的永不传入名单），每个传入参数的角色必须等于合约给它声明的角色；只有原格式条目才按派发角色表核对。此前派发表里没有运行器选项和证书材料两种类型角色，`--check` 自 10-31 起拒收已发布的配置，集成者只能改用包的解析器核对，覆盖核对因此没人跑：已发布配置有三个组合同时列在开放和未开两边。

## 不做

- 不把提示变成拒绝：有意不传入的参数（例如没有核对覆盖的主机提示符）由集成者照留。
