# 用 modern-web-guidance 重新检查控制台（2026-11-12）

来源：所有者 2026-11-12：“搜索这个项目并加载到 claude 的 skill 里面，然后利用里面的 skill 重新检查整个网站”，项目是 GoogleChrome/modern-web-guidance。分支 `fix/console-audit`，接在集成分支 `integrate/batch-ten`（PR #329）之后。

## 用的是什么

- 仓库 GoogleChrome/modern-web-guidance，提交 `4dd96834`（v1.0.0，2026-11-10），Apache-2.0。内容是两份技能说明和 208 篇指南，没有钩子、没有 MCP 服务。已按官方方式装成 Claude Code 插件（`modern-web-guidance@googlechrome`，用户级）。
- 配套的 npm 包 `modern-web-guidance@1.0.0` 提供搜索、取指南和“旧写法扫描”。包里没有安装脚本和依赖；它默认向 Google 发匿名使用统计，检查时用它自带的开关 `DISABLE_TELEMETRY=1` 关掉了。
- 检查对象是集成分支的最终代码，在本机用合成数据起的控制台（126 个任务、13 个账户、约 410 条知识）。没有碰任何真实系统。

## 怎么查的

1. **旧写法扫描**（技能里的确定性规则，35 条、覆盖 33 篇指南，约占全部指南的两成）：扫了控制台源码、设计系统、以及浏览器实际收到的样式表和脚本。**0 处命中。**
2. **按指南逐页检查**：从无障碍、HTML、表单、CSS、配色与深色模式、对话框、页签、面包屑、表格、安全、性能这几篇指南里取出能客观判断的规则，在无头浏览器里对管理员能到达的全部 349 个地址（加登录页）逐页执行；深色方案和手机宽度（390 像素）各抽 110 个地址。脚本在 `.tmp/demo/audit.ts`（不入库）。
3. **逐条核实**：每一类命中都回到页面标记和源码里看过，去掉误报。

## 结果

### 没有问题的

- 每页恰好一个 `<main>`、一个 `<h1>`，有 `lang`、标题、视口声明，不禁止缩放。
- 图片都有替代文字，装饰性图标对读屏隐藏；表头都有 `scope`；没有正数 `tabindex`，没有把可聚焦的元素对读屏隐藏。
- 浅色和深色两种方案下，文字对比度没有一处低于 4.5:1（大字 3:1）。
- 安全：内容安全策略只允许本站脚本（随机数加摘要）、禁止被嵌入、禁止 `base`；`nosniff`、同源引用策略、同源资源与打开者策略都有；会话 Cookie 是 `HttpOnly`、`SameSite=Strict`；静态资源带完整性摘要、长期缓存；脚本里没有 `innerHTML`、`eval`；没有第三方资源。
- 性能：一页只有一个样式表和两个延后执行的脚本，共约 95 KB；首次绘制中位 60 毫秒、九成在 152 毫秒内；没有布局抖动，没有长任务；动画都尊重“减少动态效果”。

| 发现 | 涉及 | 说明 |
|---|---|---|

| 面包屑不是有序列表，也不标出当前页 | 259 个地址 | 现在只列上级，当前页是下面的标题。按指南要改成 `<ol>` 并把当前页放进去 |

### 核实后去掉的误报

- 主题切换按钮上的 `tabindex="0"`：是单选组的标准键盘写法。
- 顶部搜索表单“没有放在 `<search>` 里”：它有 `role="search"`，等价。
- “表单控件没有 `name`”：是不可选条目上禁用的复选框，本来就不提交。
- “密码框没有自动填充提示”：是接入业务系统时填密钥的框，已经是 `autocomplete="off"`，合适。
- “可滚动区域键盘到不了”里的图表和页签行：里面有可聚焦的内容，焦点会带着滚动。
- “`hidden="true"`”：其实是 `aria-hidden="true"`，检查用的正则写宽了。

## 所有者选定之后做的（2026-11-12）

所有者 2026-11-12 在“需要你定的”里选了四项：触屏上放大可点目标、手机上输入框 16 像素、静态资源开压缩、其余规范项（面包屑、文件夹树、同名链接、手机上详情页的标题、代码块标记）。“换成原生对话框”和“字号改相对单位”改动大，没有选，这次不做。分支 `fix/console-audit-approved`，接在用词评审表的分支（PR #334）之后。

| 项 | 做法 | 桌面上有没有变化 |
|---|---|---|
| 触屏上的可点目标 | 只在触屏设备上（`pointer: coarse`）生效：表格、面包屑、卡片页脚这些地方单独成行的链接上下各加 4 像素的可点范围；一两个字的短链接宽度不小于 24 像素；折叠按钮、来源卡片里的“打开原文”不低于 24 像素；复选框 24 像素；输入框不低于 32 像素 | 没有 |
| 输入框字号 | 触屏设备或窗口宽度不超过 760 像素时 16 像素，iPhone 点输入框不再自动放大页面 | 没有（窗口缩到手机宽度时会变） |
| 静态资源压缩 | 样式表和两个脚本按客户端声明的编码用 Brotli 或 gzip 发送，第一次请求时压一次后留在内存里。每种编码有自己的校验标签，响应带 `Vary: Accept-Encoding`。页面本身不压：页面里有本次登录的表单令牌，压缩后的长度会泄露它 | 看不出来，传输变小 |
| 面包屑 | 改成有序列表；当前页放在最后一项，是指向自己的链接并标为当前页；分隔符由样式表画，不写进文字里 | 末尾多出当前页的名字 |
| 文件夹树 | 改成嵌套的链接列表。原来每个文件夹都包在一个永远展开的折叠元素里，点链接旁边会把它收起来 | 没有 |
| 同名链接 | “查看全文”“查看全部”“打开原文”“查看条目”各自补上给读屏的说明（哪一次提交、哪一份原文、哪一条）；总览上的“查看全部”改成“查看全部业务系统” | 只有总览那一处文字 |
| 详情页的标题 | 窗口不超过 1180 像素时列表会让位给详情，那时详情里补一个只给读屏的一级标题（页面标题）；窗口更宽时列表自己的标题在，这个标题不出现 | 没有 |
| 代码块 | 命令、命令输出、JSON 这类内容的 `<pre>` 里包一层 `<code>`；原文预览是正文不是代码，不包 | 没有 |

这次改动自己带出来、提交前已修掉的一处：给读屏补的隐藏文字放进很宽的表格之后，把整个页面撑宽了（任务“过程”页签在手机宽度下宽出 106 像素），因为隐藏文字脱离了表格的滚动框。现在滚动框会框住里面的隐藏文字，以后在宽表格里加这类文字也不会再出这个问题。

没有做的：原生对话框、相对字号（所有者没有选）；提示的触发点改成按钮、表单命名、标签用 `for` 关联、必填项的可见标记（不在选定的范围里）。

在这份代码上的实测（合成数据，本机一个进程，126 个任务、约 410 条知识；浏览器模拟触屏和 390 像素宽）：

- 管理员能到达的 347 个地址加登录页，逐页检查：低于 24 像素的可点目标 0 处（改之前每页都有），输入框字号低于 16 像素 0 处，面包屑三条规则 0 处，页面横向溢出 0 页，脚本报错 0 页。桌面宽度（1440 像素、鼠标）下同样 348 页无溢出、无报错，可点目标和字号与改之前相同。
- 仍然命中的同名链接 24 页，都是内容本身同名：同名的任务、同一分钟的时间、三份都叫 content 的原文。没有再补说明。
- 网络上实际传输：样式表 71,077 字节压到 12,740（Brotli）或 14,675（gzip），主脚本 28,519 字节压到 7,111 或 8,229；页面没有压缩。
- 功能和性能复核：管理员走查 347 个地址全部正常；点击检查 44 项、带表单的流程 19 项全部通过；32 个浏览器每 2 秒开一页，每秒 15.3 个请求，零失败，中位 45 毫秒，95% 在 0.30 秒内，最慢 0.56 秒。
- 以上是合成数据和单进程的数字，没有部署，也没有在真实手机或读屏软件上试过。
