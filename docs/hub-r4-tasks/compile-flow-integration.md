# 编译流程整合

2026-11-21，来源为所有者本轮的术语、模块整合、复现验证和公开发布要求。集成线以主线为基线。编译流程沿用[决定 179 的任务页](t18-compile-flow.md)和[决定 183 的进度记录](../hub-r4-progress.md)。

- Hub 核心覆盖 `contracts/`、`hub/` 和相应验收用例。保留已应用的迁移字节。记录、派发、运行和管理接口按各包的公开入口连接。
- 编译流程覆盖 `packs/workflow/case-compile/` 及关联工作流。工作流在收到子代理完成信号后调用一次 `pipeline.ts next`。状态、下一步文字和 CLI 声明随包发布。
- 可复用模块覆盖 `packs/skill/`。按发布声明内嵌模块，使用原技能生成副本。产品专用改动留在产品包工作分支，Hub 主线的产品包实现和冻结参考源码保持原样。产品包的合成测试接入 Hub 的通用测试读端口。
- 发布检查覆盖 `.github/checks/`、`.github/workflows/checks.yml`、`tools/`、`scripts/real/` 的合成测试及清单，以及 `AGENTS.md`、兼容性页和发布说明。实际业务系统的接入仍由部署方配置。
- Circle 的通用工作流、子代理、工具与会话改动在独立仓库核对。工具执行结果由 Circle 传给工作流，Hub 继续通过 MCP 对接。

使用合成用例、脚本模型和临时回环 PostgreSQL 验证。实机、业务内容和部署凭据不进入提交。
