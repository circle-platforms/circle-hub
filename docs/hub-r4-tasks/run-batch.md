# 管理员批量开始运行（决定 156，issue #32）

来源：issue #32；所有者 2026-11-11：“管理员本来就有所有能力，同意啊”。基线 `origin/main` 812c52b2，分支 `feat/run-batch`。

## 问题

对一条产品线重新育苗后，新根里没有用例。用例只经“用例定位”运行的喂入进树，而定位只能由客户端一份一份地跑。issue 要三样东西：一条能批量跑的命令（带并发上限、限速、失败汇总），100 份文档大概多久，以及写明育苗之后哪些包会给“没有用例”的未知、下一步是什么。

## 做法

新命令，放在已有的 `run` 命令组里：

```
circle-hub run batch --pack <工作流> --slot <输入槽> --from <文件>
    [--product <产品>] [--version <版本线>] [--per-run <每次运行的对象数>]
    [--concurrency <1–8>] [--interval-ms <毫秒>] [--failed-out <文件>] [--json]
```

- 文件每行一个外部对象标识，空行和 `#` 开头的行跳过，重复的标识只开始一次，一次最多 5,000 个。
- 管理员本人是运行者，每次运行是一次普通的 `start_run`（和客户端调用走同一个运行服务），所以权限、读取、喂入、记录都和平时一样。必须用管理员的操作令牌。
- 开始之前先核对：工作流管理员用得了；它的全部要求项都是事实（开始时由 Hub 算出结果）；有这个输入槽；`--per-run` 大于 1 时这个槽接受多项。任何一条不满足就拒绝，一次运行也不开始。
- 同时进行的运行不超过 `--concurrency`（默认 2）；任意两次开始之间至少隔 `--interval-ms`（默认 0），不论并发多少。
- 一次运行没有开始（协议错误或异常）只算它自己失败，其余照常进行。最后汇总：对象数、运行数、得到结果的、没有开始的、按错误码的原因、总用时、平均每个对象的用时、按这个速度 100 个对象大约多久。有失败时退出码是 1。
- `--failed-out` 把没有开始的对象写成同样格式的清单（文件已存在时不覆盖）。`--json` 输出同一份汇总的 JSON。

代码：循环在 `hub/server/cli-run-batch.ts`（`objectsOf`、`startBatch`、`batchLines`），命令的参数、核对和输出在 `hub/server/cli.ts` 的 `runBatchCommand`。核心代码里没有任何产品名或包名。

## “100 份文档大概多久”

没有给一个固定数字：用时几乎全在业务系统的应答上，本仓库只能用合成数据。命令每次都按实测给出平均每个对象的用时和 100 个对象的估计，以它为准。没有在真实系统上量过。

## 文档

使用说明 `docs/hub-r4-guide.md` 的“用例定位”一节加了一条：重新育苗后新根里没有用例；读用例索引的包（质量看板、回归范围、维护巡检、模板缺口）在喂回之前给“没有用例”的未知，不是不通过；下一步是管理员执行上面的命令，并给出用例定位的具体参数。
