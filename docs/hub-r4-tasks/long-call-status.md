# Query long calls through the existing read tool

The simplification plan calls for a way to check a long `start_run` or `get_nodes` after a client timeout without blindly reissuing it. Reuse the existing six-tool surface and existing call logs. `get_nodes` may take an exact original call argument object for either tool. Match its canonical argument digest and authenticated user; keep only digest, trace and start time for requests currently handled in this Hub process. Return current-process in-flight traces and bounded matching completed log entries separately. A missing log or a server restart is not proof that a call failed or never arrived: name the missing fact and a next action.

When a completed start has a run the caller may currently read, return the original run and production-result record references. This permits the client to recover the stored result without opening a duplicate run. The caller can narrow by an observed trace; without it, or when even that trace matches several calls, the entries remain candidates rather than claiming to identify the timed-out call. A completed `get_nodes` response itself is not currently stored; say so and give the read-only re-read exit rather than inventing its content. This is a partial delivery of the long-operation goal: recovering the exact lost `get_nodes` answer without leaking a source after a later permission change remains open. The history of a real timeout is not reinterpreted.

Follow-up `long-read-recovery` adds bounded in-memory retention for future read responses, rechecked before disclosure. The limitations of expired, unsupported or unverifiable responses remain explicit.

Do not record raw arguments, source text or credentials in the in-flight index. Do not reveal other users' calls, and recheck run visibility at every query. If the recent log window or active list is truncated, say so. Concurrent identical requests remain distinct traces; do not conflate an older completion with an in-flight request. No additional MCP tool or external write is introduced.

Scope: `contracts/src/tools.ts`, model and generated tool contract; the public records digest export; `hub/server` call tracking, query, text and synthetic tests; this task page and simplification inventory. Contracts and records are wide under decision 80: regenerate and run typecheck, docs, the full synthetic unit and acceptance suites, and references using adaptive concurrency. No real systems or credentials.
