# 遮盖字典：读业务系统时替换（决定 159，issue #194 第二步，2026-11-12）

来源：所有者 2026-11-11：“最多在 Hub 上增加一个正则字典功能，管理员可配置，当匹配上后自动替换成 ai 能知道是密码或者密钥 *****，如果需要使用，从 circle 直接定制变量就行了”。2026-11-12 对“在哪里替换”选了“读入时替换”：Hub 读进来时就替换，只存替换后的内容，只对文本做。分支 `feat/masking-dictionary`，接在控制台审计项的分支之后。

#194 分三步。第一步（不再因为内容像凭据而扣留、拒收或送核看）已在主线（决定 154）。这是第二步。第三步（删掉不再使用的核看与接受流程）另做。

## 做了什么

管理员配置一组规则，每条规则有三样东西：

- **规则名**：小写字母、数字和连字符，例如 `device-password`。
- **标签**：给读的人和模型看的说法，例如“密码”“密钥”“设备口令”。
- **模式**：一个正则表达式。写了名为 `secret` 的分组时只替换这个分组，周围的文字保留。

Hub 经连接器读业务系统时，对每个文本应答先按字典替换，再做其余的事。命中的片段换成：

```
[密码已遮盖 *****]
```

例如规则 `password=(?<secret>\S+)`（标签“密码”）把 `登录 password=abc123 结束` 变成 `登录 password=[密码已遮盖 *****] 结束`。模型能看出这里原来是一个密码，但看不到值。

替换发生时，Hub **只保存替换后的内容**：

- 原文的摘要、大小、逐字引文的核对、系统包的函数、模型和控制台，用的都是替换后的这一份，前后一致。
- 被替换的值 Hub 不保存，也不进日志、动作记录和读清单。
- 原文记录上写明“遮盖”：用了哪一版字典、哪几条规则各替换了多少处。控制台的原文详情里多一行“遮盖：已替换 N 处”。

## 不替换的

| 内容 | 为什么 |
|---|---|
| 没有命中任何规则的应答 | 原样保存，记录和没有字典时完全相同 |
| 表格、压缩包、图片等二进制内容，以及按声明的字符集解不出来的字节 | 替换会破坏文件；字典只处理文本 |
| 登录应答 | 登录要用它带回的令牌 |
| 成员上传的文件、写进知识空间和记忆的文字、客户端同步的内容 | 这些内容的摘要由客户端和 Hub 两边核对，Hub 单方面替换会让两边对不上 |
| 运行参数、派发出去的内容 | 同上；它们也不是“读进来”的内容 |
| Hub 自己发出去的密钥被应答原样带回 | 仍按原来的规则只保留给管理员（B02 R[6]），没有动 |

也就是说，字典管的是“Hub 从业务系统读进来的文本”。成员自己上传或写入的内容里如果有密码，字典不会替换，这一点在设置页的说明里写明了。要扩大到上传内容，需要客户端配合（上传后以 Hub 返回的摘要为准），另议。

## 规则什么时候生效

- 规则改动之后读到的应答按新规则替换。**已经保存的内容不改写**：加规则不会回头替换旧内容，删规则也不会恢复已替换的内容（值本来就没有保存）。
- 同一个对象在规则改变后重新读取，会得到按新规则替换的另一份内容和另一条记录。
- 命令行改了规则，正在运行的 Hub 在 2 秒内用上新规则。

## 怎么管

命令行（只有管理员能用，每次改动要写理由）：

```sh
circle-hub mask list                                   # 现有规则
circle-hub mask test --pattern 'password=(?<secret>\S+)' --label 密码 --file 样本.txt   # 先在样本上试
circle-hub mask set device-password --label 密码 --pattern 'password=(?<secret>\S+)' --reason "设备口令不进知识"
circle-hub mask test --all --file 样本.txt             # 用现有全部规则试
circle-hub mask remove device-password --reason "规则写错了"
```

`mask test` 只打印替换后的行和各规则命中的次数，不打印被替换的值。模式里有引号、反斜杠不方便写在命令行上时，用 `--pattern-file` 从文件读。

控制台：设置页“凭据”页签下面多一块“遮盖字典”，列出现有规则、各自替换成什么、模式是什么；“添加规则…”“删除…”打开对话框，里面是要在运行 Hub 的服务器上执行的命令。页面本身不改字典。成员看不到这一块。

## 规则设置时的检查

规则在设置时检查，不合格的不生效：

- 模式能编译，不能匹配空文本（否则每两个字之间都会插进一个占位）。
- 模式在长文本上不失控。有些写法（例如 `(a+)+$`）碰到长文本会算不完。设置时先在逐步加长的文本上试，超过 50 毫秒就拒绝，一般一秒内出结果。这是防写错，不是证明；拿真实样本用 `mask test` 再看一遍用时。
- 标签里不能有引号、反斜杠、尖括号、方括号、`&` 和 `*`。占位会写进 JSON、XML、HTML 等各种格式的文本，这些字符在那些格式里有含义。
- 最多 64 条规则，模式最长 500 个字符。

多条规则同时命中时：每条规则都对读到的原文匹配，不会去匹配别的规则换上的占位；两处重叠时取先开始的那一处。

## 存在哪里

字典是一份按内容寻址的定义（`masking-dictionary@1`），由一条资源配置决定生效，和资源、变量的做法一样。每次改动是一份新的定义和一条新的决定，历史就是决定的链。没有加新的表、记录种类、许可种类或协议码。原文记录多一个可选字段 `masking`，只有被替换过的应答才有。
