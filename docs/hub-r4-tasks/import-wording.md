# B6：团队知识导入页区分通用说明与产品来源说明（#238）

来源：所有者全量计划 #238/#199；基线 aded2ffd，`fix/import-wording`。

## 允许路径

- `hub/server/console/operations.ts`
- `hub/server/console-import-wording.test.ts`
- 本任务页、`CHANGELOG.md`

## 决定

“导入团队知识”页的第一张卡片需要选产品，却用泛称标题，说明里写“在后台只读导入构建、手册与命令树”，非该业务的用户会以为所有导入都要这些材料。只改这一张卡片的两句文字：

- 标题改为“按产品来源导入”，说明改为“从已启用产品包声明的来源，在后台只读导入团队知识，每条附来源；Hub 重启时需重新发起，已导入的内容保留。”（只去掉对材料种类的假设，其余原样）。
- “产品”字段的提示改为“已启用的产品知识来源；具体包含哪些材料（例如构建、手册、命令树）由该产品包声明”，产品专用内容仍在，只是说明来源是产品包声明的。
- 并列的“按团队读取原文导入”（无须产品包）不动；页面名和导航里的“导入团队知识”不动；“产品”“版本线”两个字段本身属于产品专用流程，保留。

## 验收

- 页面含新标题、新说明、产品字段的新提示和并列的无须产品包的卡片；旧句“在后台只读导入构建、手册与命令树”不再出现；整页过文案守卫（`wordingProblems`）。该测试在改动前失败（已实证）。

## 不做

按所选产品动态展示其构建、手册和命令树说明（议题的第二个建议）：需要界面脚本按产品切换，另做。
