# B1：判断任务是否可见时不读整段历史

来源：所有者全量计划 #200/#195/#199；基线 aded2ffd，`fix/run-visibility-probe`。与 #251、#256、#266 互相独立，也不代替它们。

## 决定

控制台实时流对每个任务事件、每个订阅账号，用 `getRun(...) !== null` 判断“这个账号能否看见该任务”。`getRun` 为此读取该任务的全部提交、全部结果正文、请求和撤回状态，只为得到一个布尔值。新增可选的内部端口 `runVisible`，只做 `getRun` 开头的同一项检查（`visibleRun`：账号可用、可查看该运行、运行依据可读），不读历史。缺该端口的引擎仍走原来的 `getRun` 回退。端口自己不保留结论（实时流原有的 30 秒缓存不变），所以撤销分享在下一次询问时就生效。

不改 MCP 六个工具、外部 schema、生成协议、迁移、配置或包版本；不改权限、完整性核验、详情页、导出或摘要读取。

## 验收

- 引擎：24 条各 64 KiB 的历史结果加 1 条生产结果；对照 `getRun` 在此基线上实测加载 50 条结果正文（全量列举 25 条，再为找最新已受理结果重读同样 25 条），测试只断言不少于 24 条，不绑定内部读法；`runVisible` 加载 0 条。
- 与 `getRun` 的结论逐一相等：所有者、管理员、未分享的成员（不可见）、分享后（可见）、撤销分享后（不可见）、不存在的运行（不可见）。
- 控制台：端口存在时 `visibleTo` 不碰 `getRun`（桩在被调用时抛错）；端口不存在时原有回退测试照旧。
