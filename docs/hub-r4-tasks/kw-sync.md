## 要做到的（验收标准）

1. **同步接口**：
   - 用专门的 HTTP 接口（例如 `/api/sync/...`）。Circle 用同一个成员令牌认证，包括经 MCP 标准授权取得的令牌和访问令牌。
   - 不新增 MCP 工具：MCP 仍是六个工具，模型看不到同步接口，也不能在任务中借它绕过“按地址读取”。
   - 接口和样例写进合约。
2. **同步范围**：
   - 调用者本人的个人空间：知识条目、原文、文件夹，以及个人记忆。
   - 个人工作流和通用技能本阶段只同步“清单与版本”，安装仍走现有流程。
   - 他人分享给本人的内容和团队内容不走同步，用现有读取接口。
   - 团队记忆只读加载，走 `get_nodes.memory` 的会话模式。
3. **同步语义**：
   - 内容寻址：列出对方缺少的对象，分批上传、下载，并校验哈希。
   - “当前版本”的移动用比较并交换。已被别的客户端推进时拒绝，并返回最新状态，由客户端合并后重试。
   - 合并：两边都有新版本时两者都保留。同一条知识或同一篇记忆被两边分别修改时，标为“有冲突”，不按“后写覆盖”取舍。本人选定其中一个，算一次新的修改。
   - 每次同步写入记录：谁、哪台客户端、补齐了多少对象、版本从哪到哪。
4. **核验**：
   - 上传的知识条目由 Hub 重新核对引文与路径，不采信客户端的“本机已验证”。核对不一致的条目记为“待验证”，并告知客户端。
   - 上传的记忆按记忆的规则做凭据扫描与大小检查，沿用 #132 的限额。
5. **同步方式**：
   - 同步方式（仅保存在本机、同步到 Hub）由本人设置，Hub 记住它，并在个人空间和团队页的成员详情中显示“同步方式”和“上次同步”。
   - 从“同步到 Hub”切回“仅保存在本机”时，Hub 清除本人个人空间的内容（知识与记忆），记录只留哈希，相关分享随之失效。页面提示本机副本不受影响。
6. **容量与限流**：同步写入计入个人空间容量（默认每人 1 GiB）；单次请求与批量大小有上限，超出时给出明确的拒收码。
7. **规范形式**：哈希前的规范形式写进合约：换行统一为 LF、去掉 BOM、Unicode NFC。两边用同一组样例核对，避免 macOS 与 Windows 上算出不同的哈希。
8. **测试**：
   - 两个客户端交替离线修改、合并与冲突、并发写入时的版本竞争、断点续传、哈希不符；
   - 读写他人空间时，回应与对象不存在相同；
   - 切回“仅保存在本机”后内容被清除，以及容量超限；
   - 记忆的同步、冲突和凭据拒收；
   - 给 Circle 端用的共享测试样例：合成的知识、记忆、对象与期望的同步结果，放进合约测试目录。

## 不在本任务

### 2. HTTP 接口与身份

统一前缀暂定 `/api/sync/v1`，请求与答复均有独立的版本化合约；不把它们并入六工具的输入 Schema、工具列表或模型提示。结构和错误码先登记合约，再生成运行时类型。路径中的会话与操作 ID 都是有界的不透明标识。

| 方法与相对路径 | 输入与输出 |
| --- | --- |
| `GET /state` | 返回本人的同步方式、清除状态、当前状态标识、同步快照、容量、实际批量限制及上次成功同步时间；空空间不因读取而创建正文 |
| `POST /clients` | 幂等登记本人客户端的随机 ID 与受限显示名称；返回服务器绑定的客户端标识 |
| `POST /sessions` | 输入客户端、已知状态及基准快照，建立有期限的续传会话，冻结下载清单；返回当前状态、清单游标和限制 |
| `GET /sessions/{id}/inventory?cursor=…` | 按冻结快照分页列出本人对象的 ID、类型、大小与关系；游标绑定本人、客户端、空间代次和快照 |
| `POST /sessions/{id}/missing` | 分批提交本机对象 ID，返回 Hub 在本人当前代次中尚未拥有的 ID；不能探测全库是否已有相同字节 |
| `POST /sessions/{id}/upload` | 输入操作幂等键及对象批次，检查结构、大小、摘要和凭据；整批接受或整批拒收，返回已接受对象及续传进度 |
| `POST /sessions/{id}/download` | 输入对象 ID 批次，按大小上限返回本人对象；不接受来源 URL、本机路径或任意 `rec:` 读取请求 |
| `POST /sessions/{id}/commit` | 输入操作幂等键、期望状态、共同基准与候选快照，重新核验后比较并交换；返回当前状态及有界的核验结果／冲突分页入口 |
| `GET /operations/{id}` | 取本人某次批次／提交／切换的安全回执，解决提交成功但应答丢失；不知道或不属于本人时统一不可用 |
| `POST /sessions/{id}/abort` | 结束本人续传会话，释放只属于它的暂存引用；不删除其他会话或当前版本使用的对象 |
| `POST /mode/check` | 本人查看切换影响：个人内容量、将失效的授权及共享数量、本机副本不受影响；不写入或清除内容 |
| `POST /mode` | 输入目标方式、期望状态、操作幂等键及明确的清除确认；切换方式并返回结果，清除未完成时据实返回进度 |

- 每个请求使用现有成员 Bearer 令牌验证，兼容现有 OAuth 取得的令牌与直接访问令牌；复用当前撤销、到期、停用检查，不另建一套账户。控制台仍只用用户名和口令登录；同步接口不接受控制台 Cookie、设置码或控制台会话令牌。需要的令牌种类／客户端信息通过 records 的认证端口取得，不在路由复制鉴权 SQL。
- 所有空间都从当前账户推导，不提供可写的 `owner`／`space` 参数。管理员同样只能同步自己；猜到他人的对象、会话、操作或快照，状态码和正文与该路由中的不存在情形相同。直接取对象／会话等统一为中性的 404／`SOURCE_UNAVAILABLE`，候选图的依赖缺失也不能区分未上传与他人持有。身份无效统一 401，在检查内容和解码大正文前拒绝。
- 客户端 ID 是账户内的设备标识，不能代替身份；OAuth 客户端等由服务器确认，设备名称与随机 ID 是客户端声明，两者在审计中区分。用新客户端 ID 或换令牌不能绕过按账户累计的限流。
- 沿用服务器的 Host、Origin、TLS、请求总量与关闭约束；不新开监听、不开放 CORS。请求和答复使用 `Cache-Control: no-store`，日志不记令牌、对象正文、标题、目录或引文。API 不在 MCP 中暴露，不提供在任务里调用同步路由的代理工具。

### 3. 对象、稳定身份与快照

不拿现有记录摘要充当跨客户端可改对象的稳定 ID。每个目录、知识条目、原文和记忆文档有稳定的随机 `item_id`；一次修改生成不可变修订对象，包含本项 ID、父修订及内容。重命名、移动和修改沿用同一个 ID；同一文本的两个独立对象仍可有不同身份。既有对象导出时由持久映射分配 ID，不能每次导出重编号。

拟在 `contracts/src/sync.ts` 定义封闭对象族，由合约生成对象种类：

| 对象 | 内容与边界 |
| --- | --- |
| 原文字节块与原文清单 | 大文件按不超过 1 MiB 的块切分；清单保留顺序、总字节数、媒体类型、原始字节摘要和文件元数据。整体仍受现有原文大小限制，分块不能绕过它 |
| 知识修订 | 现有条目内容、目录 ID、依据与逐字引文、父修订；客户端的核验标记不产生任何资格 |
| 目录修订 | 名称、父目录 ID 与父修订；根目录唯一，拒绝环、越界与名称归一化后的同级重名；空目录也同步 |
| 记忆修订 | 标题、目录、Markdown、启停及父修订；与知识条目分开，不产生输入或依据引用 |
| 包清单对象 | 已有 `pack.json` 的清单／版本信息及其摘要，区分本人已有安装与仅有清单；不含代码、不把“持有清单”当作已发布或可运行 |
| 清单页与快照 | 按类型和稳定 ID 排序的对象头列表，单项可有多个冲突头；分成有界页，以根清单引用各页，不把整个空间装进一个记录或 HTTP 正文 |

协议结构拟固定为以下字段；这里是待审结构约定，实际正反样例在合约提交时给出可运行的完整值：

- 对象封套：`{schema: "personal-sync-object@1", kind, body}`。修订对象的 `body` 含 `{item_id, parents, directory_id, content}`，目录等按具体类型使用严格 Schema；原文字节块的 `body` 为 `{bytes_base64}`。对象 ID 为该类型封套的规范 UTF-8 字节的 SHA-256，传输描述符为 `{id, kind, bytes}`。
- 物品索引行：`{kind, item_id, heads}`；快照含排序后的清单页引用及父快照，页不能重复拥有同一物品。实体修订祖先图与快照祖先图分别校验，不能把前者的摘要当作后者。
- 上传批次：`{schema: "personal-sync-upload@1", epoch, operation_id, objects: [{id, bytes_base64}]}`；服务器严格解码并解析每个对象封套，描述的类型和大小必须与实际一致。回执含批次请求摘要、接受／已有的 ID、计量与下一步，不保存原始请求副本。
- 提交：`{schema: "personal-sync-commit@1", epoch, operation_id, expected_state, base_snapshot, snapshot}`。成功回执含新状态、知识与记忆投影的内部映射、核验／冲突计数及分页游标；失配回执含本人最新状态，不能自动把 `expected_state` 换成它再执行。
- Hub 核验观察另存 `{object, rule_version, scanner, parser_lock, status, codes, checked_at}`，不嵌回客户端对象改变其 ID；具体代码与资格来自生成合约。上次成功同步仅在 `commit` 成功后更新，上传、探测、冲突拒收或部分失败不更新该时间。

删除、移动与冲突解决也生成修订。删除必须有明确的删除修订和父版本；缺少清单项不能解释成删除，上传半份清单不能静默丢掉其他客户端的内容。目录被一侧删除、另一侧增加子项，或移动后产生同级重名，作为冲突保留，不任意改名或删除后者。

每次从“仅保存在本机”开启“同步到 Hub”有新的不透明 `epoch`（空间代次）；保持原方式或成功续传不另建代次。所有会话、拥有关系、当前头、客户端操作与游标都绑定账户和该代次；它不是用户界面概念。对象 ID 相同不代表有读取权，不能凭一个已知摘要认领他人的对象。新代次不能自动恢复旧代次授权、旧令牌之外的权限或清除前的个人数据；本人明确选择重新同步后，可重新上传本机副本作为新代次的初始内容。

### 4. 批次、续传与原子提交

1. 客户端读取状态并建立会话，分页取得冻结清单，将本机与远端清单比较；调用 `missing` 补齐 Hub 缺少的对象，用 `download` 获取本机缺少的对象。只在本人的当前代次查拥有关系，不给出全库命中、其他作者或去重节省量。
2. 每批有 `operation_id`，相同操作和相同请求重放返回同一回执；同键异载荷返回既有 `IDEMPOTENCY_MISMATCH`。一个对象在同账户／代次被多次接收只计一次；一批里有摘要不符、重复 ID 携带不同内容或超限时，整批不登记。流中断的临时文件不算已接受对象，已经确认的其他批次可继续使用。
3. 上传只进入本人暂存区，尚不能被 MCP、搜索、记忆会话或授权者读取。先检查再登记，失败不把疑似凭据落成原件；临时写入、落盘、数据库登记各有故障恢复测试。哈希检查用于本任务明确要求的同步对象身份，不给无关正文另加校验流程。
4. `commit` 检查候选对象图齐全、类型匹配、无环及大小有界，继而重验知识与记忆。持本人空间锁，重新检查账户、代次、方式、容量、依赖读权和期望状态，在同一事务更新知识、记忆、目录／包清单投影和同步头；不能逐条调用会各自推进当前版本的现有写接口，造成部分成功。
5. 文件须先完成原子落盘，事务才可引用；事务失败留下的是不可见、已计暂存额度的对象，之后可续用或清理。没有成功提交的批次不改当前版本。成功后即使网络应答丢失，也能从操作回执确定结果，不猜测远端是否成功。
6. 续传会话默认 24 小时过期，返回确切到期时间。暂存对象在仍被任何活会话或已提交历史引用时不清理；放弃／过期后只回收无引用的暂存数据。过期会话拒绝继续提交，客户端保留本机修订并重建会话，不声称未提交数据永久保存。

### 5. 比较并交换、三方合并与冲突

`GET /state` 的 `state_version` 覆盖当前同步快照、知识当前版本、记忆各当前头、包清单、代次与同步方式；不含上次同步时间或心跳，避免同步本身制造无穷变化。现有控制台、MCP、共享引起的本人内容写入也要在同一空间事务更新这个状态，不能只有 HTTP 同步写入参与竞争。

提交必须同时带 `epoch`、`expected_state` 和 `base_snapshot`。基准只能是本人当前代次曾确认的快照；不接受他人根或任意记录作为共同祖先。Hub 比较并交换失败时返回 409、最新状态及清单入口，不移动头、不丢弃客户端已确认暂存的修订，也不自动重试并覆盖；客户端取得新状态后合并再提交。

两边共用确定性的三方合并规则，Hub 再检查候选是否合法：

- 只有一侧改动的对象取改动后的修订；不同对象的改动取并集；修订完全相同则合为一项。
- 同一稳定 ID 被两边分别修改，即使看似修改了不同字段，也保留两条头并生成“有冲突”的派生标记；删除对修改、目录位置竞争同理。不使用客户端时钟或到达顺序挑选正文，不做语义合并。
- 客户端不能把一个竞争头从候选快照中省略。新修订必须接续对应当前头；解决冲突时把全部竞争头列为父项，并明确选择内容或提交本人编辑后的内容，形成一次新修改。输掉的修订仍在历史里，不能伪装成已经合并。
- 冲突与引文核验是两个维度：各修订独立保留核验结果，冲突对象没有默认选中的正文。当前知识搜索／输入默认不使用未解决的对象；本人可显式查看历史，旧运行锁定的合法版本不因新冲突改写。记忆的冲突对象不自动加载，专用答复明确带冲突数量和对象，不能静默漏载；团队记忆的只读会话入口不变。
- 同步冲突不消耗运行模型修复次数，也不使用模型选版本。服务端计算冲突，不信任客户端传来的 `conflicted:false`。

### 6. 核验、来源与读取资格

沿用现有条目种类、内容和引用 Schema；每个知识修订都检查目录能否解析、依据当前是否对本人可读、解析器资格、片段位置及逐字引文。不能从客户端的 `verified`、旧回执或对象摘要推出已核验；解析器包只有清单而未安装时，同样不能声称核验完成。不得借核验自动抓取业务系统、导入命名文档或执行客户端脚本。

引文缺失／不一致等可修复情况保留为本人私有的未核验修订，返回有界的原因码与位置，不写成已核验或成功证明。存储状态沿用 `knowledge_entry_status.unverified`（现显示“未核验”，对应任务要求的“待验证”），不另造一个能绕过共享检查的资格。临时 I/O 故障与确定的不一致区分，前者写检查未完成；可以重交相同内容做新检查，但追加新的核验观察，不改旧对象。

只有在所有必需检查完成后才允许当前投影使用核验结果。依据、路径与正文在清单中缺失，或者仍有冲突时，不能成为新的已核验当前条目；共享与运行仍做自己的边界检查。对不可读的他人引用与不存在的引用保持同形，不在核验结果中透露另一成员是否持有某份原文。

记忆复用当前凭据检测、单篇 24,000 字节、每空间标题＋目录＋正文 48,000 字节及 20 篇的默认限额；拒收不保存正文，历史计入个人容量。冲突文档占一个逻辑篇数，当前额度按候选中最大的上下文字节预留，所有候选均计历史容量，不能靠冲突绕过限制；解决时持锁再查。记忆始终不作运行输入、依据或核验结果。

同步传输不改变原件的 `read_tier`、采集作者、个人凭据来源资格或上传声明。可同步的本人原件按原有上传安全规则处理，不能把只保留资料标成模型可读，也不能因在本机持有清单而取得团队解析器或外部来源资格。后续提交共享仍要求团队可用解析器与来源资格。

### 7. 规范形式与原文保真

新增版本化的同步编码规则，复用 records 的规范 JSON 编码实现；不修改现有 `canonicalize` 的全局含义，不重算已有 `src:`、条目、树根或记录摘要。

- 同步对象带类型与 Schema 标识，类型进入其摘要，避免相同载荷被另一对象种类解释。普通文本字段先严格解码 UTF-8，拒绝非法字节和孤立代理项；去掉文本开头的 BOM，把 CRLF 与单独 CR 变成 LF，再做 NFC。保留其他空白、行末空格、大小写与末尾换行，不做 NFKC 或语义修订。
- 结构对象递归使用合约声明的文本规则，再输出既有规范 JSON 的 UTF-8 字节；键顺序使用规范编码顺序，不依赖语言地区排序。重复键、归一化后碰撞的键或目录名直接拒收；非有限数、未声明字段及不符合 Schema 的输入拒收。只有合约声明为集合的数组排序，段落、步骤、文件块等有序数组不改顺序。
- **原文及逐字引文是保真字节，不做上述文本改写。** 原文字节与引文以规范 base64 的字节对象引用进入同步结构；原文仍另存原始字节摘要，片段在该原件上核对。带 CRLF、BOM 或分解形式字符的原文不能为了同步而被悄悄改成另一份证据；普通 Markdown 记忆等可编辑文本才采用 LF／NFC。
- 因此“同步对象 ID”与“原始来源摘要”是两个有明确类型的字段，不能相互替代。客户端必须上传规范对象字节，Hub 重算并比较；不一边接受非规范字节一边猜测客户端哈希。先返回规范形式／摘要拒收，客户端用共享样例修正后重试。
- 对象内容摘要不含服务端接收时间、令牌、设备显示名或 Hub 核验结果；这些进入旁边的观察／回执。客户端编辑的父修订、对象 ID 与目录关系属于对象内容，必须入摘要。

第 3 条是为同时满足 B02 原文保真与本任务规范形式提出的明确边界，需在本次协议审查确认，不把“所有原文字节也统一换行”当作安全的默认实现。

### 8. 同步方式、清除与恢复边界

方式拟登记 `local`／`hub`，界面标签分别为“仅保存在本机”／“同步到 Hub”。本人选择方式，管理员无代改入口；团队页成员详情只显示方式和上次成功同步，不因此看到个人对象、冲突正文、目录、设备秘密或同步明细。个人页可展示本人同步结果，内部状态标识不进入界面。旧账户初始上次同步时间为未知，显示“—”，不能把控制台写入时间冒充成功同步。

建议迁移时，有既有个人知识／记忆／目录或其授权的账户保持 Hub 保存，标为 `hub`，避免无提示清空；其他空账户（含新账户）默认 `local`。`local` 下 Hub 不再接受个人知识／记忆的同步、控制台或 MCP 写入，也不允许新增它们的目录授权；仍可使用团队内容、提交独立团队操作。现有个人包的发布／安装／授权不属于本次知识与记忆清除，不借开关删除其独立注册记录；其依赖私人内容时照常重查可读性。既有测试夹具需要通过本人选择方式的测试入口显式启用 Hub，不能把旧业务期待批量改成拒收。

`local → hub` 建立新代次，初次上传仍走完整核验与容量检查，不自动重新打开旧授权。`hub → local` 按以下顺序进行：

1. 本人查询影响；提交时带预检的期望状态与清除确认。数据已变化则拒绝并返回新影响，不替本人删除新增资料。
2. 在本人空间锁内变更方式与代次，追加清除意图，立即拒绝旧代次的上传、提交、下载和所有授权读取；所有旧客户端、控制台、MCP、历史 `tree:`／`src:`／`rec:`、原始提交与缓存读取均须经过同一代次守卫，不只是隐藏当前列表。
3. 个人知识与个人记忆的目录授权失效；旧授权记录保留作摘要审计，重新启用后不能重放旧授权。相关共享按来源关系追加失效／撤回状态，不能继续通过旧共享回执或依据读取已清除的私人内容；独立团队副本的边界见第 12 节。
4. 清除该代次个人内容的可读载荷、全部历史候选、暂存对象、解析／搜索／记忆投影和进程缓存，释放个人逻辑容量。操作不是停用记忆或建立空目录快照；当前服务器不得仍以旧记录正文或对象路径返还被清除内容。
5. 清除任务可崩溃恢复；事务提交后才执行不可逆的载荷清理，恢复时只能继续清理，不能自动退回旧代次。未完成返回 202 和“等待清除中”，完成后才给出完成回执与上次同步状态。重复同一切换操作不再清除新代次的数据，清理失败如实保留未完成状态。

本机副本不受影响，Hub 不发送删除本机文件的命令。旧客户端恢复联网先看到方式／代次变化，不能把清除前的本机快照自动传回；本人重新选择 `hub` 后才能初始化新代次。已发送给客户端的字节无法追回，进行中的分批响应在失效后停止交付后续批次。

**载荷存储建议**：新增按账户／代次隔离、可清除的个人载荷存储，由 records 提供专用端口。知识正文、目录名称、原文、引文、记忆、同步清单副本及客户端私有元数据均放在该域；审计记录只保存内容摘要、操作者、时间、客户端标识、数量和结果码，不能把正文再复制进拒收说明。载荷采用代次密钥加密并有原子落盘／回收，密钥不进入审计或同步协议。清除时停止访问并移除该域的密钥和载荷，不删除别人的、团队独立持有的或普通运行独立持有的同字节对象。

不能直接复用全局永不删除的 `FileObjectStore` 保存可清除私人正文，也不能只依赖移走“当前版本”。当前旧条目、目录快照及记忆在不可变记录中内联正文，必须解决旧载荷迁移，详见第 12 节；否则不能验收“记录只留哈希”。新增私有域同时纳入备份／恢复／权限测试，不能默默从备份漏掉仍在同步的个人资料；历史备份和已经独立成立的团队副本不承诺远程擦除，界面写明实际边界。

### 9. 容量、限流与错误

个人总额继续默认每人 1 GiB，沿用管理员容量设置。已提交对象、所有历史／冲突候选、暂存对象与记忆共用一份账户计量；同代次内同一对象只登记一次，暂存转提交只转用途，不重复收费。原文按实际字节计，不按 base64 膨胀后的 HTTP 长度计；快照页、目录和清单元数据也计量。旧记录已有历史用量须保留并对迁移结果核对，不能借导出／导入重置已使用额度。

暂拟默认限制如下，协议状态接口返回部署实际值：

| 项目 | 建议默认值 |
| --- | --- |
| 单个规范结构对象 | 8 MiB，另受现有条目、记忆和记录结构上限约束 |
| 原文字节块 | 1 MiB；整件原文仍受现有上传上限约束 |
| 每批对象数／解码字节 | 64 个／8 MiB，先达到者停止 |
| 每页清单 | 至多 500 项，并受正文预算约束 |
| 同账户请求频率 | 每分钟 120 次，读写共计；至多 2 个同步写请求同时核验 |
| 续传会话期限 | 24 小时；未提交对象仍占个人容量 |

HTTP wire 大小另外按 base64 膨胀与信封开销计算，且不超过服务器现有 `maxRequestBytes` 和全局在途预算；不能只约束解码后的大小。限制较小的部署协商更小对象／批次，不能返回无法实际接收的上限。容量预留、接收与提交都持同一个人空间锁，两个客户端不能各自通过后合计越限。

拟新增且同时登记到 `hub/platform/environment.ts` 的变量：`CIRCLE_HUB_SYNC_MAX_OBJECT_BYTES`、`CIRCLE_HUB_SYNC_MAX_BATCH_BYTES`、`CIRCLE_HUB_SYNC_MAX_BATCH_OBJECTS`、`CIRCLE_HUB_SYNC_REQUESTS_PER_MINUTE`、`CIRCLE_HUB_SYNC_SESSION_TTL_SECONDS`。其他大小由上述值和已有上限推导，不为每个内部常量增加配置。所有上下界与相互关系在 config 中检查，不使用退役的环境变量名。

复用 `SOURCE_UNAVAILABLE`、`IDEMPOTENCY_MISMATCH`、个人容量、凭据及记忆已有拒收码。拟登记 `SYNC_VERSION_CONFLICT`、`SYNC_OBJECT_HASH_MISMATCH`、`SYNC_OBJECT_INVALID`、`SYNC_OBJECT_MISSING`、`SYNC_BATCH_LIMIT`、`SYNC_SESSION_EXPIRED`、`SYNC_MODE_LOCAL`、`SYNC_EPOCH_CHANGED`、`SYNC_RATE_LIMITED`；最终以合约负责人审阅的代码为准，不在代码里先手写临时枚举。HTTP 分别使用 409（状态／代次竞争）、413（请求／批量大小）、422（本人对象结构／身份问题）、429（限流并带重试时间）；404 不能细分“他人拥有”与“没有对象”。

### 10. 合约、审计、迁移与界面

- 模型在当前 24 基础上顺延，覆盖 K01 的个人同步／冲突／清除边界、B02 的原文保真、R02 的本人同步权限及 D06 的六工具不变。新增 `sync_mode`、同步进度／冲突的显示轴及对象／操作封闭类型，全部由生成物提供；“同步方式”“有冲突”“上次同步”“等待同步中”“等待清除中”等标签经模型生成，不能在控制台另造词。内部 CAS、摘要和代次只出现在协议与开发文档。
- 拟新增同步方式变更、提交、传输回执与清除记录，动作复用已登记的写入／校验种类；如需新种类在审查时登记，不假借真实业务读取。每次同步记录本人、服务器确认的客户端与声明设备、起止时间、上传／下载／已存在对象数及字节、旧／新状态、结果和拒收码。审计不含对象正文、标题、路径、引文或自由客户端说明。本人看自己的明细，管理员只经已批准的成员详情看方式／时间，不获个人同步内容的隐含读权。
- 新迁移从当前 13 后追加，保存代次控制、快照头、本人对象拥有／用途、暂存会话／幂等回执、冲突和容量投影；不可变证据记录与可更新投影分开。新锁使用命名的双键命名空间，优先复用现有本人空间锁，不在持锁前后反向取得团队锁。
- 每个新运行表同步 `RUNTIME_GRANTS` 与 ownership 的 `COLUMN`，更新重建／旧库升级测试。旧迁移 SQL 逐字不动，复核新增 SQL 后才更新 `migrations.snapshot.test.ts` 的整源摘要；密码测试继续取 `MIGRATIONS.slice(7)`，不钉迁移数。
- 通过生成器同步必需协议文件；依前期同类授权，只同步四个通用技能的协议镜像／清单及必要补丁版本，不改业务代码，测试从 `repositorySkillVersion` 取版本。HTTP 同步 Schema 与模型工具 Schema 分开，不把路由加入通用技能给模型的使用说明。
- 页面只接入方式设置、本人冲突事实、成员详情两个字段及清除结果，保持现有布局；新的控制台设计系统不在本任务实现。README／CHANGELOG／决定 89 在真实实现后同步更新，说明实际完成与 Circle 客户端尚未实现的边界。

### 11. 共享样例、实施提交与验证

共享样例拟放 `contracts/test-fixtures/sync/v1/`，以纯 JSON、UTF-8 文本及明确的 base64 字节表示，附 Schema／编码版本和确定的预期字节、对象 ID、缺失清单、合并结果、拒收码。夹具无时钟、随机值、数据库 ID 或客户端私有配置依赖；稳定 ID、设备和时间均为合成常量。两边跑同一份数据，不让 Circle 依赖 Hub 数据库、服务器模块或业务代码。

样例至少覆盖：LF／CRLF／CR、头部 BOM、组合与分解 Unicode、中文／emoji、内部 BOM 与尾随空白保留；键顺序、重复键及 NFC 碰撞拒收；带 BOM／CRLF 的原文和引文保真；跨块原文、空文件、摘要不符；两台客户端各自修改不同对象、同项竞争、删除对修改、目录移动、冲突选择；CAS 失败与重试、重复批次、丢应答与续传；原文缺失／错引文的未核验；记忆冲突、篇数／上下文字节限制及编码凭据拒收。另以服务测试覆盖他人同字节对象、跨账户／代次访问、停用／令牌撤销、暂存耗尽容量和切换后旧端重放，不把完整性样例当成权限证明。
