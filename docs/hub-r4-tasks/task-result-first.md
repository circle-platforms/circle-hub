来源：所有者全量计划 #218/#199，B5 已批准的共用方向（结果、未决项在前，过程在后，不减少证据）；基线 aded2ffd，`fix/task-result-first`。

- `hub/server/console/{pages.ts,testing-task-result-browser.ts}`

## 决定

任务页原来的主区以“执行过程”（统计、时间线、耗时图）开场，任务结果只在右侧检查栏，结果分类清单在完整记录最深处。改为：

- 主区第一块是“任务结果”：结果状态、未决数、回执与结果分类计数（与完整记录里同一句，由同一个函数 `resultHeadline` 生成，不会两处不一致）、“查看结果分类与完整记录”入口（锚点到完整记录）。没有校验结果时写明原因，没有就不画。
- 等待回应中的请求（谁、做什么、期限）从完整记录深处移到结果块正下方；不在页面别处重复。
- “执行过程”保留为紧随其后的独立区域，完整记录各节一节不少，没有新增数据、查询或权限判断。
- 窄屏默认视图仍是检查栏（头部已带结果状态），“查看完整记录”后主区里结果块依然最前，无需改布局。

“管理员调试视图”这类开关不新增：证据一项没少，不需要。

## 验收

- HTTP：页面含结果块，位于时间线与“执行过程”之前；入口在结果块里且在时间线之前；证据节仍是一节；该断言在改动前失败（已实证）。
- 浏览器（隔离 Chromium、合成数据）：1440、1180、1024、760、390 五个宽度 × 默认与完整记录视图 × 浅深主题共 20 个捕获；有主区的视图里结果块一律在时间线之上且在首屏（y<400）；没有主区的窄屏默认视图里检查栏可见并带结果状态；无横向溢出，无页面脚本错误。看了其中两张（1440 浅色默认、390 深色完整记录）。
