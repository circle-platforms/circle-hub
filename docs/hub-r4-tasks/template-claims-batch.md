# Prepare template category claims in batches

The simplification plan records a remaining T1-3 friction: each `CategoryJudgment` requires the same explicit producer object even after a model identity was declared once. Keep the published claim shape and every Hub check unchanged. Add a local template-gap tool that takes one explicitly declared model identity, the existing mindmap-format quotation-locator output, and the model's explicit category and quotation selections, and constructs a `slots.coverage` list mechanically. It never chooses a category, quotation or identity; ambiguous quotations require an explicit index. Categories are exact ids from the pack's declared table. Unknown or invalid input produces no output file and no source text is printed.

The tool is local preparation only: the Hub still checks the source, quotation, case ownership and category, and the model's semantic judgment remains labeled as such. Existing locked pack versions and raw submissions remain unchanged. A new tool may prepare the old required claim shape for an old run. Increment template-gap's patch version and regenerate its manifest with its own `api.ts sign`; update the pinned version in the pack test without changing the assertion's meaning. Use synthetic tests and the adaptive affected-test workflow. No deployment, public push, real systems, credentials or business data.

Scope: `packs/workflow/template-gap/tools`, `SKILL.md`, `README.md`, `pack.json`, the version pins in pack tests and synthetic test support, tests of the new tool, this page and the simplification inventory.
