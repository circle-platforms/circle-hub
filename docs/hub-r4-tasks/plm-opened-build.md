# 任务：缺陷读法带出发现构建的名字

依据：所有者，2026-11-01，"确认plm返回数据是否有版本 如果有包不返回是包问题 如果是返回了模型不用是llm问题不管"。

核对结果：PLM 的缺陷详情给出 `openedBuild`（构建编号），没有构建名；构建名在该产品的构建列表里，可整个列表因为个别构建记录带疑似凭据，被凭据扫描整份扣下，调用方只看到"对你不可用"。数据里有版本而包没有带出来，按所有者的标准是包的问题。

- 分支和工作树：`plm-opened-build`（从 hub-redesign 开出）
- 可以改的路径：`packs/system/plm/**`（升 1.3.7）及其测试。
- 规则：真实系统只读；新路由按编号读一条构建记录，路径参数只能是数字。

## 要做的

1. 只读路由 `GET /plmquery/build/{id}/`（10-12 只读探测记下的构建详情接口）。
2. `plm:bug:<编号>` 读完详情后按 openedBuild 读那一条构建记录，content 加 `opened_build: {id, name}`；读不到名字写明原因，缺陷照常读出。
3. 发布后用管理员读取观察一次，确认单条构建记录能读、名字在哪个字段。

## 上线后补充（plm 1.3.8）

1.3.7 在生产上读缺陷时，开出构建那条单条构建记录的应答声明了约 2.4 MB，超过 `build-detail` 原定的 1 MiB 上限，读取按规则拒绝且不截断保存，`opened_build.name` 为 null 并写明了原因。上限改成和缺陷详情、需求详情、构建列表一样的 16 MiB，plm 升 1.3.8；其余不变。
