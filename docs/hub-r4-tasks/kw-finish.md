## 要做到的（验收标准）

1. **上传文件署名**（改写决定 62 中“上传不作团队根据”）：
   - 上传的文件进个人空间，按本人授权可见。
   - 引用它的知识分享到团队时，由上传人署名，来源类型记为“声明”，团队知识上显示署名人。
   - 没有署名的仍拒收（第三阶段的拒收码改为提示“需上传人署名”）。
2. **原文归档**：
   - 控制台上标着“规划中”的原文归档改为可用：原文（网页快照、文件、业务系统读取结果、会话摘录）按内容哈希存档，按空间与授权可见。
   - 条目详情能打开所引原文，定位到引文。
3. **成员停用与删除**：
   - 停用：个人空间冻结，授权暂停；恢复后照常。
   - 删除：清除 Hub 上该成员个人空间的内容，记录只留内容哈希。复用第四阶段的可清除存储与清除流程，与切回“仅保存在本机”走同一条路径，不另写一套。
   - 分享到团队的知识与记忆属于团队，保留不动；分享人显示为“已删除的成员”。其中依赖已清除个人来源的部分变为待验证，管理员可见。
   - 删除前在控制台提示影响范围，并由管理员确认（沿用决定 75 的命令与记录）。
4. **容量**：
   - 每个成员在 Hub 上的个人空间默认 1 GiB，管理员可在团队页调整。
   - 超出时拒收新的写入与同步，提示还剩多少、该怎么做。
   - 第二阶段已做的部分只补管理员的调整入口与提示。
5. **界面与文档**：控制台各处的“规划中”标记与实际一致；`docs/design/knowledge-workflows.md` 末尾补“实施状态”一节，逐项写明完成情况与对应决定。
6. **测试**：
   - 署名与拒收、原文打开与定位、停用与恢复、删除后的清除与团队条目保留、容量超限与调整。
   - 改动波及的验收场景。
