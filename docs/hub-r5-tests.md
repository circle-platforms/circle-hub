# Hub R5 测试设计：按资源分类的常见工作场景

目的：开发结束后，五个角色改做测试，按本文逐场景验收。每个场景既是验收用例，也是教 Circle 做这类工作的范例。

## 格式

- 每个场景分三栏写步骤：**Circle 向 Hub 要什么信息**、**Circle 自己做什么操作**、**做完后 Hub 核对什么**。
- 两个数据层：**合成层**进 tests/acceptance（合成产品 ORBIT/COMET（同一产品两个名字）与 lumen-api、合成连接器、临时 PostgreSQL），由机械判定；**真实层**在 Otty 用真实 Circle、真实平台和已登记的台架跑，结果由所有者判断，记录只留本机，不进 Git。
- 每个场景必须有反例：Hub 必须拒收或反驳的输入。
- 写回范围（决定 74）：Circle 的产出（报告、起草的用例、缺陷候选、复现记录）只写 Circle 本地路径，除 Hub 外不上传到任何现有系统；Hub 也不写回系统。所有真实平台（敏捷平台、PLM、手册库、SVN）在测试里一律只读。
- 通过标准：合成层全部机械通过；真实层每个场景至少一次完整跑通，终态与预期一致，所有未知都带缺的事实与下一步。

## T1 只要知识

### T1-1 知识问答

- 前置：版本线 L 的树苗已育成；用户在 Circle 里提问某命令或功能在 L 上的行为。
- 步骤：

| Hub 给信息 | Circle 操作 | Hub 核对 |
| --- | --- | --- |
| get_nodes 读 L 的命令节点与手册章节，含旁挂的用例、缺陷、教训及其等级 | 组织回答，每条结论附逐字引文 | resolve_reference 逐条解析引文；根与 L 一致；有矛盾标记的条目回答必须带限定 |

- 预期：回答里每条引文都能解析；引用了声明级教训时标出出处等级。
- 反例：引文改动一个字 → 解析失败，Circle 必须改正；引用别的版本线的根 → 拒绝。
- 不需要任务包。

### T1-2 测试脑图评审全链

- 前置：一份脑图（合成层用夹具；真实层用敏捷平台文档）。
- 步骤：定位（case-location）→ 初评（case-review）→ 独立复核（case-review-verify，另一账号与另一模型家族）→ 终稿（case-review-report）。

| Hub 给信息 | Circle 操作 | Hub 核对 |
| --- | --- | --- |
| 定位结果、锁定根、要求项、规程 | 按 test-list-review 写七类发现与等级；复核者按 review-verifier 逐条处置并用七个探针找遗漏 | 字面问题、命令与目录、引文与位置由 Hub 判；发现必须逐字引用；严重度与 P 等级区间一致；复核必须有前驱且独立；终稿唯一结论 |

- 预期：初评受理、复核 PASS/PARTIAL/FAIL 之一、终稿受理；分区计数相加等于条目总数。
- 反例：同账号或同模型家族复核 → 提交保存但独立性要求项不满足（原因：独立性未知），终稿不放行；命令树里有的命令被说成不存在 → 反驳；PASS 却带需要修正的发现 → 拒绝；终稿两个结论 → 拒绝。

### T1-3 按模板 v3 查缺

- 步骤：template-gap 对一份文档核 24 类，对锁定构建的用例索引核每个已解析命令的 9 类覆盖。
- 预期：缺的类别逐条列出，缺输入时写补齐动作、对象和期限。
- 反例：标签不在声明闭集 → 结构违规（提示档），不做同义映射。

## T2 平台事实

### T2-1 用例定位

- 步骤：文档编号（敏捷平台的脑图文档号；用例的长编号不作输入，Hub 不拆编号）→ case-location → 产品线、版本、版本线、发布火车、模块；两个名称族的构建候选；作者声明的需求与缺陷编号。
- 预期：每项都有依据（目录结构或声明）。
- 反例：目录语法认不出 → 未知并给出口；目录与标题构建名不一致 → 反驳。

### T2-2 按编号读原件（source-read）

- 步骤：Circle 用通用技能包 source-read 读一条缺陷、一条需求、一份脑图、一页构建页、一份手册文件、一份 SVN 文件。
- 预期：每份返回原件引用、投影、版本绑定、矛盾计数；读取记录存在；凭据扫描命中的按只保留档处理。
- 反例：编号不存在 → 拒绝并写明；路由未声明 → 拒绝；连不上 → SOURCE_UNREACHABLE 带下一步。

### T2-3 缺陷转用例

- 步骤：缺陷（现象、修复说明）→ defect-to-case 起草 → Hub 核命令与参数、期望引文、结构、重复。
- 预期：期望全部逐字出自修复说明；重复用例按规范化结构判出。起草的用例只写 Circle 本地路径，不回写敏捷平台。
- 反例：期望不出自修复说明 → 反驳；修复说明缺失 → 未知并给具名请求。

### T2-4 追溯矩阵

- 步骤：构建的修复清单 → traceability → 每个缺陷有没有已索引用例携带其编号。
- 预期：没有索引的记未知，写明索引缺口。

### T2-5 需求追溯矩阵

- 步骤：需求编号 → story-traceability → 命中用例与条目下限。
- 反例：无法判断的编号 → 只拒绝该编号。
- 真实层说明（2026-10-27 第一批）：真实用例索引里没有任何用例声明需求号（stories 全空），所以真实层只能展示"没有已索引用例携带该需求 → 未知并点名索引缺口"这一支；命中用例与条目下限的正例只在合成层验。不回写任何平台（决定 74），也就不能靠补声明造正例。

### T2-6 质量看板

- 步骤：quality-board 按（版本线、模块）分组统计。
- 预期：阈值越界只是提示档，从不阻断；输入外部标识写明产品和构建。

## T3 构建差异

### T3-1 回归范围

- 步骤：两个构建 → regression-scope → 按路径列命令差（变更种类）→ 命中用例。
- 预期：差集由 Hub 算；命中按锁定目录的完整语法解析，不按关键词。

### T3-2 维护巡检

- 步骤：maintenance-sweep → 命令已删除的用例记阻断；定义有差异的记提示并逐字段给两边的值。
- 反例：目录完整性由读取器自己计算，调用方不能缩小或伪造目录（用 only= 之类缩小、或上传残缺文件）：残缺绑定在启动期被拒；视图漏定义条目时该条记未知，不当作一致。

## T4 设备

### T4-1 用例转自动化（五例：IPv4、IPv6、端口接口、bond、SLB VIP）

| Hub 给信息 | Circle 操作 | Hub 核对 |
| --- | --- | --- |
| 台架事实（设备、接口、网段、触发设备）、锁定根、合约、床面基线 | 按 case-compile 方法写计划：自己选口选地址、补前置（如先建被查询记录）、机械断言、逆序清理，含"恢复到捕获值"；用本地工具生成工作簿；上传；开核验运行 | 身份与授权范围、参数类型与地址角色、逆操作义务、不得删作者命令、容量与可达性、工作簿逐字节重算、放行条件、跑前残留、跑后恢复 |

- 预期：设备判定 PASS，Hub dynamic_terminal PASS（带结果归属认证），跑前跑后探针原文逐字节相等，床面恢复。
- 反例：有残留 → 不派发并列差异行；缺逆操作 → 反驳；设备超容量 → 整卷拒绝；地址在盲网段 → 编译期拒绝；同一工作簿第二次派发 → 拒绝。

### T4-2 SSH 只读排障（Circle 自己操作）

| Hub 给信息 | Circle 操作 | Hub 核对 |
| --- | --- | --- |
| 命令树节点、手册章节、台架事实 | 用自己的 SSH 登录已预订的设备，执行 show 类命令；钩子自动上传回显为原件并提交操作记录 | 每条命令按锁定根解析；回报里的引文逐字出自回显原件 |

- 预期：操作记录带会话、设备、时间、原件；团队可检索。
- 反例：命令树里没有的命令 → 核对反驳（提示，不阻止操作）；引文不在回显里 → 拒绝该条。

### T4-3 SSH 改配置（带前后比较与逆操作）

- 步骤：捕获前状态 → 改配置 → 捕获 → 执行逆操作 → 再捕获；三次捕获都上传。
- 预期：Hub 核对逆操作按产品声明存在；恢复后的捕获与前状态逐字节相等；操作记录绑定租约。
- 反例：未恢复 → 记"床面未恢复"并阻止该台架下一次派发；无租约操作 → 记录但标未授权。

### T4-4 用户问题复现

| Hub 给信息 | Circle 操作 | Hub 核对 |
| --- | --- | --- |
| source-read 读问题单；定位版本线与构建候选；台架搜索（构建一致）；相关命令与手册；已有教训 | 预订台架，按问题单现象设计复现步骤，SSH 执行，捕获回显 | 版本绑定来自问题单结构与台架在装构建；现象引文逐字出自问题单；回显引文逐字出自捕获 |

- 预期：结论为"已复现"或"未复现"，未复现时写明差异条件（构建、配置、拓扑）。
- 反例：没有匹配构建的台架 → 未知并写明缺什么；现象描述被改写 → 拒绝。

## T5 WebUI

### T5-1 WebUI 功能测试（Circle 浏览器操作）

| Hub 给信息 | Circle 操作 | Hub 核对 |
| --- | --- | --- |
| APP 手册章节（导航、表单、取值）、模板方法 | 用自己的浏览器登录与操作；钩子上传页面文字与截图为原件；写报告 | 报告里的页面文字引文逐字出自捕获；步骤结构合模板；手册与页面不一致处打矛盾标记 |

- 预期：报告受理；不一致处的缺陷候选只留在 Circle 本地，漂移记录只由 Hub 对矛盾标记产生。
- 反例：声称的页面元素文字不在捕获里 → 反驳。
- 真实层：所有者已授权使用本机已有的设备 WebUI 凭据（2026-10-27），只放 Circle 本地密钥库，Circle 用 %NAME% 引用，不进 Hub、不进 Git。WebUI 测试和 SSH 操作一样用台架，先走台架预订；设备在跳板机之后，经本机端口转发访问。

## T6 积累闭环

### T6-1 操作记录自动上报

- 步骤：跑完 T4-2，在 Hub 里查该会话的操作记录与原件。
- 预期：记录存在，出处 client_captured，等级"声明"，团队可见；get_nodes 读相关命令节点时一并返回。

### T6-2 教训沉淀与检索

- 步骤：Circle 整合技能从共享会话提炼一条 pitfall（带逐字引文）回注；另一用户在新会话问同一命令。
- 预期：回答里带出该 pitfall 及其等级与出处。
- 反例：引文不在原件里 → 整条拒绝；版本由模型推断而非结构 → 拒绝。

### T6-3 矛盾与撤回

- 步骤：pitfall 与手册矛盾 → contradicts 关系；依赖它的结果带限定；管理员撤回。
- 预期：两边都返回，不裁决；撤回后条目失效但不删除。

## T7 治理

- T7-1 独立性：同账号或同模型家族复核 → 提交保存，但该复核不满足独立性要求项（原因：独立性未知），终稿不放行，等独立复核；换成另一账号和另一模型家族后满足。
- T7-2 判据变更：作者改判据 → criterion-review 由非作者账号复核。
- T7-3 权限：未分配包的用户只看到"对你不可用"与同形空集。
- T7-4 变更集审批：包的变更集经独立复核者批准后才启用。
- T7-5 派发：同一意图成功派发后再次派发 → 拒绝；租约被占 → 第二次预订拒绝；回执丢失 → 冻结直到管理员对账；已认证的重试前提（目标声明可容忍重复）下同一请求编号可再投一次，结果记为可能重复，不算拒绝缺口。
- T7-6 未知不终态：普查所有运行，停在未知上的记为缺陷；每个未知都带缺的事实与下一步。

## T8 产品无关

### T8-1 第二产品走同一套包

- 步骤：lumen-api 做 T1-2 评审与 T2-3 缺陷转用例。
- 预期：核心代码无产品名；结果形状与 ORBIT 相同。

## T9 健壮性

- T9-1 平台不可达与凭据扣留：不可达 → 带下一步的失败；扣留 → 管理员受理后重读成功。
- T9-2 解析器包缺失：运行需要的通用技能包未安装 → 拒绝并点名；安装后通过；旧运行的引用仍按锁定摘要可复核。
- T9-3 重启续跑：运行中重启 Hub；已存结果不变；晚到报告续跑。

## 执行方式

1. 合成层：codex 先把每个场景写成验收用例骨架（输入、调用序列、预期回执与终态、反例），各角色按类别填充并跑绿。
2. 真实层：按类别在 Otty 执行，每个场景记一行到本机 plan.md：运行号、终态、与预期的差异；所有者判定。
3. 真实层发现的每个偏差先归类：实现回归、期望落后、数据缺口，再决定改代码、改期望还是补数据。
