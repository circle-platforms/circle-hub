## 包函数的隔离

按 [Hub r4 架构](hub-r4-architecture.md)，工作流或技能里的函数在受限的子进程里运行（由 rules 包实现，待复核）：Node 权限模型禁止写文件和起子进程，只许读解压后的包；架构简报记录了在 Node 24.17 上核实过权限模型不限制网络，所以子进程另在 macOS `sandbox-exec` 下运行并禁止网络；另有时间、内存和输入输出大小的限制。在 Linux 上，这一层是 bubblewrap 加管理员装载的 Hub AppArmor 策略（见 [rules 包说明](https://github.com/circle-platforms/circle-hub/blob/main/hub/rules/README.md)）。没有可用的操作系统隔离的地方默认拒绝运行包内函数（`SANDBOX_UNAVAILABLE`）。其他平台上的等价隔离尚未确定。

公开 CI 在 Ubuntu 上运行。拉取请求只跑快的检查（`Types`、`Generated contracts match the model`、`Docs and CI checks`；其中 `Docs and CI checks` 以完整 Git 历史 `fetch-depth: 0` 运行 `npm run test:docs`，包含 `package-boundaries`、`package-cycles`、`core-names-no-pack`、`no-compat-paths`、`doc-set`、`contract-schema-freeze`、`tool-input-stability`、`test-suites`、`address-id-check` 和遇到浅克隆就失败的 `pack-version` 检查；另跑 `Reference archive`）；完整的测试由合并队列在将成为 main 的那个提交上运行，每次推送到 main 也再跑一遍。在拉取请求上，各分片和汇总它们的检查（`Unit tests`、`Acceptance on a temporary PostgreSQL`、`Linux isolation`）都跳过，必需检查把跳过算作通过；在合并队列和 main 上，每个汇总检查要求它的所有分片都通过。默认单元测试（`npm run test:unit`）只纳入 `scripts/real` 里守卫、Circle 主目录、预检和工具声明的十一个测试；其余 `scripts/real` 测试（真实系统验收、数据转换和诊断脚本）在 `.github/checks/test-suites.ts` 里列为不在默认测试集，需要时用 `node --test` 直接运行；单元测试任务从 PostgreSQL 的 apt 源安装 18 版客户端，所以备份、恢复和部署的用例在那里运行。包内函数的沙箱用例，包括对真实监听的本机服务器验证的断网，由 `Linux isolation` 任务运行：合并队列和每次推送到 main 都会触发，它安装 bubblewrap 和 AppArmor，为本任务的 Node 生成并装载 Hub 的 AppArmor 策略，隔离不可用就直接失败，然后运行按跳过条件从源码选出的单元和验收测试文件。它不改 `kernel.apparmor_restrict_unprivileged_userns`，启动器策略自带的 `userns` 规则已经够用。其他单元和验收任务没有隔离，这些用例在那里跳过。Ubuntu 上没有 `sandbox-exec`、plutil 和 launchd，所以 `sandbox-exec` 本身、plutil 和 launchd 的检查在 Ubuntu 上跳过；密钥文件在每个平台上都一样，它们的用例在那里运行。这些用例由 `macOS-only paths` 工作流在 `macos-15` 上运行，沙箱用例也在那里经 `sandbox-exec` 再跑一遍：每次推送到 main、每晚一次，也可以手动触发；拉取请求不触发它，它也不是必需检查。所以合并队列的检查是 bubblewrap 与 AppArmor 下沙箱的证据，但不是 `sandbox-exec`、plutil 和 launchd 的证据；拉取请求自己的检查对两者都不是证据。跳过不算通过；每个阶段仍在本机 macOS 上完整运行一次，命令、计数和跳过的用例记在 [Hub r4 进度](hub-r4-progress.md)里。CI 的任务摘要列出每个跳过的用例。

## 密钥存放

所有者 2026-11-03 定下（决定 137）：Hub 不再使用 macOS 钥匙串。macOS 和 Linux 一样，密钥库主密钥和操作令牌各是数据根 `keys` 目录下的一个 32 字节文件（目录 0700，文件 0600，属于服务账户），不进备份。`CIRCLE_HUB_KEYCHAIN_SERVICE` 和 `CIRCLE_HUB_KEYCHAIN_ACCOUNT` 已停用：进程里设了其中任何一个（空值也算）就不启动，并说明密钥现在在哪里。部署设置保留 `keychain_service` 和 `keychain_account` 两个字段，现在用来给密钥文件命名，所以回滚到的发布读的还是同一份设置文件。密钥还在钥匙串里的 macOS 部署，在运行含这项改动的发布之前先把它移出来：用先前发布的 `circle-hub key export --confirm` 通过管道交给新发布的 `circle-hub key import`，然后运行 `circle-hub operator-token reissue`。

密钥的各个版本、摘要规则、长度、设置者和设置时间存在数据根的 `vault/` 里，由密钥库认证，不在记录库里；重置重建时 `keys/` 和 `vault/` 都保留。

## 发布顺序

1. Hub 先：模型或合约变化时提升对应 schema 的主版本（`name@major`）并更新本页；发布需要所有者另行决定。
2. Circle 不随 Hub 同步发布：它只是 MCP 客户端，依赖的是 MCP 协议和工具的 schema。
3. 工作流与技能各自带版本，上传时自动跑包内的正例与反例（发布校验），不过不发布。

升级 `foundation/circle` 基线和各仓库的标识改名都是单独的决定，各留一条记录在本页的“历史”里。

## 历史

- 2026-11-24：合并整合分支之前的裁定（决定 194）。登录应用的配置（密钥库条目 `personal-bot.identity`）新增可选字段 `adminLogin`：绑定了外部身份的管理员账号默认不能用扫码登录控制台（`403`），在设置页「扫码登录应用」勾选「允许管理员账号用扫码登录控制台」，或在 `circle-hub bot identity-set` 的 JSON 里写 `"adminLogin": true` 才允许；发给通道适配器的配置不带这个字段。更早的提交按严格格式读这个条目，不认识这个字段：回滚到那样的提交之后要重新保存一次登录应用配置，否则扫码登录和私聊通道读不出配置。D06 R[1] 修订：Circle 里与 Hub 有关的界面限于按地址连接 Hub 的 Hub 扩展和成员私人机器人的对话页。机器人接口仍只接受成员自己的访问令牌；授权时由成员同意、此后登录令牌也可使用的机制已定要做，尚未做。
- 2026-11-24：机器人与外部通道安全与协议对齐（模型第 89 版、`release/2026-11-23` 之后未发布新兼容破坏）：
  - 入口鉴权与客户端隔离：`POST /api/bot/v1` 与 `GET`/`PUT /api/bot/v1/files/<sha256>` 强制直连成员 Bearer 令牌，拒绝 OAuth 授权应用令牌（`403 BOT_CLIENT_FORBIDDEN`）；`/mcp` 与 `/local-tools/*` 继续接受 OAuth 令牌。`/api/bot/v1` 要求请求头 `Bot-Client-Version` 满足严格 SemVer 2.0.0（缺失或格式无效返回 `400 BOT_VERSION_INVALID`，主次版本不兼容返回 `400 BOT_VERSION_MISMATCH`，接受预发布号与构建元数据）；发送给宿主的路由标识统一写为 `route.source = 'client'`，不暴露客户端名称。
  - 外部通道与文件暂存提升：`POST /api/bot-channel/v1` 与 `GET`/`PUT /api/bot-channel/v1/files/<sha256>` 改用 `Bot-Member-Subject` 头；通道 `PUT` 只写入 `bot-runtime/channel-staging/<hash>/<sha>`，直到 `{ action: 'inbound' }` 校验暂存文件并追加 `member-bot-inbound@1`（`provenance: 'declared'`）后才提升到成员文件目录。通道 `GET /api/bot-channel/v1/files/<sha256>` 同时要求 `Bot-Member-Subject` 与 `Bot-Delivery-Receipt`，并核对 `chat-intent:<receipt>` 匹配的通道、成员与 `file_sha256`。
  - 投递意图、回执与去前缀：`member-notification-intent@1` 同时覆盖 `role`（必填 `bot_message_role`）、可选严格提示码 `code`（`/^[a-z0-9_]{1,64}$/`）、`text_sha256` / `text_size` 与 `file_sha256` / `file_size` / `name_sha256` 及总 `sha256` / `size`；Hub 不再为转发文本添加前缀，`handleChannelNext` 接受 `bot_message_role` 的 `user` / `assistant` / `notice` 及可选错误提示 `code` 并原样转发（意图摘要仍只按 `text` 与 `file` 计算）；`member-notification-receipt@1` 改用 `EffectOutcomeSchema`（`issued`、`unknown`、`target_rejected`、`not_dispatched`）与 `declared` 来源，支持从 `unknown` 追加 `:confirmed`（带 `supersedes`）升为终态、同内容幂等重试（`200`）与冲突更新拒绝（`409 BOT_CONFLICT`）；缺失待投递附件时先向宿主上报 `not_dispatched` 再答 `409`。
  - 合约、配额、超时与安全日志：模型词表新增六个轴（`bot_model_protocol`（`openai`、`anthropic`、`responses`）、`external_identity_action`、`external_identity_unbind_reason`、`bot_secret_action`、`bot_secret_slot`、`bot_message_role`（`user`、`assistant`、`notice`））与十二个 `BOT_*` 协议码（`BOT_DISABLED`、`BOT_UNAUTHENTICATED`、`BOT_CLIENT_FORBIDDEN`、`BOT_NOT_FOUND`、`BOT_VERSION_INVALID`、`BOT_VERSION_MISMATCH`、`BOT_QUOTA_EXCEEDED`、`BOT_UPSTREAM_UNAVAILABLE`、`BOT_REQUEST_TIMEOUT`、`BOT_CONFLICT`、`BOT_BUSY`、`BOT_INVALID_REQUEST`，及统一错误格式辅助 `formatCallError`），所有 `/api/bot*` 与 `/api/bot-channel*` HTTP 错误响应（含未匹配路径、方法不受理、限流与请求体接收超时）统一返回 `{ code, message }`；新增审计契约 `member-external-identity@1`（带密钥 HMAC 摘要）与 `bot-secret-change@1`；机器人私聊附件限单文件 `100 MiB`（`fileLimit`）、每成员 `512 MiB`（`MAX_MEMBER_BOT_BYTES`）与 `256` 份文件（`MAX_MEMBER_BOT_FILES`）、`30` 天保留期（`BOT_FILE_RETENTION_MS`，上传配额检查前先清理过期文件，启动及每小时定期执行 30 天过期扫描，超出配额返回 `413 BOT_QUOTA_EXCEEDED`）；`cleanupBotRuntimeTempFiles` 对残留 `.part` 与 `channel-staging` 按 `15m` 年龄门槛清理以免误删在途上传；HTTP/HTTPS 监听设 `requestTimeout: 0` 并按路由施加**请求体接收**超时（`PUT /api/bot*/files/*` 为 `900s`，其余路线 `120s`，超时返回 `408 BOT_REQUEST_TIMEOUT`），不限制 MCP `tools/call` 与 SSE 的响应输出时长；`bot-runtime` 在首次使用或启动时按 `0o700` 自动创建，并在发送密钥或传输附件前经 `lstat` 核对非符号链接、目录类型、`0o700` 与当前用户属主；`circle-hub bot set | disable` 先向宿主发送带递增 `configVersion` 的 `refreshHost`（仅在套接字不存在时报告宿主未连接，其余通知失败遮盖密钥后如实输出并记入 stderr）再记录审计，Hub 启动（`listen`）时也会在存在模型或版本条目时自动发送恢复/启动配置通知（覆写宿主内存中可能更高的 `configVersion`，套接字不存在时不报错），`bot test` 及每次运行时 `callBot` 均附带当前 `config`（未启用时为 `null`）与 `configVersion`；`callBot` 与错误映射遮盖全部密钥库密钥且不向成员透传宿主原始报错，后台 `refreshChannel` 异常记入日志；外部身份控制台入口位于 `/console/identity/*`（同一来源待完成扫码请求超限返回 `429` 与 `Retry-After: 60`），管理命令为 `circle-hub bot set | disable | test | identity-set | identity-remove | identity-unbind <用户> [--issuer] | channel-set | channel-remove | channel-start | channel-stop`（设置或停用模型时自动清理遗留审校槽位 `personal-bot.reviewer`）。
