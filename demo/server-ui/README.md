# Circle Server 企业平台设计 Demo

这是前端交互原型，用来评审 Circle Server 的产品结构和工作流程。全部资料、人员、任务、运行、设备、指标和工程故事都是合成样例；输入只保存在当前浏览器。没有正式后台、公司 SSO、真实资料同步、模型调用或设备连接。

Server 以 Agent 为配置入口，提供职责、知识与工具、测试、版本和运行记录。Circle 是使用入口，选择已发布的 Agent 后委派和跟进工作。公司资料、执行环境、权限、观测、审计和研发交付作为共享或治理对象独立维护。

四对象的状态职责保留在设计详情中。B 保存知识、原件、证据与制品；C 保存持续工作、输入、运行和人员决定；D 持有操作、节点与现场；E 管理产品方法、规则和判断。这个前端的本地模拟器不作为任何正式服务的实现或安全边界。

## 本地运行

使用 Node.js 24：

```sh
npm ci
npm run dev
```

默认地址是 `http://127.0.0.1:4317/`。`npm run build` 生成静态网页；`npm test` 检查前端模拟状态的关键约束。

浏览器检查使用 Playwright 的隔离上下文：

```sh
npm run test:browser
```

需要可用 Chromium；也可以通过 `DEMO_BROWSER_EXECUTABLE` 指定已有的隔离测试浏览器，`DEMO_BASE_URL` 指定预览地址。这些测试不读取个人浏览器配置，也不验证生产服务、模型质量或设备效果。

## 从哪里开始看

1. 在 Agents 打开“网络排障 Agent”，编辑草稿、查看测试步骤，在“版本与发布”完成演示评审与发布；旧工作保留原版本。
2. 切换 Circle，选用 Agent、输入目标。可以断开再重连，回到同一项工作、运行和证据。
3. 在任务详情查看交互、步骤、运行、证据和未知项；补充输入产生新修订，旧运行的输入保持不变。
4. 从任务进入关联 SSH/Web 现场。查看与控制分权；接管后 Agent 等待；停止先记录请求，再模拟独立核对。
5. 知识库展示来源权限、固定修订、六类记录与发布快照。同步和发布不静默更改在途任务。
6. 自动化分别展示规则、每次运行和长期工作；暂停未来触发与停止当前实例是两个动作。
7. 切换安全管理、运维或审计身份，查看各自允许的内容。可以从异常追到任务，从动作追到政策、输入和原始记录。
8. 研发交付看板区分工程故事、代码、组合验收和发行；系统设计页展示对象关系和调研依据。

顶部身份切换只用于展示不同人员的视图。正式 server 需要可信身份接入，并在查询、原件读取、执行、接管、发布和恢复路径上强制检查。前端限制不能代替这些检查。
